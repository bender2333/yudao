Spec-driven Mission Flow

OpenSpec-style artifacts drive the work; Mission owns state, routing, and history.

End-to-end Flow
From intent to operational feedback
User Intent -> MissionCommand
Exploration -> MissionBrief + SpecProposal + scenarios
SpecChange -> proposed behavior delta, scope, acceptance
Design & Build -> design.md + tasks.md + patch
Verification -> scenario evidence + verdict + failure classification
Archive / Sync -> accepted behavior promoted to canonical specs
Ops Feedback -> runtime drift, incident, retrospective, new SpecChange
