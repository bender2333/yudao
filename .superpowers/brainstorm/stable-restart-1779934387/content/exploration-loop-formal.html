需求探索与瓦解循环

这是 Mission 系统的第一个正式循环：入口 agent 可以参与探索，但后续推进由 Process Orchestrator 按规则决定。

Self loop and forward progression
Inputs
入口与上下文
  • 用户自然语言
  • Hermes / OpenClaw 对话
  • 附件、截图、日志、PR、Issue
  • 仓库扫描和历史 mission
  • 运维反馈或告警
Loop

Explore & Decompose

澄清目标、补齐上下文、识别假设、限定范围、定义验收、拆分子 mission。

needs_input → ask
too_large → split
low_confidence → gather
ready → progress
Outputs
结构化事实
  • Mission Brief
  • Question Set
  • Assumption Set
  • Scope Boundary
  • Acceptance Criteria
  • Child Mission Proposals
Exit Gate
Readiness Assessment + Autonomy Mode

是否推进不只看 readiness，还要看当前 mission/loop 的自主模式。全自动可带假设推进；默认自主只问必要阻塞问题；半自主会给方案让人选；人工主导由人明确推进。

Mode 1
人工主导

agent 只整理问题和建议；必须由人点击推进。

Mode 2
半自主推荐

agent 给探索结论和推进选项；人选择下一步。

Mode 3
默认自主

只问必要阻塞问题；非阻塞假设记录后继续推进。

Mode 4
全自主

按最佳假设直接推进；只在强制安全策略命中时 gate。

Stay
继续探索

缺上下文、问题阻塞、证据不足。

Split
瓦解子 mission

范围过大、依赖复杂、目标可并行。

Gate
进入人工确认

高风险、目标冲突、资源或权限敏感。

Forward
推进设计与构建

探索达到当前模式下的推进阈值。

正式规则

A

需求探索与瓦解 = 自循环 + Readiness Gate + Autonomy Mode

入口 agent 负责形成事实和建议；Process Orchestrator 结合 readiness 与自主模式，决定继续探索、拆分、人工 gate 或推进设计与构建。
