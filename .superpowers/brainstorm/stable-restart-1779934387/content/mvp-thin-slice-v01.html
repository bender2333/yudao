MVP 薄切片 v0.1

第一版不追求每个环节深，而是打通 AI/Agent Native Mission Platform 的完整闭环。

End-to-end MVP flow
1 Entry
Hermes / OpenClaw

自然语言创建 Mission。

2 Explore
探索 DAG

生成 brief、问题、假设、验收。

3 Decide
流程编排者

按 policy 和自主模式推进。

4 Build
设计构建 DAG

方案、计划、patch、基础构建。

5 Verify
检查验证 DAG

测试、review、失败分流。

6 Feedback
反馈与评估

运行反馈、artifact、evaluation record。

Must work in MVP
端到端闭环能力
  • 入口 agent 创建 MissionThread / Mission
  • 探索 DAG 跑到 Node 粒度并产出 artifacts
  • Process Orchestrator 根据 mode 和 readiness 决策
  • 设计构建 DAG 调用至少一个代码 agent runtime
  • 检查验证 DAG 能做三向分流
  • Web Console 能看 Mission、Run、Node、Transcript
  • 每次 run 生成 EvaluationRecord
Can be shallow in MVP
第一版先做薄
  • Autopilot 先支持手动和 webhook，定时可后置
  • 运维反馈先手动录入或 webhook 模拟
  • 审批先做单人 gate，不做复杂会签
  • 进化先做评分和候选建议，不自动晋升
  • Runtime 先本地，云沙箱预留接口
  • 固定角色团队，暂不开放任意拓扑
P0 API
MissionCommand

create_mission、append_context、request_next_step、approve。

P0 Runtime
DAGRun / NodeRun

模板、节点、输入输出、状态、消息、artifact。

P0 UI
Mission Console

Mission detail、run timeline、agent live、approval inbox。

P0 Data
Event + Artifact

append-only event、artifact refs、evaluation record。

MVP Success
一条 Mission 能从入口 agent 创建，经过探索、构建、验证和反馈，在 Web 上完整追踪，并留下可评估的 run/node 历史。

这就是第一版“流程打通”的验收标准。

MVP 定义

A

MVP = Mission 全闭环薄切片

入口 agent、Mission Core、Process Orchestrator、EvoAgentX-style DAG/Node、Multica-style Web Console、EvaluationRecord 必须串通。
