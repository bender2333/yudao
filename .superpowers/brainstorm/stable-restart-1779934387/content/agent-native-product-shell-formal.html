AI/Agent Native 交互层

Product Shell 不是传统项目管理前端外挂 AI，而是 agent 原生入口 + 可观察控制台 + 配置治理面。

Interaction layer contract
Primary Entry
Hermes / OpenClaw Agent
  • 创建 mission
  • 需求探索和追问
  • 查看状态和摘要
  • 处理必要审批
  • 追加反馈和上下文
  • 触发下一步建议
Web Console
观察、配置、干预
  • Mission 列表和详情
  • Run timeline / transcript
  • Artifact 和 decision 查看
  • Approval inbox
  • Agent / Runtime / Skill 配置
  • Policy / Template 版本查看
Automated Entry
Autopilot / Webhook / Monitor
  • 定时巡检
  • Webhook 触发
  • 告警触发
  • PR / comment 触发
  • CI 失败触发
  • 用户反馈触发
Command
MissionCommand API

所有入口都用同一套命令写入平台事实源。

→
Backend
Mission Platform

保存 Mission、Run、Event、Artifact、Decision、Approval。

→
Stream
MissionEvent Feed

推送状态、消息、工具调用、制品和审批事件。

Mission
任务中心

目标、循环、子 mission、当前阻塞。

Run
执行追踪

DAG、节点、agent、tool call、日志。

Artifact
证据制品

需求、设计、patch、测试、PR、发布。

Agent
能力配置

角色、模型、skills、plugins、env、权限。

Runtime
执行环境

本地 daemon、云沙箱、CI、连接状态。

Hard Boundary
UI/Agent entry is not source of truth

Hermes、OpenClaw、Web Console、Webhook 都只是入口；Mission Platform Backend 才是唯一状态源。所有操作必须产生 append-only event。

正式规则

A

交互层 = Agent 原生入口 + Web 控制台 + 自动触发器

参考 Multica 的 agent/runtime/task 追踪体验，但所有入口统一走 MissionCommand API，所有状态统一落到 MissionEvent 流。
