v0.1 第二阶段：自举

平台要能用自己的 Mission 系统开发自己：自举既是 dogfooding，也是最早的进化数据来源。

Self-bootstrap loop
1 Internal Mission
平台自身需求

例如：新增 Approval Inbox。

2 Mission Loop
探索/构建/验证

用自己的循环推进。

3 Code Change
修改本仓库

DAG run 调用代码 agent。

4 PR / Release
提交自身变更

生成 PR、验证、发布。

5 Learn
沉淀进化样本

评估流程、模板、agent 能力。

Phase 1
v0.1A：外部项目闭环
  • 能创建 Mission
  • 能跑探索/构建/验证 DAG
  • 能在 Web Console 追踪
  • 能记录 artifact/event/evaluation
  • 能接一个代码 agent runtime
Phase 2
v0.1B：自举开发
  • 本平台 repo 作为首个受管项目
  • 内部需求用 Mission 创建和拆解
  • DAG run 修改平台自身代码
  • 验证失败可分流到探索/设计/修复
  • 生成 PR/变更记录/复盘样本
Bootstrap Guardrails
自举必须更严格

平台修改自身流程、策略、runtime、安全边界时默认需要 human gate；普通 UI、文档、小功能可默认自主推进。

Self Project
平台自身项目

repo、runtime、CI、release 都纳入 Mission。

Self Templates
自举模板

feature、bugfix、refactor、docs、runtime adapter。

Self Review
自我审查

强制验证架构边界和流程状态一致性。

Self Evolution
进化样本

用自身开发数据优化模板、prompt、routing。

正式规则

A

v0.1B = 自举开发能力

平台必须能把自身 repo 当作受管项目，通过自己的 Mission、DAG、Node、Web Console 和 EvaluationRecord 来开发、验证和改进自己。
