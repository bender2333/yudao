需求探索与瓦解 API v0.1

入口 agent 承担探索循环的一部分：把自然语言变成 Mission 事实、问题、假设、验收和子 mission 建议。

Minimal closed loop
1 Entry
Hermes / OpenClaw

用户自然语言、附件、仓库上下文、已有对话。

→
2 Thread
MissionThread

保存入口会话和来源，类似 Multica ChatSession。

→
3 Mission
Mission Draft

创建长期目标容器，状态为 exploring。

→
4 Run
ExplorationRun

EvoAgentX-style DAG run，生成结构化探索结果。

Output A
Questions

需要人补充的问题，带 priority/blocking。

Output B
Assumptions

当前推断、置信度、证据来源。

Output C
Acceptance

验收标准草案、验证方式、风险。

Output D
Sub-missions

建议拆分的子 mission 和依赖。

5 Decision
Process Orchestrator consumes exploration_result

根据 policy 决定：继续提问、启动设计构建、拆子 mission、进入 gate、暂停或拒绝。

Core APIs

A

Thread API

POST /mission-threads, POST /mission-threads/{id}/messages, POST /missions/from-thread

B

Exploration Run API

POST /missions/{id}/exploration-runs, GET /runs/{id}, GET /runs/{id}/messages

C

Fact Write API

POST /missions/{id}/questions, assumptions, artifacts, decisions, child-mission-proposals

D

Orchestrator API

POST /missions/{id}/next-step，让流程管理员按规则判断下一步，而不是入口 agent 自己决定。
