Policy & Gate 模型

自主不是无约束执行。每个 Mission、Loop、DAG、Node、ToolCall 都受 policy snapshot 约束；gate 是策略结果，不是写死流程。

Policy evaluation stack
Scope
Mission Policy

mission 级自主模式、风险偏好、owner、项目边界。

Scope
Loop Policy

探索、构建、验证、反馈各自的推进阈值。

Scope
DAG Policy

模板版本、角色绑定、runtime、超时、重试。

Scope
Node Policy

node 输入输出、失败分流、节点级审批。

Scope
Tool Policy

文件、命令、网络、凭证、发布和删除权限。

Input
Proposed Action

start_run、route_node、tool_call、release、rollback、template_promote。

→
Decision

Policy Evaluator

结合 autonomy mode、risk signals、scope、actor、runtime、tool 和 target environment 计算允许、询问、审批、阻断。

→
Output
PolicyDecision

allow、allow_with_assumption、ask_input、require_gate、deny。

Mode 1
人工主导

流程推进和高影响动作默认 gate。

Mode 2
半自主推荐

给候选动作，人选择；低风险观察可自动。

Mode 3
默认自主

自动推进；只问阻塞问题和高风险 gate。

Mode 4
全自主

按最佳假设推进；hard safety policy 仍阻断。

Hard Gates
任何自主模式都不能绕过
  • 生产发布 / 回滚
  • 破坏性 schema / 数据删除
  • 凭证、权限、安全边界变更
  • 修改 Process Orchestrator / Policy / Runtime sandbox
  • 进化候选晋升为生产模板
Soft Gates
由自主模式和风险决定
  • 需求阻塞问题
  • 范围扩大或子 mission 拆分
  • 大文件修改或跨模块变更
  • 测试覆盖不足但风险低
  • 非生产环境部署或模拟回放
Audit rule
Every gate decision is an artifact and event

PolicyDecision、ApprovalRequest、ApprovalDecision 都必须写入 MissionEvent，并引用 policy snapshot，保证后续复盘和进化能知道当时为什么放行或阻断。

正式规则

A

Policy/Gate = 自主模式 + 风险 + 作用域 + 工具边界

所有执行动作先过 Policy Evaluator；默认自主可自动推进，但 hard gate 永远不能被 agent 或 runtime adapter 绕过。
