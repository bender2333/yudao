API Surface v0.1

所有入口统一走 MissionCommand；所有状态变化写 MissionEvent；Web Console 和 agent 入口读取同一个事实源。

API groups
1 Command API
入口写入
  • POST /mission-commands
  • POST /mission-threads
  • POST /mission-threads/{id}/messages
  • POST /missions/from-thread
  • POST /missions/{id}/feedback
2 Mission API
事实查询
  • GET /missions
  • GET /missions/{id}
  • GET /missions/{id}/events
  • GET /missions/{id}/artifacts
  • GET /missions/{id}/decisions
3 Runtime API
DAG / Node 执行
  • POST /missions/{id}/runs
  • GET /runs/{id}
  • GET /runs/{id}/nodes
  • GET /nodes/{id}/messages
  • POST /runs/{id}/cancel
4 Orchestrator API
流程决策
  • POST /missions/{id}/next-step
  • GET /missions/{id}/loop-state
  • GET /decisions/{id}
  • POST /decisions/{id}/apply
  • POST /decisions/{id}/override
5 Realtime API
事件流
  • WS /events?mission_id=...
  • WS /runs/{id}/messages
  • event: mission.updated
  • event: run.message
  • event: approval.requested
6 Config API
Agent / Runtime / Policy
  • GET /agents, /runtimes
  • POST /agents
  • PATCH /agents/{id}
  • GET /dag-templates
  • GET /policies
Unifying primitive
MissionCommand

Hermes、OpenClaw、Web Console、Webhook、Autopilot 都提交 MissionCommand。后端把命令验证、归档为 MissionEvent，并触发 Orchestrator。

Command example
create_mission 
{
  "type": "create_mission",
  "source": "openclaw",
  "workspace_id": "ws_1",
  "payload": {
    "text": "帮我重构登录模块并发 PR",
    "repo_ref": "repo_platform",
    "autonomy_mode": "default_autonomous"
  }
}
Response example
command accepted 
{
  "command_id": "cmd_123",
  "mission_id": "mis_456",
  "thread_id": "thr_789",
  "event_id": "evt_001",
  "next": {
    "action": "start_dag_run",
    "run_template": "ExplorationRun"
  }
}
API rule
Commands mutate; queries project; events explain.

写操作全部通过 Command API；读操作从状态投影读取；为什么发生变化必须能从 MissionEvent、Artifact、Decision 追溯。

API 确认

A

v0.1 API = Command + Query + Runtime + Orchestrator + Realtime + Config

统一入口写入、统一事实流、统一实时追踪，为 agent 入口和 Web Console 提供同一套平台能力。
