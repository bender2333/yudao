Runtime Adapter Layer

参考 Multica 的 Backend/Session/Message/Result 抽象；ACP 是 Hermes/Kimi/Kiro 等 runtime 的一种协议，不是平台唯一协议。

Runtime adapter contract
From DAG Runtime
NodeExecutionRequest

node_run_id、prompt、cwd、model、tools、env、mcp、policy snapshot。

→
Adapter Interface

RuntimeAdapter.execute()

统一输出 RunMessage stream 和 RunResult；隐藏 ACP、JSON-RPC、stream-json、CLI JSON 等协议差异。

→
To Platform
RunMessage / RunResult

写入 NodeRun、ActionRun、ToolCall、Transcript 和 EvaluationRecord。

ACP
HermesAdapter

hermes acp，JSON-RPC session、permission、tool call。

JSON
OpenClawAdapter

openclaw agent JSON event 输出解析。

JSON-RPC
CodexAdapter

codex app-server stdio / session protocol。

stream-json
ClaudeAdapter

Claude Code stream-json CLI 输出。

Request
NodeExecutionRequest
  • node_run_id
  • runtime_type
  • prompt / system_prompt
  • cwd / repo_ref
  • model / thinking_level
  • mcp_config / tool_policy
  • env_refs / timeout
Stream
RunMessage
  • seq
  • type: text/thinking/tool/status/error/log
  • content
  • tool / call_id
  • input_summary / output_summary
  • session_id
  • created_at
Result
RunResult
  • status
  • output
  • error
  • duration_ms
  • session_id
  • usage / cost
  • artifact_candidates
Security boundary
Adapter receives a policy snapshot, not unlimited local power

Multica 有统一 backend 抽象可参考；但我们必须在 adapter 外层加 workspace containment、tool permission、credential injection、audit、cancel/retry/resume 和 approval integration。

正式规则

A

Runtime Adapter = Multica-style Backend 抽象 + Mission NodeRun 契约

上层只依赖 NodeExecutionRequest、RunMessage、RunResult；ACP、OpenClaw JSON、Codex app-server、Claude stream-json 都只是 adapter 实现细节。
