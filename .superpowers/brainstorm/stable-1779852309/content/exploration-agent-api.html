入口 Agent 与需求探索 API

入口 agent 可承担部分“需求探索与瓦解”循环，但必须把结论写入平台 Mission 事实源。

Mission-native API inspired by Multica
Multica pattern to borrow
Chat / Issue / Comment -> AgentTask
  • ChatSession 保存入口会话
  • SendChatMessage 返回 task_id
  • Issue/Comment 可触发 agent task
  • AgentTask 记录状态和来源
  • TaskMessage 形成实时 transcript
Our mission-native version
Conversation / Signal -> MissionExplorationRun
  • MissionThread 保存入口对话
  • MissionCommand 返回 mission_id / run_id
  • Context/Feedback 可触发探索 run
  • DAGRun 记录状态和来源
  • RunMessage 形成实时 transcript
Conversation API
入口上下文
  • POST /mission-threads
  • POST /mission-threads/{id}/messages
  • POST /missions/from-thread
Exploration API
需求探索与瓦解
  • POST /missions
  • POST /missions/{id}/context
  • POST /missions/{id}/explorations
  • POST /missions/{id}/submissions
Artifact API
结构化探索结果
  • POST /missions/{id}/artifacts
  • POST /missions/{id}/assumptions
  • POST /missions/{id}/questions
  • POST /missions/{id}/decisions
入口 agent 可做什么

它可以把自然语言整理成 mission draft、澄清问题、假设、边界、验收标准、子 mission 建议；但是否进入构建、是否拆分、是否要求人审，由 Process Orchestrator 决定。
