MVP: 全流程薄切片

核心不是把某一段做深，而是先打通从需求到运维反馈的可观测闭环。

MVP delivery loop
Intake
需求进入

PRD / Issue / 告警 / 人工输入

Plan
分析与编排

澄清, 设计, 分工, gate

Build
执行与验证

代码, 测试, review, 修复

Operate
交付与运维

PR, 发布, 监控, 事故反馈

闭环信号

运维事件、失败测试、线上指标、用户反馈会自动回流为新任务，保留上下文和决策记录。

每段 MVP 只保留最小能力

1

需求 intake

输入目标、约束、仓库、验收标准；agent 可提出澄清问题并沉淀决策。

2

自主编排

Planner/Reviewer/Implementer/Verifier/Ops agents 协作，系统负责状态、权限、阻塞和人工 gate。

3

受控运行时

连接本地或云端 runtime，运行 coding CLI，捕获日志、diff、测试结果和产物。

4

交付与运维反馈

生成 PR、发布记录、监控观察项；告警或回归失败能回流成带上下文的新任务。
