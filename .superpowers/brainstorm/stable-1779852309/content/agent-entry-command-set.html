Agent-first MVP 命令集

Hermes / OpenClaw 作为第一入口，必须通过平台命令 API 操作 Mission，不能把状态藏在 agent 会话里。

MissionCommand API for Hermes / OpenClaw
Create
创建和补充 Mission
  • create_mission
  • append_context
  • attach_artifact
  • create_child_mission
Orchestrate
请求流程推进
  • request_next_step
  • request_run
  • pause_mission
  • cancel_run
Observe
查询和追踪
  • get_mission_status
  • list_runs
  • get_run_timeline
  • list_artifacts
Decide
审批和反馈
  • approve_gate
  • reject_gate
  • request_changes
  • append_feedback
Agent Input
自然语言 + 上下文

用户在 Hermes/OpenClaw 里说：“帮我把登录重构做完并发 PR”。入口 agent 把意图转成 MissionCommand。

→
Platform Output
结构化状态 + 事件摘要

平台返回 mission_id、当前循环、下一步、run 状态、需要补充的信息、审批卡片和 artifact 链接。

MVP 边界

入口 agent 可以解释用户意图，但不能直接绕过 Process Orchestrator 发起危险执行；所有 run、approval、artifact 都必须落到平台事件流。

第一版入口体验

A

推荐：先做 MissionCommand API

Hermes/OpenClaw、Web Console、Webhook 都走同一套命令 API，后端保持统一事实源。

B

不推荐：先写死 agent 对话逻辑

演示快，但状态和流程容易散落在不同 agent 里，后续难以审计、恢复和进化。
