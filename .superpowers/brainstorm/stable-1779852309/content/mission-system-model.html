Mission 系统模型

把线性 8 阶段改成可循环、可递进演化的 mission 系统。Mission 是长期对象，DAG run 是一次性执行单元。

Mission-centered lifecycle
Loop A
需求探索与瓦解

澄清意图、拆解问题、定义边界、识别假设、形成子 mission。

Loop B
设计与构建

方案、架构、任务计划、代码实现、工具执行、产物生成。

Core Object

Mission

目标、约束、上下文、子任务、证据、决策、风险、当前策略、演化历史。

Mission 可以递归地产生 Sub-mission / Run / Artifact / Decision
Loop C
检查与验证

测试、review、质量门禁、事实核验、失败诊断、是否继续。

Loop D
运维与反馈

发布、监控、告警、用户反馈、事故响应、下一轮演化输入。

Meta Layer
流程编排者 / Orchestration Brain

决定当前 mission 该进入哪个循环、启动哪个 DAG run、是否需要人审、是否生成子 mission、是否结束或沉淀为流程模板。

修正后的核心原则

A

推荐：Mission + 四类循环 + 元编排者

Mission 是长期对象，四类循环反复推进，DAG run 是每次执行单元，流程编排者决定下一步和演化方向。

B

放弃：线性 8 阶段流水线

适合传统交付管理，但不适合表达递进式演化、运维反馈和 mission 递归拆解。
