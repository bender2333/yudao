Mission 系统核心对象

Mission 是长期演化容器；流程编排者只按规则调度；业务能力由 agent run 产出。

Core object model
Long-lived
Mission

目标、约束、上下文、当前循环、子 mission、证据、决策、风险、演化历史。

不是一次任务；是产品/工程目标的持续推进容器。
Business-neutral
Process Orchestrator

读取状态、规则、证据和策略，决定下一步创建什么 run、是否 gate、是否拆解。

只管流程，不判断业务内容。
Executable
DAG Run

一次性 EvoAgentX-style workflow：节点、agent、action、tool、输入输出、轨迹。

执行完归档，结果回写 Mission。
Artifact
制品

PRD、设计、patch、测试报告、PR、发布记录、告警证据。

Decision
决策

人审、agent 建议、策略选择、风险接受、回滚判断。

Event
事件

run.started、test.failed、review.rejected、alert.triggered。

Policy
规则

循环切换、gate、重试、升级、子 mission 生成、模板沉淀。

关键规则

Agent 可以给出 recommended_next_action，但最终是否推进、回退、拆解、暂停，由 Process Orchestrator 根据 policy 决定。

四类循环不是线性阶段

A

需求探索与瓦解

从模糊输入变成可执行 mission/sub-mission，产出边界、假设、验收和风险。

B

设计与构建

把 mission 转成方案、任务计划和代码/配置/文档等工程产物。

C

检查与验证

通过测试、review、事实核验和质量门禁判断是否继续、修复、回退或升级。

D

运维与反馈

发布、监控、告警、用户反馈和事故复盘，持续生成下一轮 mission 输入。
