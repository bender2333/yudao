v0.1 路线与验收

v0.1 分两段：先打通 Mission 全闭环薄切片，再进入自举，让平台开始开发自己。

v0.1 roadmap
v0.1A
Mission 全闭环薄切片

证明平台可以从 agent 入口创建 Mission，跑过探索、构建、验证、反馈，并在 Web Console 可追踪。

Mission Core + MissionEvent
Process Orchestrator MVP
EvoAgentX-style DAG / Node runtime
Hermes/OpenClaw entry command
Multica-style Web Console tracking
EvaluationRecord 基础记录
→
v0.1B
Self-bootstrap 自举开发

平台把自身 repo 作为受管项目，用自己的 Mission、DAG、Node、Console 和评价记录来开发自己。

Self Project 注册
Self Mission 模板
代码 agent 修改平台自身代码
自身变更验证与三向分流
自举 guardrails / hard gates
复盘和进化样本沉淀
v0.1A Acceptance
闭环薄切片验收
  • 入口 agent 能创建 MissionThread / Mission
  • 探索 DAG 产出 brief、questions、assumptions、acceptance
  • 默认自主能问必要问题或自动推进
  • 设计构建 DAG 能产出候选 patch / plan
  • 检查验证 DAG 能做需求/设计/实现三向分流
  • Web Console 能看到 Mission、DAGRun、NodeRun、transcript
  • 所有 run/node 生成 event、artifact、evaluation record
v0.1B Acceptance
自举验收
  • 平台自身 repo 被注册为受管项目
  • 至少一个平台自身功能通过 Mission 发起
  • 能用 DAG/Node 修改平台自身代码
  • 能生成自变更 patch / PR draft
  • 验证失败能正确回探索、回设计或回修复
  • 涉及核心流程/安全/runtime 的修改触发 human gate
  • 自举过程产生复盘 artifact 和进化候选
Non-goals for v0.1
第一版刻意不做深

不做复杂多租户、不做复杂会签、不做全自动线上流程进化、不做完整云沙箱、不开放任意 agent 拓扑。先证明 Mission 系统、DAG Node 粒度、Web 追踪和自举可成立。
