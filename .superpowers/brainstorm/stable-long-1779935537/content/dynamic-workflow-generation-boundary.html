Dynamic Workflow Generation Boundary

OpenSpec describes a bounded change. Mission Planner decides the next workflow.

One-shot Work
OpenSpec-style contract is enough when one DAG can finish the job
User request
  -> proposal.md
  -> design.md
  -> tasks.md
  -> specs/scenarios
  -> Workflow DAG
  -> verify evidence
  -> archive to canonical spec

Best fit: bounded feature, bug fix, refactor, API change, testable behavior change.

Mission Work
Mission big loop needs a planner above OpenSpec
MissionState + MissionGoal + MissionMemory
  + FeedbackSignal + MissionEvents
  + SpecChange status + artifacts
  + autonomy mode + policy boundary
  -> Mission Planner
  -> WorkflowIntent
  -> SpecChangeDraft / SpecChangeUpdate
  -> DAGTemplate selection
  -> DAGRunPlan

Best fit: evolving product goal, repeated feedback, incident loops, unclear next step, multi-stage delivery.

Responsibility Split
OpenSpec-style Artifacts
  • Describe one bounded change
  • Give agents a contract
  • Define scenarios and tasks
  • Carry verification evidence
  • Archive accepted behavior
Mission Planner
  • Decide next workflow intent
  • Create or update SpecChange
  • Select DAG template
  • Ask blocking questions
  • Route based on feedback and state
