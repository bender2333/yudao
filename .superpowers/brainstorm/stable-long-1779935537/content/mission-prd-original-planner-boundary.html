原 PRD：Mission Planner 边界

不引入 AI 组织模型，只回到已经讨论好的 Mission 大循环 + DAG 小循环。

Mission 状态 Planner 判断 Orchestrator 路由 DAG 小循环

Mission 大循环：只决定下一步该进入哪个 bounded workflow

长期状态、反馈、事件、SpecChange 状态共同构成 Planner 的输入。

Mission Projection

state / goal / memory / events / feedback

Mission Planner

轻量策略判断器，不做完整任务分解。

  • classify situation
  • decide next loop
  • select template
  • record reason

Process Orchestrator

调度、gate、路由、写事件。

Event Stream

WorkflowPlanned / RouteDecided / StateChanged

Planner 输出 WorkflowIntent，不输出完整任务树

DAG 小循环：具体拆解在 Node 内完成

OpenSpec-style artifact 约束一次 SpecChange；EvoAgentX-style Runtime 执行有边界 DAG。

Workflow Template

Exploration / Design / Implementation / Verification / Fix

DAGRunPlan

template binding + inputs + runtime target

NodeRun 是最小控制单元

Explore Node

需求澄清 / acceptance

Design Node

设计拆解 / tasks

Verify Node

测试 / 审查 / 分类

Artifacts

proposal / design / tasks / evidence

Orchestrator schedules DAGRun

Planner 不做这些

不写完整任务树，不做业务设计，不决定节点执行细节，不替代 verification verdict。

Node 输出 route_recommendation

最终 RouteDecided 仍由 Orchestrator 写入 Mission event stream。

原 PRD 保持不变 Mission 大循环负责任务连续性；每次具体执行仍是一个有边界的 DAGRun；OpenSpec-style artifacts 只约束一次 SpecChange。
Planner 的正确重量 Planner 是“下一次 workflow 选择器 + 理由记录器”。它可以选择模板和生成 intent，但细粒度分解应落在对应 workflow 的节点里。
