Agent-first 协作入口

Product Shell 不必先等于 Web UI。Hermes / OpenClaw 可以作为第一入口；Web Console 作为控制台和观察面。

Entry model for Mission System
Primary Entry
Hermes / OpenClaw Agent

创建 mission、补充上下文、查看进度、处理审批、接收运行摘要。

→
Source of Truth
Mission Platform Backend

保存 Mission、Policy、Run、Event、Artifact、Decision、Approval，不依赖 agent 会话当状态源。

→
Execution
EvoAgentX-style Runtime

启动 DAG run，调度角色 agent、工具、Codex/Claude/Hermes/OpenClaw adapter。

Agent Entry API
MissionCommand
  • create_mission
  • append_context
  • ask_status
  • approve / reject / modify
  • request_run / stop_run
Feedback Stream
MissionEvent
  • mission.created
  • run.started
  • artifact.created
  • approval.requested
  • mission.needs_input
Secondary UI
Web Console
  • 全局 mission 列表
  • runtime/agent 配置
  • timeline/transcript
  • artifact/approval 管理
  • template/evolution 管理
关键边界

Hermes/OpenClaw 是入口和执行适配器，但不是流程状态源。状态源必须是 Mission Platform Backend，否则无法做审计、恢复、跨入口协作和进化评估。

MVP 入口建议

A

推荐：Agent-first + 最小 Web Console

Hermes/OpenClaw 作为主要交互入口；Web 先做 mission/runs/artifacts/approvals 的观察和配置面。

B

Web-first

更传统、更清楚，但会降低 agent 原生工作流体验，MVP 也会更重。
