OpenSpec as Spec Artifact Layer

Use spec to drive each Mission loop, without replacing Mission Core or Process Orchestrator.

Core Placement
Mission owns lifecycle. OpenSpec-style artifacts define behavior and change intent.
Mission Core
long-lived state, event stream, relation, decision, artifact index
OpenSpec-style Spec Artifact Layer
proposal, spec deltas, design, tasks, scenarios, archive/sync history
Process Orchestrator
routes loops based on facts from specs, nodes, verification, and policy boundary
EvoAgentX-style DAG Runtime
executes bounded runs that create, update, validate, or apply spec artifacts
OpenSpec Mapping
Translate, Do Not Copy Blindly
openspec/specs/              -> canonical behavior specs
openspec/changes/<change>/   -> Mission-bound SpecChange
proposal.md                  -> Mission Brief / Why / What / Impact
specs/**/*.md                -> behavior requirements + scenarios
design.md                    -> Design Note / technical approach
tasks.md                     -> implementation checklist / DAG seed
verify                       -> Verification DAG input
archive/sync                 -> accepted behavior promoted to canonical specs
Loop Integration
Before Build
  • Exploration creates proposal and requirement scenarios
  • Design creates design artifact from accepted scope
  • Planning converts tasks into DAG templates or node seeds
After Build
  • Verification checks code/tests against scenarios
  • Ops feedback opens or updates SpecChange
  • Stable outcomes sync back into canonical specs
Boundary
What OpenSpec Does Not Replace

OpenSpec does not become the platform scheduler, mission database, runtime adapter, or approval system.

It supplies the spec-driven artifact grammar. Mission Platform supplies long-term state, orchestration, execution, UI, and evolution.
