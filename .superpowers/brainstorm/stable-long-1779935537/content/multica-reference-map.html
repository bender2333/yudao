Multica 参考地图

Multica 更适合作为产品交互和 runtime/agent/task 追踪参考；EvoAgentX 更适合作为 workflow 与评估进化参考。

What Multica contributes to our Option A architecture
Frontend Product Shell
可参考前端信息架构
  • Agents 列表和详情页
  • Runtimes 机器/daemon 管理
  • Issues 协作任务视图
  • Chat + task transcript
  • Autopilots 自动触发配置
Agent Connection
可参考 agent-runtime 绑定
  • RuntimeDevice：provider/status/last_seen
  • Agent：runtime_id/model/instructions/env/args
  • Agent skill 作为可挂载能力
  • Runtime picker 和可用性判断
  • 本地 daemon + 云 runtime 入口
Task Tracking
可参考实时任务追踪
  • AgentTask：queued/running/done/failed
  • TaskMessage：seq/type/tool/input/output
  • WebSocket 实时事件
  • 断线后 reconcile server truth
  • Transcript 时间线和敏感信息脱敏
Use Directly As Inspiration
我们的前端导航可以参考

Dashboard、Lifecycle Runs、Issues/Requirements、Agents、Runtimes、Autopilots、Approvals、Memory、Settings。

Adapt, Not Copy
我们的任务粒度要更强

Multica 的 AgentTask 是单 agent 任务；我们需要 WorkflowRun / StageRun / DAGNodeRun / AgentActionRun 分层追踪。

两套参考的职责边界

A

推荐：Multica-style shell + EvoAgentX runtime

前端、agent/runtime/task 追踪参考 Multica；workflow DAG、评估和进化参考 EvoAgentX；中间用我们的 lifecycle model 串起来。

B

偏产品：先做 Multica-like task runner

更快做出 UI 和 agent 连接，但容易退化成任务派发工具，弱化全流程 lifecycle 和 workflow 进化。

C

偏框架：先做 EvoAgentX-like workflow lab

内核能力强，但前端协作、任务追踪、runtime 接入体验会弱，不符合平台产品目标。
