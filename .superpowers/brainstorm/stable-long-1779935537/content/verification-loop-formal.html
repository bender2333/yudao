Verdict Gate
Evidence Sufficiency + Autonomy Mode

默认自主下，证据足够且未命中强制 gate 时可自动推进；半自主会给出通过/修复/回退选项；人工主导必须人确认；全自主只在高风险策略命中时停下。

Pass
通过验证

进入 PR/Release 或运维反馈。

Fix
回到实现修复

目标和设计清楚，只是功能 bug 或实现缺陷。

Design
回到架构/设计

边界没考虑清楚、方案缺口、模块职责不清。

Explore
回到需求探索

需求未定义清楚，测试和验证结论互相矛盾。

Gate
人工确认

风险高、证据冲突无法自动归因、质量边界不明确。

失败分流原则

检查与验证必须先做 failure classification：需求定义问题回探索；边界/架构问题回设计；单纯功能 bug 或实现缺陷回修复；无法自动归因才进入人工 gate。

正式规则

A

检查与验证 = 证据生成 + 失败归因 + 分流 Gate

Process Orchestrator 根据失败类型分流：需求矛盾回探索，边界缺口回架构/设计，功能 bug 回实现修复，无法归因或高风险进入人工 gate。
