EvoAgentX 复用边界

平台负责产品化、权限、运行时和审计；EvoAgentX 骨架负责工作流、agent 图、评估和后续进化。

Recommended architecture
Product Platform
研发协作产品层

工作区、项目、需求、任务、角色、权限、审计、看板、PR/发布/运维事件。

Owns: UX, policy, lifecycle state
EvoAgentX Core
编排与进化内核

WorkflowGraph、AgentManager、Evaluator、Optimizer、自进化策略、HITL checkpoint。

Owns: workflow reasoning, evaluation, evolution
Runtime Layer
执行器适配层

Claude Code、Codex、Hermes、本地 daemon；未来扩云端沙箱和 CI runtime。

Owns: CLI execution, logs, files, diff, tests
关键原则

平台 domain model 不直接等于 EvoAgentX graph；需要一层 adapter，把“需求到运维”的 stage/run/event 映射成可执行 workflow graph。

复用方式选项

A

包装 EvoAgentX 为内核服务

保留平台自己的产品模型；用 adapter 调用 EvoAgentX 的 graph/agent/evaluator/optimizer。推荐，边界清楚。

B

直接 fork 并改造成平台

启动快，但研发协作、权限、运行时、审计会和框架代码缠在一起，后期维护压力大。

C

只借鉴概念，重写内核

长期可控，但失去复用价值，MVP 会慢很多，也不利于快速验证进化能力。
