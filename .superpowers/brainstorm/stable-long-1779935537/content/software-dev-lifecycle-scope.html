研发协作平台的生命周期范围

先选 MVP 应该覆盖到哪里。完整平台可以从需求到持续运维，但第一版需要一个清晰闭环。

End-to-end software delivery loop
01
需求

PRD, issue, user story, acceptance criteria

02
设计

方案, 架构, 风险, 评审

03
计划

任务拆解, agent 分工, gates

04
执行

编码, 修改, 调试, 状态流

05
验证

测试, lint, review, 修复

06
交付

PR, merge, release notes

07
运维

监控, incident, rollback, follow-up

第一版 MVP 边界

A

执行闭环

从现有 issue/需求进入，完成 agent 编码、测试、修复、review、PR。最快做出可用价值。

B

需求到 PR 闭环

覆盖需求澄清、方案、任务拆解、agent 执行、验证和 PR。更像完整研发协作平台。

C

需求到运维闭环

一开始就覆盖需求、研发、发布、监控、故障响应和持续改进。愿景完整，但 MVP 风险最高。
