核心大流程：Lifecycle Orchestrator

这是我们必须自己设计的产品核心：把研发生命周期拆成阶段，并在每个阶段启动 EvoAgentX-style DAG run。

Lifecycle layer owns the long-running product truth
1 Intake
需求、bug、告警、chat、webhook
2 Analysis
澄清、范围、风险、验收
3 Design
方案、影响面、计划
4 Build
编码、测试、修复
5 Review
代码审查、质量门禁
6 PR
描述、证据、提交
7 Release
发布、验证、回滚
8 Ops
监控、事故、反馈
Each Stage
Stage policy decides what happens

mode、required artifacts、role team、approval gate、retry policy、runtime target。

→
Creates
One or more DAG runs

DesignRun、ImplementationRun、VerificationRun、ReviewRun、ReleaseRun、IncidentRun。

Feedback loops are events, not edges inside one giant DAG.

测试失败、review 驳回、发布失败、运维告警都会产生新的 event，并由 lifecycle orchestrator 创建下一次 run 或回到指定阶段。

MVP 要先固定的大流程骨架

A

推荐：8 阶段全流程薄切片

每个阶段最小可用，但都能产出 artifact、启动 DAG run、进入下一阶段，最符合“流程打通才是核心”。

B

开发交付优先

先强化需求到 PR，再补发布和运维；实现快，但和前面确认的 MVP 方向不完全一致。

C

运维闭环优先

突出告警到修复再发布，但需求、设计、PR 协作会弱，不适合作为完整平台第一版。
