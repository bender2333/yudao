DAG Node 粒度规则

四个 Mission 循环是大层级；循环内部的小循环必须落到 DAG Node 粒度，NodeRun 是最小可观察、可调度、可回滚的执行单元。

Granularity hierarchy
Level 1
Mission

长期目标和演化容器。

Level 2
Loop

探索、设计构建、验证、反馈。

Level 3
DAG Run

一次性 workflow 执行实例。

Level 4
DAG Node / NodeRun

最小流程控制粒度。

Level 5
Action / ToolCall

agent 执行和工具调用细节。

Rule
小循环不是随意 while loop，而是 Node-level retry / branch / route

例如“验证失败回修复”不是整个 Mission 直接重跑，而是 Verification DAG 的 failed node 产出 FailureClassification，Process Orchestrator 再路由到 DesignBuild DAG 的具体 Fix Node 或 Design Node。

Node Contract
每个 Node 必须有明确契约
  • node_key / node_type
  • required_inputs
  • expected_outputs
  • assigned_role
  • tool_policy
  • retry_policy
  • failure_classification
  • artifact_outputs
Node Control
编排者控制到 NodeRun
  • 重试单个 node
  • 跳过非必要 node
  • 插入补充 node
  • 路由到另一个 DAG template 的 node
  • 为某个 node 创建 approval gate
  • 把 node 输出写为 artifact

正式规则

A

循环内控制粒度 = DAG Node

Mission 循环负责方向，DAG Run 负责一次执行，NodeRun 负责最小流程控制；retry、branch、gate、artifact 和 failure classification 都落到 Node 粒度。
