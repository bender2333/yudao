1. 核对前提：`harness/snapshot.py` 的 `git_provenance` 用 `pygit2.discover_repository` 从起始文件夹**向上**找仓库（`harness/snapshot.py:45`），找到上层目录的 `.git` 以后用 `pygit2.Repository` 打开；归属检查失败时抛出的 `pygit2.GitError` 没有接住，一路变成 500。设计第 4.6 节已经写明「只看源目录自己：源目录本身是 Git 工作树的根目录时才读取，不向上层目录查找；源目录本身是仓库但读不出时以 `source_invalid` 拒绝，写明目录与原因」（`docs/design/existing-project-onboarding.md:205`）。建项目命令本来就把 `TreeError` 变成 `source_invalid` 拒绝并把说明原样显示（`harness/app/project_commands.py:40`），只是这里抛的不是 `TreeError`。
2. 实现（`harness/snapshot.py`）：
   - 判据从「向上发现仓库」改成「源目录自己有没有 `.git`」：`<源目录>/.git` 不存在就返回空来源，不再向上查找，上层目录里的仓库既不影响结果也不被打开（用 `os.path.lexists`，断掉的符号链接也算「有 .git」）。
   - 打开仓库失败时抛 `TreeError`，写明目录与原因（`源目录的 Git 仓库打不开：<目录>：<libgit2 的原因>`），由建项目命令转成 `source_invalid` 拒绝，页面上原样显示。
   - 读提交（HEAD）与读状态（有没有未提交的修改）失败同样转成 `TreeError` 并写明目录与原因，不再是 500。
   - 裸库仍然返回空来源（裸库没有工作树，与 `git rev-parse --is-inside-work-tree` 一致）。
3. 用例（`harness/tests/test_snapshot.py`，新增三项）：
   - `test_provenance_ignores_the_repository_above_the_source_directory`：上层目录是一个 libgit2 打不开的仓库（用损坏的 `.git/config` 模拟归属检查失败），起始文件夹本身不是仓库 → `project.create` 照常返回 200，快照的 `provenance` 为空。用例里先断言这个仓库确实打不开，前提才成立。
   - `test_provenance_is_empty_when_the_repository_above_has_no_commits`：上层目录是当前用户的仓库但还没有提交（`pygit2.init_repository`，任何机器上都能跑），起始文件夹本身不是仓库 → 照常建成，`provenance` 为空。用例里先断言上层仓库的 HEAD 读不出来。
   - `test_create_rejects_a_source_directory_whose_repository_cannot_be_opened`：起始文件夹本身是仓库但打不开 → `project.create` 返回 409 `source_invalid`，说明里有这个目录与原因，没有建立项目。
