# 工单 #563：界面：勾选加入、自动模型测试，删除「接受容量」

## 背景与目标

从父工单 #385 拆出（2026-10-16 架构师）：模型列表中勾选加入，保存以后自动模型测试，页面没有「接受容量」。#385 正文验收第 1、2、4、5 条由本工单完成；应用层的预填容量已由子工单 #562 完成（commit 426fa95d）。设计依据：[模型管理设计说明](docs/design/model-management.md) 第 4.3、9.1 节与 [ADR-0002](docs/adr/0002-candidates-need-test-to-admit.md)。

要解决的问题：
1. **删除「接受容量」与确认状态**：删除 `FormRow.capacity_confirmed`、`canSaveRows`、`rowSavable`、`patchRowCapacity` 中的确认判断以及「接受容量」按钮与「容量已确认」标记。保存只看容量是否齐全且有效。
2. **候选勾选加入与就地填写**：在展开的连接卡片中，展示候选勾选框、预填容量与来源标注；缺少容量时在候选旁就地填写；两项缺一或输出上限大于窗口时「加入」不可用并提示具体问题；勾选的候选支持一次性提交建立模型访问定义。
3. **自动模型测试与失败留候选**：保存成功以后，界面对每个新的访问定义（无论来自候选加入还是手动添加）逐个发送模型测试；测试通过即写入准入并出现在部门默认等下拉选项中；未通过时在模型行显示原因并保持在候选。
4. **测试更新与验证**：更新前端单元测试 `model-logic.test.js` 与端到端 `models.spec.ts`，补齐 AC 1 与 AC 2 真实测试，确保无 mock、无 `capacity_confirmed` 残留。

## 决策

1. **彻底清理容量确认状态与按钮**：
   - `model-logic.ts`：从 `FormRow` 接口中删除 `capacity_confirmed` 字段；`canSaveRows` 仅校验 `rowCapacityValid`；`rowSavable` 仅校验当前行容量有效性；`patchRowCapacity` 移除确认标记设置；`rowFromCandidate`、`rowFromManual`、`formStateFromProvider` 不再赋予 `capacity_confirmed`。
   - `form.tsx`：删除 `capacityConfirmed` 变量计算及「接受容量」按钮与「容量已确认」标记渲染，仅保留容量缺项或非法时的错误警告。
   - `page.tsx`：更新未能保存时的错误提示文本为「窗口或输出上限缺少或无效的行不能保存。」；删除注释中的 `capacity_confirmed`。
2. **候选列表交互增强（勾选、就地填写、一次加入）**：
   - `model-logic.ts`：导出 `CandidateCustomCapacity`、`candidateToRow`（从候选生成 `FormRow`，缺项手动填写时来源标明「手动」，有预填直接采用预填来源）以及 `canJoinCandidates`（核验勾选项容量齐全且有效，有缺项或错误时输出对应错误文本）。
   - `page.tsx`：维护 `selectedCandidates` 与 `candidateCapacity` 状态；在展开的连接卡片中渲染带勾选框、协议/窗口/输出上限预填值与来源说明的候选卡片列表；当候选缺少窗口或输出上限时，渲染数值输入框供就地填写；上方渲染「加入」按钮与错误说明；当未勾选或勾选项有容量问题时禁用「加入」按钮；点击「加入」收集所有勾选候选，与现有已保存模型合并后单次提交 `catalog.connection.save`。
3. **保存成功后逐个自动模型测试**：
   - 在 `page.tsx` 中，无论是表单保存 `runSave` 还是批量候选加入 `joinCandidates`，在保存成功后均比较保存前后模型清单，提取出新增模型定义 ID 列表 `newModelIds`。
   - 对 `newModelIds` 中的每条定义依次 `await testModel(providerId, id)` 发起测试。
   - 测试通过后，后端写入准入并广播事件，前端更新目录与 `admissions`，定义自动出现在「部门默认」的下拉选项中；
   - 测试失败时，`tests` 状态记录失败原因并在模型行的 `model-result-${model.id}` 处显示原因，准入列保持显示「候选」，未准入定义不在部门默认选项中。
4. **端到端测试用例更新与补充**：
   - 更新现有用例 199 与 596，去除已删除的 `accept-capacity` 与 `capacity-confirmed` 断言，改为核对直接采用预填容量或缺少容量不能保存。
   - 新增 AC 1 端到端用例：新建自定义连接，粘贴 Key，获取模型列表，勾选 vision-model（带容量）与 cbcn/deepseek-v4.1-flash（缺输出上限并就地填写），点「加入」，自动测试通过，验证部门默认下拉包含两个新模型，全程无「接受容量」与「模型测试」点击。
   - 新增 AC 2 端到端用例：手动添加模型并保存，自动触发测试，上游对模型返回 500 错误，该行显示原因并停留在候选；修正上游后点击测试通过，进入准入与部门默认。
