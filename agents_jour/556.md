### 第二轮：阶段状态机删掉，事项进度从成果推算

**这一轮先修了一个根因**：进程中断以后询问分支没有继续（`harness/tests/test_ask_branch.py` 的两条用例）。原因：编排器判断「这个部门在不在工作」看的是投影里主线会话的记录；进程被终止以后那条记录停在「工作中」，重启以后没有人再动它，于是提问方不再被算成在工作，询问分支没人接手。改法：编排器按本进程里的会话状态判断（`harness/orchestrator.py` 的 `_waiting_departments`），这个进程里没有会话的部门算在等待（`harness/collaboration.py` 的 `next_department(projection, waiting=...)`）。

**做了什么**

1. **阶段状态机删掉**（`harness/models.py`）：`PHASES` 与 `PRODUCT_ACTIVE`/`ENGINEERING_ACTIVE`/`QUALITY_ACTIVE` 没有了，只留 run 的状态 `RUN_STATUSES`（进行中与三个终态）与 `TERMINAL_STATUSES`。投影上的 `phase` 改名 `status`（`harness/models.py` 的 `RunProjection`），事件的 `state_before`/`state_after` 写 run 的状态，不再写部门阶段。`waiting_reason_for` 只在终态给一句话：进行中没有单一阶段可写（进度从成果推算）。
2. **阶段迁移事件删掉**（`harness/models.py`、`harness/app/payloads.py`、`harness/streams.py`）：`EventType.TRANSITION` 与 `TransitionPayload` 没有了，投影里的 `transitions` 没有了，run 事件版本 8 → 9（`harness/streams.py`）。事件里不再有「由控制核心决定下一个部门」的记录 ✓（工单验收第 1 条）。流转记录里的「版本交付」改由交付到达给出（`harness/app/read_models.py`），首页的关键事实里不再有交接（`harness/app/home.py`）。
3. **事项进度从成果推算**（`harness/app/project_queries.py`）：`WorkItemProgress` 给出当前有效的 PRD 是第几版、最新一份交付是第几版、它依据的 PRD 是第几版、对最新交付的结论（缺陷记录或放行）。`work_item.loop` 与 `project.overview` 的每一条事项都带它；客户端在概览的状态行里写这一句（`client/src/renderer/src/views/project/overview.tsx`）。接口合同、openapi 快照与客户端生成的类型一起更新 ✓。
4. **暂停与继续不再记阶段**（`harness/orchestrator.py`、`harness/app/payloads.py`）：`paused_at_phase` 与 `resumed_at_phase` 两个字段没有了。继续以后下一个谁工作由关注的成果决定，不回到某个阶段。
5. **关注关系补齐建档流程**（`harness/definitions/organization.json`）：质检多关注一项「现有结构说明」，产品多关注一项「基线核验」——建档里质检看的是工程的结构说明、工程返工看的是产品的基线核验结论。普通事项里这两项不出现，行为不变。工程对「PRD 的新版本」的判断改成与它最近一次成果（普通事项的交付、建档的结构说明）所依据的版本比较（`harness/collaboration.py`），否则建档里工程交完结构说明还会再工作一轮。
6. **当前工作材料里没有阶段**（`harness/context.py`）：`[current_work]` 的版本号改成这份材料内容的摘要，材料里不再有 `phase` 字段；产品的工作文字在基线核验要求修改时按成果给出（`has_new_baseline_review`）。
7. **指导提前安排的判定**（`harness/collaboration.py`）：原来「这一轮只回应指导」看的是阶段与指导的部门是不是同一个；阶段没有了，改成「按关注的成果本该工作的部门」是不是它（`normal_department` 与 `guidance_diverted`）。指导不算部门自己那一轮的工作（`watched_normal_work`），所以被指导的部门让开这一轮，回答完以后继续自己的工作。
8. **用户输入没有被产品处理时的可提交种类**（`harness/collaboration.py`）：原来只有产品的阶段上的部门能提交，其它部门只能回应指导；阶段没有了，改成「只有产品能提交正式成果，其它部门只能回应指导」。
9. **让出的工作在指导回应以后恢复**（`harness/projection.py`）：没有阶段迁移事件以后，让出的工作由指导回应这件事恢复（回应以后清掉投影里的让出记录）。
10. **客户端**（`client/src/renderer/src/views/project/labels.ts` 等）：阶段名换成 run 状态名（进行中、已完成、已暂停、执行失败）；概览的状态行写进度；部门页写 run 状态；决定卡片不再写「停止时所处阶段」；房间不再处理阶段迁移事件（`client/src/renderer/src/views/project/room-screen.tsx`）——楼层里包裹沿管道走的画面改由交付到达与盖章驱动，属于 #477 的完整显示。
