# 工单 #572：初始 PRD 决定请求带上 PRD 摘要

## 背景与任务

从 #138 拆出（父工单 #124）。按接入已有项目设计说明第 3.2 节，`initial_prd` 决定请求的材料包括「初始 PRD 的摘要」。
接口合同已有 `InitialPrdProposal.summary` 字段，但主机此前未填写，决定卡片一直显示「没有摘要」。

任务范围：
- **只改** `harness/projects.py` 的 `_propose_initial_prd`，以及 `harness/tests/` 下的测试。
- 摘要的写法：主机从这一轮被接纳的 `ProductSpec`（`run.product_spec`）确定性地生成，不调用模型，内容是目标原文、要求条数与边界条数，例如「目标：build an echo CLI；要求 2 条；边界 1 条」。
- 保持接口合同、OpenAPI 快照与客户端生成物不变。
- 先写失败的集成测试（经 HTTP，FakeAdapter）获取失败证据，再改实现。
- 新增测试文件登记到 `harness/tests/layers.toml`（只新增行，不删已有行）。

## 实现细节

1. `harness/projects.py`：
   在 `_propose_initial_prd` 中，从 `run.product_spec` 提取 `goal`、`requirements`、`boundaries`，按规则生成 `prd_summary`：
   `f"目标：{spec.goal}；要求 {len(spec.requirements)} 条；边界 {len(spec.boundaries)} 条"`
   放入 `candidate["prd"]["summary"]`。
   这样写入的 `INITIAL_PRD_PROPOSED` 事件和 `PROJECT_DECISION_REQUESTED` 决定请求均带上该摘要。

2. 测试与分层：
   - 新增集成测试 `harness/tests/test_initial_prd_summary.py`，模拟完整两轮建档（经 HTTP 与 FakeAdapter），断言第 1 轮 initial_prd 决定请求与 `initial_prd_proposed` 事件携带的 `prd.summary`，经 `decision.answer` 提出修改后，断言第 2 轮决定请求与事件携带更新后的 `prd.summary`。
   - `harness/tests/layers.toml` 新增 `"test_initial_prd_summary.py" = "integration"`。
