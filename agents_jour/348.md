## 勘察与设计对齐

- 第 6.3 节的要点：全部接口路径都要 `Authorization: Bearer <令牌>`，页面文件豁免；没有令牌或令牌无效一律 401 且不附原因；令牌用 256 位随机值；数据目录里只存 SHA-256 摘要、名称与建立时间，明文不落盘；令牌只在服务所在机器用 `python -m harness token create/list/revoke` 管理，不提供接口命令。
- 确认客户端已有 `eventsource` 5.1.2，`EventStreamClient` 已经接受 `token` 并经自定义 fetch 注入请求头，只是从未被填入。
- 阻塞项 #372 已关闭（PR #391 合入 main），`client/tests/e2e/` 的 Playwright 装置可用。

## 令牌定义与持久化

- 新增 `harness/app/access_tokens.py`。放在应用层是因为导入检查的合同「接口层只导入应用层」不允许 `harness.api` 导入新的顶层模块；`harness.__main__` 是允许导入应用层的入口之一。
- 记录含名称、摘要、建立时间与撤销时间，落进数据目录的 `access-tokens.json`（临时文件加 `.replace()`，避免写一半被读到）。
- `name_of` 每次校验都重新读文件，因此命令行撤销以后运行中的服务立刻生效，不需要失效通知机制。
- 名称在未撤销的记录里唯一，撤销后的名称可以重新建立，旧令牌仍然无效。
- 比较摘要用 `hmac.compare_digest`。

## 命令行

- `harness/__main__.py` 加 `token create --name <名称>`、`token list`、`token revoke <名称>`，都接受 `--data-dir`。
- 不取数据目录的进程锁，也不打开控制核心：服务运行时也要能撤销。
- `token create` 的输出是令牌明文，只出现一次；`token list` 三列按制表符分隔：名称、建立时间、有效或已撤销。

## 鉴权与提出者

- `harness/api/access.py`：`INTERFACE_PATHS = ("/api/", "/openapi.json")`，`requires_token` 按前缀判断；`token_from` 对 `bearer` 大小写不敏感并去空白。
- 中间件在本机访问方式下提出者是 `user:local`；局域网访问方式下对接口路径校验令牌，缺失或无效返回 401 且响应体为空；页面文件豁免。
- 有效令牌的提出者是 `user:<令牌名称>`，写进事件。
- `create_app` 增加 `tokens` 参数，`serve` 在给出数据目录时构造 `AccessTokenStore`。

## 客户端令牌携带

- `connect` 与 `interfaceFor` 接受令牌，经 `createConfig` 的 `headers` 放进请求头；地址里没有令牌。
- `connect` 看到 401 返回 `unauthorized` 状态，页面据此显示填写令牌的表单。
- `ClientApp` 把令牌存成字段，`open`、重新同步与事件流都用它；`EventStreamClient` 的第四个参数一直是令牌的位置。
- 令牌在服务接受以后才写进浏览器（`localStorage` 的 `yudao.access-token`）：被拒绝的令牌不保存，否则刷新以后浏览器里留着服务已经拒绝的令牌。
- 新增 `TokenGate` 表单，输入框是密码类型，页面不回显。

## 顺带修掉的缺陷

- `crypto.randomUUID` 只在安全上下文存在。局域网访问方式下页面经 `http://<局域网地址>` 提供，不是安全上下文，页面上任何命令都因 `crypto.randomUUID is not a function` 失败。这是端到端用例里暴露出来的：`pageerror` 报出这句话，命令请求完全没有发出。
- 改为按 RFC 4122 第 4 节用 `crypto.getRandomValues` 取随机字节拼标识，`crypto.getRandomValues` 在任何上下文里都有。新增 `client/src/renderer/src/contract/command-id.ts`，替换 6 处调用（`use-snapshot.ts`、`floor-screen.tsx`、`models/page.tsx` 四处、`model-logic.ts` 两处）。
- 导入写成 `../../contract/command-id.ts` 带扩展名：单元测试直接用 Node 的加载器跑 `.ts`，不带扩展名解析不到。
