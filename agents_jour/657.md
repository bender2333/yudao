## 记录

执行者 minimax-M3.1-Flash / 2026-10-22 03:30 /
1. 动手前核对：
   - 依据检查：`git log --oneline 6bbe6166..origin/main -- docs/user-session-log.md docs/design/web-interface-and-release.md` 无输出；
   - 符号检查：`overview.tsx` 的状态行无条件把 `phase` 翻成阶段名（`label(PHASE_LABELS, item.phase)`），`labels.ts` 第 45 行把 `FAILED` 译成「执行失败」；后端把取消的终态记成 `phase=FAILED` 配 `stop_reason=cancelled`（`harness/projection.py` 第 705 行），与工单正文一致；
   - 「只改」清单：`overview.tsx` 与 `labels.ts` 两个手写文件，新增 `client/tests/unit/cancelled-item-status.test.ts`，都在清单内，没有扩充。
2. 实现：
   - `labels.ts` 增加 `phaseLabel(phase, stopReason)`：没有阶段名时不写阶段；停止原因是 `cancelled` 时不写阶段名（取消是用户自己的决定）；其余照旧翻成阶段名。阶段词表本身没有改，真失败的译法没有动；
   - `overview.tsx` 的状态行改用 `phaseLabel(item.phase, item.stop_reason)`：取消过的事项显示「已停止」，不再有「· 执行失败」；真正失败的事项仍显示「· 执行失败」。
3. 一并检查的结果（工单第 3 条）：
   - 整个客户端里「执行失败」只有一处，就是 `labels.ts` 的阶段词表；循环画面（`floor-screen.tsx` 与像素层）不读阶段名，看板卡片写的是事项状态与停止原因（取消时写「运行已被取消」），都不出现「执行失败」；
   - 部门工作间页面的「部门状态」本来就先判 `status === "stopped"` 写「已停止」，取消的事项在那里也是「已停止」；
   - `harness/app/labels.py` 里 `FAILED` 的通用译法没有改，接口合同没有变。
4. 测试：
   - 客户端单元测试新增 `client/tests/unit/cancelled-item-status.test.ts` 五项：取消过的事项不写「执行失败」、真正的失败（`provider_error`、`time_limit`、`provider_timeout` 与没有停止原因）仍然写「执行失败」、没有阶段名时不写阶段、进行中的事项写自己的阶段名、取消以外的其他停止原因照旧写阶段名。
5. 本地自测：
   - `cd client && npm run typecheck`：通过；
