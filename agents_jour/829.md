## 2026-10-28 10:12 修一处自己留下的空转（import-linter 的 overlapping modules）

执行者 solo-deepseek-v4.1-flash / 2026-10-28 10:12 / 实现

- 第一次写三条合同时用的是 `forbidden_modules = ["harness"]`。反向验证（在 `harness/app/home.py` 末尾加
  `from ..watched_outputs import ROUTING`）**没有失败**，`lint-imports -v` 的输出里有
  `Skipping overlapping modules harness.app and harness.`——禁止的模块是来源模块的祖先时，import-linter 把这一对
  直接跳过，合同因此什么都没查。改成 `forbidden_modules = ["harness.*"]`（与仓库里原有的第一条合同同一个写法，
  通配展开成具体的子模块，不再是来源的祖先）以后三条都真的生效：
  - `harness.app.home` 加一行 `from ..watched_outputs import ROUTING` →
    「应用层只导入控制核心的公开接口」broken，报 `harness.app.home -> harness.watched_outputs (l.220)`；
  - `harness/tightening_contract.py` 加一行 `from . import watched_outputs` → 「契约模块只导入内核与标准库」broken；
  - `harness/watched_outputs.py` 加一行 `import harness.orchestrator` → 「应用不导入薄驱动的内部」broken。
  三处都是逐条改、跑、`[IO.File]::WriteAllText` 还原，`git status` 只剩本单自己的改动。
- 应用层那条合同另加 `allow_indirect_imports = true`：只查直接导入，公开接口模块自己再往下导入内核的哪几块
  （`harness.runtime` 导入薄驱动、`harness.projects` 导入工件与 Git 版本）不归应用层的这条规则管；
  不加这个选项时一条 `from ..watched_outputs import ROUTING` 会顺着 `watched_outputs → models → actions`
  报出十几条间接链，报的不是这一条规矩。
- 这一处是我自己的错，不是设计问题：`pyproject.toml` 原有的第一条合同已经给出了写法，我没照着写。
