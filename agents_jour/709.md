# 工单 #709：采纳成果以后页面上没有写回的入口

依据：工单正文与架构师的三条评论（写回与导出的界面缺口、源目录一节没有写回、资料页文本文件没有下载）。分支 `issue-709`，worktree 在 `C:/project/yudao-worktrees/issue-709`，起点是 main 的 41a5ce03。

## 记录

执行者 solo-minimax-M3.1-Flash / 2026-10-23 13:08 /
1. 分诊（工单评论）：这是真缺陷，三样东西缺着——写回设置、发起写回的入口、写回结果的可见性。查到的具体事实：客户端全目录检索「写回」与 `writeback`，只命中生成的接口类型与像素画面登记表；`settings.tsx` 的源目录表单提交 `source_directory.save` 时只带名称、路径与基准版本，而 `harness/projects.py` 的 `configure_source_directory` 把没有给出的字段一律写成缺省值，用户改一次路径就把写回关掉了；`harness/writeback.py` 的三种目标不可用（路径不存在、不是 git 仓库、目标分支不存在）一路冒到接口层变成 500；写回记录只在控制核心的投影里，没有查询能读。
2. 位置按架构师评论里的结论定：项目设置页的「成果写回」一节（源目录已经在那儿，写回是源目录的另一半），概览页的「当前成果」多一行写回状态（用户不知道还差这一步，这一层比「没有入口」更要紧）。
3. 实现（服务端）：
   - `harness/app/project_queries.py` 新增查询 `project.writeback`：写回记录按最近的在前，给出状态、停止原因、推送的分支、目标分支、合并请求（标题与「还只是本地记录」这个事实）、冲突的文件路径与发生的时间；五种写回事件列入 `changed_by`，写回以后页面自己更新。
   - `harness/writeback.py` 增加 `WritebackTargetUnavailable`（带着是哪一种与目标是什么），三处抛异常的地方改为抛它。
   - `harness/app/project_and_work_item_commands.py` 的 `_execute_writeback` 接住它，按 `not_allowed` 给出中文说明（目标仓库不存在／不是 git 仓库／目标分支不存在）。
4. 实现（客户端）：
   - `client/src/renderer/src/views/project/writeback-text.ts`（新增）：写回状态与停止原因的中文名、写回结果与源目录写回设置的说明。单独成模块是因为客户端单元测试用 node 直接跑 TypeScript，带 JSX 的 `.tsx` 模块引不进来（`#748` 已定这个做法）。
   - `client/src/renderer/src/views/project/writeback.tsx`（新增）：设置页的「成果写回」一节（发起写回、列出写回记录）与概览页的写回状态；查询与命令都在能力清单里才显示。
   - `client/src/renderer/src/views/project/settings.tsx`：源目录一节多一列写回设置，修改表单补上「打开写回」「目标分支」「远端仓库」，保存时把写回检查的命令与凭据引用按原来的值写回（不因改路径而清空）。
   - `client/src/renderer/src/views/project/overview.tsx`：「当前成果」多一行写回状态；建档基线按设计不写回，页面照实写明。
5. 测试：
   - `harness/tests/test_issue_709.py`（新增，模块层）：真实写回以后查询给出页面上要的字段；写回停止（冲突）时给出冲突的文件路径；目标分支不存在与目标仓库不存在时命令给出中文的拒绝说明（接口层回 409，不再是 500）。
   - `client/tests/unit/writeback.test.ts`（新增）十条用例：五种结果的说明、合并请求只是本地记录时照实写明、页面上不出现英文内部标识、源目录写回设置的摘要。
   - `client/tests/e2e/project.spec.ts`（新增一条）：设置页的「成果写回」一节能发起写回，没有可写回的东西时页面给出服务端的中文理由；概览页的「当前成果」里有一行写回状态与到设置页的入口。
   - `harness/tests/openapi/openapi.json` 与 `client/src/renderer/src/api/generated/` 按合同重新生成；`harness/tests/test_api.py` 的查询清单补一行。
6. 文档：`docs/design/app-and-interface.md` 补查询一行与「写回在页面上的显示」，`writeback.execute` 一行补上目标不可用时的拒绝；`docs/design/existing-project-onboarding.md` 第 5 节「列在事项详情里」改为列在项目设置页与概览页（界面上没有事项详情这个位置）；四条问题登记在 `docs/architecture-issues.md`。
7. 这张工单里没有做的：`run.export` 的导出入口与 `run.asks`、`replay.check` 的入口（与写回是两条独立的路径，工单评论里写明另开工单）；写回检查的命令的界面入口（只有服务端能填，界面上没有入口，另开工单）。
