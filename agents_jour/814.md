claude-opus-5-5 / 2026-10-31 06:25 / 实现方案

- `contract/run-export.ts`（合同侧）：
  - `type RunExportData`：与生成的 `RunExportResult` 对齐的窄化类型（run_id、projection、events、attempts、usage）。
  - `runExportFileName(data)`：纯函数。文件名带事项与 run 的标识：`run-<run 标识后 8 位>-<事项标题 slug>.json`；事项标题从 `projection.work_item_id` 与页面传入的事项清单解析，标题为空时落到 run 标识；非法字符替换为 `-`。
  - `runExportBlob(data)`：纯函数。`JSON.stringify` 整包（缩进 2），返回 `Blob`（`application/json`）。
- `views/project/run-export.ts`（页面侧）：`downloadRunExport({app, runId, workItemTitle})`：`app.queryOne("run.export", {run_id})` → 组名 → 组包 → 建临时 `<a download>` 点击 → 释放 URL。失败交给调用方的原因（`contract/read-failure.ts` 的 `failureReason`）。
- `observe.tsx`：请求详情页头部加「导出这次运行」按钮（run 标识来自路由或列表反查，事项标题来自 `project.overview`），导出中禁用、失败写一句原文；记录页不加（观测页的记录行没有 run 上下文整页包）。
- 测试 `client/tests/unit/run-export.test.ts`：文件名的中文与空标题、非法字符、slug 后缀；`runExportBlob` 的整包字段与序列化；页面侧下载通过注入假 DOM 的 `createElement`/`click` 记录 `href` 与 `download` 名（node:test，不连网络）。守 R3（看得见阶段二写明的导出入口）与 R2（`run.export` 合同字段的读取）。

claude-opus-5-5 / 2026-10-31 06:35 / 实现记录与两处实现判断

- 页面侧的 `saveWithAnchor` 去掉了 `document.body.appendChild/anchor.remove()`：把元素挂上 DOM 再移除，在真实页面没有对应的好处；脱离 DOM 的 `<a download>` 点击在 Chrome/Edge/Electron 界面里照常触发下载。单元测试替换保存入口，不经过这一个函数。
- 入口放在观测页的「请求详情」页（`ObserveDetailPage` → `AttemptDetail`）：run 标识取自 `run.attempt` 的 `attempt.run_id`（详情数据本身带着它，比从路由取更可靠），事项标题取自 `project.overview` 的 `scopeName`，标题缺失时 `contract/run-export.ts` 回退到整包里的 `projection.task` 与 `projection.work_item_id`。
- 「只改」清单里的页面只有 `observe.tsx` 一张；部门工作间与事项的运行记录属于别的文件，本单不改。观测页的请求记录一行只带 `run_id`，同样能进详情页再导出，路径不断。
