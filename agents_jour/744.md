3. 实现的取舍（写在这里，事后好核对）：
   - **一处函数，三处显示**：`usage-text.ts` 里的 `usageText` 同时给请求记录表的「用量」列与请求详情的「用量」行，两处逐字相同（#301 的约定），列名由「输入 / 输出」改回「用量」。
   - **「未上报」只留给「这一次什么都没上报」**：报了总量、没报进出的两段时写「总 8,993 token，输入 未上报，输出 未上报」；总量前面加「总」字，表格里才分得清这个数是总量而不是输入。
   - **服务端说没有上报就不写数值**：`reported: false` 时即使记录里还留着数值也不显示。理由是用量统计的「上报用量的请求」与总 Token 只数上报了的那些，两处必须对得上；这一条也盖住「原文读不到、只剩摘要」的情况（`source: "unknown"`，见 `harness/tests/test_observability_module.py` 第 173 至 183 行）。
   - **逐项按 `coverage` 说**：服务端逐项说明过就按它说（`missing` 的那一项写「未上报」），没有说明时看这一项有没有数值。
   - **上报了用量但没有 token 数值**（只报了成本或缓存明细）写「上报了用量，没有 token 数值」，不写成一句「未上报」。
   - **用量统计页签写清上报了多少个**：「请求数 N（上报 M）」拆成「请求数」与「上报用量的请求」两行，一个都没有时写「未上报」；按部门、按模型的分组表加同一列。这个数按当前筛选范围统计（请求记录一页 50 条、可以加载更多），这一点写在页签的说明里。
   - 接口不变（`usage` 的形状没动），因此 OpenAPI 快照与客户端类型都不重新生成，`API_VERSION` 不必提高。
