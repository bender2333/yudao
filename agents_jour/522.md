# 工单 #522：集成层第 5 次整跑剩余 7 个失败（只改 harness/tests/）

## 现象与根因

两个文件共 7 个失败，根因都是 #471 引入的「提交必须声明依据版本」校验被测试脚本绕过/漏掉，
与 #507、#501 同一范式。产品代码未改，也未放松断言。

### 1. `test_smoke_guidance_audit.py`（模块级夹具 `saved_combined` → 6 个 ERROR）

夹具第 68 行用裸 `product_spec(...)` 提交修订版产品要求，没有 `basis_product_spec_hash`。
#471 起 `harness/validation.py` 拒绝依据版本与当前版本不符的提交，修订版被拒后
run 停在非 DONE，`assert projection.phase == "DONE"`（第 88 行）失败，连带 6 个用例 ERROR。

改法：换成已有轮次构造函数 `product_spec_turn(...)`，它从请求里的 `current_product_spec`
取当前 `content_hash` 填依据版本（`harness/proposals.py` 37–53 行），与真实模型从上下文读到的一致。
`delivery_turn`/`review_turn` 本来就带依据，无需改。

### 2. `test_department_providers.py::test_http_provider_bindings_route_full_consultation_and_engineering_rework`

三处，全部是脚本提交不带依据版本，被主机拒绝后 run 停在 FAILED：

- `provider_b` 的 `delivery(...)` 不带 `basis_product_spec_hash`：
  每次 `submit_delivery` 都被拒（`submitted artifact is based on None; current version is 'sha256:2c469d…'`）。
- `provider_a` 的 `review(...)` 不带 `basis_delivery_spec_hash`：
  每次 `submit_review` 都被拒（`submitted artifact is based on None; current version is 'sha256:ea7718…'`）。
- 工程被拒后重做那一步：`_part` 对无工具请求读 `body["input"][1]`，脚本没有无工具分支时
  工程重试请求拿到工具调用，触发 `harness/engine.py` 367–378 的
  `ProviderError("model returned tool calls although the request declared no tools", retryable=True)`。

关于第三处：实测（在 `provider_b` 里打印 `bool(body.get("tools"))`）这条路径上工程只发 3 个请求、
全部带工具（`counts == {"product": 2, "engineering": 3, "quality": 2}`，`len(result.model_requests) == 7`），
无工具压缩请求根本没有出现。因此**没有为它加压缩分支**：加了也是本用例永远不执行的死代码，
且无法做反向验证（引擎把该错误当可重试失败重试，破坏它用例照样绿）。
压缩响应的既有写法见同文件 #508 用例 888–889 行（`if not body.get("tools"): return _chat_stream([], …)`），
`_chat_stream` 90–92 行、`_messages_stream` 113 行已覆盖「无工具只回摘要文本」的形状。

## 改动

- `harness/tests/test_smoke_guidance_audit.py`：
  - 第 13 行导入加 `product_spec_turn`；
  - 第 68 行 `product_spec(` → `product_spec_turn(`。
- `harness/tests/test_department_providers.py`（只动目标用例）：
  - 第 348 行 `review(...)` 加 `basis_delivery_spec_hash=_material_hash(body, "current_delivery_spec", "content_hash")`；
  - 第 376–377 行 `delivery(...)` 加 `basis_product_spec_hash=_spec_hash(body)`。

用的都是文件里已有的构造函数/助手（#508 用例同款：`_spec_hash`、`_material_hash`），
不手写哈希。删除的行只有 1 行（`payload = delivery(files=["src/echo.py"], check_names=["smoke"])`），
原注释零丢失。
