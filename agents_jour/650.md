### 第 2 轮（逐场景回放剩一处姿势不同）

执行者 minimax-M3.1-Flash / 2026-10-23 /

逐场景回放（`client/tests/unit/pixel-room-replay.test.ts`）54 份场景里只剩一处不一致：`sc-todo-loop__engineering` 的第 43、44 个样本，原型那边工程架构师的姿势是 `carry`（搬着计划走），客户端是 `walk`（空手走）。动作、头顶的话、房间状态都相同。

定位过程（临时诊断脚本用完即删）：

1. 先排除速度：原型的角色速度默认 84（`engine.js` 的 `addActor`），客户端 `scene.ts` 的 `addActor` 同样是 84，`go` 步骤都用 `距离 / 速度` 算时长，两边一致。
2. 再排除走位与步态参数：两边的位置表、走位算法、步态参数、说话目录逐项核对一致。
3. 最后用逐步骤对照定位：临时脚本在原型页面与客户端页面上分别包住 `scene.run` 与 `scene.play`，把同一个场景的脚本步骤与每次姿势切换记下来对照（临时脚本 `client/tests/unit/_diag650.ts` 与 `_trace650.ts`，用完已 `git clean` 删除）。

对照的结果：两边给这个角色排的五个脚本（步骤列表逐字相同）只差最后一处的起始位置——原型在 (306,200)，客户端在 (301,200)。再看时间线：原型的第 5 个脚本在 t=17050 开始，客户端在 t=17100 开始，整条时间线差一帧（50 毫秒）。

根因在每帧的执行顺序：

- 原型 `docs/prototypes/v11/js/pixel/engine.js` 的 `frame`：`realT` 前进后**先跑定时回调**（`updateTimers`），再走小人（`updateActor`），再粒子与飞行物。
- 客户端 `client/src/renderer/src/pixel/world/scene.ts` 的 `stepScene`：**先走小人**，再飞行物与粒子，最后才跑定时回调。

定时回调里开始的新脚本因此晚一帧起步：回调那一帧小人已经在走旧脚本的收尾动作，新脚本要等到下一帧才开始第一步。工单 #650 的这个场景里，封装（`seal`）动作的 `scene.after(4600)` 回调安排的是「取件并送到管道口」的第二段脚本，晚一帧起步就让搬运动作晚了 50 毫秒开始，取样时正好落在两段之间，姿势于是从 `carry` 变成 `walk`。

修正：`stepScene` 的顺序改成与原型的 `frame` 一致——先到点的回调，再小人，再粒子与飞行物。

验证：

- 逐场景回放 54 份场景零不一致（`node --test tests/unit/pixel-room-replay.test.ts`，约 130 秒）；楼层与楼的回放同样零不一致。

### 第 3 轮（盖章说明仍然没有说出来的原因）

执行者 minimax-M3.1-Flash / 2026-10-23 /

逐场景回放过了，端到端还有一条不过：「工具类与盖章类的说明」在质检房间失败，房间里出现过的说明是「完成了！ / 收到工程的询问：交付前需要确认哪一条验收条件 / 现在整理资料 / 现在提交回答 / 收到交付箱，来自工程」——没有「现在盖放行章」，也没有「现在开始检查」。

原因：v11 第 2 条的实现只看了队列的第一条。

- 原型 `docs/prototypes/v11/js/pixel/room.js` 的 `keepPending` 与客户端 `client/src/renderer/src/pixel/room/driver.ts` 的同名函数原来都是「队列的第一条是交接或盖章才算」。
- 真实运行里质检房间的队列不是这样：质检收到交付以后，工具类动作、询问与回答先后排进队列，放行盖章排在这些动作的后面，事项完成到达时盖章不在队首。
- 事项完成是状态类动作（立即执行），`keepPending` 判成假，队列被清空，放行盖章连同它要说的话一起没了。

改成「队里的任何一条是交接或盖章就算」（原型与客户端同时改）：

- 状态类动作到达时，队列只留交接与盖章，状态类动作排在它们后面；盖章先做完并把话说完，状态类动作再做。
- 原型改了就重新录制：54 份房间调用重新录（控制台错误 0），像素登记表重新生成；客户端与新录制逐场景回放零不一致。
