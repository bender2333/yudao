# 工单 #510：smoke 回执读取侧按 #481 的位置改从工具事件工件读

## 任务

`harness/smoke.py` 的 `summarize_run` 只读运行工作区回执，而 #481 起质检会话在自己的检查工作区里跑检查、会话结束即删（`harness/environment.py:636 record_check` → `harness/sessions.py:56-66 cleanup_run`），质检回执永远读不到，`_receipt_evidence` 报 `quality: no successful host check bound to the final contract and snapshot`。

## 基线

- `test_smoke.py`：4 failed, 58 passed（`test_native_audit_checks_every_step_and_actual_host_receipts`、`test_receipt_audit_rejects_new_contract_even_with_unchanged_spec_and_tree[effective_contract]`、`test_model_input_audit_tracks_new_input_and_prompt_versions`、`test_unmatched_host_receipt_does_not_pass`）。
- `test_run_check.py`：1 failed, 11 passed（`test_delivery_citing_a_run_check_receipt_is_accepted_and_quality_releases_on_it`）。

## 绑定探针证据

`.tmp/probe_510.py`（非交付物）：native happy 运行与 collaboration/demo 运行两种场景，逐条核对工具事件 `run_check` 工件：

- native：workspace digest `sha256:714c2339…` == 交付树 digest；质量事件（stream_version 57、64）`snapshot_hash` 等于该 digest，`delivery_spec_hash` = 最终 `delivery_spec.content_hash`，合同与规格哈希匹配，`exit_code=0`、`tree_changed=false`。运行工作区只有工程 2 条回执。
- collaboration：workspace digest `sha256:1555facb…` == 交付树 digest；最后一轮质量事件（191 `echo`、193 `flags`、195 `usage`）`snapshot_hash` 等于该 digest，`delivery_spec_hash` = 最终 delivery `content_hash`，哈希匹配，`exit_code=0`。早轮（150 `usage` exit 1）快照不同，天然不参与绑定。
- 合并读法下两个部门都有有效回执，`test_model_input_audit_tracks_new_input_and_prompt_versions` 的绑定前提成立。

## 实现

`harness/smoke.py`：

- `summarize_run` 第 161 行改调 `_check_receipts(system, run_id)`，删掉只服务该行的 `workspace = …` 行。
- 新增 `_check_receipts`：运行工作区回执文件 + 工具事件 `run_check` 主机执行工件合并去重。去重键 `(department, name, activation_id, snapshot_hash, exit_code)`——同一次检查在两处各有一份、字段值相同，不去重会被核对循环算成两条回执。工件条目补 `"department": event.department`。
- 新增 `_host_check_executions`：`_receipt_evidence` 内联的 executions 收集 + 激活核对 + 读数异常备注原样搬入，返回 `(executions, notes)`；`_receipt_evidence` 改用它。匹配循环、快照取法、`("engineering","quality")` 绑定循环一字未改，判定条件一个不放松。
- 保留工作区回执来源的原因：`test_unmatched_host_receipt_does_not_pass` 删掉全部 `run_check` 事件后必须出现 `no matching host execution` 备注，回执只读工件会把回执一起删光。

`harness/tests/test_run_check.py`：按工单验收 #2 迁移该用例——工程回执仍读运行工作区（`len == 1`、`exit_code == 0`），质检回执从 `tool_called` 工件读（断 `executor == "host"` 与 `exit_code == 0`）。证明的行为「工程与质检各跑过一次、都是主机执行的真实进程」不变。新增 `import json` 与 `ArtifactRef` 导入。
