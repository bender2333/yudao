# 工单 #551 执行日记

## 任务目标
实现询问工具与一层询问分支（ADR-0036、三部门循环结构第 4.1 至 4.3 节）：
1. 新增询问工具 `ask`（三个部门均有，控制核心处理）与回答工具 `answer`（仅在询问分支中提供，产品可附 PRD 修订）。
2. 提问方在 `ask` 调用处暂停步骤循环等待分支回答，当前激活不结束。
3. 控制核心在被询问部门历史上开出独立 `session_id` 的询问分支，分支请求包含被询问部门已有历史、每步重新计算的状态与问题；分支内无 `ask` 工具。
4. 产品的回答可附 PRD 修订，通过版本核对后接纳新版本，提问方下一步收到新 PRD 版本并继续工作。
5. 被询问部门历史只多一条问题与回答记录，排除分支内部读取过程。
6. 工程/质检分支在检查工作区中运行，拒绝写入运行工作区、提交交付、缺陷记录与放行；产品分支仅允许提交回答。
7. 新增事件种类 `ask_started` 与 `ask_answered`，登记载荷合同与 `KEY_FIELDS`。
8. 新增事件序列场景 `ask_answer_with_spec_revision` 并建立基准。

## 第 2 轮执行过程（审查问题修复）
1. **审查问题定位**：
   - 审查意见 1.1：`orchestrator.py` 在 `commit_prd_revision` 中手工拼装 `spec_payload`，绕过了 `submit_product_spec` 的 schema 与业务校验（`_validate_schema` 与 `_accept_product_spec`），导致回答附带修订时如果缺少必填字段（如只传 `requirements` 时 `acceptance_criteria` 变成空列表，`change_record` 为 None，有效产品决定被清空）依然被接纳放行；且触发条件过宽（仅带 `basis_product_spec_hash` 也会写出空 PRD rev2）。
   - 审查意见 1.2：`orchestrator.py:1481` 在还没有 PRD 时用 `"build an echo CLI"` 硬编码兜底，连同 `[]` 兜底需要一并删除，由必填字段校验自然拒收。
2. **测试先行**：
   - 在 `harness/tests/test_ask_branch.py` 中新增用例：
     - `test_ask_answer_requirements_only_rejected_and_cannot_lose_acceptance_criteria`：断言只传 `requirements` 时 `answer` 工具调用被拒（返回字段校验错误给分支），重答带完整规格后方可接纳，且 rev2 的 `acceptance_criteria` 不会丢失。
     - `test_ask_answer_echoing_only_basis_hash_creates_no_revision`：断言仅回显 `basis_product_spec_hash` 时判定为无修订意图，不出新版本（保持 rev1，不发出 `spec_accepted`，`ask_answered` 的 `with_spec_revision` 为 False）。
