# 工单 #513：GitHub App 的令牌入口

## 计划

工单要求 `scripts/github-app/` 下提供入口，角色进程设两个环境变量后，`gh` 与 `git push` 以 App 的安装身份运行。入口分两层：

- 四个入口脚本（`gh`、`gh.cmd`、`git`、`git.cmd`）：只负责找到真正的 `gh` 与 `git`，两个变量都没设置时直接 exec 过去，不经 Python。
- `yudao_github_app.py`：签名、换令牌、缓存、透传。`gh` 走 `GH_TOKEN` 环境变量；`git` 走 credential 助手协议，凭据只在 git 真的请求网络时才取。

## 实现要点

- App JWT：RS256，`iat` 提前 30 秒，有效期 540 秒（GitHub 要求不超过 10 分钟）。
- 安装编号：`GET /app/installations` 里按 `account.login == bender2333` 选中，不另外配置。
- 令牌缓存：`%LOCALAPPDATA%\yudao\github-app-token-<App 编号>.json`，只写令牌与过期时刻。剩余不足 600 秒换新，否则复用。
- `git` 侧用 `GIT_CONFIG_PARAMETERS` 先把 `credential.https://github.com.helper` 置空，再放我们的助手。命令行配置排在用户全局与系统配置之后，不清空的话 Git Credential Manager 与全局 gh 助手会先应答。
- 入口可能由任意 Python 启动（系统 Python 往往没有 cryptography），`ensure_interpreter` 探测一个能 import cryptography 的解释器再 exec 过去，探测过打标记避免循环。
- 私钥文件不存在或不可读时报错写明变量名与路径，不回退到其他身份。
- 令牌只经环境变量或 credential 协议的 password 一行传给子进程，不进任何日志。

## 踩到的问题

测试里的假 `gh` 脚本用 `echo %*>> "路径"`，`--limit 5` 的 `5` 紧贴 `>>`，cmd 把它当成 5 号描述符的重定向，末尾参数被吃掉，记录文件是空的。`>>` 前加一个空格即正常。行尾会多出这个空格，读记录的 helper 里 `rstrip(" ")`。

## 依赖

`cryptography` 加到 dev 依赖组并显式声明（trustme 已经传递带着同一个包，这里不依赖传递关系）。运行依赖不变。
