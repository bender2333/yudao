# 工单 #731：升级以后实例永久停在排空状态

依据：架构师分诊与更正（2026-10-23，工单评论）与[应用层与接口层设计说明](docs/design/app-and-interface.md) 第 3.2 节「升级」（main 的提交 `caac7d4b`，2026-10-22：**排空在下一次启动时结束，不比较版本**）。[用户使用记录](docs/user-session-log.md) U67（2026-10-22 用户走「实例升级」这条没走过的路径时实测）。分支 `issue-731`，worktree 在 `D:/codes/yudao-worktrees/issue-731`，起点是 main 的 4a0100b7。

## 记录

执行者 minimax-M3.1-Flash / 2026-10-23 /

1. 核对现象（U67 实测 + 这一轮复核代码）：
   - 目录流里只有 `runtime_drain_started` 与 `runtime_force_upgrade_requested` 两种事件，**没有「排空已结束」** ✓；
   - `harness/runtime.py` 的 `drain` 属性：只要有排空事件，状态就是 `ready` 或 `draining`，**永远回不到 `idle`** ✓；
   - `harness/app/project_and_work_item_commands.py` 第 184 至 187 行：新建事项的判断是 `drain.state != "idle"` → 排队 ✓；
   - 排队的事项**只在服务启动时**被补建 run ✓——所以升级只恢复了一次 ✓。
2. 口径：设计说明第 3.2 节写明「排空在服务下一次启动时结束，**不比较版本**」✓（提交 `caac7d4b` ✓，提交标题就是「排空在下一次启动时结束（#731）」✓）。架构师第一版分诊写成「比较版本」✓，与这条冲突 ✓，已在工单评论里更正 ✓，这一轮按设计说明做 ✓。
   - 为什么按设计说明：**它才修好用户走查里的那件事** ✓——用户 2026-10-22 的走查是「排空 → 重启 → 第一个事项自己开始了 → 建第二个事项又不动」✓（U67），不比较版本时第二个事项这一次就直接开始 ✓；比较版本时同一个版本重启以后第二个事项仍然排队 ✗，用户看到的症状还在 ✗。
3. 实现：
   - `harness/streams.py`（核心文件）：新的事件种类 `runtime_drain_finished` ✓ 与常量 `DRAIN_FINISHED` ✓；加一个共用函数 `last_drain_event(events)`——目录流里最后一条与排空有关的事件 ✓（控制核心与项目服务都用它判断排空还有效 ✓）。
   - `harness/models.py`（核心文件）：`CatalogEventType.RUNTIME_DRAIN_FINISHED` ✓。
   - `harness/app/payloads.py`（核心文件）：新的 `RuntimeDrainFinishedPayload`（排空状态的版本）✓；**`runtime_drain_started` 的载荷一个字没改** ✓（不比较版本就不需要记发布版本 ✓）。
   - `harness/app/labels.py`：新事件的说明 ✓。
   - `harness/runtime.py`（核心文件）：
     - `drain` 属性按**最后一条排空事件**算状态 ✓（最后一条是「排空已结束」时回到 `idle` ✓）；
     - `finish_drain_on_startup()`：启动时把还没结束的排空记成已结束 ✓（已经结束的不重复记 ✓）；
     - `start_drain` 不变 ✓（只多一条事件种类，不改载荷 ✓）。
   - `harness/projects.py`（核心文件）：`_draining()` 同样按最后一条排空事件判断 ✓——排空结束以后排队的事项这一次就补建 ✓。
   - `harness/app/system_queries.py`（核心文件）：系统状态这一处查询声明的事件种类加上新的那一种 ✓。
   - 启动顺序：`LoopSystem.__init__` 里结束排空这一步在**补建排队事项的 run 之前** ✓——所以不用再重启一次 ✓，那批排队的事项这一次就补建并开始 ✓。
   - `client/src/renderer/src/views/system/drain-text.ts`：排空时的提示写清下一步 ✓（装上新的版本以后重新启动，排空会解除 ✓）。
   - 生成的接口快照与客户端类型随合同重新生成 ✓（接口版本仍是 7 ✓）。
4. 测试（`harness/tests/test_drain_upgrade.py`，模块层与集成层，三条）：
   - 下一次启动排空结束 ✓，目录流里留下「排空已结束」✓，再下一次启动不重复记 ✓；
   - 排空 → 排队一个事项 → 下一次启动 → 排空结束 ✓，排队的事项这一次补建并跑完 ✓，之后新建的事项直接开始 ✓；
   - 新增的事件种类能读出来、中文说明有登记 ✓（事件流不断 ✓）。
   - `client/tests/unit/drain-text.test.ts`：提示写清下一步 ✓（新增一条用例 ✓）。
