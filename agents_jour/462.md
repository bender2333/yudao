# 工单 #462：实例升级的三个目录事件登记负载契约

## 背景与目标

`32865edb`（#355 发布检查）在 `harness/models.py` 的 `CatalogEventType` 加了三个事件：
`instance_upgrade_requested`、`instance_upgrade_answered`、`instance_upgrade_withdrawn`，
但没有在 `harness/app/payloads.py` 的 `PAYLOADS` 登记负载契约。后果是
`EVENT_TYPES = tuple(PAYLOADS)` 里没有它们，能力表与 OpenAPI 事件联合也不含这三个事件。

目标：登记三份契约，删掉 `test_api.py` 里为这个缺口开的差集，重新生成接口快照与客户端类型，
契约检查覆盖这三个事件（需要有产出它们的场景）。

## 事实来源

三个事件的写出方：

- `instance_upgrade_requested`：`harness/release_check.py` 的 `decision_request_payload`（约 385 行）
  与 `request_instance_upgrade(system, report)`（约 403 行），经
  `system.writes.transact(catalog_stream(), decide)` 写入，`actor="system"`。
- `instance_upgrade_answered`：`harness/orchestrator.py:1677-1682`，`answer_decision` 的目录流分支。
- `instance_upgrade_withdrawn`：全仓无写出方，只有 `harness/projection.py:167-172` 的并入处理，
  读 `payload["decision_id"]` 与 `payload["reason"]`。

写出载荷（唯一事实来源）：

- requested：`kind="instance_upgrade"`、`blocks="instance"`、
  `options` 只有 id/label（`DecisionOption.note_required` 默认 False）、
  `description`、`facts=[report.text]`、`report` 八字段。
- answered：`decision_id`、`option`、`note`、`base_version`。
- withdrawn：`decision_id`、`reason`。

## 决定

- 三个事件各建一个独立载荷类，不复用 `DecisionAnsweredPayload`：`payloads.py` 文件头约定
  「现有每个事件种类一个 pydantic 类型」，`ProjectDecisionAnsweredPayload`/
  `ProjectDecisionWithdrawnPayload` 已是同字段也另建一类的先例。
- `report` 建成嵌套 `InstanceUpgradeReport`（八字段全必填），`findings` 用
  `list[dict[str, Any]]`，与 `CatalogCandidatesCollectedPayload.candidates` 先例一致。
- `InstanceUpgradeWithdrawn.reason` 是 `str`，不是 `StopReason`：目录流决定不绑定 run，
  参照 `ProjectDecisionWithdrawnPayload`。
- `instance_upgrade_withdrawn` 没有生产写出方，在 `test_event_payloads.py` 的场景里用目录流写入口
  直接写出（`test_decision_projection.py` 对 run 流用同一手法）；requested 走发布检查的真实入口
  `request_instance_upgrade`，answered 走 `orchestrator.answer_decision` 的目录流分支。
- 不动 `DecisionView.request` 联合与 `DECISIONS_LIST.changed_by`：#355 遗留缺口、非本单验收项，
  登记到 `docs/architecture-issues.md`。

## 改动

- `harness/app/payloads.py`：新增 `InstanceUpgradeReport`、`InstanceUpgradeRequested`、
  `InstanceUpgradeAnswered`、`InstanceUpgradeWithdrawn` 四个类，PAYLOADS 表末尾加三条映射。
- `harness/app/labels.py`：加三条事件说明。占位只用载荷确有的字段（`report`、`facts` 不写进说明，
  否则 `test_every_label_renders_without_a_blank_placeholder` 与
  `test_every_label_placeholder_is_a_field_of_that_events_payload` 会红）。
  必须一起改：`harness/app/event_stream.py:26` 对流过的事件调 `event_label`，未登记种类会 KeyError。
- `harness/tests/test_api.py`：删掉 `unregistered` 差集，断言恢复为
  models 三类枚举全集 = 能力表 = OpenAPI 判别联合。
- `harness/tests/test_event_payloads.py`：场景里产出三个事件（requested 经发布检查入口，
  answered 经 orchestrator，withdrawn 经目录流写入口），`assert_payloads_follow_contract(events)`
  覆盖它们。
- `docs/architecture-issues.md`：登记 `decisions.list` 的缺口。
- 生成物：`harness/tests/openapi/openapi.json`（`--write-openapi-snapshot`）、
  `client/src/renderer/src/api/generated/*`（`npm run generate:api`）。

工单正文写的 `docs/design/openapi.json` 不存在（已核实），实际快照是
`harness/tests/openapi/openapi.json`。
