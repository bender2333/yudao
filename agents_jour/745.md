2. 根因（三个文件，客户端两个、服务端一个但服务端是对的）：
   - `client/src/renderer/src/views/project/observe.tsx` 第 388 行：「引用」这一行用 `optionalText` 读 `artifact_refs` 的四项，而**工件引用是对象**（种类、内容摘要、工件路径、媒体类型），不是文字。
   - `client/src/renderer/src/views/project/common.tsx` 第 23 至 36 行：`text()` 只认字符串、数字与布尔，对象落到最后一行变成空串；`optionalText` 再把空串变成 null；`show()` 把 null 变成「未上报」。**同一个词「未上报」在这里盖住了两种完全不同的情况：这一次没有上报，与这一次有、但取不出来**——工单正文的 Notes 说的正是这件事，这两种情况的修法不同。
   - `harness/observability.py` 第 80 至 85 行：服务端把四项引用原样放进 `artifact_refs`（有就是工件引用对象，没有就是 `null`），**服务端不用改**。
3. 顺带核过（工单正文第 4 条）：客户端全部 `optionalText` 调用点都读过一遍——`department.tsx` 读的是部门设置与调用目标里的文字字段，`observe.tsx` 读的是调用目标、尝试记录、栏目、事件与工具回执里的文字字段，`overview.tsx` 读的是 git 版本。**只有「引用」这一行读的是对象，没有第二处。**（`text()` 遇到对象一律变成空串，页面上不会出现 `[object Object]`。）
4. 服务端的形状实地核过（不提交的一次性脚本）：用真实 Responses 协议跑一次运行，读 `run.attempt` 的 `artifact_refs`，四项都在，每项是 `{content_hash, kind, media_type, path}`（`request` 的 kind 是 `sdk_request`，`events` 是 `sdk_stream_events`，`usage` 是 `model_usage`）。**与工单正文的证据一致，服务端确实是对的。**
5. 实现的取舍（写在这里，事后好核对）：
   - 新增 `client/src/renderer/src/views/project/artifact-ref.ts`（纯函数，界面与单元测试共用）：工件引用的取值与显示。
   - **内容摘要取十六进制的前 12 位，不带算法前缀**：`sha256:b407eb8c…` 显示成 `b407eb8c…`。这样页面上没有英文标识，摘要仍能与工件路径里的文件名、事件里的完整摘要对上（决定卡片的「指纹」是同一口径的既有写法，见 `client/src/renderer/src/views/decisions/card-logic.ts`）。
   - **没有内容摘要时给工件路径**，两个都没有才写「取不出」。
   - **不显示工件的种类与媒体类型**：`sdk_request`、`application/json` 这类内部标识不面向用户。
   - **三种状态分开**：没有这一项引用写「未上报」并写明是哪一项；有引用但取不出标识写「取不出」；有引用给可核对的标识。
   - **不改 `common.tsx` 的 `text()`**：让它认识对象会到处打印 `[object Object]`，工单正文也不推荐；工件引用单独给一个函数。
   - 接口不变（`artifact_refs` 的形状没动），因此 OpenAPI 快照与客户端类型都不重新生成，`API_VERSION` 不必提高。
6. 实现（客户端）：
