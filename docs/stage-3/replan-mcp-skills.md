# Stage 3 重排方案：将 MCP 和技能提前到 Stage 3

更新：2026-10-12。状态：提议，未经用户确认采纳，不改变当前的 Stage 3 计划、路线图与工单。决定：[ADR-0035](../adr/0035-mcp-and-skills-move-into-stage-3.md)。依据：[Stage 3 计划](../stage-3-plan.md)、[总体路线图](../program-roadmap.md)、[D36 网络取回与 MCP 工具](../requirements/network-and-mcp.md)、[网络取回与 MCP 工具设计说明](../design/network-and-mcp.md)、[阶段需求概览](../requirements/stage-requirements-overview.md)、跟踪工单 #9。

## 1. 背景

- **收窄的目标**：2026-09-19 前后的讨论与 2026-09-24 的路线图调整把 Stage 3 收窄为通用工具、可靠恢复与并行，先得到一个能稳定运行的普通 harness；语义系统（D25）与部门内多角色（D26）移到后面的阶段。
- **技能移出 Stage 3**：2026-09-24 的路线图调整写明「语义系统、部门内多角色、技能、Yudao 自身可观测性、前端优化组成 Stage 4」，9 月 28 日重新编号后技能归 Stage 5。路线图当时对技能的描述：「技能：注册、适用性、执行与展开、异常出口与比较。稳定过程有独立证据，封装后质量不降，收益覆盖维护成本。」阶段需求概览（2026-10-07）写「技能只有路线图」，仓库中没有技能的工单。
- **此后范围的增长**：Stage 3 陆续加入远程执行（3.2C，D29）、评测工作线（D32）、网页界面（D30、ADR-0032）、浏览器（3.2D，D34）、模型管理（D24，2026-09-28 移入）、迭代底座与自举工作线（D38，2026-10-06）。3.2B 网络取回与 MCP 工具（D36，2026-10-01）已在 Stage 3，设计第 1 节把 OAuth 登录、SSE 传输，以及 MCP 的资源、提示、采样、roots 与向用户请求输入列为不在范围内。

## 2. 用户新决定

2026-10-12 用户提出的规则：

1. MCP 与技能作为功能本身移入 Stage 3。
2. MCP 与技能所依赖的前置能力（执行环境的合同、工具登记、凭据、许可、事件与恢复契约、设置界面的基础等），如果在后面的阶段或者还没有，同样移入 Stage 3。
3. 依赖 MCP 或技能的功能（使用方，例如 #62 的探索者）不移动，留在原阶段；3.2D 浏览器已在 Stage 3，不变。

说明：用户原话中还有「后续阶段里写明依赖 MCP 或技能的功能清单……这些是要提前的」，与第 3 条冲突；本方案按第 3 条处理，冲突项在第 4 节标出，待用户确认。
