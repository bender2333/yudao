## 1. 可信项目：文本报表工具

三个场景使用同一个项目；基线由场景 A 的第一个事项建立，后续事项在同一项目上继续（采纳与继承由现有项目层保证）。

### 1.1 目标结构（v1）

| 文件 | 职责 |
| --- | --- |
| `src/report.py` | CLI 入口：`python src/report.py <path>` 读取输入并打印报表，退出 0；文件不可读时向 stderr 输出 `error: cannot read <path>` 并退出 1 |
| `src/parse.py` | `parse_lines(text)`：非空行必须是 `name,amount`（amount 为非负整数）；空行跳过；其它行抛 `ValueError("invalid line <n>: <line>")`（行号从 1 开始） |
| `src/format.py` | `render(records)`：首行 `total=<sum>`，随后按输入顺序每行 `<name>=<amount>` |
| `samples/normal.txt` | `alpha,3`、`beta,5`、一个空行、`gamma,7` |
| `samples/empty.txt` | 空文件 |
| `samples/bad.txt` | `alpha,3`、`broken-line` |

### 1.2 公开检查（主机执行，argv 由模型提交）

| 名称 | argv | 期望 |
| --- | --- | --- |
| `report_normal` | `python src/report.py samples/normal.txt` | exit 0 |
| `report_empty` | `python src/report.py samples/empty.txt` | exit 0 |
| `report_bad` | `python src/report.py samples/bad.txt` | exit 1 |
| `report_categorized` | `python src/report.py samples/categorized.txt` | exit 0（场景 A 新增） |
| `report_category_order` | `python src/report.py samples/categorized.txt`，`red` 必须出现在 `blue` 之前 | exit 0（场景 B） |
| `report_top` | `python src/report.py samples/categorized.txt --top 2` | exit 0（场景 B） |

## 2. 场景 A：多文件增量变更

- 事项 1（建立基线）：任务原文见 §2.1；工程检查 `report_normal`，质检检查 `report_normal`、`report_empty`、`report_bad`。
- 事项 2（增量变更）：任务原文见 §2.2；工程检查 `report_normal`、`report_categorized`，质检四项全跑。
- 完成条件：新旧公开检查均通过；工程与质检各自独立检查；交付、Git、采纳与 replay 对应；输入含正常、空与非法情况。

### 2.1 任务原文（事项 1）

```text
Build a small local Python text report tool in this repository.

Create exactly these files:
- src/report.py: CLI entry. `python src/report.py <path>` reads the input file, prints the report to stdout and exits 0. If the file cannot be read, print `error: cannot read <path>` to stderr and exit 1.
- src/parse.py: `parse_lines(text)` splits the input into records. Each non-empty line must be `name,amount` where amount is a non-negative integer. Empty lines are skipped. Any other line raises ValueError("invalid line <n>: <line>") with the 1-based line number.
- src/format.py: `render(records)` returns the report text: first line `total=<sum>`, then one line per record in input order `<name>=<amount>`.
- samples/normal.txt: exactly `alpha,3`, `beta,5`, one empty line, `gamma,7`.
- samples/empty.txt: an empty file.
- samples/bad.txt: exactly `alpha,3`, `broken-line`.

Engineering must have the host run the check `report_normal` with argv `python src/report.py samples/normal.txt` and it must exit 0.
Quality must independently have the host run `report_normal`, `report_empty` (argv `python src/report.py samples/empty.txt`, exit 0) and `report_bad` (argv `python src/report.py samples/bad.txt`, exit 1).
```

### 2.2 任务原文（事项 2）

```text
Extend the existing text report tool with a category summary while keeping all current behavior.

- Input lines may have an optional third column: `name,amount,category`. Lines with two columns keep working and count as category `uncategorized`.
- src/parse.py: parse the optional category and keep rejecting invalid lines exactly as before.
- src/format.py: after the per-record lines, append a section: a line `categories:` followed by one line per category in first-appearance order `<category>=<sum>`.
- src/report.py: pass the new data through; no CLI change.
- samples/normal.txt must stay exactly as it is (two-column lines only).
- samples/categorized.txt: exactly `alpha,3,red`, `beta,5,blue`, `gamma,7,red`.

Engineering must have the host run `report_normal` and `report_categorized` (argv `python src/report.py samples/categorized.txt`) and both must exit 0.
Quality must independently have the host run `report_normal`, `report_empty`, `report_bad` and `report_categorized`.
```

## 3. 场景 B：返工与定向指导

- 前置：场景 A 的 v2 已采纳。
- 受控缺陷（事先声明）：场景脚本在创建事项后把 `src/format.py` 覆写为"分类按字母序输出"的版本；任务要求本事项不修改 `src/format.py`；质检的 `report_category_order` 会失败，质检据此要求返工。
- 完成条件：出现一次返工并引用正确版本；定向指导进入合法上下文；最终交付通过；受控缺陷在报告中标注，不称为自然回归。

### 3.1 任务原文（事项 3）

```text
Add a `--top N` option to the report tool.

- `python src/report.py <path> --top N` prints only the N records with the largest amounts, in descending amount order, then the `total=<sum>` line, then the `categories:` section as usual.
- Without `--top`, behavior must stay exactly as it is.
- Do not modify src/format.py in this item: it is under review.
- Engineering must have the host run `report_normal` and `report_top` (argv `python src/report.py samples/categorized.txt --top 2`) and both must exit 0.
- Quality must independently have the host run `report_normal`, `report_top` and `report_category_order`; in `report_category_order` the output of `python src/report.py samples/categorized.txt` must list `red` before `blue`.
```

### 3.2 定向指导（工程激活期间追加，不改变目标）

```text
修复分类顺序时请保持两列输入与 total= 行的现有行为不变。
```
