# Stage 3 试用与自举准备的验收合同

更新：2026-10-08。状态：合同已确认；M1、M2 的实际发布与走查尚未完成。工单：M1 #183、M2 #184、自举父工单 #395，准备子工单 #416。每次交付使用 [验收证据规则](../agents/acceptance-evidence.md) 的身份、结论与未解决项。

## 1. M1 网页与模型管理

试用指南由架构师在实际发布版本上走完以下路径后写定。路径使用发布的 wheel、独立的数据目录与端口；记录发布标签、wheel 摘要、源提交、浏览器版本、Provider 目录摘要和实际模型。Key 在页面输入，凭据保持在实例的数据目录和内存中。

| 操作 | 必须观察到的结果 | 证据 |
| --- | --- | --- |
| 安装发布包并手动启动 | `/` 提供该发布的页面，服务和页面的版本相同；浏览器按启动选项打开 | 安装与启动记录、能力清单、页面截图 |
| 在页面添加 OpenCode Go | 选择方案、输入 Key 后保存；列表可以取得，ID、名称和凭据引用由表单自动填写 | 页面操作、脱敏的目录查询、列表请求记录 |
| 从列表勾选加入模型 | 协议与容量来源可见，自动测试通过才准入；失败显示原因且不准入 | 页面截图、访问定义、模型测试结果 |
| 配置三个部门并运行事项 | 三个部门使用选定模型，质检放行并采纳；楼层、房间与文字列表显示同一事项事实 | 事项/run 身份、事件、交付、放行与采纳、截图 |
| 制造模型配置不可用并回答决定 | 首页、项目入口与大厅卡片显示同一请求；配置恢复后继续或停止，结果写入事件 | 决定身份、回答事件、继续或停止后的结果 |
| 查看报告和回放 | 已看过的位置正确更新；回放位置在刷新后保持；返回现在恢复实时 | 事件位置、页面操作、快照 |
| 重启与版本变化 | Ctrl+C 释放实例锁；服务重启后页面重新连接；页面与服务版本变化时重新加载 | 启停记录、连接状态、版本查询 |
| 核对画面 | 两种窗口、三种设备像素比、浅色与深色主题的联系表与确认的原型相符；流转类别与回放场景都覆盖 | #376 的联系表、逐场景回放结论、#365/#378–#386 的验收 |

M1 的相关缺陷、回放失败 #414 和流转原型差异 #415 有处理工单并完成；#183 的每项能力都有同一发布版本的证据以后，才改为 `ready-for-human`。0.1.1 的指南保留它的版本身份；0.1.2 的实际指南随发布另写并在 #183 引用。

## 2. M2 恢复、建档与写回

M2 先核对 #139 的真实 openai-agents-python 建档与 issue 842，#338/#410 的真实进程测试，#347 的写回，#351 的项目级检查时限，#157 的测试分层，以及修正后的评测报告。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 建档与确认 | 初始 PRD、结构说明、逐条基线核验与树摘要可追溯；在网页决定卡片确认后采纳基线 |
| 后续变更 | 从建档基线开始，独立质检按完整有效 PRD 核验，交付与采纳绑定同一树 |
| 真实进程中断 | 在事先声明的模型、文件或命令位置结束自己启动的进程；同一版本重启后自动继续；已用时间和次数连续；未知外部动作先核实 |
| 排空与强制升级 | 排空停止新事项；run 事件版本不同按已确认的升级规则停止并重新开始；项目流中的采纳和决定仍可读取 |
| 采纳写回 | 三方合并保留期间的独立修改；冲突和核验失败停止；成功分支引用最终树与目标提交；未知结果核实后继续 |
| 参数修改与撤回 | 界内修改和改回原值各写事件，只影响之后创建的 run；项目检查使用冻结的时限 |
| 评测 | 场景 2、3 规定的运行次数完整，材料和评分版本相同；结束、放行、用量未知与费用未知分别记录；版本比较含有效样本数 |

报告按尝试列出应用版本、定义与参数版本、注入位置、run、动作身份、事件与工件、首次结果和重新运行结果。受条件限制的场景保留受阻结论。#184 在其余 M2 子工单、集成和真实走查完成后交给用户确认；M2 关闭作为自举准备的前提。

## 3. 自举准备

准备工单 #416 属于 #395，在 M2 关闭并完成以下清单后，由后台执行者交付、独立审查者核对。准备不会实现 #396 至 #401 的功能。

1. 从发布包运行实例，记录安装包、提交、定义与参数版本，使用独立数据目录和端口。
2. 用 `project.onboard` 接入 Yudao 仓库，记录来源提交、公开树摘要、初始 PRD、结构说明和基线核验；初始 PRD 由用户确认。
3. #347 的三方写回与 #351 的项目级检查时限已验收；登记检查命令能验证最终树，包括集成层运行。
4. omp 基线的未知值修正工单 #413 完成，导出范围、真实运行记录、未归因失败和有效样本数均可复核。
5. 在运行配对任务前固定试点约定：六张任务文本、同一份原型与评价材料、模型组合、每对共同起点、先后轮换、匿名的审查材料、失败及补跑计入方法。共同起点包含该工单已经解除的实际依赖。

用户确认尚未到达时，准备工单保留 `waiting` 并记录等待内容。准备审查通过和架构师核对以后，#396 至 #401 按各自里程碑与原生依赖开放，#395 的配对验收按路线图第 6.1 节进行。
