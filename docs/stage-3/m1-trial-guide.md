# M1 试用指南：桌面客户端与模型管理

试用版本：0.1.1（标签 `v0.1.1`，提交 `70fdcce5`，在集成层通过的 `9ebafdd5` 上只改了版本号）。试用工单 [#183](https://github.com/bender2333/yudao/issues/183)。对应 [Stage 3 计划](../stage-3-plan.md)第 1 节的这几项能力：在模型管理页维护模型目录与准入、每个项目单独选择各部门的模型与推理档位、质检的模型不能看图时得到提醒；在桌面客户端的系统首页看到需要自己决定的事与离开期间发生了什么、在托盘收到提醒；每项能力都有对应的界面。旧的 Web 控制台已经删除，试用全程只使用桌面客户端。

0.1.0 的走查发现三个影响试用的缺陷（按 `--data-dir` 启动的服务仍读写用户默认目录里的模型目录、回答待恢复的决定以后跑完的事项没有被采纳、部门页签之间切换报错），0.1.1 已经修好，不要使用 0.1.0。

## 1. 试用前的准备

- 一台 Windows x64 电脑，已安装 [uv](https://docs.astral.sh/uv/) 与 GitHub 命令行 `gh`（已登录，用来从私有仓库的 Release 下载安装包）。
- 一个可用的模型服务：请求地址、模型名与 API Key。产品、工程、质检三个部门都要选模型，一个模型可以三个部门共用。步骤 3 新建事项需要真实的模型回答，一个小事项通常一到七分钟，费用由你的服务方案承担。
- 试用从空的数据目录开始（默认 `%LOCALAPPDATA%\Yudao`）。开发时 `.yudao/` 下的数据不会带过来。
- 想与已经在用的 Yudao 分开：启动服务时加 `--data-dir <目录>` 与 `--port <端口>`，模型目录文件 `providers.json`、准入记录 `admissions.json` 与 `.env` 都放在这个目录里；客户端在「连接设置」里把「访问方式」选为「局域网内的控制主机」，地址填 `http://127.0.0.1:<端口>`。

## 2. 步骤

### 步骤 1：安装服务与客户端，连接

1. 取得安装包：`gh release download v0.1.1 --repo bender2333/yudao --pattern "*.whl" --dir <下载目录>`。
2. 安装服务：`uv tool install --python 3.12 <下载目录>\yudao_harness-0.1.1-py3-none-any.whl`。uv 提示目录不在 PATH 时运行 `uv tool update-shell`，重新打开终端。
3. 安装客户端：`yudao client install`，它运行 wheel 附带的安装程序，装到 `%LOCALAPPDATA%\Programs\Yudao`，开始菜单有「Yudao」。
4. 从开始菜单启动「Yudao」。客户端默认连接「本机」（`http://127.0.0.1:8765`）：服务没有运行时，客户端在 PATH 里找到 `yudao` 命令并在后台启动 `yudao api`，通常九秒左右，最多等 30 秒。

应该看到：先是整页「连接中…」，随后左上角出现品牌「Yudao」，顶栏右侧显示「已连接」。首页是空的：状态项「待你决定」为灰色的「无」，「全部项目与机器」下写「还没有项目」，「待你决定」下写「没有等待回答的决定」，「离开期间的报告」下写「上次查看：未知时间」；左侧「系统」组里只有「模型管理」。

没有找到 `yudao` 命令：页面跳到「设置」，写着「本机没有运行 Yudao 服务，也没有找到 yudao 命令。」并给出安装命令，按它安装后点「重新检测」。命令找到了但服务 30 秒内没有起来（端口被占、数据目录被另一个服务进程占用）时，界面也是这句话，原因在 `%APPDATA%\Yudao\yudao-service.log` 与数据目录的 `logs\` 里。

### 步骤 2：模型管理——配置 Provider 与模型，为部门选择模型

1. 左侧栏「系统」→「模型管理」。窗口窄时先点顶栏「菜单」。
2. 点「添加 Provider 配置」，「服务方案」选「自定义」，填「ID」「名称」、「协议」（Responses、Chat Completions、Anthropic Messages 三选一）、「地址」（该协议的请求基址，请求路径由 Yudao 拼接）、「凭据引用」（一个环境变量名，例如 `MY_MODEL_KEY`）。展开「高级选项」，在「模型列表地址」填请求地址加 `/models`（没有它「获取模型列表」得到「候选未知：未提供模型列表地址…」，也可以用「手动添加一行」）。点「添加」，表单收起，没有成功提示。
3. 凭据有两种写法：（一）凭据引用写成环境变量名，并且在启动服务的环境里设置这个变量，页面显示「已配置，来源 环境」；（二）卡片「展开」→「编辑」，在「凭据」区的「API Key」框填入 Key，想让重启以后仍然有效就勾「写入 .env」（写到数据目录的 `.env`），点「保存 Key」，变为「已配置，来源 …」。Key 不会回填，页面与网络响应里都没有它。
4. 点「获取模型列表」，在候选里点「建立访问定义」。预填的「ID」若含「/」（例如 `cbcn/deepseek-v4.1-flash`），要改成简单的名字（例如 `deepseek-v4.1-flash`），否则保存被拒；「上游模型 ID」保持原值。「窗口」与「输出上限」都要填（输出上限不大于窗口）：在「窗口」里输入第一个数字时，「接受容量」按钮就消失并显示「容量已确认」，这时输出上限还是空的，把它也填好。模型支持推理档位时，同一行声明「支持档位」「默认档位」「推理参数方式」三项。点「保存」。
5. 点这一行的「模型测试」：按钮变「测试中…」，约几秒，成功以后「准入」列变「已准入：…」，卡片摘要变「已准入 1 · 候选 0」。模型测试没有结果文字，失败时也没有提示，以「准入」列为准。「测试连接」只读取「模型列表地址」，看到「连接测试：连接测试通过（N 毫秒）」，请求地址写错时它仍然通过。
6. 页面下方的「部门默认」：「产品」「工程」「质检」各选一个已准入的「模型」（下拉里显示的是上游模型 ID），模型声明了档位时再选「推理档位」，点「保存部门默认」，看到「已保存部门默认。」三个部门都要选，否则新事项被拒绝：「当前事项」区块下方显示「bindings.quality: 部门 quality 未绑定 Provider 与模型（原因 provider_unavailable）」这样的英文提示，事项没有创建。
7. 保存以后，质检选的是只收文字的模型时，页面出现「quality 部门的模型建议具备图像输入…」的提醒，不阻止使用。

对应能力：模型目录与准入、每个部门的模型与推理档位、质检模型不能看图时的提醒。

### 步骤 3：新建项目、登记检查命令、开始事项，看三个部门工作

1. 左侧栏「从想法新建」，填「项目名称」与「长期目标」（例如名称「回显工具」，目标「做一个命令行回显工具：读取标准输入，原样输出；空输入输出空」），点「新建项目」，看到「已提交，等待写入结果」。新项目出现在左侧「项目」组、首页「全部项目与机器」与「项目」表里；表单不会自动关闭，点「取消」关闭。新建项目只登记项目，不开始事项。
2. 点左侧的项目名进入概览（页签：「概览」「产品」「工程」「质检」「资料」「观测」「设置」）。
3. 登记一条检查命令（工程交付必须带检查回执，登记表在事项创建时冻结）：页签「设置」→「登记命令」→「登记新命令」。弹窗有五项：「登记名」填 `smoke`，「固定参数」填含程序名的完整命令行，例如 `python -c print(1)`（按空格拆分，没有引号语法，输入框的提示文字写的是「例如 --mode strict」，以这里为准），「允许的额外参数」「时限（秒）」「输出上限（字节）」用默认值，点「保存」，表格里出现「smoke … 第 1 版」。
4. 回到「概览」，「当前事项」区块的文本框「新的要求」里写要求（例如「实现回显：读取标准输入，原样输出到标准输出」），点「作为新事项开始」。想看到小人头顶的话，先停在概览或某个部门页（「产品」「工程」「质检」页签）再点开始：动作由实时事件驱动，事后打开不会重播。在部门页签之间切换时，0.1.1 已经不再报错。

应该看到：
- 侧栏项目名旁出现标记「运行中」；「当前事项」区块的状态行依次是「进行中 · 产品处理中」「进行中 · 工程处理中」「进行中 · 质检处理中」；「事项看板」按「产品」→「工程」→「质检」→「已采纳」移动。事项一般一到七分钟完成并被采纳（走查中六个事项用了 59 秒到 6 分 24 秒，质检把交付退回时更久），完成以后「当前事项」区块变回「项目没有进行中的事项…」，要看「已采纳 · 已完成」，在顶栏的「事项」下拉里选中这个事项。
- 概览的「循环画面」是项目楼层：三个部门的房间、传递文件的管道、大厅里的信箱与告示板、成果库，画面下方有文字列表。
- 页签「产品」「工程」「质检」打开部门房间，小人头顶的话说明自己现在做什么，真实运行中观察到的有：产品房间的「现在开始工作」「现在整理资料」「现在把PRD送给工程」，工程房间的「收到PRD，来自产品」「想到办法了」「现在提交交付说明」「现在装箱封存」「现在把交付箱送给质检」，质检房间的「收到交付箱，来自工程」「完成了！」；交接的两端各在自己的房间说一句，每句只停几秒，要看到两端就在两个房间的页签上各停一下；思考时是圆点尾巴的气泡，流式输出的文字逐字接在里面。系统设为「减少动画」时小人少走动，气泡照样显示。
- 部门页下方有「产品工作间」：部门状态、当前生效的模型及来源、最近一次请求实际使用的模型、协议与发送的档位，「动作与回执」「Context」「部门设置」检查页签，「部门消息」与「部门指导」。

### 步骤 4：回答「待恢复」的决定请求

模型引用无法使用时，下一次模型请求不发送，事项进入待恢复，等你决定。事项只要一到七分钟，要在「作为新事项开始」之后几秒内制造故障（走查中八秒时改地址，一秒多以后出现决定请求）：到「模型管理」把连接的「地址」改成一个不存在的地址（例如 `https://changed.invalid/v1`），点「保存」，弹窗「确认保存」列出受影响的引用方（部门默认与「进行中事项」），点「确认保存」，准入作废。一两秒以后出现决定请求。

应该看到：决定卡片「模型引用无法使用，等待恢复」，带标签「阻塞 run」，写明部门、模型与具体问题（「准入已作废，请重新执行模型测试」），有「前往模型管理」与「前往本项目的部门设置」（项目「设置」页签）的链接，选项「继续执行」「停止事项」，可选的「说明」。三个入口都能回答，同一份请求同时出现：

1. 首页「待你决定」区块里的卡片，状态项「待你决定」与顶栏「待你决定：N」同步。
2. 项目页顶栏右侧的按钮「待你决定 · N」，展开的下拉里有同一张卡片。
3. 项目楼层大厅地面上的告示板（牌子「待你决定」，每个请求一张便条）：点板子摊开一张纸，在「说明」横线上写字，点章回答，盖「已回答：继续执行」；多张时用左右方向键翻页，Esc 关闭。

没有修好配置就选「继续执行」会再发一个新的决定请求，可以借此在三个入口各答一次。最后把「地址」改回去，保存：准入立刻恢复，不用再点「模型测试」；再答一次「继续执行」，事项接着跑完并被采纳（0.1.1 已修好：以前停在「已放行」，要等下一个事项开始才被采纳）。选「停止事项」会结束事项并释放执行槽位，紧接着可以新建事项。卡片页脚的「在项目中查看」会跳到还没有内容的恢复页，不要点它（见第 3 节）。

### 步骤 5：离开期间的报告、时间轴回放、托盘提醒、观测页

- 首页「离开期间的报告」：范围按钮「自上次查看」「最近 24 小时」「最近 7 天」，汇总项「完成与放行的事项」「用量」，发生返工时才出现「返工」；点一项展开来源事件。「已看过」把「上次查看」更新到当前位置：服务端立即更新，页面要离开首页再回来才刷新。想看到「离开期间」：先跑完一个事项，点「已看过」，再产生新的事件，回到首页看「自上次查看」。
- 时间轴与回放（首页报告下方，项目概览的「循环画面」下方只含本项目）：「播放」「单步」「1×」「2×」「4×」「回到现在」；点刻度或「播放」进入回放，首页出现横幅「回放中 · {时间}」，楼与项目表按该位置的快照显示；「回到现在」恢复实时。刷新页面以后回到实时。
- 托盘提醒：点窗口关闭钮只隐藏窗口，客户端留在托盘；托盘图标带待决定数量，悬停提示「Yudao：N 项待你决定」；新的决定请求到达时弹出系统通知，标题「Yudao：有新的决定请求」，正文目前不完整（见第 3 节）。保持一个事项在跑，关闭窗口，等下一次决定请求。点托盘图标或菜单「打开窗口」恢复，菜单「停止 Yudao」仅连接本机时出现，「退出客户端」退出。
- 观测页：项目页签「观测」。「请求记录」可按「部门」「状态」「关键词」「Provider 配置」「请求的模型」「实际的模型」筛选，每页 50 行与「加载更多」，每行「详情」打开「请求详情」，写明调用目标、选择来源（「部门默认」或「项目设置」）、请求与实际发送的协议与档位、用量；「用量统计」只读显示请求数、输入与输出 token、缓存读写、耗时、费用，上游没有回报的写「未上报」。

### 步骤 6：确认没有 Web 控制台

浏览器打开服务的地址（例如 `http://127.0.0.1:8765/`），得到 404：服务只提供机器接口，界面都在桌面客户端里。

## 3. 已知问题

下面的问题已经建成工单，不用重复反馈。「0.1.1 之后已修」的在下一个修订版本里。

- 回答待恢复的决定卡片页脚「在项目中查看」跳到还没有内容的恢复页（#181，M2）。
- 模型管理页：模型测试的结果文字没有显示；新建连接表单的「超时（秒）」默认 60，后端默认 600，真实模型的请求可能超过 60 秒，需要时在「高级选项」里改大；「接受容量」的校验规则不一致（#294）。
- 第一次配置自定义方案的障碍：模型列表地址要自己填、候选 ID 含「/」要改、只填窗口时提前显示「容量已确认」、添加与保存没有成功提示、「测试连接」只测模型列表地址、质检的图像输入提醒保存以后才出现（#302）。
- 项目与部门页：新建表单提交以后不自动关闭、「固定参数」的提示文字不含程序名、没有事项时部门页一直显示「正在读取数据」（#295，0.1.1 之后已修）。
- 概览与看板里的开发用语与英文提示：「待决问题」行的英文、已采纳卡片的「未知部门」「停止原因：released」、被取消的事项写「新建 run」、概览里的工单编号与接口名、顶栏路径是英文页名（#303）。
- 外壳与托盘：服务起不来时的提示不准确、点击系统通知不会定位到决定卡片、断线时窗口不变灰只有顶栏提示、回放位置不写进路径、「返回原界面」回到首页（#296）。
- 服务不可达时客户端控制台持续报错、有客户端连接时停止服务要等三秒并在日志里写回溯、系统通知正文为空（只有「提出等待回答的决定（model_unavailable）：」）、「已看过」以后页面不立即刷新、请求详情页的「正在读取数据」不消失、模型管理页头的「配置状态」保存以后仍写 `deleted`、侧栏标记连写成「运行中待核实 1」（#301）。
- README 的「测试」一段与 `yudao demo` 的输出还提到已经删除的 Web 控制台（#297，0.1.1 之后已修）。
- 离开期间的报告里采纳那一行写成「采纳了交付物（第  版）」，缺版本号；用户停止的事项在部门页写「执行失败」、在首页楼层写「中断」，看板里还留在「产品」列（看板部分在 #303）；房间里小人头顶只出现上面列出的话，阅读资料、检查交付、盖章等动作的说明没有出现；回答决定请求以后卡片同时有两行提交提示；首页、项目概览、项目设置、观测页与连接设置页还留着「数据来自 projects.list」「令牌与 TLS 保留位置，当前不发送（设计说明第 6.3 节 TODO）」这类开发说明（#319）。

## 4. 走查没有覆盖的部分

0.1.1 的走查用发布的 wheel（装进虚拟环境）、解包的客户端与真实模型完成。下面几处没有执行，试用时请留意：

- 步骤 1 的安装命令（`uv tool install`、`yudao client install`）与从开始菜单启动：走查为了不改动这台电脑上的安装，用虚拟环境与解包的客户端代替；解包的客户端与安装包里的程序逐字节相同。
- 在「API Key」输入框填入 Key，以及「写入 .env」（走查只用环境变量引用与手工放置的 `.env`）。
- 系统通知是否真的弹出、托盘图标悬停提示的显示、告示板有多张便条时用方向键翻页、点击系统通知。
- 服务起不来时的提示、推理档位三项的声明、「返工」汇总项（走查中没有出现返工事件）。
