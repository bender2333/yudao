# M1 试用指南：桌面客户端与模型管理

试用版本：0.1.0（提交 `400ee9c4`，标签 `v0.1.0`）。试用工单 [#183](https://github.com/bender2333/yudao/issues/183)。对应 [Stage 3 计划](../stage-3-plan.md)第 1 节的这几项能力：在模型管理页维护模型目录与准入、每个项目单独选择各部门的模型与推理档位、质检的模型不能看图时得到提醒；在桌面客户端的系统首页看到需要自己决定的事与离开期间发生了什么、在托盘收到提醒；每项能力都有对应的界面。旧的 Web 控制台已经删除，试用全程只使用桌面客户端。

## 1. 试用前的准备

- 一台 Windows x64 电脑，已安装 [uv](https://docs.astral.sh/uv/)，Git 命令行在 PATH 中（`git --version` 有输出）。
- 一个可用的模型服务：服务的请求地址、模型名与 API Key，三个部门（产品、工程、质检）都要选模型，一个模型也可以三个部门共用。第 3 步新建事项需要真实的模型回答，一个小项目通常几分钟到几十分钟，费用由你的服务方案承担。
- 试用从空的数据目录开始（默认 `%LOCALAPPDATA%\Yudao`）。开发时 `.yudao/` 下的数据不会带过来。
- 想与已经安装的 Yudao 分开：启动服务时加 `--data-dir <目录>` 与 `--port <端口>`，客户端在「连接设置」里改成同一个地址。

## 2. 步骤

### 步骤 1：安装服务与客户端，连接

1. 取得安装包：`gh release download v0.1.0 --repo bender2333/yudao --pattern "*.whl" --dir <下载目录>`。
2. 安装服务：`uv tool install --python 3.12 <下载目录>\yudao_harness-0.1.0-py3-none-any.whl`。uv 提示目录不在 PATH 时运行 `uv tool update-shell`，重新打开终端。
3. 安装客户端：`yudao client install`，它运行 wheel 附带的安装程序，装到 `%LOCALAPPDATA%\Programs\Yudao`，开始菜单有「Yudao」。
4. 从开始菜单启动「Yudao」。客户端默认连接「本机」（`http://127.0.0.1:8765`）：服务没有运行时，客户端在 PATH 里找到 `yudao` 命令并在后台启动 `yudao api`，最多等 30 秒。

应该看到：先是整页「连接中…」，随后左上角出现品牌「Yudao」，顶栏右侧显示「已连接」。首页是空的：状态项「待你决定」为灰色的「无」，「全部项目与机器」下写「还没有项目」，「待你决定」下写「没有等待回答的决定」，「离开期间的报告」下写「上次查看：未知时间」；左侧「系统」组里只有「模型管理」。

出现「没有找到 yudao 命令」：页面会跳到「设置」并给出安装命令，按它安装后点「重新检测」。命令找到了但服务 30 秒内没有起来（端口被占、数据目录被另一个服务进程占用）时，界面也是这句提示，日志在 `%APPDATA%\Yudao\yudao-service.log` 与数据目录的 `logs\`。

### 步骤 2：模型管理——配置 Provider 与模型，为部门选择模型

1. 左侧栏「系统」→「模型管理」。窗口窄时先点顶栏「菜单」。
2. 点「添加 Provider 配置」，「服务方案」选「自定义」，填写「ID」「名称」、「协议」（Responses、Chat Completions、Anthropic Messages 三选一）、「地址」（该协议的请求基址，请求路径由 Yudao 拼接）、「凭据引用」（一个变量名，例如 `MY_MODEL_KEY`），点「添加」。
3. 卡片出现后点「展开」→「编辑」。「凭据」区写着「凭据引用 …：缺失，请填写 API Key」：在「API Key」框填入 Key，想让重启以后仍然有效就勾「写入 .env」（写到数据目录的 `.env`），点「保存 Key」，应该变为「已配置，来源 …」，输入框清空。Key 不会回填，页面与网络响应里都没有它。
4. 点「获取模型列表」，在候选里点「建立访问定义」，填「窗口」与「输出上限」（输出上限不大于窗口），点「接受容量」，看到「容量已确认」。模型支持推理档位时，在这一行同时声明「支持档位」「默认档位」「推理参数方式」三项。点「保存」。
5. 点这一行的「模型测试」：按钮变「测试中…」，成功以后「准入」列变「已准入：…」，卡片摘要变「已准入 1 · 候选 0」。可以再点「测试连接」，看到「连接测试：连接测试通过（N 毫秒）」。
6. 页面下方的「部门默认」：「产品」「工程」「质检」各选一个已准入的「模型」，模型声明了档位时再选「推理档位」，点「保存部门默认」，看到「已保存部门默认。」三个部门都要选，否则新事项会被拒绝，提示「部门 X 未选择模型访问定义，请配置部门默认或本项目的部门设置」。
7. 质检选一个只收文字的模型时，页面出现「quality 部门的模型建议具备图像输入…」的提醒，不阻止保存。

应该看到的对应能力：模型目录与准入、每个部门的模型与推理档位、质检模型不能看图时的提醒。

### 步骤 3：新建项目、登记检查命令、开始事项，看三个部门工作

1. 左侧栏「从想法新建」，填「项目名称」与「长期目标」（例如名称「回显工具」，目标「做一个命令行回显工具：读取标准输入，原样输出；空输入输出空」），点「新建项目」，看到「已提交，等待写入结果」。新项目出现在左侧「项目」组、首页「全部项目与机器」与「项目」表里。新建项目只登记项目，不开始事项。
2. 点左侧的项目名进入概览（页签：「概览」「产品」「工程」「质检」「资料」「观测」「设置」）。
3. 登记一条检查命令（工程交付必须带检查回执，登记表在事项创建时冻结）：页签「设置」→「登记命令」→「登记新命令」，「登记名」填 `smoke`，「固定参数」填完整的命令行，包含程序名，例如 `python -c print(1)`（按空格拆分，没有引号语法），点「保存」。
4. 回到「概览」，「当前事项」区块的文本框「新的要求」里写要求（例如「实现回显：读取标准输入，原样输出到标准输出」），点「作为新事项开始」。想看到小人头顶的话，先停在概览或某个部门页再点开始：动作由实时事件驱动，事后打开不会重播。

应该看到：
- 侧栏项目名旁出现标记「运行中」；「当前事项」区块依次显示「产品处理中」「工程计划中」「工程处理中」「质检处理中」「已完成」；「事项看板」按「产品」→「工程」→「质检」→「已放行」→「已采纳」移动。
- 概览的「循环画面」是项目楼层：三个部门的房间、传递文件的管道、大厅里的告示板，下方有文字列表。
- 页签「产品」「工程」「质检」打开部门房间：小人的姿势来自部门状态，头顶的话说明自己现在做什么，例如「现在开始工作」「现在思考」「现在提交产品规格」「现在把计划贴上白板」「现在装箱封存」「现在开始检查」「现在盖放行章」「完成了！」；交接时两端各说一句，例如「现在把PRD送给工程」与「收到PRD，来自产品」；思考时是圆点尾巴的气泡，流式输出的文字逐字接在里面。系统设为「减少动画」时小人少走动，气泡照样显示。
- 部门页下方有「产品工作间」：部门状态、当前生效的模型及来源、最近一次请求实际使用的模型、协议与发送的档位，「动作与回执」「Context」「部门设置」检查页签，「部门消息」与「部门指导」。

### 步骤 4：回答「待恢复」的决定请求

模型引用无法使用时，下一次模型请求不发送，事项进入待恢复，等你决定。试用里这样制造：事项运行时，到「模型管理」把连接的「地址」改成一个不存在的地址，点「保存」，弹窗「确认保存」列出受影响的引用方（含「进行中事项」），点「确认保存」，准入作废。下一次模型请求就会发出决定请求。

应该看到：决定卡片「模型引用无法使用，等待恢复」，带标签「阻塞 run」，写明部门、模型与具体问题，有「前往模型管理」与「前往本项目的部门设置」的链接，选项「继续执行」「停止事项」，可选的「说明」。三个入口都能回答，同一份请求同时出现：

1. 首页「待你决定」区块里的卡片，状态项「待你决定」与顶栏「待你决定：N」同步。
2. 项目页顶栏右侧的按钮「待你决定 · N」，展开的下拉里有同一张卡片。
3. 项目楼层大厅地面上的告示板（牌子「待你决定」，每个请求一张便条）：点板子摊开一张纸，在「说明」横线上写字，点章回答，盖「已回答：继续执行」；多张时用左右方向键翻页，Esc 关闭。

没有修好配置就选「继续执行」会再发一个新的决定请求，可以借此在三个入口各答一次；最后把「地址」改回去，重新点「模型测试」，再答一次，事项从那次请求接着跑。「停止事项」结束事项并释放执行槽位。卡片页脚的「在项目中查看」会跳到还没有内容的恢复页，不要点它（见第 3 节）。

### 步骤 5：离开期间的报告、时间轴回放、托盘提醒、观测页

- 首页「离开期间的报告」：范围按钮「自上次查看」「最近 24 小时」「最近 7 天」，汇总项「完成与放行的事项」「用量」「返工」，点一项展开来源事件；「已看过」把「上次查看」更新到当前位置。想看到「离开期间」：先跑完一个事项，点「已看过」，再产生新的事件，回到首页看「自上次查看」。
- 时间轴与回放（首页报告下方，项目概览的「循环画面」下方只含本项目）：「播放」「单步」「1×」「2×」「4×」「回到现在」；点刻度或「播放」进入回放，首页出现横幅「回放中 · {时间}」，楼与项目表按该位置的快照显示；「回到现在」恢复实时。
- 托盘提醒：点窗口关闭钮只隐藏窗口，客户端留在托盘；托盘图标带待决定数量，悬停提示「Yudao：N 项待你决定」；新的决定请求到达时弹出系统通知「Yudao：有新的决定请求」。保持一个事项在跑，关闭窗口，等下一次决定请求。点托盘图标或菜单「打开窗口」恢复，菜单「停止 Yudao」仅连接本机时出现，「退出客户端」退出。
- 观测页：项目页签「观测」。「请求记录」可按「部门」「状态」「关键词」「Provider 配置」「请求的模型」「实际的模型」筛选，每行「详情」打开「请求详情」，写明调用目标、选择来源（「部门默认」或「项目设置」）、请求与实际发送的协议与档位、用量；「用量统计」只读显示请求数、输入与输出 token、缓存读写、耗时、费用，上游没有回报的写「未上报」。

### 步骤 6：确认没有 Web 控制台

浏览器打开 `http://127.0.0.1:8765/`，得到 404：服务只提供机器接口，界面都在桌面客户端里。

## 3. 已知问题

下面是试用前核对源码与走查时发现的，不用重复反馈；已经建了工单的写在后面。

- 卡片页脚「在项目中查看」与恢复相关的链接指向恢复页，这个页面还没有实现，落到占位页（工单 #181，M2）。
- 模型测试的结果文字没有显示：成功只能看「准入」列变化，失败时没有提示。
- 新建连接表单的「超时（秒）」默认 60，后端默认 600；真实模型的请求可能超过 60 秒，需要时在「高级选项」里改大。
- 「固定参数」输入框的提示文字是「例如 --mode strict」，实际要填含程序名的完整命令行。
- 「从想法新建」提交成功以后表单不自动关闭、字段不清空。
- 项目还没有事项时，部门页下方的「正在读取数据」一直显示。
- 系统通知没有点击处理，点击不会定位到决定卡片；回放的位置不写进路径，刷新以后回到实时；断线时窗口不变灰，只有顶栏提示「连接中断，数据可能过时」。
- 真实 Provider 的待恢复往返只在本版本的真实验收里核对过一次，其他服务方案可能表现不同。

## 5. 试用后的清理

卸载客户端（Windows「设置」→「应用」→「Yudao」），`uv tool uninstall yudao-harness`，需要时删除数据目录 `%LOCALAPPDATA%\Yudao`。卸载不会删除数据目录。
