# 界面由 Yudao 服务以网页提供，服务手动启动

[ADR-0015](0015-desktop-client-and-http-contracts.md) 把界面做成 Electron 桌面程序，[ADR-0023](0023-client-installed-apart-release-is-one-wheel.md) 规定服务与客户端分开安装、一次发布是一个带客户端安装程序的 wheel。M1 试用（0.1.1）时用户认为客户端很重，体现不出客户端应用的优势：安装与更新要分两步，wheel 约 131 MB；客户端里装的是网页，外壳只有约 880 行（窗口、托盘、本机服务的启动与停止、更新、链接协议、设置与给页面的接口），用起来与网页没有区别；打包、发布与驱动 Electron 的端到端测试又拖慢了执行。2026-10-07 用户逐轮采纳推荐，决定：

- 界面是 Yudao 服务提供的网页。构建好的页面文件随 wheel 发布，接口层在提供接口的同时提供这些文件；在浏览器里打开服务的地址就是界面，局域网中的其他电脑打开同一个地址。需要单独的窗口时，用 Edge 或 Chrome 的「安装此站点为应用」。以 Windows 上的 Edge 与 Chrome 为准，不考虑手机。
- 删除 Electron 客户端：外壳、托盘、本机服务的启动与停止、更新页、客户端安装程序、`yudao client install`、本机停止请求，以及发布脚本中构建客户端安装程序的部分。页面代码（React、PixiJS 画面）与接口层的合同保留；界面的端到端测试用 Playwright 驱动浏览器。
- 服务手动启动：启动服务的命令在服务就绪以后用默认浏览器打开页面地址，停止服务就是结束这个进程。现阶段不注册为系统服务，也不在登录时启动，因为测试与试用中留下的系统服务清理麻烦；迭代稳定以后再做成服务启动（Stage 4 的长时间运行）。局域网访问用启动参数 `--access lan`。
- 不主动推送提醒。原来由托盘发出的系统通知（[D30](../requirements/web-game-frontend.md)：出现决定请求、进入等待模型服务、磁盘空间不足），在本机打开页面时由浏览器发出，标签页的标题显示待决定的数量；离开期间发生的事由首页的待回答决定与离开期间的报告给出。

考虑过的做法：

- 保留 Electron，补足桌面程序才有的功能（托盘常驻、系统通知、本机服务管理）。用户不在场是常态，托盘与系统通知只在用户坐在这台电脑前时有用；独立窗口浏览器可以提供；其他电脑使用还要再安装一次。
- 换成更轻的外壳（Tauri，使用系统的 WebView2）。体积变小，但单独安装、单独发布与外壳代码都还在，问题相同。
- 服务主动推送到手机或邮箱。需要另一个通知渠道与接收配置；Yudao 的目的是尽量自己运行，需要用户回答的时候少，回来时看报告即可。

理由：

- 一个版本只有一处安装：`uv tool install` 一个 wheel，页面与服务出自同一个包，版本总是一致，不需要更新页与版本不一致的处理。
- 局域网中的其他电脑不需要安装任何东西。
- 页面代码本来就只通过 HTTP 接口工作（ADR-0015、[ADR-0007](0007-boundaries-for-distributed-deployment.md) 第 5 条），去掉外壳不改变界面与服务之间的边界。

后果：

- ADR-0015 中「客户端是桌面程序，外壳使用 Electron」「后端不提供界面文件」两条与 Electron 的理由由本决定取代，其余不变；ADR-0023 整篇由本决定取代。
- 一次发布仍是一个 wheel，包含构建好的页面文件与执行代理的安装包；发布脚本、版本号与私有仓库 Release 的做法不变（[网页界面的提供与发布设计说明](../design/web-interface-and-release.md)）。
- 浏览器只允许 https 页面与本机地址使用系统通知与「安装此站点为应用」。从其他电脑经局域网的 http 地址打开时，没有系统通知，只能在普通标签页中使用；离开局域网之前加入 TLS 时一起解决（ADR-0015 的 Status 行）。
- 页面所在的标签页或窗口不可见时，浏览器暂停画面的绘制；回到可见时画面按当前状态继续。
- 原来由客户端提供的「登录时启动」「重新启动服务」「停止 Yudao」都不再提供，开机启动与崩溃后重新启动随 Stage 4 的长时间运行设计。
