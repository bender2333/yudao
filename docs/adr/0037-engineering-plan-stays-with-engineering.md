# 工程计划留在工程一侧

此前工程写入文件之前必须提交工程计划，提交计划就结束这次激活，之后的写入只能在计划的范围之内；交付说明、检查回执与放行都绑定计划的摘要。部门内的步骤循环因此在计划提交处被切断。决定：工程计划不再是正式成果；写入文件之前没有计划的检查，也没有写入范围的检查；交付只绑定有效 PRD 的版本与代码快照，交付说明写明做了什么；工程怎样安排工作由工程自己决定，计划留在工程自己的历史里。

理由：

- 计划是作者的工作过程，按 [ADR-0029](0029-departments-form-by-information-cohesion.md) 留在作者一侧。
- 质检按 PRD 核验交付，计划的摘要放在证据链里，没有增加核验的内容。
- 运行工作区本来就是隔离的，只由持有交接的工程写入，写入范围检查保护的东西很少。

后果：

- ADR-0029 共享清单中的「工程计划」一项由本决定取代。
- 计划的提案合同与工具、计划的上下文栏目、写入范围的工具许可、交付与放行对计划的绑定一起删除。
- 设计见[三部门的循环结构](../design/department-loop.md)第 8 节。
