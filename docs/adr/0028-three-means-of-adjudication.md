# 裁决有三种手段，控制核心的决定只依据已记录的事实

Status: 「以上都判定不了的，升级给一个更强的、与生成这份产出的模型不同的模型」与后果中「判定点的升级使用判定点声明的第二个判定者」由总图第三节「判定点」取代（2026-10-25 记）：判定点不确定时，下游有独立核验兜底就按声明的去向继续，没有就升级成决定请求，不另设更强模型的一步；需要另一个模型独立判断的地方作为定义里的角色或检查，是独立的证据。见[总体架构](../design/architecture/overall-architecture.md)第 7.7 节。其余决定继续有效。

控制核心掌握状态迁移的主权。只用确定的规则，需要判断的局部问题（例如一份回答是否回应了询问）只能交给用户，而用户不在场是常态；直接让模型推进流程，又违反「生成者不裁决自己」。本地的实测显示，决策模型在没有参照材料时接近随机，输入里的无关文字能改变结论，`jev-latest` 在版本之间可能改变答案（[JEV 调研](../research/jev-decision-model.md)）。决定：

- 一个待判断的问题按顺序处理：代码能精确判定的，由确定的规则判定（测试、构建、类型检查、改动范围、轮次与时间、本体校验）；需要判断但有参照材料的局部问题，在事先声明的判定点上交给决策模型；以上都判定不了的，升级给一个更强的、与生成这份产出的模型不同的模型；仍然不确定时按判定点声明的去向处理，没有独立的下游核验能挡住错误时发出决定请求，阻塞范围取能够隔开的最小范围（[ADR-0020](0020-block-only-when-no-downstream-check.md)）。
- 控制核心的每个决定只依据已记录的事实与事先规定的去向。决策模型的判断先写成事件（输入摘要、问题、选项顺序、模型版本、概率、阈值、结果与去向），再被使用；重放读取记录的结果，不发出请求。
- 判定点是定义，写明问题、参照材料、固定版本的模型、两个阈值、通过、不通过、不确定三种结果的去向、校准状态、拦截什么与花费多少。结构校验拒绝没有参照材料、去向不全或模型不是固定版本的声明；去向只能取自一份允许清单，清单里没有放行、接纳产品合同、采用定义与修改限额。
- 校准通过之前，判定点只记录，流程按没有判定点时的去向继续。准入用两批真实运行的样本，第一批选阈值，第二批复核，自动判定部分的准确率与自动判定的比例都达到声明值。模型版本或问题文本变化、抽样复核的不一致率超过界限时，状态自动回到只记录。

理由：

- 模型的判断先记录、再按事先规定的去向使用，判断可以重放与审计，控制核心的决定仍然只依据事实。
- 去向的允许清单用结构保证决策模型不负责质检放行、产品取舍与规则修改。跨步骤的因果判断与代码是否正确这两类问题无法用结构排除，靠判定点属于结构性定义、采用之前经用户批准来把关。
- 降级自动发生、升级只经校准，与「放宽需要证据」方向相同。

后果：

- 「不自动改用其他模型」只适用于角色的模型失败的情况；判定点的升级使用判定点声明的第二个判定者，角色的模型不变。
- 证据核对是第一个判定点；它声明的「不确定」去向是只标记，事实的状态不变，并作为开环列出。流转上的判定点各自校准。
- 判定点的合同见[总体架构](../design/architecture/overall-architecture.md)第 7.2 节。
