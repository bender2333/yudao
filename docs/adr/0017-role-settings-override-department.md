# 模型选择中角色设置优先于部门设置

部门内有多个角色以后，探索者与审查者适合使用与中心角色不同的模型与档位（[D26](../requirements/department-roles.md)、[部门内多角色设计说明](../design/department-roles.md)第 14 节）。决定：在部门设置之上增加角色一层。每次模型请求按「项目角色设置、角色默认、项目部门设置、部门默认」的顺序，取第一个写入了的模型访问定义；请求档位按同样的顺序取得，都为空时使用所选模型的默认档位，并限制到支持范围；角色 Prompt 在项目角色设置中有时使用它，否则使用内置角色 Prompt；部门 Prompt 作为全部门的规则放入本部门每个角色的请求。

理由：

- 按 [ADR-0005](0005-resolve-call-target-per-request.md)，调用目标在每次请求时解析，增加一层只是在解析顺序中多一个来源，不改变生效时机与记录方式。
- 角色设置没有写入的项继承部门设置，只使用部门设置的用户不需要做任何修改。

后果：

- 角色默认是全局的，每个角色一份；项目角色设置每个项目的每个角色一份，只写入覆盖的项，保存在项目事件中，带版本。
- 请求事件记录角色与选择来源（四层中的哪一层）、请求档位与实际发送的档位、部门 Prompt 版本与角色 Prompt 版本。
- 引用无法使用时，流程编排发出待恢复的决定请求，写明部门、角色、模型与原因；新建事项之前解析每个部门的每个角色，任何一个失败时拒绝新建。
