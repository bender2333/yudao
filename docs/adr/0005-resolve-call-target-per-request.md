# 调用目标按每次模型请求解析

每次模型请求按「项目部门设置，未写入的项使用部门默认」取得选择，由 Provider 模块解析出这一次请求的调用目标：连接、协议、地址、上游模型、容量、发送的推理档位与凭据。设置只有全局的部门默认与项目部门设置两层。项目部门设置、部门默认、目录与凭据的修改，都从相关部门的下一次模型请求起生效，包括进行中的事项；正在进行的请求不中断，一次请求内的重试沿用该请求的调用目标。

理由：模型、推理档位与部门 Prompt 都需要在运行中更换（D24）。OMP 与 opencode 都按每一轮当前的模型解析调用目标，并按它计算容量。运行中可以更换模型时，只有逐次记录请求才能说明某次请求实际使用了什么。

后果：每个模型请求事件记录调用目标的公开部分、选择来源与部门 Prompt 版本。选中的模型无法使用时，该部门的请求失败并说明原因，不改用部门默认或其他模型。进程重启后按当前凭据来源继续解析调用目标。部门 Prompt 只在项目部门设置中修改。部门历史回放推理内容时，按是否同一连接、协议与上游模型决定保留或丢弃。
