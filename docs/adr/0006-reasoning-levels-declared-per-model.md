# 推理档位由模型声明，请求时限制到支持范围

推理档位全集为 minimal、low、medium、high、xhigh、max。模型访问定义声明支持档位、默认档位与推理参数方式；没有声明的模型不发送推理参数。部门默认与项目部门设置保存请求档位，每次请求按实际模型限制：取不高于请求档位的最高支持档位，没有时取最低支持档位。各协议按推理参数方式编码：Responses 使用 `reasoning.effort`，Chat Completions 使用 `reasoning_effort`，Anthropic Messages 使用 adaptive 方式的 `output_config.effort` 或 budget 方式的 `budget_tokens`。

理由：同一档位名在不同模型上的可用范围不同，OMP 目录按模型记录支持档位并在请求时限制，运行中更换模型后原请求档位仍然有效。固定四档的滑块无法表达模型之间的差异，也会向不支持推理的模型发送参数。

后果：推理参数方式的修改作废准入，支持档位与默认档位的修改保持准入。模型测试按默认档位发送推理参数。摘要请求使用最低支持档位。请求事件同时记录请求档位与实际发送的档位。开关型参数、其他服务的专用字段与「关闭推理」列为后续工作。
