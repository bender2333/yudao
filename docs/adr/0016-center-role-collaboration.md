# 部门采用中心型协作，经理是部门唯一的对外接口

部门内部需要多个角色分工（[D26](../requirements/department-roles.md)）。决定：三个部门都采用中心型协作。每个部门有一个中心角色（产品架构师、工程架构师、测试工程师），负责规划与判断，保管部门的主要上下文；探索者、主程与审查者是中心角色的工具，只接受中心角色分派的任务，交回结构化的角色结果，工具角色之间不直接往来；经理是部门唯一的对外接口，转交询问、指导与通知，提交部门成果，不分派部门内的工作，不编写产物。

理由：

- 中心角色持有需要连续积累的核心上下文，会产生大量中间内容的查证与实现交给工具角色，中间过程不进入中心角色的上下文（[部门内多角色设计说明](../design/department-roles.md)第 2、4 节，Anthropic 的多 agent 研究系统与 Cognition 的做法）。
- 部门对外只有一个接口，部门之间的往来与上下文隔离由控制核心在一处执行；工具角色没有对外通道，权威拓扑保持设计时的常量。
- 审查者每次从新的上下文开始，审查不受作者思路的影响。

后果：

- 角色清单作为带版本的定义随系统发布（[ADR-0014](0014-versioned-definitions.md)），用户可以修改角色的 Prompt 与模型，不能增删角色；角色清单的变化属于 Stage 6 的组织演化。
- 分派、等待、追加说明、取消、更新计划、起草、对外发问与完成是中心角色的主机工具；转交、专家请求、提交部门成果、提醒与汇报是经理的主机工具。
- 部门成果按部门规定的交出检查判断后才能交出，其中包括针对提交版本的审查通过记录。
