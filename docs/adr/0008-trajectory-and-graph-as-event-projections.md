# 轨迹与图谱是事件的投影，存放在现有 SQLite 中，不引入 Semantica

语义系统需要记录工作过程的轨迹，以及由证据、事实、知识、决定、要求、实体、推测构成的图谱（[D25](../requirements/semantic-system.md)）。决定：轨迹与图谱都是事件的投影，存放在现有的 SQLite 中，类型用 pydantic 定义；角色只提交记录，主机按本体校验后写成事件；重放事件可以完整重建，重放不调用模型。Semantica 不作为依赖。

理由：Semantica 的定位与 Yudao 最接近，但它与三条架构原则冲突（[Semantica 参照调研](../research/semantica-reference.md)第 5 节）。它没有事件重放，ContextGraph 在进程内，只能整份保存为 JSON；图谱有多条写入路径，都不经许可；嵌入失败时静默改用随机向量，决定写入来源记录的异常被吞掉；它的 provenance 模块自己用 SQLite 保存版本链，引入后会形成第二个事实来源。核心安装 377 MB，0.x 版本仍有破坏性变更，CI 只运行推理模块的测试。

借用的做法：来源关系对应 W3C PROV-O；有效开始、有效结束、记录时间、被取代时间四个时间字段；决定附带理由与结果，决定之间有因果；本体由类与属性定义，约束写成形状，由主机校验；冲突按类型记录。

后果：

- 本体、校验、投影与全文索引由 Yudao 自己维护；本体随系统版本发布，变化属于 Stage 6 的演化。
- 增加新的内容种类或投影以后，重放事件即可按新规则重建全部历史内容，惊讶机制以后按这种方式接入。
- 不引入图数据库；按关系的查询在 SQLite 中完成，全文检索使用 FTS5 trigram。
