# agent 试用分别记录现场发现、独立复现与问题裁决

状态：已采纳并实施，相关本地验证完成（[实施与验证结果](../trial/skill-revision-validation-2026-10-29.md)）；依据：用户在 `/grill-with-docs` 逐轮采纳 Q1–Q11，并回复「可以」同意完整方案；路线位置：各阶段的薄片试用与路线图第 5 节「能度量」「看得见」。

agent 试用的首要目标是发现真实用户会遇到的问题，并交出可信证据。交付评分与性能比较作为单独结果。

现场证据完整、已经观察到的问题，可以进入正式问题表。独立复跑没有触发相同条件时，明确标注「已观察，尚未独立复现」；记录分别说明现场发生的事情与独立复现做到的位置。

行为符合现有设计，但新手反复找不到入口、误解状态或不知道如何继续时，可以列为「体验问题候选」，交给架构师裁决。是否符合设计与是否妨碍用户完成目标分别判断。

这项取舍保留了难以重复触发的真实问题和符合设计的体验障碍，同时要求明确证据的范围。一次观察足以成为试用发现，是否成立为缺陷仍须裁决；既有设计也可以在体验证据出现以后被重新审视。

每轮运行 F1、R1 的规定流程。额外改变需求、配置等探索放在单独事项或实例中，分别记录固定试用任务与探索任务的结果。

产品、工程、质检允许使用不同模型，按照运行配置确定分工。独立复现逐部门保持相同的被测配置，负责观察和操作的代理可以使用另一个模型；任务集与技能统一这一约定。

独立复现优先处理挡住用户目标的问题，以及状态、恢复、并发等异常。静态文字和布局问题可以先由另一个观察者复核，并明确标注「证据复核」，分别记录复核与复现结果。

评分或独立复现未完成时，允许发布「部分完成」的报告，逐项注明缺少什么及其原因。已取得的可靠发现可以交付，相应检查保持明确的未完成状态。

每条试用发现分别记录问题是否成立、是否已经修复、修复后是否重新验证通过。缺陷命中率依据架构师明确的成立或不成立裁决计算：成立数除以成立数与不成立数之和；尚未裁决的主张不计入这一比例，体验问题候选另外记录是否采纳改进建议。工单关闭状态不自动代表问题成立，后续未复验也不改变原来的问题裁决。

复现代理接收操作步骤、触发条件和待观察现象，任务书不预先给出作者认定的根因。复现时间用完仍未触发时，记录「未触发」并结束该项；「同条件触发后未出现」「条件不一致」「仅复核原证据」分别记录。未触发不作为误报的依据。

报告发出前核对实际运行版本、数字来源、证据引用与脱敏。评分没有完成时可以明确写缺项；实际运行版本说不清、数字相互矛盾、含有明文凭据等问题，需要处理以后再发布。已有结论必须符合现有证据能够支持的范围。

整轮上限保留约 4 小时 45 分，F1 最多 120 分钟，R1 最多 55 分钟。提前结束省下的时间，优先补测未覆盖的承诺能力和复现高影响问题，再用于新探索。
