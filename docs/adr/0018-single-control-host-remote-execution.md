# 一台控制主机，执行环境分布到多台机器

可以预见的时间内 Yudao 只有用户一个人使用，同时会部署到多台电脑与树莓派一类能运行 Linux 的板子上（[D29](../requirements/remote-execution.md)，2026-09-28）。多台机器的用途是让工程的构建、质检的检查与运维的操作在对应的机器上进行。决定：

- 控制核心、事件日志、工件存储、Provider 模块与观察者在一台机器上运行，这台机器称为控制主机。事件日志继续使用 SQLite。控制核心不做主备，不按项目分成多个实例，不换用服务端数据库。
- 执行环境是一个服务，合同经过 HTTP 加 JSON（[ADR-0015](0015-desktop-client-and-http-contracts.md)），有三种实现：本机进程、本机容器、远程机器上的执行代理。执行代理是运行在其他电脑或树莓派上的一个小服务，在登记的目录中读写文件、启动进程，并交回动作回执。
- 用户在项目中登记机器，写明地址、用途与授权范围；执行代理只接受控制主机的请求，连接使用访问令牌与 TLS。
- 控制核心持有每个 run 的执行权，执行权编号在写入口与领域写入一起核对，用于进程重启与两个进程同时恢复的情况；执行权没有期限与续期。
- 远程动作的存活按动作判断：执行代理在动作进行期间按时发送心跳，超过时限没有心跳时，动作结果记为未知，按 3.1 的动作核实处理；之后到达的回执按动作身份记为迟到事实，不改变已经做出的决定。

本决定取代 [ADR-0012](0012-single-control-core-scalable-execution.md) 中「为可用性做主备」「需要时按项目把 run 分给多个控制核心实例」「服务端数据库的选择在 Stage 6 按故障场景与总成本比较」三项，以及 [ADR-0007](0007-boundaries-for-distributed-deployment.md) 第 3 条中「所有权带有期限，由执行者按时续期」一句。ADR-0007 的其余边界继续作为执行环境服务的合同。

理由：

- 控制核心的每一步工作量很小，负载在等待模型与工具。一个人使用时，一个控制核心足够；控制主机停机后重新启动，由 3.1 的恢复从已提交的状态继续。
- 主备、多实例与服务端数据库各自增加故障点与维护成本，对单人使用没有收益。
- 需要靠近硬件与平台的是执行：在树莓派上构建与检查、在树莓派上部署与观察交付的软件。执行环境服务同时满足本机的隔离（容器）与多机的执行（执行代理），只需要一份合同。
- 凭据留在控制主机，远程机器上不保存模型凭据。

后果：

- 路线图中原 Stage 6 分布式部署不再单独作为阶段，远程执行由 Stage 3 的 3.2C 执行环境服务提供。
- 3.2C 依赖 3.1 的动作核实与 #110（工作区的建立与交付的封存经过执行环境），排在 3.2B 网络与 MCP 之前，外部内容进入模型输入之前，任意代码已经可以在容器中隔离运行。
- 运维部门（[D27](../requirements/operations-department.md)）通过执行代理在登记的运行环境中部署、回滚、重启与读取运行数据。
