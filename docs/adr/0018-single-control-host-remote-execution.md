# 一台控制主机，执行环境分布到多台机器

可以预见的时间内 Yudao 只有用户一个人使用，同时会部署到多台电脑与树莓派一类能运行 Linux 的板子上（[D29](../requirements/remote-execution.md)，2026-09-28）。多台机器的用途是让工程的构建、质检的检查与运维的操作在对应的机器上进行。决定：

- 控制核心、事件日志、工件存储、Provider 模块与观察者在一台机器上运行，这台机器称为控制主机，使用一台常开的机器（台式机、小主机或树莓派）。事件日志继续使用 SQLite。控制核心只有一个实例，不做主备。
- 执行环境是一个服务，合同经过 HTTP 加 JSON（[ADR-0015](0015-desktop-client-and-http-contracts.md)），有三种实现：本机进程、本机容器、远程机器上的执行代理。执行代理是运行在其他电脑或树莓派上的一个小服务，在登记的目录中读写文件、启动进程，并交回动作回执。
- 用户在系统中登记机器，写明名称、地址与用途，同一台机器可以供多个项目使用；每个项目授权使用其中的机器，写明登记的目录、可以执行的操作与是否作为本项目的运行环境，授权范围按项目分开（2026-09-29 用户决定）；只在局域网内使用期间，连接的认证与加密保留位置并标为 TODO（2026-09-28 用户决定），离开局域网之前加入访问令牌与 TLS，使执行代理只接受控制主机的请求。
- 控制核心持有每个 run 的执行权，执行权编号在写入口与领域写入一起核对，用于进程重启与两个进程同时恢复的情况；执行权没有期限与续期。
- 远程动作的存活按动作判断：执行代理在动作进行期间按时发送心跳，超过时限没有心跳时，动作结果记为未知，按 3.1 的动作核实处理；之后到达的回执按动作身份记为迟到事实，不改变已经做出的决定。

扩展途径。资源调度与并发的限制有三处，各自的扩展方式不同；拆分只改变部署方式，不重写核心，依靠的是 ADR-0007 的边界（消息往来、状态持久化、执行权编号、查询接口）：

| 限制 | 扩展方式 | 触发条件 |
| --- | --- | --- |
| 构建、测试、部署占用的 CPU、内存与硬件 | 登记更多机器，执行环境池按机器的能力与负载分派动作 | 执行槽位长期占满，或者动作在排队等待机器 |
| 模型服务的限流 | 增加连接与订阅 | 限流成为等待的主要原因 |
| 控制核心的处理能力 | 按项目分成多个控制核心实例，每个实例负责一部分项目、持有这些项目的执行权、保存自己的事件日志，写入口的接口不变（[ADR-0013](0013-event-log-and-single-write-path.md)）；步骤驱动可以移到其他机器上运行 | 控制主机的处理延迟影响到正在运行的 run |

部门不作为拆分单位：并发的单位是事项与项目，同一个事项的各部门轮流工作；部门的隔离由控制核心的装配规则与可见范围保证。项目之间没有共同的事实，按项目拆分以后，每个实例内部仍然只有一份事实来源与一个写入口。

本决定取代 [ADR-0012](0012-single-control-core-scalable-execution.md) 中「为可用性做主备」「服务端数据库的选择在 Stage 6 按故障场景与总成本比较」两项，以及 [ADR-0007](0007-boundaries-for-distributed-deployment.md) 第 3 条中「所有权带有期限，由执行者按时续期」一句。ADR-0007 的其余边界继续作为执行环境服务的合同。

理由：

- 控制核心的每一步工作量很小，负载在等待模型与工具。一个人使用时，一个控制核心足够；控制主机停机后重新启动，由 3.1 的恢复从已提交的状态继续。
- 主备与服务端数据库各自增加故障点与维护成本，对单人使用没有收益。控制核心每一步的工作量很小，一个进程可以同时照看几百个在等待的 run，达到这个规模以前不需要多个实例。
- 需要靠近硬件与平台的是执行：在树莓派上构建与检查、在树莓派上部署与观察交付的软件。执行环境服务同时满足本机的隔离（容器）与多机的执行（执行代理），只需要一份合同。
- 凭据留在控制主机，远程机器上不保存模型凭据。

后果：

- 路线图中原 Stage 6 分布式部署不再单独作为阶段，远程执行由 Stage 3 的 3.2C 执行环境服务提供。
- 3.2C 依赖 3.1 的动作核实与 #110（工作区的建立与交付的封存经过执行环境），排在 3.2B 网络与 MCP 之前，外部内容进入模型输入之前，任意代码已经可以在容器中隔离运行。
- 运维部门（[D27](../requirements/operations-department.md)）通过执行代理在登记的运行环境中部署、回滚、重启与读取运行数据。
