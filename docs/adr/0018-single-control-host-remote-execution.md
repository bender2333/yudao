# 一台控制主机，执行环境分布到多台机器

状态：有效；依据：[D29](../requirements/remote-execution.md)；路线位置：阶段四「拆开部署」。

可以预见的时间内 Yudao 只有用户一个人使用，同时会部署到多台电脑与树莓派一类能运行 Linux 的板子上（[D29](../requirements/remote-execution.md)，2026-09-28）。多台机器的用途是让工程的构建、质检的检查与运维的操作在对应的机器上进行。决定：

- 控制核心、事件日志、工件存储、Provider 模块与观察者在一台机器上运行，这台机器称为控制主机，使用一台常开的机器（台式机、小主机或树莓派）。事件日志使用 SQLite。控制核心只有一个实例，不做主备。
- 执行环境是一个服务，合同经过 HTTP 加 JSON，有两种实现：本机进程与远程机器上的执行代理。执行代理是运行在其他电脑或开发板（例如树莓派、Orange Pi AIpro）上的一个小服务，在登记的目录中读写文件、启动进程，并交回动作回执；本机进程在控制核心的进程内直接调用同一个接口，不经过 HTTP（2026-09-29 用户决定）。代码在执行位置上直接运行，不使用容器（[执行环境服务设计说明](../design/execution-environment.md)第 8 节）。
- 用户在系统中登记机器，写明名称、地址与用途，同一台机器可以供多个项目使用。每个项目授权使用其中的机器，写明登记的目录，阶段四起还写明是否作为本项目的运行环境；项目把机器设为执行位置，就能在那里执行全部动作（[ADR-0038](0038-function-first-commands-without-registration.md)）。授权范围按项目分开（2026-09-29 用户决定），存法见执行环境服务设计说明第 7.1 节。只在局域网内使用期间，连接的认证与加密保留位置并标为 TODO（2026-09-28 用户决定）；离开局域网之前加入访问令牌与 TLS，使执行代理只接受控制主机的请求。
- 控制核心持有每个 run 的执行权，执行权编号在写入口与领域写入一起核对，用于进程重启与两个进程同时恢复的情况；执行权没有期限与续期。
- 远程动作的存活按动作判断：执行代理在动作进行期间按时发送心跳，超过时限没有心跳时，动作结果记为未知，交还发出它的会话（[ADR-0038](0038-function-first-commands-without-registration.md)）；之后到达的回执按动作身份记为迟到事实，不改变已经做出的决定。

扩展途径。资源调度与并发的限制有三处，各自的扩展方式不同；拆分只改变部署方式，不重写核心，依靠的是总图第四节的缝与第六节的规矩（消息往来带身份、状态持久化、执行权编号、只经命令与查询）：

| 限制 | 扩展方式 | 触发条件 |
| --- | --- | --- |
| 构建、测试、部署占用的 CPU、内存与硬件 | 登记更多机器，执行环境池按机器的能力与负载分派动作 | 执行槽位长期占满，或者动作在排队等待机器 |
| 模型服务的限流 | 增加连接与订阅 | 限流成为等待的主要原因 |
| 控制核心的处理能力 | 按项目分成多个控制核心实例，每个实例负责一部分项目、持有这些项目的执行权、保存自己的事件日志，写入口的接口不变（总图第四节「写入口」缝） | 控制主机的处理延迟影响到正在运行的 run |

只有一份的是一份事实、写入口、裁决、边界与薄驱动；部门成员（一个会话）可以有多份，放在任何登记的位置（总图第六节）。并发的单位是事项与项目。项目之间没有共同的事实，按项目拆分以后，每个实例内部仍然只有一份事实来源与一个写入口。

理由：

- 控制核心的每一步工作量很小，负载在等待模型与工具。一个人使用时，一个控制核心足够；控制主机停机后重新启动，按[恢复契约](../design/recovery-contract-and-fault-matrix.md)从已提交的状态继续。
- 主备与服务端数据库各自增加故障点与维护成本，对单人使用没有收益。一个进程可以同时照看几百个在等待的 run，达到这个规模以前不需要多个实例。
- 需要靠近硬件与平台的是执行：在开发板上构建与检查、部署与观察交付的软件。执行环境服务用一份合同覆盖本机进程与多台机器上的执行代理。
- 凭据留在控制主机，远程机器上不保存模型凭据。

后果：

- 运维部门（[D27](../requirements/operations-department.md)）通过执行代理在登记的运行环境中部署、回滚、重启与读取运行数据。
