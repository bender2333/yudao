# 预置表数据驱动且版本可见，不做远端热更

服务方案预置（端点、认证方式、默认协议、模型列表地址）会随厂商演进过时，需要一个增长方式。决定：预置是模块内的一份数据表，带 `revision` 与来源链接并在界面可见；新增厂商等于新增一行数据，不改代码；**不做**远端热更、生成管线或兼容基线。

理由：cc-switch 把 50+ 预设硬编码在 60–106KB 的 TS 文件里，模型改名与能力更新靠人工跟进，滞后是它公开的痛点；LiteLLM 走另一端，每个进程启动时从 GitHub main 拉能力表，并用端点暴露 `source_revision`。2.7 的规模用不上拉取管线（仓库规则 2），但「我现在用的是哪一版表」必须能回答（仓库规则 7）。

后果：预置表过时需要发版更新；界面必须显示 revision 与来源，让用户能判断手上的表是否已旧。能力字段不随预置表发布——它们仍走采用定义与真实验证。
