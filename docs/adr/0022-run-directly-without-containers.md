# 代码在执行位置上直接运行，不使用容器

Status: 「Yudao 继续保证」中的「命令只能是登记的命令」「进程的环境变量中没有凭据」两项由 [ADR-0038](0038-function-first-commands-without-registration.md) 取代：命令接受任意命令字符串，进程得到 Yudao 进程或执行代理进程的全部环境变量。其余决定继续有效。

[ADR-0018](0018-single-control-host-remote-execution.md) 规定执行环境有本机进程、本机容器、远程执行代理三种实现，本机容器用来在控制主机上隔离运行任意代码，评测的场景镜像与 3.2D 的试用镜像都建立在它上面。控制主机是用户的 Windows 11 家庭版电脑，容器需要 Docker Desktop 与 WSL2。2026-09-30 用户决定不使用容器，并在专题讨论中确定不使用 WSL（[决策记录](../decision.md) 2026-09-30「不使用容器」与「不使用容器以后的执行环境」两条）。决定：

- 执行环境服务有两种实现：本机进程在控制核心的进程内调用；远程执行代理运行在登记的其他电脑与开发板上，经过 HTTP 加 JSON 的合同。Yudao 不使用容器，也不使用 WSL；需要在 Linux 上构建与检查时，使用一台登记的 Linux 机器，例如 Orange Pi AIpro 开发板。
- 代码在执行位置上直接运行：在控制主机上使用运行 Yudao 的账户的权限，在登记的机器上使用执行代理所在账户的权限。
  - Yudao 继续保证：文件工具只读写工作区；命令只能是登记的命令；进程的环境变量中没有凭据；模型凭据只在控制主机上，不进入工作区，也不发给执行代理。
  - Yudao 不提供操作系统层面的沙箱：登记的命令运行的代码（测试、构建脚本、试用中启动的交付软件）能读写这个账户能访问的全部文件。
- 来源不明的仓库不需要单独的机制：把这个项目的执行位置设到另一台登记的机器。
- 3.2D 的试用在 run 的执行位置上直接进行：Playwright MCP 与无界面的 Chromium 在那里运行；每个试用会话由 Yudao 分配一个空闲端口，经环境变量 `PORT` 交给交付的软件。computer use 的屏幕从哪里来另行讨论（[阶段需求概览](../requirements/stage-requirements-overview.md)第 6 节）。
- 评测在控制主机上直接运行：每次运行在 Yudao 仓库之外新建目录；两边使用同一套版本固定的工具；隐藏检查、条目表与参考解法在运行结束以后才复制到评分目录（[评测场景设计](../design/evaluation-scenarios.md)第 3 节）。

理由：

- 可以预见的时间内只有用户一个人使用，而且只在局域网内（ADR-0018、[D29](../requirements/remote-execution.md)）；用户对安全的要求是保留位置、放低优先级（D29、[D34](../requirements/browser-and-computer-use.md)）。自主推进中的执行者 omp 同样直接在这台电脑上运行代码。
- 本机容器带来的工作（镜像的构建与复用、容器与卷的生命周期、按标签找回、容器引擎的检查、约 1 GB 的试用层）只为控制主机上的隔离服务。按执行位置选择机器已经能把不信任的代码放到另一台机器上，隔离由机器的边界提供，不增加新的机制。
- 多机执行的合同（执行代理、心跳、结果未知与迟到回执、执行权编号）不变；远程机器上的执行代理本来就直接在登记的目录中运行代码。

后果：

- 3.2C 的关闭条件：同一事项的工程构建在控制主机上完成，质检检查在开发板上完成（[执行环境服务设计说明](../design/execution-environment.md)第 10 节）。
- 3.2B 与 3.2D 的工单只依赖执行环境的合同（#128），不等待 3.2C 的远程部分；Stage 3 的关键路径随之缩短（[Stage 3 计划](../stage-3-plan.md)第 8 节）。
- 执行位置上需要的程序（git、uv、项目自己的构建工具、试用用的 Node.js 与 Playwright 的 Chromium）由用户在这台机器上安装，执行环境的环境信息列出它们（执行环境服务设计说明第 5.2 节）。
- 不同项目的 run 共用执行位置的端口与依赖缓存：试用的端口由 Yudao 分配，依赖缓存使用各工具在这台机器上的缓存。
- 本决定取代 ADR-0018 中的本机容器一项、理由中「执行环境服务同时满足本机的隔离（容器）」、后果中「外部内容进入模型输入之前，任意代码已经可以在容器中隔离运行」；取代 [ADR-0012](0012-single-control-core-scalable-execution.md) 中「执行环境的容器实现」。[ADR-0010](0010-control-core-drives-role-steps.md)、ADR-0012、[ADR-0015](0015-desktop-client-and-http-contracts.md) 中「外包 agent 的运行容器」改为外包 agent 的运行进程：外部 agent 在执行位置上以自己的进程运行（[D31](../requirements/outsourced-agent-roles.md)）。
