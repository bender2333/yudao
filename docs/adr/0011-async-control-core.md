# 控制核心在一个异步事件循环中运行

控制核心要同时驱动多个事项与多个角色任务：3.4A 按执行槽位同时运行多个事项，D26 的一次性角色可以同时进行多个任务，界面要逐字接收模型输出。决定：控制核心在一个异步事件循环中运行。事项与角色任务都是可以取消的任务；模型调用、工具与检查的进程、事件的推送都以异步方式等待；计算量大的工作（树摘要、全文索引、Git 操作）放到线程池中执行。

理由：

- Provider 层内部已经使用 `AsyncOpenAI` 与 `AsyncAnthropic`，每次调用再用 `asyncio.run` 包在同步函数里；控制核心同步调用它，形成线程与「每次调用一个事件循环」两种做法混用。
- 取消现在靠每 20 毫秒检查一次 `threading.Event`（部门循环的重试等待与 Provider 的调用），D06 要求取消立即生效。任务取消可以沿调用链直接传递。
- 执行槽位、并行角色任务、事件流推送都是在等待模型、进程与网络；等待期间不占用其他任务。
- OMP 与 opencode 都用单一的异步运行时驱动多个会话。

后果：

- Provider 模块对控制核心提供异步接口，内部不再为每次调用新建事件循环。
- 工具与检查的进程用异步方式启动与等待，超时与取消结束整个进程树。
- 事件日志的写入经过唯一写入口（[ADR-0013](0013-event-log-and-single-write-path.md)），写入串行进行。
- 单机部署时，接口层与控制核心运行在同一个事件循环中（[ADR-0015](0015-desktop-client-and-http-contracts.md)）。
- #43 的步骤驱动直接写成异步；3.4A 与 D26 在同一个事件循环中增加同时运行的任务，不改变执行方式。
