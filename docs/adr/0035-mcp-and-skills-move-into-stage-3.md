# 将 MCP 和技能提前到 Stage 3

状态：提议（2026-10-12），未经用户确认采纳。方案：[Stage 3 重排方案](../stage-3/replan-mcp-skills.md)。

背景：

- 2026-09-24 的路线图调整把 Stage 3 收窄为通用工具、可靠恢复与并行，技能移到后面的阶段（重新编号后在 Stage 5），仓库中没有技能的工单。
- 3.2B 网络取回与 MCP 工具（[D36](../requirements/network-and-mcp.md)、[设计说明](../design/network-and-mcp.md)）已在 Stage 3，工单 #122、#68、#69、#236 至 #239 均未开始；设计把 OAuth 登录、SSE 传输，以及 MCP 的资源、提示与向用户请求输入列为不在范围内。
- 此后 Stage 3 加入了远程执行、评测、网页界面、浏览器、模型管理、迭代底座与自举工作线。

决策（提议）：

- MCP 与技能作为功能本身移入 Stage 3：3.2B 留在 M3；MCP 的扩展（OAuth、提示与资源、向用户请求输入、SSE）与技能放在新的里程碑 M5。
- MCP 与技能依赖的前置能力，如果在后面的阶段或者还没有，同样移入 Stage 3。
- 使用 MCP 或技能、本身不是 MCP 或技能的功能留在原阶段：#62 探索者（Stage 5）、圈复杂度与变异测试的研发工具（Stage 4）、跨任务经验与自动采用经验（随 Stage 6）。3.2D 浏览器已在 Stage 3，不变；computer use（#150、#246、#247）仍是以后的专题。

理由：

- 质检的独立核验依赖 Playwright MCP 的浏览器工具（#149 使用 #69 的 MCP 客户端模块），浏览器又是评测场景 1 的前提；MCP 不完整，Stage 3 的质检操作交付与评测都无法完成。
- MCP 的前置能力已经在 Stage 3 完成：恢复契约（#17、#18、#242）、带版本的定义（#48）、用户决定（#49）、凭据来源（D24）、界面基础（#80、#175、#177、#372、#377）；只剩执行环境的合同 #128，它已经没有阻塞。
- 技能是以后各种扩展的基础：跨任务经验、自动采用经验与以 skill 加 MCP 形式提供的研发工具都建立在它之上。

后果：

- #9 的工作包与关闭条件要修改：增加 M5，#173 与 #100 放在 M5 之后。
- 按 CLAUDE.md 的工单规范新建 MCP-1 至 MCP-5 与 S0 至 S5（[方案](../stage-3/replan-mcp-skills.md)第 5 节）；技能需要一份新的需求记录（新的 D 编号）。
- 推翻 2026-09-24「技能移出 Stage 3」的决定，以及 D36 中相应的「不在范围内」的取舍。ADR-0025 不变。
- 采纳以后同步修改路线图、Stage 3 计划、阶段需求概览、总体架构、D36 与网络取回与 MCP 工具设计说明、决定记录与当前验收基线（[方案](../stage-3/replan-mcp-skills.md)第 7 节）。
