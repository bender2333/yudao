# 画面是单独的应用，按画面合同与诚实性验收

状态：有效；依据：[总图](../architecture.html)第一节「画面」方框与第四节「画面」的缝、[画面总图](../architecture-view.html)、[画面与播放设计说明](../design/visualization.md)；路线位置：[路线图](../program-roadmap.md)第 4 节，画面自己的阶段。

画面（首页的楼、项目楼层、部门房间，以后的机房与城）是系统外面的一个使用方。它和产品的基础部分变化的快慢不同：基础部分跟着工单与功能走，画面要的是空间、表演与画法上的反复尝试。两者放在一起时，画面成了基础部分每一步的前置条件；分开以后，各走各的。

决定：

- 画面是单独的应用：单独的目录、构建、测试与里程碑，以单独的页面打开。它像观察者一样只经接口读查询快照与事件流，用户在画面里的操作只发现有的命令；不要专用查询，不导入基础部分的任何代码，由导入方向的测试守住。Yudao 是它的第一个宿主。
- 「看得见」由基础部分的页面负责：回答决定、看状态、分清开环完成与放行、点开原始事件都在页面上。系统的阶段与薄片只看页面验收，不等画面；画面的测试不挡基础部分的合并。
- 画面只按画面合同与诚实性验收：不说谎、能回链到事件、开环完成不画成放行。不对照原型或草图的像素。系统加了画面不认识的部门或事件，画面画成通用的屋与小人或者不画，列进缺口清单，不让测试失败。
- 每加一个空间或元件，先画事实层，状态直接换上去；走位、气泡、排队这些表演以后再补。
- 原型只回答设计问题：一张用假数据的单页草图，不带翻译层与播放时间线，答完就扔，不演进成工程代码，也不当外观的标准。
- 画面里面的结构不变：画面层是实体—组件—系统，世界与系统不依赖渲染；有行为的实体（角色、管道）各有一个 XState 状态机；GSAP 负责走动与包裹的移动，与 PixiJS 共用一个时钟，测试用确定的时钟；PixiJS 8 渲染，纹理最近邻采样，在逻辑尺寸乘整数倍的画布上绘制，文字用微软雅黑；画面层只认画面合同，播放节奏归画面层。这些是画面自己的实现选择，可以整体重写，重写以后诚实性测试照过。

理由：

- 逐像素对照原型逼着原型写到实现级，同一个画面写了两遍，产品每变一步都要先改原型、再改客户端、再重录回放。外观不是事实，诚实性测试已经守住事实，外观上的问题由试用发现。
- 画面只经接口读事实，和命令行、评测、观察者一样，接口的版本与字段只增已经保证旧画面能读新系统；它落后时只是画得少，不会画错。
- 换一个事实源（例如外部 agent 的会话记录）只要换翻译器与壳，画面层不动。

后果：

- 客户端里画面相关的代码（画面层、翻译层、楼层与房间的画布、回放）搬成单独的应用；只在画面上有的事实先补到页面。
- 对原型的逐像素回放、录制与按原型生成的登记表不再是验收办法，随搬出一并去掉；原型归档。
- 画面落后于系统是常态，缺口清单说明还没画的部分。
