# 界面的像素画面按实体—组件—系统结构实现

状态：有效；最近一次改动：2026-10-28 与原型的外观核对改为逐像素回放核对，联系表不再交给用户查看，去掉旧编号与已删除的引用；依据：当前定稿的原型（[原型变更记录](../prototypes/CHANGELOG.md)开头一行）、[画面与播放设计说明](../design/visualization.md)；路线位置：阶段一「画面」缝。

像素画面采用实体—组件—系统结构：角色、包裹、房间、管道、设备都是实体，房间与管道按图结构声明，域事件变成任务放进角色的队列或者变成信号，管道持续流动。这个方向是 2026-09-29 用户看过原型 v8 以后定下的：v8 的画面是查询快照整体替换加一次性动画，没有持续运行的模拟。界面使用 React 19、TypeScript、Vite、PixiJS 8、XState 5 与 GSAP（2026-09-25 用户确认，[总体架构](../design/architecture/overall-architecture.md)第 9 节）；原型用自己写的画布原语与引擎，不依赖这些库。原型是结构与行为的参照，界面用这些技术实现这个结构（2026-09-30 用户决定）；界面的依据是当前定稿的原型，版本号只写在原型变更记录开头（2026-10-10 用户决定）。

决定：

- 世界与系统用 TypeScript 写成不依赖渲染的模块：实体与组件、房间与管道与节点的声明、任务目录与派发、角色队列的规则、信号、管道的流动、说话目录。声明与两份目录（原型的 `floor-decl.js`、`say.js`）是数据与规则，内容照原型搬过来。
- 有行为的实体各有一个 XState 状态机：角色（按持续状态摆放、走向任务位置、做任务、待机活动、外出）与管道（流动、空闲、停止）。包裹、房间、设备不需要状态机。
- GSAP 负责小人的走动与包裹沿管道折线的移动，时长取自任务目录与速度常量。GSAP 与 PixiJS 共用一个时钟，测试时使用确定的时钟。
- PixiJS 8 渲染：每个房间、管道、角色、包裹、设备对应一个显示对象，按世界的状态更新。原型 `sprites.js`、`engine.js` 的像素画法改写为 TypeScript，用来生成 PixiJS 的纹理。图形与文字按屏幕的实际分辨率绘制：与原型相同，在逻辑尺寸乘整数倍的画布上先设缩放再绘制；纹理使用最近邻采样，画风与原型一致。画面中的文字使用微软雅黑。
- React 只负责挂载画面对象；传给画面的是翻译层给出的画面合同（状态与动作），播放节奏归画面（[画面与播放设计说明](../design/visualization.md)第 4、6 节）。
- 原型的代码从定稿起不再修改。与原型的核对分为行为与外观两部分：
  - 行为与状态由测试比较：原型 `behaviors.js` 的检查改写为界面的测试，直接对世界、系统与状态机运行；原型录下的 19 个场景的调用序列送进界面的画面，在每个事件之后的固定时刻比较每个角色的任务、姿势与头顶的话、每个包裹的去向、每根管道的状态与各个信号。录下的调用序列与原型的状态记录存入界面的测试目录，只经重写开关更新。
  - 外观由逐像素回放核对：同一份画面合同状态，界面的画法与当前定稿原型的画法在每段录制的最后一个检查点逐像素相同（画面与播放设计说明第 8 节，2026-10-26 用户确认）。

理由：

- 这些技术是用户确认过的；原型验证的是结构与行为，与渲染方式无关，每个有行为的实体对应一个状态机，与 XState 的用法一致。
- 世界与系统不依赖渲染，行为可以不经过画面测试；声明与目录照原型搬过来，增加部门或事件种类仍然只写声明。
- 纹理由原型的画法生成，画风不需要重新绘制素材。

后果：

- 当前定稿原型的代码是逐像素核对与录制的来源。原型的设计说明与构建约定只写与前一版不同的地方，前一版的说明一同作为依据。
