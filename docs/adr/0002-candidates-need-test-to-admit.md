# 候选必须经真实测试准入，未知能力不猜

上游模型列表只返回模型 ID，不返回上下文窗口或工具能力，公开资料也拿不全。决定：拉回的模型是**候选**；点击后可以预填容量，用户改过或明确接受之前不能保存；模型测试通过后才允许绑定到部门；保存后的容量不再另猜。协议由所属连接决定，见 [ADR-0004](0004-one-protocol-per-connection.md)。

理由：Yudao 的失败代价是任务中途失败并消耗 D09 次数，宁可挡在准入之前。cc-switch 在这类场景选 fail-open（未知模型按 text+image 放行），但它的代价结构不同——它只往别的 CLI 写配置文件，不让模型跑 Agent 循环。Cherry Studio 与 LiteLLM 都不猜：前者对目录不认识的模型保留上游名、不带能力元数据，后者让用户自行挂键。

后果：模型测试必须是一次真实最小推理。连接测试不改变准入。地址、凭据引用、上游模型 ID 或协议的修改，使受影响的访问定义回到候选，并清空指向它们的部门绑定。名称、超时、模型列表地址不废准入。已确认容量的修改不废准入，只影响之后创建的事项。同一凭据引用后面的 Key 更换不改目录，不废准入。
