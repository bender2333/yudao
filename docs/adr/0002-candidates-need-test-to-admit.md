# 候选必须经真实测试准入，未知能力不推测

上游模型列表只返回模型 ID，不返回上下文窗口或工具能力，公开资料也拿不全。决定：获取模型列表得到的模型是**候选**；加入模型访问定义时窗口与输出上限可以预填（先取上游模型列表返回的值，没有时取模型能力表，见 [ADR-0003](0003-versioned-preset-table-no-remote-refresh.md)），每一行在用户修改或明确接受之前不能保存；模型测试通过后，才允许被部门默认或项目部门设置选用。准入记录只由模型测试写入，目录文档的编辑、导入与导出都不含准入记录。协议由所属连接决定，见 [ADR-0004](0004-one-protocol-per-connection.md)。

理由：Yudao 的失败代价是事项中途失败，宁可在准入之前阻止。cc-switch 在这类场景选择 fail-open（未知模型按 text+image 放行），但它的代价结构不同——它只往别的 CLI 写入配置文件，不让模型运行 Agent 循环。Cherry Studio 与 LiteLLM 都不推测：前者对目录不认识的模型保留上游名称、不带能力元数据，后者由用户自己填写模型能力字段。OMP 内置目录 4776 个模型中有 764 个没有窗口数据，这些模型的主动压缩从不触发。

后果：模型测试必须是一次真实的最小推理请求，声明了推理档位的模型按默认档位发送推理参数。连接测试不改变准入。准入按字段判断：地址、凭据引用、协议的修改，使该连接下全部访问定义回到候选；上游模型 ID 或推理参数方式的修改，使该定义回到候选。名称、超时、模型列表地址、容量、支持档位、默认档位、输入方式与是否接受要求调用工具的修改保持准入，从下一次模型请求起使用新值；输入方式与是否接受要求调用工具取自模型能力表与用户声明，直接使用，模型测试不另外核实。同一凭据引用后面的 Key 更换不改变目录，保持准入。测试一个模型不影响其他模型的准入。准入作废后，部门默认与项目部门设置中的引用保留并显示无法使用，使用它的事项在相关部门的下一次模型请求前进入待恢复，写明部门、模型与原因，用户修复以后继续，不改用其他模型。
