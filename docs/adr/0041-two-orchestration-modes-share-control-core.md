# 两种编排模式共用控制核心：成果驱动与黑板

Status: 暂缓。用户 2026-10-23 决定暂时不做，还没有完全想明白；本 ADR 与 D39、设计说明保留在 PR #751 里不合并，不作为已采纳的决定，现有设计仍只有成果驱动一种流转方式（ADR-0039）。

用户 2026-10-22 提出任务池方案（[D39](../requirements/blackboard-orchestration.md)）：部门通过发布、认领、拆分、打回任务驱动循环，循环的形状由任务决定；并在审查以后决定保留两种模式，把验证者与作者分开这类要求限定在三部门的方式里。此前的设计只有一种流转方式：[ADR-0039](0039-departments-work-from-watched-outputs.md) 让部门按关注的成果开始工作，正式成果写明依据的版本，只有质检的放行结束事项。决定：

- 控制核心分成模式无关的共享部分与编排模式两层。共享部分：写入口与事件日志、保存的投影、步骤驱动、上下文装配、工具许可、边界的核对、定义的加载与结构校验、判定点、Provider、执行环境、接口层的命令、查询与事件流。编排模式只负责一件事：什么时候让哪个部门开始一轮工作，一轮工作以什么结束，事项以什么结束。
- 编排模式有两种实现：成果驱动模式（ADR-0039 与[三部门的循环结构](../design/department-loop.md)）与黑板模式（[黑板编排设计说明](../design/blackboard-orchestration.md)）。两种实现都在流程编排模块里，对步骤驱动、装配、裁决与写入口的调用方式相同。
- 模式写在组织定义里（`orchestration`，取 `watched_outputs` 或 `blackboard`），随定义的版本改变（[ADR-0014](0014-versioned-definitions.md)）。一个事项按它开始时的定义版本确定模式，中途不换。
- 黑板是事件日志的一个保存的投影。任务的发布、认领、完成、打回、阻塞都是经写入口写入的事件；认领在写入口按流版本核对，同一个任务只有一次认领成功。不引入 PostgreSQL、Redis 或第二份事实来源。
- 黑板模式不要求验证者与作者分开，不要求先判断后看解释，没有正式成果的版本核对与放行。任务由完成它的部门自己写明验证结果，控制核心不裁决；任何部门可以打回已完成的任务。这一处按基础规则 2 记为开环，由评测的隐藏检查在外部评价。
- 黑板模式保留：写入只经写入口，模型只能提议；每个工具调用经过工具许可；一定会停（事项运行时间、每轮步数、任务数与打回次数的上限，停止原因属于封闭清单）；事件可以完整重放；收敛状态由投影计算。
- 两种模式用同一套评测场景与隐藏检查评价。模式之间的比较按[规则登记与参数设计说明](../design/rules-and-parameters.md)第 4 节的对照进行。

理由：

- 用户要的是两条路并存：三部门的方式继续演进，黑板作为更简洁的动态方式与它比较。把两种方式做成流程编排的两种实现，共享部分只有一份，差异集中在一个模块里。
- 黑板需要的看板、原子认领、不可变历史、实时广播，现有结构已经提供：投影、写入口的流版本核对、事件日志、事件流订阅。另建存储会出现第二份事实来源，与 [ADR-0013](0013-event-log-and-single-write-path.md) 相反。
- 模式作为定义里的数据，切换与撤回不需要发布新版本，符合可迭代状态的判据「改动便宜且可撤回」。
- 独立性要求在黑板模式里不由结构保证，就必须有别的传感器。评测场景的隐藏检查在两种模式之外，是两种模式共用的锚点。

考虑过的做法：

- 只保留一种机制，用对照实验比较两份组织定义（整份成果与带版本的工作包）。架构师推荐这个做法，用户决定保留两种模式。
- 黑板用 PostgreSQL 与 Redis 单独存储（用户方案的原文）。与共用底层的决定相反，并且会出现第二份事实来源。
- 把任务做成成果驱动模式里的一种成果。能表达发布与认领，但不能去掉版本核对与放行，用户认为不够简洁。

后果：

- 基础规则的适用范围需要用户在 [docs/foundation-rules.md](../foundation-rules.md) 写明。建议的措辞，加在规则 3 的具体规则之下：「黑板模式下，任务完成由完成它的部门自己写明验证结果，控制核心不裁决；按规则 2 记为开环，由评测的隐藏检查在外部评价（ADR-0041）。」规则 1 中「放行必须绑定当前有效的合同、计划、交付与代码快照」只适用于成果驱动模式。
- [三部门的循环结构](../design/department-loop.md)是成果驱动模式的设计说明；[循环与收敛设计说明](../design/loops-and-convergence.md)第 6 节的五条判据对两种模式都适用，第 5 节的进展度量按模式各自定义。
- 组织定义增加 `orchestration` 与部门的能力标签；事项种类定义增加根任务的默认标签；工具定义增加任务工具，只在黑板模式可用；规则登记增加黑板的上限参数；停止原因增加黑板的完成原因。
- 术语表增加编排模式、成果驱动模式、黑板模式、黑板、任务、能力标签、认领、打回。
- 实施排在 M0 的 #474 之后：#474 删除阶段状态机以后，流程编排才有可以放第二种实现的位置。在路线图中的位置由用户决定。
