沿用一个可信、小型 Python 文本报表项目，避免三个完全不同系统造成无法比较。测试准备先固定需求、输入样本、每次变更和公开检查；这些清单入库后才采集结果。

| 场景 | 固定要检验的行为 | 完成条件 |
| --- | --- | --- |
| 多文件增量变更 | 在已有采用成果上增加报表能力，保留旧行为；输入含正常、空和非法情况 | 新旧公开检查均通过，工程与 QA 独立检查，完整交付、Git、采纳和 replay 对应 |
| 返工与定向指导 | 在验收副本植入一个事先声明的缺陷，QA 指出后工程修复；工程激活期间追加一条不改变目标的指导 | 返工引用正确版本，指导实际进入合法上下文，最终交付通过；植入缺陷标为受控场景，不称自然回归 |
| 小窗与方向调整 | 同一任务资料触发真实压缩；产品处理一次事先固定的需求变更 | 至少一次有效压缩后仍完成最终合同的独立 QA，原始材料、摘要来源、旧结果失效、最终交付均可追溯 |

每个场景至少一条完整真实流程通过，所有首次失败与复跑纳入报告；这是功能覆盖，不是统计成功率或学习收益证明。功能链路无法完成时修复并重新冻结受影响版本。小窗大小在采集前根据固定材料与模型有效容量确定，不临场缩改材料或扩大限额去获得成功。
