# Yudao 总体路线图

总图的顺序索引，只写阶段怎么区分、怎么演进；进度看 GitHub 的里程碑与工单。

路线图只回答一个问题：总图 [architecture.html](architecture.html) 与它展开的[画面总图](architecture-view.html)按什么顺序变成真的。总图是正本，路线图上的每一项都是总图上的一个方框、一道缝、一个状态或一环；总图上没有的东西不进路线图，先交总架构师。怎么做写在设计说明与需求记录里，不写在这里。总体意图见 [D38 系统意图与基础规则](requirements/system-intent.md)：独立高质量交付、长时间自己运行并自己修复、两层自举。

## 1. 怎么推进

**结构与内容一起长。** 总图把系统分成两种东西。固定的结构是循环、边界、裁决三样，落在一份事实与写入口、裁决与边界、薄驱动与三道共用的槽位、十三道缝、系统之外的评价、进程之外的看门狗上；结构有限，建完就定型。填进结构的内容：部门与角色、核验角色、轮转方式、工作单元的大小、装配的减法、动作与工具、模型与判定点、画面、观察者、部署形态；内容开放，随运行证据一直加。不设用户看不到东西的纯骨架阶段：每推进一档用户用得到的能力，顺手把碰到的模块边界收成总图第四节的缝，一道缝要有第二种实现（哪怕只是测试用的）接得上才算立住。一切改动守总图第二节的三环。

**形态是内容，四层是判据。** 单 agent、普通多 agent、三部门、子组织是同一套结构填进不同的内容（[形态与核验角色设计说明](design/forms-and-verifier-role.md)）。每加一种形态，只许改路由与组织（定义）两层；要动事实与裁决或循环，就是抽象没立住，先交总架构师。页面上开环完成与放行分开写，换形态不另写页面。

**画面走自己的阶段。** 画面在系统外面，像观察者一样只经接口读事实、发现有的命令（总图第一节「画面」方框，展开见[画面总图](architecture-view.html)）。阶段与薄片的交付只看系统与页面，「看得见」由页面负责；画面有自己的里程碑与第 4 节的阶段，每一步只画系统已经有的记录，系统不等它，它的测试也不挡系统的合并。第 4 节的步 0「搬出」放在阶段二里做：它主要是页面接过只在画布上的事实、测试拆开，是基础部分自己的事。

**阶段、薄片与试用。** 一个阶段是一个 GitHub 里程碑，标题就是阶段名。阶段里按薄片推进，一个薄片回答这个阶段的一个问题（第 2 节的表），做完发一个版本交给你试用，不挡下一个薄片；试用暴露的缺陷排到队列最前面，薄片的先后与细节按试用反馈调整。最后一个薄片的试用就是整个阶段的试用，通过以后关闭里程碑。认为总图缺了什么或错了，交总架构师先改总图；反馈调整的是走法，不增删总图上的东西。里程碑、阶段工单、试用工单与清理单的规矩见 `docs/agents/ticket-spec.md`。

**门：可迭代状态。** 从建结构走到大规模填内容与自己演化，要逐条核对五条判据：有持续的真实负载、能度量（带噪声范围与费用）、改动便宜且可撤回、看得见（循环停在哪一层、为什么）、锚点受保护。第 5 节写每个阶段结束时五条各到哪里。

## 2. 五个阶段

五个阶段的顺序是依赖：没有诚实的单机闭环，自动继续就是把错误继续下去；没有可靠的自转与看门狗，拆开只是把故障分到多台机器；没有独立评价与可撤回的定义，系统自己演化就会失控。

~~~mermaid
flowchart LR
    P1["阶段一：单机诚实闭环，三道槽位立缝"] --> P2["阶段二：可靠恢复、接入真实项目、独立评价、形态可换"]
    P2 --> P3["阶段三：常驻自转、运维部门、看门狗兜底"]
    P3 --> P4["阶段四：拆开部署、细粒度协作"]
    P4 --> P5["阶段五：受治理的演化（第二层自举）"]
~~~

每个阶段的薄片、父工单与试用工单写在置顶的阶段工单里，这张表不写工单号。阶段三至五的薄片在进入那个阶段时切，在那以前「内容」一列是要建的几块。

| --- | --- | --- | --- |
| 阶段一：单机诚实闭环，三道槽位立缝 | 一个小的新项目，三部门能不能在网页上用真实模型交付出来：你下意图，三部门写代码、跑命令、回答一次决定请求、放行交付，页面与回放一致 | 一份事实、你、薄驱动、三道槽位为已建；写入口、路由、装配、执行、模型、投影、接口七道缝立住 | 一个薄片：核心打通与换骨架；剩下的工单与它的试用并进阶段二，和阶段二的薄片并行做 |
| 阶段二：可靠恢复、接入真实项目、独立评价、形态可换 | 你的一个真实项目接进来、改一处、关掉再开它接着做；一个场景（在已有仓库上加功能）的对照报告说明比单个 agent（OpenCode）好多少；换一份定义，同一件事改由一个角色直做，页面上分得出开环完成与放行 | 产品、工程、质检、独立的证据、页面、裁决与边界、定义、评价为已建，「模型与工具」本机部分已建；轮转方式里直做与按成果已建，核验角色任何路由都能放，形态随事项冻结；「定义」「评价」「动作」三道缝立住；验收表三层（内核、缝、真实场景）都在运转 | 先并进阶段一剩下的工单与核心打通的试用、画面搬出（第 4 节步 0），与下面的薄片并行；搬出排在最前：它合进去以前，画面与页面还共用目录、依赖与合并检查，两条线并行不起来。① 真实项目接着做 ② 比单个 agent 好多少：在已有仓库上加功能这一个场景，Yudao 与 OpenCode 各跑 3 次 ③ 质检自己核验网页（在 ① 之后）④ 改一处、看得见、能撤回：改参数、换形态（直做与开环完成），页面上看得见循环停在哪里、开环完成与放行分开写，都能撤回 ⑤ Yudao 做自己的工单（在 ① 与 ④ 之后；试点的做法见[自举需求记录](requirements/self-hosting.md)） |
| 阶段三：常驻自转、运维部门、看门狗兜底 | 你不在的一周里，一次进程中断与一次模型服务中断都自动接续，一次故障由运维发现、经三部门修复、运维重新部署 | 第四节「看门狗」的缝从未定到已定并立住；看门狗、运维为已建；第五节第一层自举为已建 | 只写声明加运维部门；进程之外的看门狗与两个槽位；第一层自举成为常态与内核守卫 |
| 阶段四：拆开部署、细粒度协作 | 质检在另一台机器上检查；两个项目并行；一个事项由任务池与外包角色承接并整份放行；一个部门的内部是子组织，它的结果作为一份提案回到上一层 | 轮转方式（含任务池）、模型与工具（含远程与外包）、观察者为已建，第三节「子组织」成立；第六节变成图上画的样子；「观察者」的缝立住，写入口、动作、模型、接口四道缝过网络验收 | 拆开与四道过网络的缝；第三种路由（任务池与工作单元）；子事项承接部门内多角色，外包角色；语义系统、判定点与观察者 |
| 阶段五：受治理的演化（第二层自举） | 系统根据运行证据提出组织定义、流转规则与工作单元降解的候选，经独立评价限定采用，劣化时撤回 | 六节全部方框已建；两层自举与三层验收形成闭环 | 振荡信号进边界，观察者的元观察；第二层自举的闭环（提出、独立评价、限定采用、对比与撤回）；稳定工作单元的确定性降解 |

## 3. 十条内容道

结构建好以后，具体能力的扩充都归入十条并行的道。每条道对应总图上一个槽位、一道缝或一类定义；任何新内容按同一规矩进入：写定义或槽位实现 → 过缝层的契约测试 → 真实场景计分 → 限定采用 → 可撤回。道上「已规划」的项目是总图写明的，都要建；「未知落点」是给没想到的东西留的位置。

| 道 | 总图位置 | 已规划的项目（按先后） | 未知落点 |
| --- | --- | --- | --- |
| 01 部门与核验 | 第一节产品、工程、质检、运维、下一个部门、独立的证据 | 三部门闭环 → 核验成为角色的性质，任何形态都能放 → 只写声明加运维 | 任何新职能的部门，只写声明；新的核验方式 |
| 02 角色与外包 | 第二节「定义」的角色材料；第三节「子组织」；第四节「执行」的缝 | 单循环的部门角色 → 外包角色（ACP），没有下游核验时记开环完成 → 子事项承接部门内多角色与分形 | 新的角色种类、新的外部代理协议；核验角色的结论不外包 |
| 03 路由与形态 | 第一节「轮转方式」；第四节「路由」的缝 | 按成果 → 直做（单 agent 与普通多 agent，开环完成） → 任务池与工作单元的参数化 | 第四种轮转方式、自适应的拆分 |
| 04 装配与语义 | 第四节「装配」的缝 | 减法视图与压缩（保留失败的尝试） → 五层轨迹与七类图谱 → 按依赖与焦点取、提示缓存复用 | 新的减法、跨项目经验的检索与失效重验 |
| 05 动作与工具 | 第一节「模型与工具」；第四节「动作」的缝 | 本机改文件与跑命令（带差异与回执） → 网络取回与 MCP → 浏览器与截图 → 远程执行代理 | 桌面操作（computer use）、技能、降解的脚本 |
| 06 模型与判定点 | 第四节「模型」的缝；第三节的判定点 | 多协议无状态调用与凭据隔离 → 能力表与按部门选模型 → 声明的判定点与校准的决策模型 | 新协议、本地小模型、自适应档位 |
| 07 观察者 | 第一节「观察者」；第四节「观察者」的缝 | 离线的经验候选 → 只读订阅与写入口提案 → 教训发现、振荡检测、元观察、降解信号 | 任何只读事实、只出证据与提案的模块；观察者不做部门 |
| 08 评价与验收 | 第一节「评价」；第四节「评价」的缝；第五节验收表 | 内核重放与契约测试 → 固定回归场景与单 agent 对照（OpenCode） → 操作代理照说明书判分 → 留出场景与发布检查 | 新评测题、变异测试与圈复杂度守卫、新领域的判分器 |
| 09 画面与空间 | 第一节「画面」方框；第四节「画面」的缝；[画面总图](architecture-view.html) | 按第 4 节画面自己的阶段：搬出 → 楼跟着定义伸缩 → 机房 → 城 → 规则物件 → 子事项的小屋 → 铺传送带 | 无级缩放的导航、三维（出现需要第三轴的量时）；接别的宿主，只换翻译器 |
| 10 部署与环境 | 第六节「部署是定义」；第四节「定义」的缝 | 单机单进程 → 常驻服务与进程外看门狗 → 控制主机加远程机器与开发板 → 多项目隔离并行 | 按项目拆多个控制核心实例；一个 Yudao 运维另一个 |

**未知的去处**：内容的未知落在道上，按上面的规矩进入；结构的未知（新方框、新缝、内核改动）只走一条路：先交总架构师改总图，第二环向后兼容，第一环经你批准才动工。

## 4. 画面自己的阶段：楼、机房、城

画面不是装饰，是一份事实的投影与高带宽的指挥语言（总图第一节「画面 = P_view(事实)」，展开见[画面总图](architecture-view.html)）。所有视觉元素都绑定事件回链，关掉表演以后看到的全是事实断言。楼的形状从事项冻结的定义推出：一个角色直做是一间屋，三部门是一层楼，子事项是屋里的一间小屋；没有的东西不画。空间的映射（楼、机房、城与七种元件）的依据是调研[游戏世界与代码世界的映射](research/game-world-as-projection.md)与需求记录 [D41 三个空间](requirements/game-world-three-spaces.md)。

画面是系统外面的一个使用方，有自己的里程碑，按下表一步一步走，不跟第 2 节的阶段绑在一起；只有步 0「搬出」放在阶段二里做，因为它改的主要是基础部分的页面与测试。每一步的前提只有一条：系统已经有了这一步要画的记录。每一步都先画事实层（屋子、灯、章、刻度，状态直接换上去），表演（走位、气泡、排队）后补；验收看画面合同与诚实性测试，不对照原型的像素。系统加了画面不认识的部门或事件，画面简单画或不画，列进缺口清单，到下一步再补。

| 步 | 空间 | 建成的画面 | 要等系统先有的记录 | 你能做的 |
| --- | --- | --- | --- | --- |
| 0 搬出 | 楼与机房 | 现有的楼、楼层、部门房间与回放成为单独的应用，经接口接上 Yudao，以单独的页面打开；认不出的事件简单画或不画，列进缺口清单；只在画面上有的事实先补到页面 | 无 | 和现在一样看与回放；点物件到页面看原始事件 |
| 1 跟着定义伸缩 | 楼 | 房间与连接从冻结的定义推出，一间屋到三部门，认不出的部门画成通用的屋；开环完成与放行用不同的章；检验覆盖的视图；上下文容量刻度 | 冻结的定义与形态、开环完成的记录、放行报告与来源回链、上下文清单 | 一眼看出事项有没有经过独立核验；从任一物件点开原始事件、上下文摘要或真实的差异 |
| 2 机房 | 机房 | 已交付的软件是运行中的设备（版本牌、健康灯、备份柜）；故障冒烟并向楼投递修复包裹 | 运维观察记录、故障记录、部署与回滚事件 | 看生产环境的健康；理解修复为什么插队；批准回滚与恢复备份 |
| 3 城 | 城 | 页面、接口、数据表是建筑，模块是街区，依赖是道路，要求是蓝图，验收条件是检查站，证据让蓝图变建筑，试用会话是访客 | 语义图谱、检查回执、浏览器试用记录与截图 | 点一栋建筑直接说话；看哪片街区缺检查站或长期停在蓝图 |
| 4 规则物件 | 三空间 | 规则成为物件与物理：可改的规则（模型接线、机器门牌、常设授权牌）是可操作的物件，不可改的（写入口的盖章机、部门的隔离墙）是推不动的边界 | 带版本的定义、项目设置、模型目录流、机器流 | 在空间里操作物件下发配置；直观看到安全边界 |
| 5 子事项 | 楼（房间内） | 子事项是屋里的小屋，门框上是余量与层数，远看是一个在转的小盒子、推近进去；屋里的白板、任务卡与草稿堆 | 子事项的事件流、语义系统的五层轨迹 | 看子组织与外包角色的瓶颈与重试消耗 |
| 6 铺传送带 | 楼与定义 | 编辑房间与传送带的连接，生成组织定义的候选交独立评价 | 组织定义候选、第二层自举的通道 | 用空间布局演化组织拓扑 |

## 5. 五条判据与总图的阶段对照

每个阶段结束时按这张表和第 2 节的「结束时总图」核对 main；表里是预期，核对不过就不改缝的已定、未定。核对的做法与记录的位置见[验收证据规则](agents/acceptance-evidence.md)第 6 节。进度看 GitHub 的里程碑与工单。缝的已定、未定只由总架构师改。

| 维度 | 阶段一结束 | 阶段二结束 | 阶段三结束 | 阶段四结束 | 阶段五结束 |
| --- | --- | --- | --- | --- | --- |
| 第一节已建的方框 | 一份事实、你、薄驱动、三道槽位 | 加产品、工程、质检、独立的证据、页面、裁决与边界、定义、评价、模型与工具（本机）；轮转方式有直做与按成果 | 加看门狗、运维 | 加观察者、轮转方式（任务池）、模型与工具（远程与外包）；部门内部可以是子组织 | 全部 |
| 第四节十三道缝 | 写入口、路由、装配、执行、模型、投影、接口七道立住 | 「定义」「评价」「动作」立住，动作含网络与浏览器；路由的缝有直做与按成果两种实现 | 「看门狗」由未定变已定，并立住 | 「观察者」立住；写入口、动作、模型、接口过网络验收 | 全部稳定，支持定义的限定采用 |
