# 试用任务集

试用跑的任务。这里是带版本的数据：方法在 [试用 skill](../../.claude/skills/trial/SKILL.md)，任务在这里。Yudao 的能力变了就改这个文件，不改 skill。

当前版本 `trial-tasks@3`。改了任何一个任务的输入、步骤、判据或读法，版本号加一；新旧版本的读数不直接比较，以前版本的读数不再用于比较。任务集属于评价标准，只由用户修改。

两个任务都跑，先 F1 后 R1。每个任务都先走新手段、再走专家段（skill 第 4、5 节）。一次一轮。F1 运行中不做任何打扰；配错凭据、指导、停服务与改主意都集中在 R1。

## F1 固定任务：评测场景 3

**材料**：`evals/scenarios/scenario-3`，材料版本 `scenario-3@2`（以 `materials/manifest.json` 的 `material_version` 为准，写进读数）。

**准备**（试用者在新手段开始前做，新手段不读这些文件）：

- 起始文件夹：在仓库外新建一个文件夹，只放 `evals/scenarios/scenario-3/files/subway_data.json`，新建项目时填进页面的「起始文件夹」；
- 输入文本：`evals/runner/yudao.py` 的 `requirement_text()` 生成的文本，去掉请工程自己写出数据文件的那一段，与 2026-10-20 的评测读数写法相同。

**新手段**：新建项目（名称 `subway`，目标抄输入的第一句），三个部门绑试用者这一次给的同一个模型，建事项时粘贴输入，等到放行、停止或 120 分钟。到时间就在页面上取消。时限与评测相同（[评测场景](../design/evaluation-scenarios.md)第 3 节）。

**判据**：交付对错只看评分器（skill 第 6 节）：完成度、正确性、做错与没做的检查。另记过程检查点（`yudao_metrics.collect` 的 `checkpoints`），其中第 4 项「质检没有误放行」用评分器里失败的检查算。

**对照**：同模型的 OpenCode 一侧读数，条件相同时复用 `docs/evaluation/` 下已有的。

**可比性**：专家段记下部门所用的模型、上下文窗口与输出上限的取值。三样都与评测相同时，F1 的评分可以与同一提交在 `docs/evaluation/` 的场景 3 读数并排列出；有一样不同，F1 的读数只在试用之间比较。

## R1 模拟用户任务：记账小工具

这个任务由架构师编写，模拟一个普通用户：配错了凭据，第一句话有歧义，中途给部门发指导，离开一会儿再回来，回来以后改了主意。内容和 Yudao 自己无关，不做成自举。

R1 也是用户亲自试用的第一个场景：用户照下面的「步骤」原样操作一遍，之后随意（`/trial-intake` 的导游卡指到这里）。

**准备**：空项目，没有起始文件。下面的两句话与两段指导原样提交，不改写、不加提示。开始前在「模型管理」里把这次要用的 Key 改错一位，不点测试。

**步骤**：

1. **配错凭据**。建事项，提交第一句：

   > 帮我做个记账的小工具，记一下每天花了多少钱，能分类看

   页面出现决定卡片以后，先只凭卡片上的话判断出了什么事、该怎么继续，再到「模型管理」把 Key 改正，在卡片上选「继续执行」。

2. **两段指导**。页面上看到工程部门开始工作，给工程发送：

   > 不要装第三方的包，用自带的就行

   接着给产品发送（产品正在工作时，等它停下再发）：

   > 数据存在哪里？一句话告诉我

3. **离开再回来**。页面上看到产品的回答，或者第二段发出 5 分钟以后，停掉服务（结束进程）。用同一个数据目录重新启动，先只看页面，把看到的状态按新手段格式记一步，再继续。

4. **改主意**。重启以后，作为追加输入提交第二句：

   > 分类不要了，太麻烦。按月看总共花了多少就行，再加个导出 Excel

**上限**：55 分钟，到时间在页面上取消。

**有意留下的难处**（专家段对照用）：

- 第一句有四处歧义：命令行还是网页；分哪些类；「分类看」是按类筛选还是按类汇总；数据存在哪里。
- 第 1 步是演练：试用者知道 Key 是自己改错的，判断的是假如不知道，看页面能不能明白。
- 第二句改了主意，同时带进一处新的歧义：Excel 是 xlsx 还是 csv 也行。导出 Excel 一般要装第三方的包，和第 2 步给工程的指导冲突。

**出岔子时**：

- 决定卡片没有出现，或者改正 Key 以后事项接不上：记一条问题，改正 Key 以后新建事项，从第一句重新开始，上限照算。
- 重启以后恢复不了：记一条问题，第二句不再提交，写明原因。

**读什么**：没有隐藏检查，不打交付分，试用 agent 也不判断交付对错。专家段从导出与页面读八件过程事实：

1. 决定请求：卡片说了什么，从出现到回答用了多久；回答以后事项从哪里接着做，已完成的工作与已用的量是否保留。
2. 四处歧义，产品是去问了，还是按常见做法定了并写进 PRD；用户在页面上看不看得到这些选择。
3. 给工程的指导：工程下一步有没有照做（指导的事件、之后的动作、交付里的依赖）。
4. 给产品的指导：回答有没有回到页面上；这期间工程与质检是否照常工作。
5. 重启以后页面状态讲不讲得通；事项接着做、从头来，还是卡住（`run.recovery`）；重启前后的已用时间、用量与剩余量是否连续。
6. 追加的输入有没有进同一个事项（`work_item.inputs`）。
7. PRD 有没有新版本，新版本里分类去掉了没有、按月汇总加上了没有。
8. Excel 这处新歧义怎么处理的，和「不要装第三方的包」这段指导怎么调和。

**超预算时**：只做到「离开再回来」，不提交第二句（skill 第 1 节）。

## 读数

两个任务都记：结束状态、循环次数、返工次数、询问次数、模型请求数、用量、费用、耗时、空响应（`yudao_metrics.collect`），以及新手段的步数与卡点数。F1 另记评分结果、对照与三样取值。R1 记八件过程事实。
