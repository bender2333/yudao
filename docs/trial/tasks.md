# 试用任务集

试用跑的任务。这里是带版本的数据：方法在 [试用 skill](../../.claude/skills/trial/SKILL.md)，任务在这里。Yudao 的能力变了就改这个文件，不改 skill。

当前版本 `trial-tasks@2`。改了任何一个任务的输入、判据或读法，版本号加一；新旧版本的读数不直接比较。`trial-tasks@1`（回显工具等五个轻量任务）的读数不再用于比较。

两个任务都跑，先 F1 后 R1。每个任务都先走新手段、再走专家段（skill 第 4、5 节）。一次一轮。

## F1 固定任务：评测场景 3

**材料**：`evals/scenarios/scenario-3`，材料版本 `scenario-3@2`（以 `materials/manifest.json` 的 `material_version` 为准，写进读数）。

**准备**（试用者在新手段开始前做，新手段不读这些文件）：

- 起始文件夹：在仓库外新建一个文件夹，只放 `evals/scenarios/scenario-3/files/subway_data.json`，新建项目时填进页面的「起始文件夹」；
- 输入文本：`evals/runner/yudao.py` 的 `requirement_text()` 生成的文本，去掉请工程自己写出数据文件的那一段，与 2026-10-20 的评测读数写法相同。

**新手段**：新建项目（名称 `subway`，目标抄输入的第一句），三个部门绑试用者这一次给的同一个模型，建事项时粘贴输入，等到放行、停止或 90 分钟。到时间就在页面上取消。

**判据**：交付对错只看评分器（skill 第 6 节）：完成度、正确性、做错与没做的检查。另记过程检查点（`yudao_metrics.collect` 的 `checkpoints`），其中第 4 项「质检没有误放行」用评分器里失败的检查算。

**对照**：同模型的 OpenCode 一侧读数，条件相同时复用 `docs/evaluation/` 下已有的。

## R1 模拟用户任务：记账小工具

这个任务是编写的，不是用户原话。它模拟一个普通用户：第一句话有歧义，中途离开，回来以后改了主意。内容和 Yudao 自己无关，不做成自举。

**准备**：空项目，没有起始文件。下面两句原样提交，不改写、不加提示。

**第一句**（建事项时提交）：

> 帮我做个记账的小工具，记一下每天花了多少钱，能分类看

有四处歧义：命令行还是网页；分哪些类；「分类看」是按类筛选还是按类汇总；数据存在哪里。

**离开再回来**：页面上看到工程部门开始工作，停掉服务（结束进程）。用同一个数据目录重新启动，先只看页面，把看到的状态按新手段格式记一步，再继续。

**第二句**（重启以后作为追加输入提交）：

> 分类不要了，太麻烦。按月看总共花了多少就行，再加个导出 Excel

改了主意，同时带进一处新的歧义：Excel 是 xlsx 还是 csv 也行。

**上限**：45 分钟，到时间在页面上取消。

**读什么**：没有隐藏检查，不打交付分，试用 agent 也不判断交付对错。专家段从导出与页面读五件过程事实：

1. 四处歧义，产品是去问了，还是按常见做法定了并写进 PRD；用户在页面上看不看得到这些选择。
2. 重启以后页面状态讲不讲得通；事项接着做、从头来，还是卡住（`run.recovery`）。
3. 追加的输入有没有进同一个事项（`work_item.inputs`）。
4. PRD 有没有新版本，新版本里分类去掉了没有、按月汇总加上了没有。
5. Excel 这处新歧义有没有被处理，怎么处理的。

重启以后恢复不了，本身就是一条问题；第二句不再提交，写明原因。

**超预算时**：只做到「离开再回来」，不提交第二句（skill 第 1 节）。

## 读数

两个任务都记：结束状态、循环次数、返工次数、询问次数、模型请求数、用量、费用、耗时、空响应（`yudao_metrics.collect`），以及新手段的步数与卡点数。F1 另记评分结果与对照。R1 记五件过程事实。
