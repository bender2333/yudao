# 试用任务集

试用跑的任务集。这里是带版本的数据：方法在 [试用 skill](../../.claude/skills/trial/SKILL.md)，任务在这里。Yudao 的能力变了就改这个文件，不改 skill。

默认跑完下面五个任务，每个任务几分钟。试用者可以按参数增补自己的任务，增补的任务单独一节记，不与固定任务混在一起算读数。

每个任务写四样：给 Yudao 的输入（原样提交，不改写、不加提示）、准备、判据（别人能照着核对）、检查动作。要记的读数按 [试用 skill](../../.claude/skills/trial/SKILL.md) 第 6 节，五个任务都记。

## 任务集版本

当前版本 `trial-tasks@1`。

改了任何一个任务的输入、判据或检查动作，版本号加一。**新旧版本的结果不直接比较**：任务变了，指标就没有可比性。版本号写在帖子标题的提交号后面，并写进读数表。

## T1 最小编码交付

**输入**：`做一个命令行回显工具：读取标准输入，原样输出；空输入输出空`

**准备**：项目名与长期目标照抄这句话。登记一条检查命令：登记名 `echo`，固定参数填完整的命令行（按空格拆分，没有引号语法），允许的额外参数、时限与输出上限用默认值。检查命令在事项创建时冻结，登记以后不能改。

**判据**：

1. 质检放行——事项的 phase 是 `DONE` 且 stop_reason 是 `released`。
2. 交付物里有实现文件，取回后能在本地跑起来。
3. 登记的检查命令通过。
4. 输入接到命令上，输出与输入一致；空输入输出空。

**检查动作**：建项目 → 建事项 → 用 `project.flow` 看流转 → 用 `run.export` 取读数 → 用 `delivery.file` 取回交付物 → 在本地跑一次检查命令和一次手工输入。

**记**：循环次数、返工次数、询问次数、模型请求数、用量、耗时、是否放行。

**常见偏差**：质检放行了但检查回执对应的不是最后那份交付；工程自己写了测试数据而不是用给的；质检没有实际运行检查就放行。

## T2 追加需求与定向指导

**输入**：先提交 T1 的原始意图；事项运行中追加 `同时支持 UTF-8 编码`；给工程部一条定向指导 `只用标准库，不要第三方依赖`。

**判据**：

1. 追加输入没有新建事项，在同一事项里生效。
2. 最终交付同时满足原始意图、追加的要求与部门的指导。
3. 部门指导到达了工程部，没有绕到产品部。

**检查动作**：事项运行中调 `work_item.append_input` 与 `guidance.send`（department 为 engineering）；用 `work_item.inputs` 看输入到了没有；用 `department.workspace` 看指导到了没有；用 `run.asks` 看它有没有变成部门之间的询问。

**记**：同上；另记追加与指导之后轮数与返工增加了多少。

**常见偏差**：追加输入走成了新事项；指导落到了产品部；指导没有生效但流程照旧放行。

## T3 故意出错，看报错能不能看懂

**输入**：`把一个不存在的文件 data/input.csv 读出来并打印它的内容`

**判据**：

1. 系统在合理时间内给出能指路的说明：做了什么、为什么不行、人接下来该做什么。
2. 没有空转、没有崩溃、没有把内部错误码当成人话。
3. 没有任何东西被当成合格交付放行。

**检查动作**：建事项 → 观察流转 → 用 `project.attempts` 找失败的那次尝试 → 用 `run.attempt` 看它的输入、输出与错误 → 看界面上的提示长什么样。

**记**：失败原因能不能定位到具体一步；错误信息里有没有内部术语泄漏（英文枚举、内部 id、栈）。

**常见偏差**：做不成的需求写成了缺陷记录却没有告诉人；界面只显示「失败」两个字；事情在原地空转了几轮。

## T4 重放一致性

**输入**：没有新输入，在 T1 结束以后做。

**判据**：

1. `replay.check` 返回与记录一致。
2. 命令行 `yudao replay <run_id>` 能重建投影，重建出来的投影与当时一致。

**检查动作**：`GET /api/queries/replay.check?run_id=<run id>`；命令行 `yudao replay <run_id>`（只读）；把重建的投影与 T1 的读数逐项比。

**记**：重放耗时；重放能不能拿到交付快照。

**常见偏差**：重放与记录不一致；重放拿不到交付；重放要写入才能完成。

## T5 导出与数据

**输入**：没有新输入，在 T1 结束以后做。

**判据**：

1. `run.export` 能拿到完整的事件与投影。
2. `delivery.file` 能取回交付物，取回的内容与封存的一致。
3. 导出里没有凭据、Key、请求头，也没有试用者机器的绝对路径。

**检查动作**：把导出写到文件，搜 `key`、`token`、`password`、`Authorization` 与盘符开头与 `/home/` 开头的路径；记导出的体积。

**记**：导出体积；能不能离线核对。

**常见偏差**：导出里出现凭据或绝对路径；取回的交付物是封存前的内容。
