# agent 试用技能修订方案

状态：已实施，相关本地验证与三项原生 subagent 复核完成；最近一次改动：2026-10-29 补充实际验证与适用范围；依据：[ADR-0039](../adr/0039-agent-trial-observation-reproduction-and-judgment.md)、用户逐轮确认及最终回复「可以」；路线位置：各阶段的薄片试用与路线图第 5 节「能度量」「看得见」。

## 目标与已经确认的取舍

agent 试用优先发现真实用户会遇到的问题并提供可信证据，交付评分和性能比较单独记录。一次有现场证据的问题可以进入正式问题表，独立复现情况单列；符合设计的体验障碍可以作为候选交给架构师裁决。

每轮按规定流程运行 F1 和 R1，额外探索放在单独事项或实例中。部门模型按照运行配置分工，独立复现逐部门保持相同的被测配置，观察代理可以换模型。

独立复现优先处理挡住目标及状态、恢复、并发异常；静态文字和布局可以先由另一个观察者复核。复现任务书给操作、触发条件和待观察现象，根因分析留在作者一侧；超时仍未触发就记录「未触发」。

问题是否成立、是否修复、修复后是否验证通过分别记录。缺陷命中率只按明确裁决计算；体验候选另记采纳情况。工单关闭状态不自动代替裁决。

评分或复现未完成，可以发布明确标注缺项及原因的部分完成报告。报告发出前核对实际运行版本、数字来源、证据引用和脱敏。整轮上限约 4 小时 45 分，F1 最多 120 分钟，R1 最多 55 分钟；省下的时间优先补测承诺能力和复现高影响问题，再做新探索。

本轮归档使用结构化记录保存以下内容，原始事件、截图和文字材料保留原样。

新一轮读取历史发现时，引用实际的维护者裁决并在本轮生成回查结果。裁决、修复进度或回归结果发生变化时，保留来源与所对应版本；原始归档中的观察证据不被覆盖。

## 检查结果的解释

- 现场问题已经发生，独立重跑还没有完成：保留问题，标注「已观察，尚未独立复现」。
- 达到同样触发条件而未出现、没有达到触发条件、被测条件不一致、仅复核原证据：分别记录，不能合并成「没复现」或据此判断误报。
- 某项评分或复现因条件不足未完成：报告可以写「部分完成」，缺项给出原因；事实表格不填估算的数值。
- 实际运行版本与声明不一致、数字与来源矛盾、引用的证据定位不到或含有凭据：报告检查给出位置，处理以后再发布。
- 问题是否成立、体验改进是否采纳，由架构师依据事实判断；机器检查只核对能够机械确定的身份、读数、引用、状态与脱敏条件。

## 验证与完成条件

验证采用已有实际记录中的反例，保留原始材料。辅助脚本可以离线核对的部分使用本地归档，不需要重跑整轮真实模型任务。

1. **身份核对**：在独立安装的 wheel 实例与真实 editable 安装上分别检查，前者能给出实际包身份，后者不能被当成同一 wheel；重启仍对应同一数据目录和明确的进程。
2. **配置核对**：用 `f61ac6a6` 原试用与复现实例中质检模型不同的记录，验证它们被标为条件不同；各部门的窗口不能被错误地混成一个数。
3. **时间与用量**：用现有五份导出重算，核对实际事件时间、尝试数、部门用量与费用未知状态；`e28ea596` 的交付收下时间与取消时间分别呈现。
4. **裁决与比例**：用 #845 的设计结论、#1160 明确排除的误报、#1212 与 #1231 的回查差异，核对关闭状态无法自动生成确认，且分子、分母均可从裁决来源重算。
5. **报告完整性**：已有 F1 交付而缺评分、原始第一眼记录已有内容、复现只重读旧导出等情况，都必须在输出中如实出现；缺项可交付，矛盾不能伪装成确定结果。
6. **凭据交接**：从环境读入凭据时，任务书、命令参数、日志与输出只显示引用或状态；检查失败只报告文件与位置，不回显值。
7. **手册一致性**：Q1–Q11 在流程、任务书、结果字段与报告中均有相应位置；任务集版本引用一致，新手与专家可读范围一致，预算及优先次序一致。

实现完成时列出实际运行的相关检查、结果与剩余限制。离线验证、实例身份检查和下一轮真实试用分别报告，技能修订完成的结论不代替产品验收。
