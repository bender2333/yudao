# 阶段一试用指南：网页上跑完一个事项（0.2.0）

试用版本 0.2.0，main 的发布提交 `_______`（发布时填）。试用工单 [#994](https://github.com/bender2333/yudao/issues/994)。这次要你回答的是阶段一薄片的那一个问题：**一个小的新项目，三个部门能不能在网页上用真实模型把它交付出来，三道槽位的契约与画面合同立住了没有。**

这一步只看你亲手用得怎么样。上一轮的机器试用（[#1153](https://github.com/bender2333/yudao/discussions/1153)）找出的十二个问题已经修完，九张工单合并进 main；这次不再让你重复跑那些已修的东西。

## 1. 试用前的准备

- 一台 Windows x64 电脑，已装 [uv](https://docs.astral.sh/uv/)。
- 一个能用的模型服务：请求地址、模型名、API Key。产品、工程、质检三个部门各绑一个模型，同一个模型可以三个部门共用；质检那个最好支持图像输入（不支持不阻止使用，页面会提醒）。
- 一个空的数据目录（默认 `%LOCALAPPDATA%\Yudao`）。开发时的数据不会带过去。
- 一次约半小时到一个小时的整块时间：一个事项要真实模型跑几轮，中途打断也能接着跑。

## 2. 安装与启动

1. 取得安装包：`gh release download v0.2.0 --repo bender2333/yudao --pattern "*.whl" --dir <下载目录>`。
2. 装进独立环境（不动你已经装的那一份）：

   ```powershell
   uv venv $env:TEMP\yudao-trial
   uv pip install --python $env:TEMP\yudao-trial\Scripts\python.exe <下载目录>\yudao_harness-0.2.0-py3-none-any.whl
   ```

3. 启动（在当前目录**不在**仓库里的窗口里跑）：`$env:TEMP\yudao-trial\Scripts\python.exe -m harness api --data-dir <数据目录> --port 8766`。服务就绪以后会自动打开页面；没有自动打开就自己打开 `http://127.0.0.1:8766/`。
4. 核对：页面能打开，`http://127.0.0.1:8766/api/capabilities` 返回 200。

## 3. 配置模型

左侧「系统」→「模型管理」，顺序是：**连接服务 → 选择模型 → 部门使用**。地址与 API Key 在「连接服务」这一步一次填完——点「获取模型」就把连接、Key 与候选一起存下来；勾选候选以后系统自动补参数并做模型测试，通过的模型变成「已启用」；首个启用的模型自动成为三个部门的部门默认，一般不用手动改。四个实测过的坑，照做能省时间：

- **凭据引用不用你手填**：系统按服务地址自动生成（形如 `HOST_9ROUTER_HUIJU_ASIA_KEY`），只用大写字母、数字与下划线。**不要自己改成带连字符的名字**——那种名字会把 `.env` 写坏、服务回 500（这条已经修好会给出提示，但别去试）。
- **「获取模型」按钮旁边会写缺哪一项**：点不动的时候读那一句就行。容量（窗口、输出上限）由上游模型列表自动补全，页面上会标明来源是「上游模型列表」还是能力表。
- **模型测试通过以后模型才是「已启用」**：没通过的不能绑给部门，页面会拒。**失败原因写在那个模型旁边**，并有「重新验证」按钮。
- **质检绑文本模型时页面会出现「质检的模型建议具备图像输入」的提醒**，不阻止使用。

**页面停在忙碌态、候选区全禁用又没写原因时**（2026-10-31 试用实测，已建工单 #1355）：刷新一下页面再继续，先别怀疑自己配错了。

三个部门都要绑，否则新事项会被拒绝。

## 4. 试用要做的六件事

按顺序走，每件都记一下你看到的现象（做得到、做不到、卡在哪一步）：

1. **新建一个事项**：填项目名称与目标，说一句想法，作为新事项开始。看到工程写代码的同时质检按 PRD 起草测试；事项只在质检放行时完成。
2. **让工程去问产品**：工程问一句，产品在回答里改 PRD，回答回到工程，质检收到 PRD 新版本的通知；界面上能看到进行中与已结束的询问。
3. **给部门发指导**：给正在工作的部门发一段，下一步按指导调整；给不在工作的部门发一段，看到它的回答，其他部门照常跑。
4. **不登记任何命令**：工程用 `bash` 装依赖、构建、在后台起服务并访问它；质检在交付快照的全新副本上跑自己的测试，凭检查回执放行。
5. **中途关掉再启动**：询问或命令进行到一半时关掉服务再启动，会话接着工作；取消事项时全部部门与后台命令一起停下。
6. **看画面**：楼层、房间、首页的楼都由画面合同驱动，与原型 v13 一致；几个房间同时在工作时询问在房间之间传；画面与回放一致。

第 1 至 5 件是网页上的操作，第 6 件用眼睛看。看不清哪个牌子或哪盏灯是什么时，按你看到的说，别猜。

**机器试用（2026-10-31）没有走到的**：第 2 件（工程询问产品 → 产品修订 PRD → 回答回到工程）与第 5 件的取消那一半，两段都没走到。所以这两处你要是遇到，是**第一次有人走到**，请把看到的原样记下来。

## 5. 卡住的时候

- 页面不动、报错、或者一直转：先看启动服务的那个窗口，再看数据目录下的 `logs\`。
- **页面上写「模型服务失败」但不知道是哪个模型**：到「观测」页签看失败的那几行，那里有请求模型与服务返回的状态码（2026-10-31 试用实测：上游确实会整段时间挂掉，页面当时只写一句「模型服务失败」，得自己翻到观测页签才看得出是哪个模型）。
- **事项停了以后页面上没有「重试这张事项」的入口**：现在只能「作为新事项重新开始」，同一件事重试会在项目里堆出好几张一样的卡片（2026-10-31 试用实测，已建工单 #1373）。你要是也这么撞上了，把你当时看到的卡片原样记下来。
- 想让我查：把看到的那句话原样记下来，附上大概的时间点。
- 服务起不来（端口被占、数据目录被占用）：换一个 `--port` 或另一个数据目录再试一次。
