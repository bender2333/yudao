# 「职能之间：转实」试用指南：网页上跑完一个事项（0.2.2）

试用版本 0.2.2（`v0.2.2`）。试用工单 [#994](https://github.com/bender2333/yudao/issues/994)、[#1706](https://github.com/bender2333/yudao/issues/1706)、[#1717](https://github.com/bender2333/yudao/issues/1717)。这次要你回答的是「职能之间：转实」这个阶段的问题：**一个小的新项目，循环能不能在网页上用真实模型自己把它从意图转到放行，中间的向用户追问、职能相互询问、决定请求、打回与返工走得通不通，五标签页控制台与按位置读出的事实一致不一致。**

这一步只看你亲手用得怎么样。前序机器试用（[#1153](https://github.com/bender2333/yudao/discussions/1153)、[#1780](https://github.com/bender2333/yudao/discussions/1780)）与 `v0.2.1` 用户试用（[#1796](https://github.com/bender2333/yudao/discussions/1796)）指出的阻断与控制台需求都已经修完合并进 main；这次按新的五标签页控制台与 `0.2.2` 交互流程试用。

## 1. 试用前的准备

- 一台 Windows x64 电脑，已装 [uv](https://docs.astral.sh/uv/)。
- 一个能用的模型服务：请求地址、模型名、API Key。产品、工程、质检三个职能各绑一个模型，同一个模型可以三个职能共用；质检那个最好支持图像输入（不支持不阻止使用，页面会提醒）。
- 一个空的数据目录（默认 `%LOCALAPPDATA%\Yudao`）。开发时的数据不会带过去。
- 一次约半小时到一个小时的整块时间：一个事项要真实模型跑几轮，中途打断也能接着跑。

## 2. 安装与启动

1. 取得安装包：`gh release download v0.2.2 --repo bender2333/yudao --pattern "*.whl" --dir <下载目录>`。
2. 装进独立环境（不动你已经装的那一份）：

   ```powershell
   uv venv $env:TEMP\yudao-trial
   uv pip install --python $env:TEMP\yudao-trial\Scripts\python.exe <下载目录>\yudao_harness-0.2.2-py3-none-any.whl
   ```

3. 启动（在当前目录**不在**仓库里的窗口里跑）：`$env:TEMP\yudao-trial\Scripts\python.exe -m harness api --data-dir <数据目录> --port 8766`。服务就绪以后会自动打开页面；没有自动打开就自己打开 `http://127.0.0.1:8766/`。
4. 核对：页面能打开，`http://127.0.0.1:8766/api/capabilities` 返回 200。

## 3. 配置模型

左侧「系统」→「模型管理」，顺序是：**连接服务 → 选择模型 → 职能使用**。地址与 API Key 在「连接服务」这一步一次填完——点「获取模型」就把连接、Key 与候选一起存下来；勾选候选以后系统自动补参数并做单轮带测试工具的模型测试，通过的模型变成「已启用」；首个启用的模型自动成为各职能的职能默认，一般不用手动改。实测与新版要注意以下几点：

- **凭据引用不用你手填**：系统按服务地址自动生成（形如 `HOST_9ROUTER_HUIJU_ASIA_KEY`），只用大写字母、数字与下划线。**不要自己改成带连字符的名字**——那种名字会把 `.env` 写坏并触发校验拒绝。
- **「获取模型」与代理模型输入方式预填**：不可用时按钮旁会写明缺哪一项。容量（窗口、输出上限）与调用协议只在识别出的服务商内查找；对于带提供方前缀或推理后缀的模型（如网关或中转服务列表里的模型），若能力表全部匹配条目对是否支持图像结论一致，输入方式会自动预填或回填，但容量严禁跨服务商借用。
- **候选行精简「测试」按钮**：还未选用的候选行带有固定文案为「测试」的按钮，用来在选用前确认该模型文本连通可达；它只发一次不带工具的最小文本请求，行内仅显示「等待测试 / 测试中 / 测试通过 / 测试未通过」，不提前写准入也不改默认。
- **模型测试通过以后模型才是「已启用」**：没通过的不能绑给职能，页面会拒。**失败原因写在那个模型旁边**，并有「重新验证」按钮；已启用模型区支持直接勾选切换「图像输入」开关。
- **质检绑纯文本模型时页面会出现「质检的模型建议具备图像输入」的提醒**，不阻止使用。

**页面停在忙碌态、候选区全禁用又没写原因时**：刷新一下页面再继续。

三个职能都要绑，否则新事项会被拒绝。

## 4. 试用要做的六件事

按顺序走，每件都记一下你看到的现象（做得到、做不到、卡在哪一步）：

1. **新建项目与事项**：点左侧边栏「从想法新建」（`#/projects/new`）或「接入已有项目」（`#/projects/onboard`），在右侧全宽页填项目名称并点选形态卡（默认「产品 · 工程 · 质检」，另可试「工程」「产品 · 工程」两种直做形态）建立项目。建好后在对话输入框输入想法开始事项：顶部提供「对话 · 成果库 · 组织 · 事项与用量 · 设置」五个一级标签页；「对话」页上方可切换深色与纸面两种 `troupe` 循环蓝图主题，下方内嵌「现场窗口 · live」实时查看步骤与输出；产品接纳 PRD 后对话主轴呈现可就地展开的完整结构化 PRD 主卡片，箭头面板与「成果库」页同样完整可读；事项只在核验角色放行时完成（无核验角色的直做形态记为「开环完成」）。
2. **前沿追问与职能互审**：存在影响范围或交互的关键不确定性时，角色先探索工作区再通过多题前沿决定卡片（`ask_user`）一次性发出互斥选项与唯一推荐项供你逐题点选或「全部采用推荐」，等待回答期间只暂停发起方当前这一轮，其余职能继续推进；工程与质检也会依据你的原始输入与已回答决定通过 `ask` 询问产品并在回答里修订 PRD，页面箭头面板与「成果库」都能看到每版更新。
3. **给职能发指导**：给正在工作的职能发一段（可直接点循环图节点切收件人），下一步按指导调整；给不在工作的职能发一段，看到它的回答，其他职能照常跑。
4. **不登记任何命令**：工程用 `bash` 装依赖、构建、在后台起服务并访问它；质检在交付快照的全新副本上跑自己的测试，凭检查回执放行。
5. **中途关掉再启动**：询问、待答决定或命令进行到一半时关掉服务再启动，会话幂等接着工作；取消事项时全部职能与后台命令一起停下。
6. **附带看一眼画面**（不计入这次的结论，画面按自己的里程碑验收）：打开服务地址下的 `/view/`（例如 `http://127.0.0.1:8766/view/`），楼层、房间、首页的楼能打开；几个房间同时在工作时询问在房间之间传。

第 1 至 5 件是网页上的操作，第 6 件用眼睛看。看不清哪个牌子或哪盏灯是什么时，按你看到的说，别猜。

## 5. 卡住的时候

- 页面不动、报错、或者一直转：先看启动服务的那个窗口，再看数据目录下的 `logs\`。
- **页面上写「模型服务失败」但不知道是哪个模型**：到项目的「事项与用量」页切到「模型请求与用量」子视图查看失败记录（从「对话」页节点面板点「本职能的模型请求」也可直接带着筛选跳过去），那里有请求模型与服务返回的状态码。
- **事项停了以后页面上没有「重试这张事项」的入口**：只能「作为新事项重新开始」，同一件事重试会在项目里堆出好几张一样的卡片。你要是也这么撞上了，把你当时看到的卡片原样记下来。
- 想让我查：把看到的那句话原样记下来，附上大概的时间点。
- 服务起不来（端口被占、数据目录被占用）：换一个 `--port` 或另一个数据目录再试一次。
