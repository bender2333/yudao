# 架构执行问题记录 (Architecture Execution Issues)

本文档记录智能体在执行计划与工单实现过程中遇到的架构设计问题、规范冲突、未覆盖边界及阻塞事项。

## 记录规则
1. 严禁在代码中私自编写违背架构原则的临时兼容层或绕过逻辑。
2. 发现架构冲突、设计缺漏或规范矛盾时，必须在此如实登记。
3. 登记条目必须包含工单上下文、具体问题描述、受阻范围与处置建议。
4. 认为总图（`docs/architecture.html`）本身有错的，问题描述开头写「总图」与节号，由总架构师处理；设计说明与代码和总图不符的，改设计说明与代码，不在这里登记。

## 记录格式规范
`模型 ID / 时间（到分钟） / 工单编号或任务 / 遇到的架构问题与冲突 / 影响与建议处置方案`

## 2026-10-25「总图 第六节：容器」

claude-opus-5-5（子架构师）/ 2026-10-25 13:44 / 设计说明与 ADR 按总图对齐 / 总图 第六节「拆开部署」把部门成员画在「容器 B」「容器 C」，图例写「一台机器或一个容器」；[ADR-0022](adr/0022-run-directly-without-containers.md) 与[总体架构](design/architecture/overall-architecture.md)第 3 节第 6 条、第 9 节写「Yudao 不使用容器，也不使用 WSL」，依据是 2026-09-30 用户的决定（控制主机是 Windows 11 家庭版，容器要 Docker Desktop 与 WSL2；不信任的代码靠放到另一台登记的机器隔离）。两处怎样对上有两种读法，要用户定：

- 读法一：总图的「容器」只是「放成员的地方」的泛称，指另一台机器、另一个进程或以后可能有的隔离环境，不要求 Yudao 现在建容器实现。ADR-0022 照旧有效：执行环境只有本机进程与远程执行代理两种，成员放到「另一处」就是放到另一台登记的机器。要改的只有总图第六节的字样（例如「容器 B」改成「机器 B」，或在图例里写明容器是以后的选项），由总架构师改。
- 读法二：总图有意把容器作为拆开部署时放成员的一种位置。那样 2026-09-30「不使用容器」的决定在拆开部署这一段被推翻，要定的是：容器在哪台机器上跑（控制主机要装 Docker Desktop 与 WSL2，或只在登记的 Linux 机器上跑容器）、执行环境加第三种实现「容器里的执行代理」（合同不变，ADR-0018 原来就是这样设计的）、什么时候做。ADR-0022 改为只管到拆开部署之前，另写一条 ADR。

影响：现在什么都不挡，全部在一个进程里跑，两种读法都不改现在的代码。建议读法一：总图第六节要说的是「成员可以放在别处、合同不变」，与用不用容器无关；隔离仍由机器边界提供，不为一种以后才用的放法推翻用户的决定。交用户决定，决定以后由总架构师改总图或 ADR。
