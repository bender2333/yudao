## 1. 本阶段结束时是什么

从没有模型配置的控制台出发，用户可以完成既有兼容服务或 Go 订阅的配置，保存后立即创建新事项。正常工作、压缩、重试、测试和命令行全部经独立 Provider 模块调用。已有任务保持冻结配置，观察证据能解释用了哪份连接、模型、协议和凭据来源版本。

支持多厂商与自定义接入：预置服务方案表 + 自定义连接，凭据只接 API Key。OpenCode Go 是第一个落地的服务方案，其 Responses / Chat Completions / Messages 三种协议按模型访问定义选择，至少各一个代表模型独立通过。模型列表负责发现，测试负责准入。全协议平台、OAuth 与预置之外的厂商适配不在本次。

2.7.1 先保持已有 Responses 行为，再逐项切换调用方；这是一个替换工作包的实施过程，不发布两套长期可选实现。每个可运行子结果及时提交/推送，包关闭时旧路径删除。

2.7.3 内部先做服务方案预置表与自定义连接（含模型列表地址覆写），再让 Go 作为第一个预置落地：Responses 打通设置→任务，复用已有 SDK 接 Chat，最后接 Messages；列表刷新与逐模型测试随后补齐。每个协议单独提供可审查结果；只有多厂商要求、三协议要求和综合验收全部通过才关闭 2.7。

研究资料、模拟服务夹具、接口契约和 UI 状态样例可并行准备；涉及公共请求契约与上下文转换的实现需在一个明确版本上整合，避免不同代理各自设计一套消息模型。

## 4. 设计取舍与复杂度

| 取舍 | 理由 |
| --- | --- |
| 进程内独立模块，不部署 Provider 服务 | 现在需要统一调用与维护位置，没有独立服务的部署需求 |
| 服务方案、模型协议、凭据分开 | Go 已真实证明一个套餐跨多个协议，订阅不等于 OAuth |
| 统一管理和调用接口 | Web/CLI/内核不再各做凭据、重载和测试，新增入口不会复制复杂性 |
| 保留内核重试与上下文责任 | SDK 不接管工具或部门流程；D09/D17 行为继续可审计 |
| 原子目录发布，任务固定目标 | 热更新管理配置与在途任务可以同时成立 |
| 额度查询可选，只读 | 官方控制台是可用入口；未公开稳定 API 不应成为正常推理前置 |
| 按当前模型能力逐项启用 | 公开模型列表缺协议/容量，不能把发现当成支持 |
| 新结构直接替换 | 不保留 Provider 级旧协议默认、不做迁移和多入口兼容 |

## 5. 验收基线与证据

开始前固定原 Responses 的回归结果、当前失败清单和接口事实，避免重构后无法判断行为退化。已有本机测试环境问题必须重新定位，不一概豁免。

阶段验收分四类：
1. **模块合同**：不加载 Web/部门内核，覆盖结构合法但未就绪配置、冻结版本、凭据来源、请求取消、协议错误与输出映射。
2. **本地 HTTP/流式捕获**：三协议实际发送格式，工具调用/结果配对、会话/尝试身份、部分流失败、取消、重试计数和新输入；敏感数据脱敏。
3. **真实服务**：每协议至少一个明确模型及真实工具往返；能力参数有来源；一个与既有服务混合绑定的三部门任务完成 QA/release。多厂商验收含两家不同厂商与一个自定义端点，其中至少一个模型来自列表刷新并经模型测试准入。受控错误与真实服务错误分别记录。
4. **产品完整流程**：空启动、页面接入、磁盘/.env 修改、在途冻结、失败修复、回到项目创建任务；1440/390、键盘与错误状态均可验证。

每份报告带应用 SHA、配置修订与脱敏身份、模型/协议/能力来源、场景与检查版本、任务/尝试 ID、实际请求响应、工具回执、用量未知项和停止原因。完整运行附交付、Git、封存与 replay 结果；诊断请求有独立证据，不能伪装成部门任务。

Python 全量、Node UI 及受影响的浏览器验收完成后关闭，历史成功不代替新版本。缺 Go 凭据或服务不可用时保留真实受阻状态，不以模拟完成关闭阶段。
