`docs/architecture.html` 是架构约束的正本，本目录记录上述提交的实现视图。代码现状与总图的关系见建模方法中的对应表；本目录不改变总图的规则与已定状态。

C4 的四个层次分别是软件系统、容器、组件、代码。容器包括应用运行单元与数据存储。浏览器中的网页和 Python 服务属于不同运行环境；服务内的部门、契约和 Python 文件按照职责归入组件。代码层选择对架构保证重要的类型与接口展开。这里使用 Mermaid 表达 C4 的语义，节点标注种类与技术；动态视图和部署视图补充结构图。

图中的 `S*` 是软件系统，`P*` 是人员，`X*` 是外部系统，`C*` 是容器，`B*` 是服务组件，`F*` 是网页组件。标识跨文件保持一致；关系箭头表示调用、读取、写入或发送，具体含义写在箭头标签中。图保留主要关系，完整登记的关系及其证据在 `model.json` 中。

正式 C1–C3 图由 `model.json` 的元素和关系投影得到。代码图与时序图是选定场景的展开。机器可读模型中的 `evidence` 保存源码相对路径、基线文件 SHA-256、定位行和符号；行号用于阅读，路径与符号用于后续定位。`verification` 保存本次核对范围与结果。
