## 本轮明确的设计选择

这些是依据用户授权与简单原则作出的本轮选择，不改写成用户此前逐项确认的原话。

- 首个输入入口继续支持文本。逐次输入分别有原文工件；`intend.md` 依接收顺序直接拼接原始 UTF-8 字节，输入边界记录各段字节范围与来源，时间和状态另存。界面逐条展示，允许无末尾换行的输入精确复原。未支持附件类型明确报错。
- 产品提交经接纳后，主机从同一有效合同生成 `PRD.md`，含已接纳补充决定与变更说明。事件中的合同为权威，Markdown 是可重建表示；研发不能直接改写此文件。
- 研发先提交包含影响范围、有序任务、可验证产出和必要重构的计划，再修改交付代码。主机保存 `PLAN.md` 及版本；普通计划自动接续。职责内计划调整记录原因，产品要求或重要承诺改变先回产品。
- 当前有效合同标识覆盖需求与实际生效的补充决定。计划、请求、交付、检查、摘要适用性和当次执行均引用对应版本；合法新需求记录改变、保留、废止及理由，不重新绑定旧结果。
- 通用协作一次处理一个未结请求，记录发起者、接收者、依据、预期结果与返回工作。首版不嵌套咨询；接收方可以回应、拒绝或说明需要进一步工作。取消、超时和版本失效有明确结果，随后回到适用的原工作。完成通用路径后删除旧专用 Ask/React 路由。
- 可请求补充说明、查看实现、执行公开检查、修正需求或按有效计划修正交付。接收者沿用自己权限；请求的接纳、实际工具结果和回复分别记录。咨询意见不直接变更需求，也不直接形成 QA 放行。
- 运行中新输入先原文落盘并确认接收。已开始工具完成后转产品，模型请求中到达的输入在其返回后、执行工具或接纳提案前处理；未启动工具明确不执行并补齐协议结果。先接纳的新输入阻止旧 release；终态后的新工作明确创建新任务。
- Web 的普通文本用于创建或补充当前任务，首批命令沿用明确的开始、新任务与取消操作；文本停止命令 `/stop`、`/cancel` 对应立即取消。命令接收状态与产品已处理状态分开呈现。
- prompt 编辑默认只作用于当前任务，在目标部门下一次激活生效；请求已发出时保持原版本。隐藏只是折叠。当前不建设全局默认编辑；改变需求的内容仍交产品处理，硬权限和 QA 完成权不受 prompt 修改。
- 专业补全采用项目约定、适用规范及成熟组件；常规缺口由部门处理，影响目标、承诺或重要成本且无法推断的取舍才询问。记录默认依据，不把模型默认冒充用户原文。
- 每次接纳交付前封存主机公开范围内完整文件树，含未声明文件、二进制、隐藏文件与空目录；私有事实另存。链接、范围外路径和采集中变化明确拒绝。封存与检查共用文件树规则，恢复只从持久工件到新目录，不读取旧工作区补缺。
- 工程可在公开工作区内删除和移动，受当前合同与计划约束；不覆盖已有目标，不进入主机私有目录。实际动作及理由可查，相关引用和有效行为由计划、自检和 QA 核验。
