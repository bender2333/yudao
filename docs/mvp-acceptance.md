# 三部门循环 MVP 验收记录

## 验收目标

本阶段面向自治系统研发者，交付可以在本地 Web 启动和观察的三部门循环。产品、工程、质检通过当前有效 spec 交接；工程可以 Ask，产品可以 React；只有独立质检基于当前代码和真实检查回执放行，控制层才结束任务。

Grok Build 负责实现与返修，Codex 负责设计、独立审查和验收。长期记忆、知识图谱、部门内部递归、异步调度与新增部门不属于本阶段。

## 最终放行依据

1. 相关自动化测试通过，包括独立审查给出的反例。
2. 主 provider 完成直达与 Ask → React 场景，核对文件、两个部门的检查回执、spec 引用与事件重放。
3. 浏览器可启动真实任务并观察事件，取消之后不再接受迟到提交，界面恢复可用状态。
4. 预算和循环上限暂停并保留事实；错误和取消明确失败；自然语言完成声明不能绕过质检。
5. 文档如实区分已交付、已验证和后续阶段，运行命令可复现，凭据不进入文档或事件。
