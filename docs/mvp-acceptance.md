# 三部门循环 MVP 验收记录

## 原生循环重构

2026-09-06 根据用户确认，循环推进与上下文控制改由 Yudao 原生内核负责。OMP 仅保留代码级参考价值，旧 RPC 运行适配器、启动隔离覆盖文件和相关测试已删除。Provider 层只做一次模型请求，宿主工具执行、部门交接、每步上下文组装和停止判定由内核负责。

当前原生数据目录为 `.yudao/native-loop`，真实 smoke 使用 `.yudao/native-validation`。旧 OMP 事件库保留为历史证据，不迁移、不提供兼容读取，不作为原生架构验收结果。

新的输入验收口径包括：每步完整 developer 输入、原始任务、本部门完整历史、工具 schema 与工件摘要绑定；历史逐项对应同一任务内本部门已记录的模型输出与宿主工具结果，跨激活延续且不混入其它部门私有历史；模型调用尝试与上下文准备分别记录；工程和质检的成功检查对应宿主执行、当前合同与最终代码快照。调用尝试不等于网络请求已送达，只有实际返回结果才作为已观察到的模型执行证据。

本次原生架构的真实 provider 与浏览器验收仍在执行，结果将在完成后补入本节。下文所有旧运行 ID、测试数量、OMP 指纹及费用均属于旧实现的历史记录，不能代表新架构已经验收通过。

## 验收目标

本阶段面向自治系统研发者，交付可以在本地 Web 启动和观察的三部门循环。产品、工程、质检通过当前有效 spec 交接；工程可以 Ask，产品可以 React；只有独立质检基于当前代码和真实检查回执放行，控制层才结束任务。

主要实现由 Grok Build 完成；质量未达要求或恢复会话网络不可达时，由实现子 agent 收尾。Codex 负责设计、独立审查、验收和分批推送。长期记忆、知识图谱、部门内部递归、异步调度与新增部门不属于本阶段。
