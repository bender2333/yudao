# Web 验收返修

继续上轮 Web 实现，仍由你完成代码与测试。只改原任务授权的 Web 文件和 Web 测试；主代理与另一 Grok 正在修复 runtime/adapter/tool 等模块，禁止越界。`harness/__main__.py` 新增 smoke 子命令来自后端同伴，必须保留。

上轮创建/取消命令、SSE 续传、转义和中文表单方向符合目标。请完成以下已定位问题，再运行 Web 测试。

1. `refreshRun` 只在请求返回后检查一次 gen，但其后 `await loadRuns()` 结束时直接 setStatus。用户此时切换任务，旧任务会覆盖新任务顶部状态。同一任务收到密集 SSE 时还会并发 refresh，旧快照可能晚于新快照返回并渲染。用最简单的请求序号或串行合并方法保证旧响应不能覆盖新状态，所有异步提交 UI 的位置都遵守当前任务。`openEvent` 的请求失败和切换任务结果也应处理，不留下未处理 Promise。
2. POST 预算字段当前 `int(body[key])` 会把小数静默截断并接受 bool。API 应要求正整数并返回 400；负数、0、bool、小数、非数字等不能启动任务。未知 run 的 `/events` 也应与其他 run 路由一样返回 404。
3. `_run_worker` 不应静默吞异常。后台异常必须能在服务错误信息和 UI 中观察到，且不允许伪称任务完成或直接修改事件/投影；用现有引擎能力或简单独立的执行错误状态解决。若确需修改后端公开接口才可完成，报告明确依赖并保持文件边界，不擅自改后端。
4. 长任务文本、长文件路径、长错误、事件 JSON 必须在手机/桌面均可换行，不能撑宽 grid 或与按钮重叠。检查主 grid 使用允许收缩的轨道、子项 min-width 与文本换行；紧凑头部允许换行。
5. 按已确认视觉约束，去掉页面 section 的整块浮动卡片边框，以分隔线和普通区域组织四视图；现有主调褐色/金色换成中性灰背景加明确区分的状态色。letter-spacing 全部为 0。开始/取消图标使用官方 Lucide 资源（可仅包含本地小型 SVG 资源及必要许可证），不要手绘 SVG、不要引入 UI 框架或依赖运行时 CDN。保留 aria-label/title。
6. 开始/取消的禁用或等待状态需与正在提交、当前所选任务可取消性一致，避免连点重复请求。provider 未配置错误应在界面有稳定位置，不被历史任务状态覆盖后完全消失。

保留核心简单结构，不加复杂队列或通用状态库。测试使用假数据/受控 mock，不调用真实 provider；为异步错误和输入行为补充真正验证行为的测试，避免只检查源码存在某个字符串。完成后报告改动、测试与尚未完成事项。
