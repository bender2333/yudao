# 里程碑 3 — 分级评分题库（点3：质量必须综合评分，不得只对错）

> 与 batch-1 的根本区别：oracle 输出 **0-100 加权分数**，而非 PASS/FAIL。
> 分数由多维度组成，其中**鲁棒性维度故意包含任务描述未明说但合理的边界**——
> 这是检验「multi 的额外成本是否买到鲁棒性」这一核心假设的关键。
> 题目描述只给核心需求，刻意不列全边界；oracle 藏在 runs/m3/_oracle/。

## 评分维度（每题通用骨架，权重可按题微调）
- **基础功能 base（40）**：正常路径、任务明确要求的行为。
- **鲁棒性 robust（30）**：任务未明说但合理的边界（空输入、超大/超小、畸形、Unicode、前后空白…）。不崩溃 + 合理处理才得分。
- **错误处理 errors（20）**：该报错的报错、退出码正确、错误信息到 stderr。
- **代码健壮性 quality（10）**：机械可测部分——不 traceback 崩溃、无副作用泄漏、可重复运行。

> 满分 100。base 是「对不对」，robust+quality 是「好不好」——梯度就在后者。

## G1 — 日期规范化器 normalize_date.py（设计范本）

**给 agent 的任务描述（只给核心，不列全边界）：**
> 创建 normalize_date.py：接一个日期字符串参数，把它规范化为 ISO 格式 YYYY-MM-DD 输出。
> 支持常见输入格式（如 2026-3-5、2026/03/05、20260305）。无法解析的输入打印 'error: invalid date'
> 到 stderr，退出码 1。自己运行验证。

**隐藏评分（oracle 打分，agent 不可见）：**
- base(40)：`2026-3-5`→`2026-03-05`；`2026/03/05`→`2026-03-05`；`20260305`→`2026-03-05`；已是 ISO 原样。（每项 10）
- robust(30)：前后空白 ` 2026-3-5 ` 能处理(6)；闰年 `2024-2-29` 合法→`2024-02-29`(6)；单位数月日补零(6)；`2026-13-01`(非法月)判 invalid(6)；`2023-2-29`(非闰年 2/29)判 invalid(6)。
- errors(20)：非法输入 exit 1(7)；错误信息含 'error: invalid date'(7)；空字符串参数判 invalid 不崩(6)。
- quality(10)：任何输入都不 traceback（用一批乱七八糟输入喂，只要不崩就得分）。

> 设计意图：闰年、非闰年 2/29、非法月份、补零——**任务描述一个都没提**。solo 很可能只做 base，multi 的验证阶段若较真该覆盖更多 robust。这就是质量差的观测点。

## 执行
- 每题每模式 ≥2 run；multi max-steps 50、max-rounds 3。
- oracle 输出：`{score, base, robust, errors, quality, details:[...]}` JSON。
- 报告按**分数**比较 solo vs multi（均值±范围），而非 PASS/FAIL。
- 出题纪律：每个边界在 oracle 里都有对应断言；题目描述**不泄露** robust 清单。
