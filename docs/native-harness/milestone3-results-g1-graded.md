# 里程碑 3 — G1 分级评分结果（第一个干净的质量信号）

> **成本勘误（2026-07-10）**：本文保留历史质量结果，但 multi calls/token 存在重复累计，`duration_ms` 也不是真实墙钟。原成本倍数不得继续作为证据；纠正值与原因见 `milestone4-complex-study-protocol.md#12-历史成本勘误`。

> 数据 runs/m3g/（G1 normalize_date，solo/multi 各 3 run）。gemini-2.5-flash。
> oracle = grade_g1.py（0-100 加权分，agent 不可见）。裁判 = 主线。

## 分数

| 模式 | 各 run 分 | 均值 | robust 维度均值 |
|---|---|---|---|
| solo | 94, 88, 94 | **92.0** | 22.0/30 |
| multi | 94, 100, 100 | **98.0** | 28.0/30 |

- **质量差 = multi 比 solo 高 +6.0 分**，差异**全部来自 robust 维度**（+6.0）——base/errors/quality 两模式满分持平。
- 即：两者"基本功能都对"，差距在**任务没明说的边界**（闰年校验、非法月份、非闰年 2/29）。**这正是分级题设计要捕捉的东西，且它捕捉到了。**

## 成本

| 指标 | solo | multi | 倍数 |
|---|---|---|---|
| prompt tok 均值 | 15,228 | 261,693 | **17.2×** |
| calls 均值 | 12.0 | 82.7 | 6.9× |
| 墙钟均值 | 43.8s | 255s | 5.8× |

## 结论（诚实 epistemic 口径）

**能说的（有梯度、可解释）：**
1. **multi 确实买到了一点质量**：+6 分，且**精确落在鲁棒性维度**——它的验证阶段较真地覆盖了任务未要求的边界（闰年/非法日期），solo 常只做到"常见格式能转"。这是本项目**第一次**观测到"结构带来正向质量"，方向上支持"multi 的成本买到鲁棒性"的假设。
2. **但代价极不成比例**：为这 +6 分（92→98，约 6.5% 提升），multi 花了 **17× 的 prompt token、7× 调用、6× 墙钟**。按"每分质量的成本"算，multi 比 solo 贵一个数量级。
3. **multi 不稳定**：3 run 里 1 个 escalated（撞 max_steps）。solo 3/3 都正常收敛。

**不能说的：**
- n=3、单题，是**方向性信号非定论**。92 vs 98 的差可能被 seed 噪声影响（solo 那个 88 拉低了均值）。
- consult 三次都是 0——自由调用机制仍未被真实模型触发，质量提升来自验证阶段自身较真，不是 consult。
- 单题无法排除"这题恰好有丰富边界所以 multi 占优"——需要更多题才能一般化。

## 与前两批一致的大图景
- **成本铁律再次确认**：multi 是 solo 的数倍到十几倍成本，跨三批稳定。
- **新增**：在**有鲁棒性空间**的任务上，multi 首次显出正向质量差（+6，全在 robust）。但性价比极低。
- 呼应旧 EXPERIMENT：结构价值只在"任务有质量梯度可挖"时显现；纯对错任务上是纯开销。

## 下一步候选
1. **扩题**：再出 3-4 道有鲁棒性空间的分级题，看 +质量差 是否稳定复现（排除单题偶然）。
2. **控成本**：multi 的 17× token 主要花在验证阶段反复跑测试——若能压缩，性价比才可能翻正。
3. **加中间臂**：solo + "显式要求你考虑边界" 的 prompt——区分"结构价值" vs "光提示考虑边界"的价值。
