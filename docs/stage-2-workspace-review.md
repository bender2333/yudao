## 查询与采集

| 编号 | 已确认的问题 | 修正后的完成依据 | 责任 |
| --- | --- | --- | --- |
| O1 | 在途请求已有部分模型输出，详情仍只显示请求中和等待响应 | 能区分准备、已发送、实际收到数据、部分输出和终态；部分输出不冒充完整 Response，不进入工具执行 | 采集与查询 |
| O2 | SDK 原始事件没有观察时间，并被直接接在运行生命周期事件之后 | 新采集保留主机观察时间及本地顺序；旧数据说明时间未采集，按来源分组，不拼造单一时序或 Provider 时间 | 采集与查询 |
| O3 | `status=cancelled` 经查询映射为失败，筛选无法区分 | API、列表、详情及筛选保留取消事实，任务停止说明与实际取消一致 | 查询与界面 |
| O4 | 失败尝试的部分消息被当作普通部门工作记录显示 | 有效部门消息不混入失败输出；观察详情仍能查看对应失败片段与原文 | 查询与界面 |
| O5 | `reported=False` 的非零用量被计为已上报 | 非上报数据不进入 Provider 上报小计及覆盖率；未知不补零，原始证据可查 | 查询 |
| O6 | 用量总计条未展示已取得的费用 | 有来源及币种时显示相应小计；缺失或不同币种不可合计时明确区分 | 界面 |

采集继续复用事件与工件。实时进度采用有界的阶段或频率更新，不能逐 Token 重建完整投影或反复保存整份响应；最终完整 SDK 原文也不能被进度摘要替代。

## 浏览与布局

| 编号 | 已确认的问题 | 修正后的完成依据 |
| --- | --- | --- |
| U1 | 浏览器后退从 B 回到 A 时，URL 已是 A，缓存仍显示 B 的内容，并读取 A 草稿 | 跨任务历史导航重新核对对象并隔离迟到响应；内容、草稿、命令及 URL 始终属于同一任务 |
| U2 | 部门页收到 SSE 后仍渲染旧部门缓存；详情页关闭 SSE 后不再更新 | 停留在部门、列表或详情均能看到当前对象变化；刷新不切换选定快照、丢失草稿或重置 Raw 阅读位置 |
| U3 | 真实长任务全文重复占据观测范围及详情关联条 | 范围和关联条使用已有的简短任务目标，原始全文从任务输入查看；窄屏首屏能进入主要查看内容 |
| U4 | 64KB 真实 Request 在 320px 视口形成约 36805px 高的页面，Raw 开始位置约为 888px | Raw 使用适合视口的可滚动区域，保留全文与复制/导出；不得仅以没有横向溢出宣称布局完成 |
| U5 | 请求/返回模型在 API 中独立，但无响应请求的页面主要显示未知模型 | 失败或在途时仍能看清实际请求目标；请求模型和提供方上报模型明确区分，不互相回填 |
| U6 | 旧控制台在任务终态时将同一个提交按钮自动改为新建，曾误建任务 | 新工作台保留旧任务草稿且停止发送；只有显式新建入口才能产生新 run |

保持冻结原型的导航、颜色、字体、间距、检查区比例及响应式规则。用实际长 JSON、长模型身份、失败片段和原始输入验证，不能只使用短标题或没有 Raw 内容的 fake 样例。

## 部门指导

| 编号 | 初版缺口 | 必须补齐的行为 |
| --- | --- | --- |
| G1 | `_finish_guidance_batch` 仅因存在 Context、请求或拒收事件就标为 processed | 目标部门必须给出针对冻结批次的明确回应；声称动作完成时提供实际接纳或主机结果。准备、发送和失败观察不能替代处理结果 |
| G2 | 非活动部门只等待自然流程再次轮到 | 当前激活和既有协作结束后安排指定部门；保存被让出的工作依据，仅恢复仍然有效的工作 |
| G3 | QA 可以先被拒一次，批次随后因已有事件自动 processed，下一次即放行 | QA 等待真正的处理结果；新指导、工具在途、协作、要求变化及取消均有明确的接纳顺序 |

沿用原生循环，不增加部门聊天运行器。模型不必机械抄写当前批次的系统标识，当前批次由宿主绑定；私有指导不自动广播，全局原文与部门原文继续分别保存。跨部门需要正式产品处理时，保留必要的准确原文及来源。
