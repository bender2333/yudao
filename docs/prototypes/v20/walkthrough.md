# 页面原型 V20 走查

依据：[项目的组织设计说明](../../design/project-organization.md)的 4.12 至 4.15 与第 5 节七份脚本。每份脚本对应一个同名的示例项目。

## 打开方式

用浏览器打开 [index.html](index.html)，不用安装，不连服务，全部是示例数据。刷新以后项目、对话与演示进展回到原样。右下角的「场景」菜单切换情形（中断、要你决定、发布改了形态等）。

项目页只有两页：**对话**（上面带循环图）与**设置**。职能的状态、往来、成果与版本、组织都在循环图上看；改定义走设置页底部的「高级」。

循环图的读法，七个项目都一样：

- 节点是职能。做核验的节点带「✓ 核验」；外部 agent 做的节点写它的名字（例如「OpenCode」）和「推理档位由它定」；由子组织做的节点带「子组织」，能点「看内部」；自有角色不加标记。
- 箭头只放成果与版本（原文、PRD、交付、缺陷记录……），写版本号与第几轮；虚线框、箭头朝左的是回头的成果（缺陷记录）。
- 放行与打回标在那一版上：「质检打回」「放行 · 质检」。打回之后工程交出的新一版是新的一条箭头。
- 最左边是事项的来源（你的输入、建档），最右边是结束：有核验角色时写谁放行，没有时写开环完成，外部 agent 做时注明外包。
- 旁边的职能（虚线框）放在它对接的那个职能上方，中间一格写它们之间的往来。
- 同时有几件事时，图上方一行「图上画」选事项；别的事项在节点上记「另 N 件」；点线程里事项之间的细线也能选。
- 点节点：看这个职能在做什么、它的往来，收件人切到给它的指导，有「职能详情 ›」入口。点箭头：看那一版与差异，同一种成果能「‹ 上一版 / 下一版 ›」逐版看。
- 窗口 800px 宽及以下，图收成一行：节点名与当前箭头。

线程的读法：一条线程跨多个事项，事项之间一条细线写标题与结果；默认只露你写的、要你决定的、交完成或放行三种话，角色之间的往来折成一行「工程与质检往来 N 条」，点开才展开。要你决定的气泡里有按钮，拍板只在这里；节点上的「要你决定」与左侧栏项目名旁的数字只跳到气泡。左侧栏的数字从两个职能起显示。输入框上方一行收件人，默认按状态选好，能切。

## 新建项目

左侧栏点「新建项目」：一个名字框、四张形态卡。每张卡有形态名、两个标记（轮转、结束）、一句话和一张小循环图。

1. 「产品 · 工程 · 质检」排第一，标「默认」；小图里质检节点带核验标记，结束写「质检放行」。
2. 「工程」：一行，你的输入 → 工程 → 开环完成。
3. 「产品 · 工程」：工程在主线上交付，产品在工程上方，中间一格写「询问与回答」，不是先后两步。
4. 「产品 · 工程 · 质检 · 运维」灰着，写「发布带还没有」，不能点；小图多一个运维节点，下面一行写故障从图外进来、开一件新事项。

名字空着时点卡不建，提示先写名字。写好名字点一张卡，项目就建好并打开对话。「选起始文件夹」「高级」（和某项目一样）是底部两个小入口。

## 脚本一：「工程」，由外部 agent 做 —— 日志清理脚本

1. 打开「日志清理脚本」。头部标签：「工程」、直做、开环完成 · 外包。
2. 循环图一行：你的输入 → 工程 → 开环完成 · 外包。工程节点带「OpenCode」与「推理档位由它定」。
3. 线程底部一条状态条：OpenCode 在跑、推理档位由它定、交回的快照与差异经写入口成为提案。
4. 上方「图上画」切到「清理 30 天前的日志」：最后一条箭头「交付 v1」指向「开环完成：没有人核验 · 外包」；点它看交回的差异。线程里那一条写「开环完成：没有人核验 · 外包（OpenCode）」，不写放行。
5. 点工程节点 → 「职能详情 ›」：「由谁做」里外部 agent 已选 OpenCode，可以换成 Claude Code，一步生效，只对之后新建的事项生效；模型一组写「模型经受控入口由本项目定；推理档位由外部 agent 自己定」，没有可调的档位。
6. 设置页的组织一行：「「工程」，只有一个职能，工程由外部 agent（OpenCode）做，没有人核验」。

## 脚本二：「工程」 —— 个人博客

1. 打开「个人博客」。图一行：你的输入 → 工程 → 开环完成；左侧栏项目名旁没有数字（只有一个职能）。
2. 线程里「首页要不要保留旧的访问计数？」是要你决定的气泡，按钮在气泡里；工程节点上的「要你决定 1」点了跳到这条气泡。
3. 有事项在做时收件人默认「给工程的指导」；切到「开始一个新事项」，下面一行写「排在「把首页的文案改成新站点的介绍」后面，它做完才开始」。
4. 已结束的「迁移文章」只露分隔线与交完成一条，写「开环完成：没有人核验」；点「看这一版」，图切到那件事并打开「交付 v1」的差异。
5. 设置页点「加独立核验」：头部形态名变成「工程 · 质检」，标签变成「核验：质检」，轮转仍是直做；组织一行写「工程交付，质检核验后放行，轮转仍是直做」；线程里一句话写明只对之后的事项生效、在跑的按原来的做完。回到对话，图仍按在跑那件冻结的组织画，下面一行「之后新建的事项按现在的组织走」的小图里多了带核验标记的质检节点。左侧栏开始显示数字。同一处能「去掉独立核验」。
6. 不出现成果库页、职能页、组织页、轮次以外的执行细节。

## 脚本三：「产品 · 工程」 —— 活动报名小程序

1. 打开「活动报名小程序」。图上工程在主线上（你的输入 → 工程 → 开环完成），产品在工程上方，中间一格「询问与回答 3 条」。
2. 线程里「工程与产品往来 3 条」点开才展开；「满员后要候补名单吗？」是工程要你决定的气泡；左侧栏项目名旁有数字 1。
3. 收件人默认「给工程的指导」；点产品节点，收件人多出并切到「给产品的指导」，面板里是产品的往来。
4. 已结束的「活动页文案」写「开环完成：没有人核验」。设置页组织一行写明「加独立核验就会等它放行」。
5. 加自己的职能（例如「运营」）走设置页「高级」→ 组织，必填它对什么负责、凭什么判断、怎么工作。

## 脚本四：「产品 · 工程 · 质检」 —— 订单系统重构

1. 打开「订单系统重构」。图上方「图上画」一行五件事，默认是最近在跑的「导出订单为 CSV」。
2. 图：你的输入 → 原文 v1 → 产品 → PRD v1 → 工程 → 质检 → 质检放行才结束。工程与质检之间四条箭头：「交付 v1 · 第 1 轮 · 质检打回」「← 缺陷记录 v1」「交付 v2 · 第 2 轮 · 质检打回」「← 缺陷记录 v2」；工程节点写「写导出功能」与「另 2 件」，质检节点「另 1 件」。产品节点带「要你决定 1」。
3. 点「交付 v2」：面板写「质检打回这一版」、改了的文件与差异，「‹ 交付 v1」能逐版看。
4. 「图上画」切到「订单状态机」：「交付 v1 · 质检打回」之后是新的一条「交付 v2 · 第 2 轮 · 放行 · 质检」，结束写「完成 · 质检放行」。切到「订单列表分页」：交付 v2 在等质检核验。
5. 点质检节点：面板写它是核验角色、它的往来；收件人切到「给质检的指导」。收件人一行还有「开始一个新事项」「追加输入（产品接，重新验收）」与每个职能的指导。
6. 窗口拉到 800px：图收成一行「产品 → 工程 → 质检（核验） · 当前：缺陷记录 v2 · 第 2 轮 → 工程」，线程不被挤。
7. 加设计职能、新建成果种类走设置页「高级」→ 组织，那里显示三个职能、质检标核验角色、全部跟随发布。

## 脚本五：「产品 · 工程 · 质检 · 运维」 —— 线上商城与运维的设计预览

1. 新建项目与设置页「换形态」的卡里，「产品 · 工程 · 质检 · 运维」灰着，写「发布带还没有」；小图多一个运维节点和一行从图外进来的故障。
2. 「线上商城」现在用「产品 · 工程 · 质检」，图与订单系统重构同一种画法。
3. 打开「线上服务与运维 · 设计预览」（标「设计预览」）：运维节点在质检上方，中间一格「↑ 交付 v1」（放行的交付交给运维）与「↗ 部署记录 v1」。图下面一条红色虚线框：故障记录从图外进来，产品接，开一件新事项，和打回分开。
4. 点运维节点 →「模拟发现故障」：开一件新事项，图切到它，最左边写「运维发现的故障」，第一条箭头是「故障记录 v1」；故障框里记「已开 1 件」。「运行环境 · 设计预览」打开部署与授权的演示。

## 脚本六：观察者层 —— 内部报表工具

1. 打开「内部报表工具」。图一行，和「工程」一样；观察者不在图上。
2. 线程里「观察者 · 振荡检测 · 要你决定」的气泡：第 2 轮和第 1 轮在改同一段代码，要不要停下来看看。节点上不标这一条，因为观察者在圈外。
3. 设置页「观察者」三个开关，教训发现与振荡检测开着；勾一下就生效，不进草稿；它不改事项怎么结束，仍是开环完成。
4. 读取范围在设置页「高级」→ 组织里改。

## 脚本七：职能里的子组织层 —— 固件升级服务

1. 打开「固件升级服务」。主线：产品 → 工程 → 质检；工程节点带「子组织」与「看内部 ›」。本项目加的硬件适配在工程上方（「↓ 适配包 v1」），文档在质检上方。
2. 点「看内部 ›」：路径「固件升级服务 › 工程 › 内部 · 中心型小组 · 子事项 D-1.1」。内部图：上一层交来的任务 → 工程架构师 → 主程 → 审查者（带核验标记），探索者在工程架构师上方（「↓ 调研结论 v1」）；「改动 v1 · 审查者打回」之后是「改动 v2 · 第 2 轮」。出口写「还没交回工程」；图下一句写明结果作为工程的提案回到上一层，放行只留给事项自己那一圈。
3. 「回到上一层」回到外层；「图上画」切到「升级失败自动回滚」再看内部：「改动 v1 · 审查者通过」，出口「交回工程」。
4. 点工程节点 → 「职能详情 ›」：「一个角色还是一个小组」选着一个小组；内部角色的详情从「看内部的职能」进；层数到上限时小组一项灰着。

## 设置页

名字、长期目标（可选）、起始文件夹、模型一行、组织一行与「加独立核验」（或「去掉独立核验」）「换形态」、观察者开关、「高级」。

- 「换形态」打开四张形态卡，点一张一步生效；本项目改过东西时先确认一次，列出会丢掉哪些。
- 「高级」里三个入口：组织（四问、职能表、加职能、编辑定义、草稿与校验、版本与历史）；成果写回、机器授权、执行位置、MCP 服务器；和某项目一样。走高级的采用要写理由。
