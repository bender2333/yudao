# 原型设计变更记录 (Prototype Changelog)

本文档记录 Yudao 原型设计各版本的演化历程、核心设计决策与交互改进。

原型分两种。页面原型画基础部分的页面：不带画面，用假数据、能点，交给用户试用，一版接一版，试用的结论写进设计说明。画面的原型只回答设计问题：一张假数据的单页草图，不带翻译层与播放时间线，答完就扔（[ADR-0021](../adr/0021-client-pixel-view-follows-v9-structure.md)）。两种都只说明设计意图，不当逐像素的标准，工单与代码只引设计说明；画面是单独的应用，按画面合同与诚实性验收（[画面与播放设计说明](../design/visualization.md)）。[v13](../archive/prototypes/) 已归档：客户端的对照测试、录制与按原型生成的脚本随画面搬出一起删掉，已经生成的登记表与声明表当普通源码留下。[v20](v20/index.html) 是当前页面原型：项目页只有对话（上面带循环图）与设置两页，新建项目是名字加一张形态卡，任务池与运维是设计预览。操作路径见 [V20 走查](v20/walkthrough.md)；[v19](v19/index.html) 留在目录里；[v18](v18/index.html) 留在目录里；[v17](v17/index.html) 留在目录里；[v16](v16/index.html) 与 [v15](v15/index.html) 也留在目录里，等 v18 以后的版本定稿再归档（v15 的模型管理取自 v14）；v14 留在归档里（[v14](../archive/prototypes/v14/)），更早的版本在 [docs/archive/prototypes/](../archive/prototypes/)。

**原 v15 待办与去向**：下一版 v15 是页面原型，从 v13 的页面部分起步，去掉画面；画面搬出以后原来只在画布上看得到的事实，也在 v15 的页面上画出来。十三条按归属处理。归页面、在 v15 里按各条推荐处理、交给用户试用，结论进基础部分的设计说明：第 2、3、4、5、7、8、9 条。归画面、进画面自己的待办：第 6、10、11、12 条。作废：第 1 条（推荐本来就是不显示）、第 13 条（只为原型的模拟接口存在）。各条原文：

1. 事项用的是哪一种路由，界面显示不显示（B15）：推荐现在不显示，任务池上线时再定。
2. 「定义版本不同」的卡片列不列出变了哪几份定义，路由改变走不走这张卡片（A12）：推荐列，按名字写；路由属于组织定义，走同一张卡片；事项开始时要记下每份定义各自的摘要。
3. 使用本机桌面与停止使用桌面的入口（A22）：推荐桌面会话进行期间每一页顶部显示一条「质检正在使用桌面 · 停止使用」；屏幕边缘的提示框由控制主机上的执行代码画。
4. 内核修改的决定卡片与自举示例项目（A23 的一半）：推荐现在不做，等自举工作线做到内核修改的界面时再定。
5. 放行在等发给产品的输入处理完时怎样显示（B22）：推荐质检的状态写「等待工作」，原因写「放行在等产品处理完新的输入」，进度行写「结论：放行（等产品处理完新输入）」。
6. 像素画面里保留的旧字样：楼层信息条的「当前部门」、机房里控制主机的 3 个容器格子，推荐 v13 改（信息条写「所在部门」，容器格子删掉）；检验台的「返工」章保留，缺陷记录到了以后工程确实在返工，这个词没有问题。
7. 流转记录的种类：服务端现在是版本交付、询问、问题反馈、PRD 新版本（#882），v12 的示例数据是按成果一种一条（用户输入、PRD、交付、缺陷记录、询问、回答、放行、采纳）。推荐服务端照 v12 改，v13 的示例数据不动。
8. 连接设置页的两行接口版本（B11）：客户端没有这一页，推荐不新建，版本不一致时的提示里写两边各是第几版就够；v13 可以删掉这一页。
9. 离开期间的报告新增的四项（A30）：验证的独立性设计说明第 9 节与应用层与接口层设计说明第 4.3 节不一致，先改设计（推荐以第 9 节为准），再决定画不画。
10. 上下文容量刻度：路线图第 4 节步 0 与 [D41](../requirements/game-world-three-spaces.md) 把它列在楼的画面里（动力是模型接线与上下文容器），v13 的像素房间没有，只有页面上的上下文来源列表。画哪一种、读什么数据，等 M0.5 的装配契约定下上下文清单暴露哪些数据（比如已用量与窗口上限，有没有要看契约）以后再设计；它承载事实，设计时在[画面与播放设计说明](../design/visualization.md)第 8.1 节的视觉通道表里补一行。
11. 拖包裹调优先级：路线图第 4 节步 0 写了这一条，v13 画面的回调只有选决定、跳转、点开机房的门、在时间轴上查看。页面的看板已经能拖动排序（概览页，修复事项固定在最前面），画面里拖包裹应当走同一条命令：给画面合同加一个回调，只交出操作（事项与目标位置），命令仍由页面发。设计时先核对这条命令的合同能不能直接用；D41 第 5 条把「队列顺序」归在步 4（规则成为物件），路线图步 0 也写了，放哪一步一并核对。
12. 机房的设备画面：路线图阶段一写了「机房的基础视图」，v13 原型有设备节点与管线（远程动作、部署、回滚的包裹沿管线走），客户端只有地下室、通往机房的管线与楼层上的机房门，没有设备的画面，原先的决定把它划给 3.2C（路线图第 6 节：远程执行属于阶段四）。设计时核对：阶段一单机的机房要画什么，与 3.2C 的分界在哪；阶段三机房里软件设备的版本牌、健康灯与冒烟随运维部门的设计另写（D41「待定」）。
13. 模拟接口的形状向真实接口靠拢（2026-10-26，#957 的回放对照中查明；推荐，等用户确认）：v13 的 `project.loop` 里事项有 `title` 与 `sign` 两个字段，真实接口只有 `sign`（值是事项标题）；还有真实接口阶段一没有的 `stamp`、覆盖层与来源的数据。v14 的示例数据按真实接口的字段写，没有的数据放在能一键关掉的覆盖层里；这样录制不用去掉数据，逐像素回放的范围也不用单独声明（[画面与播放设计说明](../design/visualization.md)第 8 节）。

### 这一版新增
- 项目页只有对话与设置两页。协作区、窄带、成果库页、职能页、组织页并进对话上面的循环图；改定义走设置页底部的「高级」（组织页与旧的设置页只从那里进）。`dept.js`、`collaboration.js` 删掉。
- 循环图（`js/lean.js` 与 `styles/loop.css`）按选中事项冻结的组织画，读合成结果：主线从接「你的输入」的职能沿「交出 → 关注」走到交出最后采纳成果的职能，再接核验角色；其余职能放在它对接的那个职能上方。箭头只放成果与版本，写第几轮；放行与打回标在那一版上；结束写放行与核验角色的显示名，或开环完成（外包时注明）。节点标记三种：核验、外部 agent 的名字加「推理档位由它定」、子组织（能点进去看内部的循环图，出口写「交回工程」）。点节点看在做什么、往来，收件人切到给它的指导，进职能详情；点箭头看那一版与差异，能逐版看。窄屏（800px 及以下）收成一行。同时几件事时上方一行选事项，别的事项在节点上记数。
- 七个示例项目都是循环图加对话，各对应一份脚本：订单系统重构（两次打回、轮次）、个人博客、日志清理脚本（OpenCode，线程里有状态条）、活动报名小程序（产品在工程上方接询问）、内部报表工具（观察者的气泡）、固件升级服务（工程由子组织做，内部图）、线上商城；任务池与运维两个设计预览项目保留，运维多一个节点、故障从图外进来开新事项。七个项目都有线程种子。
- 新建项目是名字加四张形态卡：形态名、轮转与结束两个标记、一句话、一张同画法的小循环图；「产品 · 工程 · 质检」排第一标默认，「产品 · 工程 · 质检 · 运维」灰着写「发布带还没有」。点卡就建好。
- 设置页：名字、长期目标、起始文件夹、模型一行、组织一行与「加独立核验」「换形态」、观察者开关（勾了就生效）、「高级」。「加独立核验」一步采用，头部形态名变成「工程 · 质检」，同一处能「去掉独立核验」；「换形态」点卡一步生效，有改动时确认一次。
- 职能详情：由谁做（自有角色或外部 agent，一个角色还是一个小组）一步生效，不经草稿；外部 agent 的模型一组写明推理档位由它定。
- 拍板只在对话里「要你决定」的气泡；首页、节点与左侧栏只跳到气泡。左侧栏数字从两个职能起显示。
- 页面文字改成新说法：职能、形态名列出职能、「加独立核验」「换形态」；发布带的形态去掉「一个外包角色直做」（外包是职能详情里由谁做的一个选项），日志清理脚本改成「工程」加由谁做选 OpenCode。

### 在设计说明之外定的事
- 主线与旁边职能的摆法（见上）；关注被核验那种成果的职能（运维、文档）摆在核验角色上方。
- 「工程」与「产品 · 工程」的成果名从「交完成」改成「交付」，箭头写「交付 v1」，结束的格子写开环完成；「交完成」只当动作用在线程里。
- 子组织内部的核验通过写「审查者通过」，不写放行；内部还没交回时出口写「还没交回工程」。
- 刚加了独立核验、在跑的事项还按旧组织时，图仍画在跑那件，下面多一行「之后新建的事项按现在的组织走」的小图。
- 头部「改过几处」不算加独立核验、由谁做与观察者（它们一步生效，不走高级）。
- 收件人：直做只列接输入的职能的指导，点了别的节点再多出那一项；按成果每个职能一项。
- 观察者的气泡不标在任何节点上（观察者在圈外）。
- 「看这一版」在图上打开那条箭头，不另开页面。

### 设计说明里写不清的地方
- 4.14 写「点线程里事项之间的细线也能选」，又写已结束的事项默认收起；原型里细线上的标题点了选事项，「展开对话」是旁边另一个按钮。
- 「产品 · 工程 · 质检」的 PRD 同时给工程与质检，图上只画给工程的那条（不相邻的箭头不画）。
- 「线上商城」在脚本五里只用来看灰着的卡，原型没有给它画出打回的示例。

### 请用户试用时重点看
- 只看形态卡和小图，分不分得清谁交付、有没有独立核验、怎么轮转。
- 订单系统重构的图：打回与第几轮一眼看不看得清，选事项那一行好不好用。
- 固件升级服务点进内部再回来，层次清不清楚。

## [v19] - 2026-11-03

### 原型交付
- 原型文件：[v19/index.html](v19/index.html)（浏览器直接打开，纯静态，不连服务、不用构建）。走查文档：[v19/walkthrough.md](v19/walkthrough.md)：开头怎么打开、这版只试的两件事、脚本二三四各一份、两个判断题。
- 依据：[项目的组织设计说明](../design/project-organization.md)的 4.14、4.15 与第 5 节脚本二、三、四；决策记录「组织设定：交互骨架是一条线程加看得见的收件人，v19 画三级」。整份复制 v18（对象 `Y19`，类名 `y19-`，模型页 `m19-`，存储键 `y19.`，`ln-` 类名保留），v17、v18 原样不动。v18 带的「新增」标签去掉。
- 只说明设计意图，不当逐像素的标准。

### 这一版新增
- `js/lean.js` 泛化成一条线程骨架，页面由合成结果伸缩（角色数、有无核验角色、是否按成果轮转），不写三份：一个角色是对话与设置两个标签，顶上「只看交付」开关；几个角色加成果库、线程上方「谁在做什么」、左侧栏项目名旁的数字；三部门再加线程上方一条窄带（输入 → 需求 → 交付 → 放行）、部门页、组织页与成果库的结论，没有流转、概览、时间轴、资料、观测。
- 线程：事项之间一条细线写标题与结果；默认只有你写的、要你决定的、交完成或放行；角色之间的往来或进展折成一行「某某与某某往来 N 条」，点开展开，再点收起；要你决定的气泡里有按钮，点了线程多一条你的回答；左侧栏数字点了跳到那条气泡并亮一下。
- 收件人：输入框上方一行按钮，选中的绿色实心，按状态选好默认（没有事项在做是开始一个新事项，有事项在做是给正在工作的部门或角色的指导），用户手动切过的发送前不被改掉，发送后回到默认；下面一句灰字说明这一句会怎样（马上开始、排在某某后面、下一轮读到、已有的交付要重新验收）；发出的话气泡上方小字写收件人；排队的新事项在当前事项做完后自动开始。
- 三个示例项目都按此重写线程，打开时各有一个事项在跑、各有一条未回答的决定。新建项目选一个角色、几个角色、三部门三张卡都走这条线程。
- `app.js`：判断用 `Y19.OLD` 的旧样例 id 清单（线上商城、固件升级服务、日志清理脚本、内部报表工具），其余都走线程；三部门项目的 `dept`、`org` 路由用原来的页面。

### 在设计说明之外定的事
- 一个角色的项目没有往来，也把工程的进展折成一行「工程的进展 N 条」，三级骨架一致。
- 几个角色的新事项里，另一个做事角色（产品）会在折叠行里回一句；三部门的新事项把往来放进「产品与工程往来」「工程与质检往来」，线程里只露放行。
- 直做时有核验角色，工程交完成进折叠行「工程与质检往来」，线程里只露放行。
- 「看这一版」：一个角色（没有成果库页）在线程里展开差异；角色多于一个时跳到成果库。
- 示例里本来就在做的事项，有后面的事项排着时才开始走假进展（从中途接着走），所以排队后不用手点停止也会开始。
- 追加输入没有事项在做时也能发，折叠行里记一句「收到追加输入，已有的交付要重新验收」；原型不真重新验收。
- 加或去掉核验角色后，线程里加一条细线写那一句说明（脚本二第 6 条）。

### 设计说明里写不清的地方
- 4.14 写「几个角色起左侧栏数字」，加了核验角色的个人博客有两个角色，数字就出现；原型按角色数判断，没有单独说明。
- 「给某个部门的指导」在直做里只有接输入的那个角色；几个角色里产品没有单独的收件人，原型只给工程。
- 三部门有事项在做时「正在工作的部门」随窄带走（需求是产品，交付是工程，核验是质检），设计说明没写怎么算。

### 请用户试用时重点看
- 折叠后的线程刷不刷屏。
- 写「再加一个 RSS 订阅」想开第二件，会不会投成指导；记第几次、投到哪。

1. 去掉的部门在组织页灰着显示，保留改过的名字；还在跑的旧事项的部门，标签与部门清单里叫它冻结时的名字或改过的名字，并标「只在旧组织里」。

6. 事项创建时冻结的是合成结果整份，不含观察者；「和项目现在的组织相同或不同」比较部门、角色、成果、核验与轮转，不含观察者；摘要（版本）含观察者。
