# 页面原型 v16 走查

这一版把「项目用什么组织」画出来了：看组织、改组织、加部门、新建项目与事项时选组织。依据是[项目的组织设计说明](../../design/project-organization.md)。请你像平时用它一样走一遍，把判断写给架构师。

## 怎么打开

- 用浏览器直接打开 `docs/prototypes/v16/index.html`，不用启动任何服务。
- 页面右下角有「场景」菜单，切换不同的情形；本文件里的三个新场景也从这里进。
- 内容全部是假数据。刷新页面，数据回到原样；只有「草稿」存在这个浏览器里，刷新以后还在。
- 页面上带紫色「新增」小标签的地方，是这一版新画的，请重点看。
- 项目有四个：订单系统重构（三部门，本项目改过 1 处）、内部报表工具（三部门，全部跟随发布）、个人博客（一个外包角色直做）、固件升级服务（部门多，工程指向子组织）。主线用三部门。

## 主线（三部门）

### 1. 新建项目，默认三部门

做什么：点左侧栏的「新建项目」。名称写「官网改版」，长期目标随便写一句，组织保持「默认：三部门」，点「新建项目」。

应该看到：

- 项目出现在左侧栏和首页的项目表里，页面自动打开它的概览。
- 概览顶部有一块「这个项目还没有事项」，有「新建事项」和「看组织」两个按钮。
- 项目名下面一行标签：「三部门」「按成果」「核验：质检」。项目标签有产品、工程、质检三个部门。
- 点「组织」标签，三个部门全部标「跟随发布」，质检标「核验角色」，「事项怎么结束」写「质检放行才算完成，打回时工程返工」，历史只有一条。

请你判断：建项目时选组织的位置好不好找；三个选项（默认、发布带的形态、和某项目一样）的说明够不够你做决定；项目头部那一行标签有没有用。

### 2. 新建事项

做什么：在刚建的项目概览点右上角的「新建事项」。原文写「把首页的主视觉换成新的品牌图」，先不要点新建，看对话框里写了什么，再点「新建事项」。

应该看到：

- 没有写原文时，「新建事项」按钮灰着。
- 对话框写明「这段话先交给：产品」和「这个事项怎么结束：质检放行才算完成，打回时工程返工」，还写了这份组织整份冻结进事项的版本。
- 新建以后进入事项详情，里面有一块「这个事项用的组织」，写形态「三部门」和版本，和项目现在的组织「相同」。

请你判断：「先交给谁」这句话够不够让你放心；事项详情里「这个事项用的组织」放在这个位置是否合适。

### 3. 看组织页

做什么：打开「订单系统重构」，点「组织」标签。从上往下看。

应该看到：

- 头部：用哪份形态（三部门，改过 1 处）、版本、轮转方式一句话、事项怎么结束一句话。「修改」「换一份形态」两个按钮。头部下面写「改动只对之后新建的事项生效」，并写有 1 个事项在按旧组织跑，这几个字能点开。
- 部门表：每个部门一行，写目标、什么时候开工（关注的成果）、交出什么、谁核验它或它核验谁、模型、来源。工程那一行标「本项目改过」（多一个只读数据库的工具）。
- 「成果怎么走」四行：你的输入 → 产品 → PRD → 工程、质检；工程 → 交付 → 质检；质检 → 缺陷记录 → 工程；质检 → 放行 → 事项完成。
- 观察者：教训发现、振荡检测开着，元观察关着；观察者不在部门表里。
- 历史：两条，第一条是建项目，第二条是给工程加工具。

请你判断：部门和角色合成一页，你看得明白吗；「成果怎么走」这四行你能不能一眼读懂；观察者单独放一块，位置对不对。

### 4. 把质检改名并采用

做什么：在订单系统重构的组织页点「修改」，在质检那一行点「改名」，改成「验收」。看页面顶部的草稿条，然后点「采用」，先不写理由点「确认采用」，再写一句理由，再点「确认采用」。

应该看到：

- 顶部一条「草稿，还没有生效」，下面常驻校验结果：「过了结构校验，可以采用」，一条提醒「还有几个事项在按旧组织跑」，和「这样改以后事项怎么结束：验收放行才算完成」。
- 点「采用」弹出对话框，列出差异（「质检」改名为「验收」）；理由为空时对话框里写「理由不能为空」。
- 采用以后，全站的名字一起变：项目标签、部门表、概览里事项的原因、成果库里的「放行（验收）」。历史多一条。
- 打开进行中的事项「订单列表分页」，「这个事项用的组织」仍写旧版本，和项目现在的组织「不同」；点「打开那一份（只读）」，里面部门还叫「质检」，并列出「「质检」改名为「验收」」。

请你判断：改名这件事只改名字、不改身份，页面上看得出来吗；采用对话框里的差异够不够你放心；进行中的事项仍按旧版本，这个设计你接受吗。

### 5. 草稿里去掉验收，看提醒，再改回

做什么：点「修改」，在验收那一行点「去掉」。看顶部草稿条里的提醒和「这样改以后事项怎么结束」。点灰着的那一行里的「恢复」试一下，再点「去掉」。想先试试可以点「放弃草稿」；这里点「采用」，理由写「先不要独立核验」。再回概览点「新建事项」。最后回到组织页，在历史里找到改名那一条，点「改回这一条」，再点「采用」。

应该看到：

- 去掉以后出现提醒「事项最后采纳的成果没有核验角色核验，事项以开环完成结束」，「采用」仍然可用；「这样改以后事项怎么结束」变成「交了完成就结束，记为开环完成」。去掉的部门灰着显示，有「恢复」。
- 采用以后，项目标签里出现「验收（只在旧组织里）」，因为还有事项在按旧组织跑；概览的部门表里也标「只在旧组织里」。
- 新建事项的对话框多一块写着「开环完成」的黄色说明。
- 历史有四条，改名和去掉都在；点「改回这一条」以后，草稿条出现，采用后版本回到改名那一版；再新建事项，对话框又写「验收放行才算完成」。

请你判断：去掉核验角色这条路径，页面有没有让你清楚「以后的事项不再有人独立核验」；「改回」和「放弃草稿」两个入口的区别你分得清吗；开环完成的说明够不够醒目。

### 6. 加一个设计部门

做什么：点「修改」，再点「加部门」。起点保持「空白」，显示名写「设计」，三样说明先全部留空；关注的成果勾「PRD」；勾「新建一种成果」，名字写「设计稿」，「让哪些部门关注这种新成果」勾「工程」；模型选一个，点「加入草稿」。回到组织页看校验，再点设计那一行进入部门详情，把三样（它对什么负责、凭什么判断、怎么工作）填好，回组织页采用。最后到左侧栏的「模型管理」看「部门使用」。

应该看到：

- 加入草稿以后，组织页顶部出现一条拒绝：「新增的「设计」还缺「它对什么负责」、「凭什么判断」、「怎么工作」」，「采用」灰着。设计那一行标「本项目加的」，工程的关注里多了「设计稿」。
- 在加部门页里填三样说明时，下面的 Prompt 底稿会同时生成，可以改。
- 填好以后拒绝消失，「采用」可用。采用以后设计部门的标签出现。
- 模型管理的「部门使用」仍然只有发布带的几行，没有「设计」；设计用的模型写在这个项目的部门设置里（部门详情的「模型与 Prompt」）。

请你判断：三样必填写在这个位置，你会不会漏；新建成果种类的几项（名字、说明、依据、检查回执、代码快照）够不够用；先加进草稿再补说明，和一次填完再加，哪种你更顺手。

### 7. 看部门详情和编辑定义

做什么：在草稿状态下，打开「工程」的部门详情（组织页点工程那一行）。再回组织页点「编辑定义」。

应该看到：

- 部门详情分六组：职责、由谁做、权限、模型与 Prompt、位置、事项种类的工作说明。前三组标「之后新建的事项」，模型与 Prompt 标「下一次模型请求，包括进行中的事项」，位置标「创建 run 时」。
- 每一项标「跟随发布」或「本项目改过」，改过的有「恢复为跟随发布」。工程的工具许可标「本项目改过」。
- 「编辑定义」是文档视图：左边是本项目的改动，右边是合成结果，只读。把左边改坏（比如写一个不存在的字段）：顶部立刻出现拒绝。

请你判断：部门设置和角色设置并进部门详情以后，一页的内容多不多；六组的顺序对不对；文档视图你用得上吗。

### 8. 新建事项时临时选一个角色直做

做什么：回到订单系统重构概览，点「新建事项」，原文写「把这个小脚本改一下就行」，组织下拉选「临时用「一个角色直做」，只影响这个事项」，点「新建事项」。

应该看到：

- 对话框里「这段话先交给：工程」，并写明「这个组织没有核验角色核验最后的成果：事项交了完成就以开环完成结束」，还写「临时选的形态只影响这个事项，项目的组织不变」。
- 新建以后，项目的组织页版本没有变；这个事项详情的「这个事项用的组织」写「一个角色直做」，打开那一份，成果怎么走是「你的输入 → 工程 → 交完成 → 开环完成」。

请你判断：临时换形态这个入口放在新建事项里，你会不会误点；它只影响一个事项，页面上说得够不够清楚。

### 新建入口的另外两种选择

- 点「新建项目」，组织选「和某项目一样」，下拉里选「固件升级服务」：对话框写明复制什么（形态名、本项目的改动、项目部门设置与项目角色设置）、不复制什么（机器授权、执行位置、源目录、MCP 服务器）。新建以后，新项目的组织页是三部门、改过 5 处，硬件适配的部门详情里模型和 Prompt 都在，设置页里没有源目录。
- 点「接入已有项目」，填名称和源目录：新项目带一个进行中的「建档：为已有项目建立基线」事项。组织选「发布带的形态」里的「一个外包角色直做」，事项的原因写「建档以开环完成结束」。

## 两头

### 个人博客（最少的一头）

打开「个人博客」。

应该看到：

- 项目标签里没有「流转」，概览的事项表没有「所在部门」列，也没有「谁问谁」和「流转汇总」。项目头部标签：「一个外包角色直做」「直做」「开环完成（外包）」。
- 「成果库」写开环完成并注明外包，结论是「开环完成 · 没有核验角色 · 是否外包：是」，不出现放行。
- 「组织」页：形态「一个外包角色直做」，工程这一行标「外包 · OpenCode」，成果怎么走只有一行「你的输入 → 工程（外包）→ 交回快照 → 开环完成」，表里多一列「谁交完成」，观察者写「这份形态没有观察者」。

请你判断：最少的这一头，页面有没有留下多余的东西；「外包」「开环完成」的标记够不够清楚。

### 固件升级服务（复杂的一头）

打开「固件升级服务」。

应该看到：

- 部门有五个，项目标签收进一个「部门」下拉，选一项进入那个部门。项目头部的标签写「三部门（改过 5 处）」，改过的项目都这样写，没有改过的只写「三部门」。
- 「组织」页：三部门起步，改过 5 处，新加的「硬件适配」「文档」标「本项目加的」，工程标「内部是子组织」，名字下面写「内部：工程架构师、主程、探索者、审查者」。「成果怎么走」里有「工程 → 交付 → 质检、文档」，最后多一行「文档 → 升级说明 → 成果库」：没有部门关注的成果，这一行写到成果库为止。观察者三个（教训发现、振荡检测开着，元观察关着），不在部门表里。
- 打开工程的部门页，多一块「内部的角色在做什么」，列出工程架构师、主程、探索者、审查者各自在做什么和对应的子事项。
- 工程的部门详情里，「模型与 Prompt」只有部门这一层的模型、推理档位和部门 Prompt，不列角色，下面写「内部的角色在各自的详情里写，没写入的跟随这个部门」，带「打开内部」；进到主程的详情，才有角色的模型与角色 Prompt。
- 在工程的部门详情点「打开内部」：路径是「组织 / 工程 / 内部」，同一个页面，每一行是一个角色，工程架构师关注的是「上一层交来的任务」，有自己的「成果怎么走」，最后一行写「审查者 → 放行 → 结果作为提案回到上一层」，没有观察者块。点「修改」，进入主程的详情，「由谁做」还能选「子组织」；选上它，点「打开内部」，再进审查者的详情，「由谁做」里的「子组织」灰着，写「已到嵌套上限，不能再选」。
- 关掉观察者：在「组织」页点「修改」，把教训发现的开关取消勾选，点「采用」。采用以后立即生效，历史多一条。

请你判断：部门多了以后，下拉的收法顺不顺手；子组织和上一层用同一个页面，你会不会迷路；观察者放在组织页里关开，位置对不对。

## 三个新场景

从右下角「场景」菜单选，选完会自动打开订单系统重构的组织页。

### 发布改了三部门

应该看到：组织页写明「和这个项目上一个事项（支付回调重试）用的组织相比，有这些不同」，列出「工程」的工具许可增加：迁移脚本检查；版本变了；还有几个事项在按旧组织跑。打开工程的部门详情，工具许可里有这个新工具。

请你判断：这个差异说明放在组织页头部下面，你会不会注意到。

### 发布的改动合不到一起

应该看到：组织页头部下面一块黄色说明「发布的改动与本项目的改动合不到一起」，写明原因：「工程」的工具许可里有「只读数据库（MCP）」，这个发布没有这个工具。点「新建事项」，对话框里「新建事项」按钮灰着，写「现在不能新建事项」和同样的原因。进行中的事项不受影响。点「在草稿里处理」，进部门详情，工具许可里「这个发布已经没有的工具」单独列出，取消勾选，回组织页，拒绝消失，采用以后新建事项恢复可用。

请你判断：原因的说法你看得懂吗；要你自己去草稿里处理，这个要求合不合理。

### 系统提了一个候选

应该看到：组织页多一块「待采用的候选」：标题、来自元观察、差异、证据、对照结果。这个场景里元观察是开着的，观察者表里它「最近的产出」写「1 个候选」，历史里多一条打开元观察的记录。点「放进草稿」，草稿里教训发现的读取范围变成「缺陷记录、返工与询问」，写理由采用，走的和你自己改是同一条命令。

请你判断：候选里写的差异、证据、对照，够不够你决定采不采用。

## 从 v15 带过来的内容

这些没有改动，在 v16 里照样能看到。每条写在哪一页能看到，详细说明见 [v15 的变更记录](../CHANGELOG.md)（`## [v15]` 一节）。

- A 类事实：首页的项目表（此刻谁在做什么、事项在哪个部门、执行槽位、待你决定）；项目概览的事项、部门、询问、中断、等待模型服务、流转汇总；成果库页三种结论分开计数；部门页的实时输出、手边、等待模型服务、远程结果未知；各处的来源小标记，点开按位置看一条事件，再跳到时间轴。
- B 类七条：第 2 条「定义版本不同」卡片，场景「有等待回答的决定」，在首页；第 3 条桌面会话条，场景「桌面会话进行中」，每页顶部；第 4 条不画；第 5 条内部报表工具的质检部门页写「等待工作」；第 7 条流转页按成果一种一条；第 8 条场景「版本不一致」；第 9 条首页「离开期间的报告」里带「新增」的四项。
- 模型管理：左侧栏底部「模型管理」，连接服务、获取候选、勾选后自动补全与验证、部门使用、失败情形（页面底部「原型演示」里切换）；候选的「测试」按钮和每页 8 个的候选分页也在。「部门使用」仍然是发布带的几个部门，项目里自己加的部门不在这里。
- 系统页：机器、运行与执行槽位、工具与扩展，结构不变。
