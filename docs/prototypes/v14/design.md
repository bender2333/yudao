# V14：填写连接信息，选择模型即可使用

本次原型回答的问题：用户填写 URL 和 API Key 后，能否通过选择模型完成配置，并清楚知道何时可用、失败后如何继续。

依据是用户在本次会话明确提出的操作目标。V14 本轮只制作模型管理部分，外壳、导航、项目页面与画面沿用 [V13](../v13/index.html)。当前定稿仍为 V13；本原型等待用户查看。

## 页面与操作

1. 填写 URL 和 API Key，点击「获取模型，开始选择」。连接信息随这次操作保存，不要求填写连接 ID、名称和凭据引用。
2. 获取时立即显示进行中的状态。成功后收起连接表单，将模型选择放在主要位置；修改 URL 或 Key 的入口仍然可见。
3. 默认显示可自动配置的对话模型，每次先显示八个；提供模型名称、提供方和上游 ID 搜索，以及图像、推理、全部模型和已选筛选。图片生成、语音和向量候选在「全部模型」中可见，明确标注无法执行部门任务。
4. 勾选模型后，自动经历「补全参数」「验证调用」「已启用」。上下文窗口、最大输出、协议、工具调用和图像输入信息由系统处理。自动配置的参数和来源在模型详情中可查看，不要求手动抄写能力表。
5. 首个通过验证的模型自动供产品、工程、质检三个部门使用。选择多个模型后可以分别设置部门，切换立即生效。失败或等待识别的模型不进入部门下拉列表。
6. 已选模型和各自的进度在列表旁持续显示。取消选择会取消该选择的后续结果；刷新候选保留已启用模型和部门配置。更换连接信息后，旧配置的准入立即失效，重新获取并验证。

## 失败与未知

| 情况 | 页面行为 | 用户可以继续做什么 |
| --- | --- | --- |
| Key 被拒绝 | 连接表单旁显示 HTTP 401 和凭据被拒绝的原因 | 修改 Key，再次获取 |
| 地址不可达 | 连接表单旁显示无法连接和检查提示 | 修改 URL 或检查网络后重试 |
| 空列表 | 写明已连接但服务没有返回模型 | 检查 Key 的模型权限、刷新列表 |
| 单个模型调用失败 | 模型旁显示 HTTP 403、权限原因，保留所选项 | 重新验证、修改 Key 或选择其他模型 |
| 容量无法识别 | 明确显示缺少上下文窗口和最大输出，保持不可用 | 重新识别或选择已识别的模型 |
| 搜索无结果 | 显示无匹配和清除入口 | 清除搜索与筛选 |

容量未知时不填写任意数值。真实实现应读取服务元数据，或匹配有来源和版本的模型资料；识别不到的情况需要真实呈现。原型不证明某个提供方实际返回哪些参数，也不证明真实模型测试通过。

## 演示方式

打开 [index.html](index.html)，填写示例 URL 和 Key 即可操作。页面底部「原型演示」可以填入示例，以及切换上述异常场景。

- 正常场景提供 139 个示例候选，其中 12 个对话模型具备示例能力参数。
- 「Key 被拒绝」示例使用含 `invalid` 的演示 Key；修改为其他演示值可以继续。
- 「无法连接」使用 `.invalid` 示例地址；修改为 `https://api.example.com/v1` 可以继续。
- 「模型验证失败」中首个模型被拒绝，其他模型可以继续启用。
- 每个异步步骤使用固定的演示等待，方便查看状态。全部数据、容量和返回结果都是原型示例。
- 原型不发送模型请求、不写入真实目录；刷新页面会清空本轮模型配置。请使用示例凭据。

## 范围与运行

入口、模型页面、增量样式在 V14 内；V13 的公共脚本和样式通过相对路径复用。运行对象仍使用 V13 的外壳接口，`window.Y14` 引用该接口，新增模型状态独立保存在内存中。V13 目录保持原有内容。

直接用浏览器打开 V14 的 `index.html`，或在仓库根目录运行 `uv run python -m http.server 8914 --bind 127.0.0.1`，访问 `/docs/prototypes/v14/index.html#/sys/models`。

本次原型的模型选择和部门设置在模型管理页内演示，其他页面继续使用 V13 的示例业务数据。此处没有修改正式客户端、Provider 接口、模型准入规则和真实配置存储。
