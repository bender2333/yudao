# Provider 配置界面原型

日期：2026-09-15，2026-09-18 按已实现 `harness/web/static/provider-config.js` + `server.py` 对齐补齐。性质：Stage 2 工作包 2.2 的最小界面合同，不是运行代码。

依据：`docs/stage-2-implementation-plan.md` 2.2；底层目录已在 D18 / `harness/provider_catalog.py`。用户此前预留配置原型；实施计划允许最小列表+表单。本目录取代“继续等待”的空缺，不引入项目级第二套目录。

- [可打开预览](provider-config.html)

## 它在系统里的位置

三层不变：

| 层 | 本页做什么 | 不做什么 |
| --- | --- | --- |
| 界面 | 展示系统目录；把增删改、绑定、测试、导入导出变成命令 | 不保存密钥，不改在途 run，不生成运行事实 |
| 业务引擎 | 校验目录、解析凭据引用、冻结新事项的三部门目标 | 不在运行中换模型；压缩与重试仍用该事项已冻结目标 |
| 基础设施 | 读写 `--provider-config` 指向的同一份 JSON；环境变量提供密钥 | 不把密钥写入文件、事件、Git 或浏览器 |

目录是宿主级，不是项目设置。入口在项目列表顶栏「模型与 Provider」，未进入项目也可打开。项目设置里的部门 Prompt 保持原位，二者不混用。

## 一页三块

不做独立子站或新前端框架。沿用现有控制台的字体、色值和窄屏单列。桌面 1440：左列表/右表单；390：上列表/下表单，无横向滚动。

1. **Provider**  
   列表：名称、协议、地址、凭据引用、凭据是否已解析（只显示“已配置 / 缺失”，不显示值）。选中行高亮，点击切换右侧表单。  
   表单：`id`（新建后不可改）、`name`、`protocol`（`responses`；`fake` 只给测试，保存时清空地址与凭据引用）、`base_url`、`credential_ref`（环境变量名）、`timeout_sec`（默认 600）。  
   按钮：新建 / 保存 / 测试连接 / 删除。测试中按钮禁用显示“测试中…”；未保存的新建项先保存再测试。  
   删除前检查是否被任一部门绑定或任一模型引用，有依赖返回 409 并指出位置。

2. **模型**  
   属于某个 Provider。字段：`id`、`model`、`context_window`、`max_output_tokens`。  
   容量必须是正整数；未知则拒绝保存，不套用其他模型。  
   超时不放在模型上，沿用所属 Provider 的 `timeout_sec`。  
   按钮：新建模型 / 保存模型。切换所属 Provider 为原子移动：旧归属不残留同 id，引用旧归属的部门绑定跟随新归属。

3. **三部门绑定**  
   产品 / 工程 / 质检各选 Provider + 模型，另有“未绑定”选项。展示所选模型的窗口和输出上限。  
   三部门可以相同，也可以不同。缺任一部门则不能创建事项。

另有：连接测试、导入、导出。导出即当前目录的 `to_dict()` JSON，不含密钥。

## 命令与生效

| 用户动作 | 系统行为 |
| --- | --- |
| 保存 Provider / 模型 / 绑定 | 校验后写成新的 `ProviderCatalog`，覆盖配置文件，替换内存中的默认目录；顶部消息区显示成功或字段级失败原因 |
| 测试连接 | `POST /api/providers/{id}/test`：解析凭据并发一次最小 Responses 请求；成功显示“连接成功 · 实际上报模型 · 耗时 ms”，失败显示分类后的原因；`fake` 直接返回成功不发请求；不创建事项 |
| 导入 | 整份替换默认目录；校验失败保持旧目录；顶部消息区提示结果 |
| 导出 | 下载脱敏 JSON |
| 已在跑的事项 | 继续使用创建时冻结的快照 |
| 新建事项 | 使用保存后的默认绑定；缺绑定、缺凭据、未知容量、不支持协议时 503，并指出哪个部门 |

`id` 规则与现目录相同：`[A-Za-z0-9][A-Za-z0-9._:-]*`。地址必须是 http(s) URL。

## HTTP

与实施计划 2.2.3 一致，全部走现有 `harness/web/server.py`，不新建服务：

- `GET /api/providers` 列表（含模型与绑定，无密钥）
- `POST /api/providers` 新增
- `PUT /api/providers/{id}` 更新（不可改 id）
- `DELETE /api/providers/{id}` 删除（有依赖则 409）
- `POST /api/providers/{id}/test` 连接测试
- `GET /api/department-bindings` 当前三部门绑定
- `PUT /api/department-bindings` 更新绑定
- 模型作为 Provider 的嵌套资源写在 Provider 的 POST/PUT 体里的 `models` 数组，或同页保存；不另起模型微服务

健康检查 `/api/health` 继续只读。创建事项仍走 `POST /api/projects/{id}/work-items`。

## 明确不做

- 不在表单中粘贴 API key
- 不热重载已冻结事项
- 不自动发现模型、不 OAuth、不按角色回退
- 不把本页放进项目设置，以免被理解成每个项目一份目录
- 不在本阶段做第二协议适配器（除测试用 `fake`）

## 验收路径

1. 打开项目列表 → 模型与 Provider。
2. 新增一个 Responses Provider 和模型，绑定三部门，测试连接看到成功或明确失败原因。
3. 缺一个部门绑定时创建事项被拒绝，提示该部门。
4. 凭据环境变量缺失时提示要补的引用名，不回显密钥。
5. 导出再导入得到同一份非敏感目录。
6. 1440 与 390 均可完成上述步骤。
