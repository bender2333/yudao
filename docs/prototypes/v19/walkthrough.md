# 页面原型 V19 走查

本次调整按[页面结构提案](design-update.md)更新，沿用 V19 的绿色、明暗主题和基础组件。单个角色直接使用对话；多个角色共用「对话、成果库、组织」三个入口，项目设置放在名字旁。

## 打开方式

使用浏览器打开 [index.html](index.html)，无需安装依赖或连接服务。所有操作使用示例数据。刷新后项目、对话和演示进展恢复原样；组织草稿保存在当前浏览器中，可在组织页放弃草稿。

新建项目只需填写名字并选择模板。可选直做、按成果、任务池与包含运维的组织；角色内部的小组从角色详情设置。任务池与运维均标明「设计预览」，不代表正式发布目录已提供这些能力。

直做约 3.5 秒交回结果；最终成果有核验角色时，约 5 秒核验并放行。任务池由用户点击演示认领、交回和核验，不会自动放行。

## 单个角色：个人博客

1. 打开「个人博客」。头部保留项目名字、「查看交付」和「项目设置」，默认显示对话。
2. 已结束事项只显示事项摘要与结果。点击「展开对话」查看原始要求和折叠的角色进展；点击「看这一版」查看文件与差异。
3. 当前事项的问题直接出现，点击回答后继续演示工作。输入框上方始终显示发送用途和后果。
4. 默认「指导工程」会把内容作为指导。选择「开始新事项」时，正在进行的工作会出现在排队说明中；发送新事项后收件人恢复默认。明确选中的指导对象在连续发送时保持不变。
5. 在项目设置中查看名字、文件夹和当前组织。长期目标、模型与高级配置按需展开。模型选择显示实际生效值与跟随来源，保存和恢复跟随会改变同一份项目设置。

## 多个角色直做：活动报名小程序

1. 打开「活动报名小程序」。主入口统一为「对话、成果库、组织」。
2. 宽屏对话旁、窄屏对话上方常驻「协作状态」，直接显示工程主执行、产品按需回应询问，以及各自状态。
3. 点选产品或工程，在同一工作页查看等待原因、回答问题或发送指导。输入区仅显示选中的指导对象和开始新事项，提示区分当前事项指导与部门指导。连续发送保留所选部门。
4. 点击「查看往来」展开当前线程中的最近往来；点击次级「配置」进入部门详情。打开组织，查看输入接收方、完成者与核验安排。
5. 打开工程或产品详情，按需展开模型、Prompt、执行方式、工具与成果关系。

## 直做增加核验角色

1. 新建「一个角色直做」项目并发送第一件工作，在它结束前进入「项目设置 → 查看与调整」。
2. 点击「调整组织 → 添加部门 → 自定义或复制部门」，从起点选择发布提供的质检，加入草稿。
3. 查看结构校验、结束条件和差异，填写理由后确认采用。
4. 第一件工作继续按原来的冻结组织开环完成。之后新建的事项等待核验并放行。

## 按成果协作与可变部门

1. 打开「订单系统重构」。常驻协作状态显示输入接收方、放行条件及每个部门的成果去向，例如「交付 → 质检」「缺陷记录 → 工程」。
2. 部门行区分当前事项和其他事项，质检核验分页时仍保持执行状态。点选部门查看等待原因、其他工作与指导记录；停止当前导出事项后，其他工作和状态仍保留。组织页保留完整的「成果与交接关系」。
3. 点击「调整组织 → 添加部门 → 自定义或复制部门」，填写设计等自定义部门的名字、三项职责说明与模型。
4. 三项说明缺少内容时可以保存草稿，但不能采用。进入角色详情补全后，再查看差异并采用。成员数量和列表随定义变化。
5. 输入接收方、直做的完成者、按成果的最终采纳成果与任务池的单元大小，按协作方式显示。成果和核验的详细定义可从相同页面进入高级配置。

## 任务池：设计预览

1. 打开「任务池 · 设计预览」。协作区显示部门结构和工作单元摘要，分别统计待认领、依赖阻塞、进行中、待核验与已完成。
2. 点击「查看工作单元」。CSV 实现可认领；边界检查等待前置工作完成。
3. 选择角色认领 CSV 实现，交回结果，演示打回后由原认领者修改，再次交回并通过单元核验。部门状态随认领与交回同步变化，分别显示执行中、待单元核验与待整份核验。
4. 前置单元通过后，认领并完成边界检查。此时事项仍未放行，需要单独点击「核验整份交付并放行」。
5. 新事项可以排队；整份交付结束后释放槽位并开始下一件工作。停止事项后，单元不再等待认领或核验。

## 工程内部的中心型小组

1. 在「边缘网关固件」工作页点选工程，原地查看主程等内部角色状态；点击「查看内部工作」查看各自正在做的事。在其他项目的工程详情中，也可以调整为子组织，查看差异并采用。
2. 点击「进入内部小组」，查看该层自己的角色、成果关系和结束条件。页面路径保留外层组织与所在角色。
3. 点击「查看内部线程演示」，演示内部完成后向上层交回提案。页面分别写明本层结束与外层核验，不将内部完成记作整个项目放行。
4. 内部角色模型默认跟随上层；覆盖模型后可恢复跟随。达到两层嵌套上限时，子组织选项禁用并说明原因；核验角色的外包选项禁用。

## 运维：设计预览

1. 打开「线上服务与运维 · 设计预览」，协作区的运维行持续显示健康与部署版本，以及故障成果的去向。点选可指导运维，从「运行环境与部署」进入环境详情。
2. 查看当前部署版本、健康情况、常设授权与故障记录。点击「模拟发现故障」，按定义中的故障来源与接收方建立修复事项；已有事项进行中时排在后面。
3. 修复经项目核验并放行后，选择该版交付并演示部署。部署记录独立于核验结论，故障记录随所选修复交付更新。
4. 打开授权之外的操作，演示用户决定。一次授权不会扩大常设授权。
5. 在其他组织的草稿中可直接添加运维预览；它关注当前最终成果，不增加固定串行阶段。新增部门后环境和授权尚未登记，须在环境页面单独登记。完整故障来源流程由运维预览模板提供。

## 高级配置与原有场景

从角色详情、项目设置或组织进入高级配置时保留项目导航。点击「返回原页面」回到原路径，恢复配置组的展开状态及滚动位置。

原有中断、等待模型、额外事项和决定请求以摘要保留。完整运行详情、组织候选、发布冲突和采用历史均有入口。原型底部的十种场景继续提供演示。
