# 页面原型 v17 走查

这一版按「五份形态、两个层」的目录重画项目的组织：头部先回答四个问题，「换一份」打开目录，新建项目与新建事项用同一份目录，事项的来源写在定义里、每一种都要有部门接。依据是[项目的组织设计说明](../../design/project-organization.md)，下面七份脚本就是它第 5 节的七份脚本，每份给一个同名的示例项目。请你像平时用它一样走一遍，把判断写给架构师。

## 怎么打开一节

- 用浏览器直接打开 `docs/prototypes/v17/index.html`，不用启动任何服务。
- 页面右下角有「场景」菜单，切换不同的情形；补充条里的几个场景也从这里进。
- 内容全部是假数据。刷新页面，数据回到原样；只有「草稿」存在这个浏览器里，刷新以后还在。刷新以后你新建的项目没有了。
- 页面上带紫色「新增」小标签的地方，是这一版新画的，请重点看：组织页头部的四个问题与小图、「换一份」目录、新建项目里的目录与两个层、加部门的起点。
- 项目有七个，每个对应一份脚本：日志清理脚本（一个外包角色直做）、个人博客（一个角色直做）、活动报名小程序（几个角色直做）、订单系统重构（三部门）、线上商城（三部门，用来在目录里看三部门加运维）、内部报表工具（一个角色直做加观察者）、固件升级服务（三部门，工程内部用子组织）。
- 每份脚本分六段：谁、要做什么项目；新建项目选这一级时对话框说什么；第一个事项谁接；中途有哪些页、没有哪些页；怎么结束、页面上写什么；这一级的用户最常做的一个改动。每段先写脚本，再写「在原型里」怎么点、应该看到什么、请你判断什么。

## 脚本一：一个外包角色直做（日志清理脚本）

1. 谁、要做什么项目：已经习惯用外部 agent（例如 OpenCode）的独立开发者，想让 Yudao 管住时间与用量、留下快照与记录；项目「日志清理脚本」。
2. 新建项目选这一级时对话框说什么：事项的来源你的输入与建档由工程（外包）接；工程是一个外包角色，选一个外部 agent；没有核验角色，以开环完成结束并注明外包。
3. 第一个事项谁接：工程（外包）。快照进，外部 agent 在工作区里做。
4. 中途有哪些页、没有哪些页：有事项页、成果与记录；没有流转页，没有所在部门列，没有谁问谁。
5. 怎么结束、页面上写什么：外部 agent 交回快照与差异，经写入口成为提案，被采纳；到时间或用量上限会停。记录与页面写开环完成并注明外包，不写放行。
6. 最常做的改动：换一个外部 agent；采用以后新建的事项用新的。

在原型里：

做什么：

1. 点左侧栏「新建项目」，组织目录里选「一个外包角色直做」，先不新建，看目录下面那块说明；点「取消」。
2. 打开「日志清理脚本」，点右上角「新建事项」，原文随便写一句，看对话框。取消。
3. 看项目标签：只有概览、工程、成果库、时间轴等，没有「流转」；概览的事项表没有「所在部门」列。
4. 点「成果库」，看「清理 30 天前的日志」那一行的结论。
5. 点「组织」，看头部的四个问题和小图。点「修改」，点工程那一行，在「由谁做」里把外部 agent 换成 Claude Code，回组织页，点「采用」，写一句理由。

应该看到：

- 目录卡和对话框说明写「事项的来源：你的输入、建档 → 工程（外包）」「一个外包角色「工程」，外部 agent：OpenCode」「没有核验角色」「怎么结束：工程（外包）交回快照就结束，记为开环完成并注明外包」。
- 新建项目对话框里选了这一级，「工程内部用子组织」一项灰着：外包角色本来就由别人做，不再分形。
- 新建事项的对话框写「这段话先交给：工程（外包）」，并有黄色说明「开环完成」「注明外包」。
- 概览没有「所在部门」列、「谁问谁」、「流转汇总」。
- 成果库里结论是「开环完成 · 没有核验角色 · 是否外包：是」，不出现放行。
- 组织页头部：四个问题各一句；小图从左到右是「事项的来源（你的输入、建档）→ 接它的部门（工程（外包））→ 关注关系 → 核验（没有核验角色）→ 结束（开环完成，注明外包）」；图下面「成果怎么走」只有一行「你的输入、建档 → 工程（外包） → 交回快照 → 开环完成」。
- 采用以后，历史多一条，差异写「工程」由谁做改了外部 agent；在这个事项之后新建的事项用新的外部 agent。

请你判断：对话框里一句话能不能让你放心「外包角色直做」是怎么回事；「开环完成并注明外包」的说法清楚吗；最少的这一头，页面上有没有多余的东西。

## 脚本二：一个角色直做（个人博客）

1. 谁、要做什么项目：做个人小项目、不想要三个部门往返的人；项目「个人博客」。
2. 对话框说什么：你的输入与建档由工程接；一个自有角色，用工程的名字、工具与模型设置；没有核验角色，交完成就结束。
3. 第一个事项谁接：工程。
4. 中途有哪些页、没有哪些页：有事项页与成果；没有流转页，没有所在部门列，没有谁问谁。
5. 怎么结束、页面上写什么：工程交完成，事项结束，记录与页面写开环完成，没有发决定请求。
6. 最常做的改动：加核验，从发布的部门里加上质检，核验工程交的完成；采用以后新建的事项以质检放行结束，已经在跑的事项按原来的组织跑完。补充：新建事项时可以临时选一个角色直做，只影响这个事项，项目的组织不变，记录上写开环完成。

在原型里：

做什么：

1. 新建项目目录里选「一个角色直做」，看说明；取消。
2. 打开「个人博客」，新建事项看对话框；看成果库里「迁移文章」的结论；看「组织」页：头部、部门表（只有工程，多一列「谁交完成」）、「全部跟随发布」。
3. 点「修改」，点「加部门」，起点选「发布的部门：质检」，看显示名、三样说明、工具、写入范围、核验声明都已带上，模型一栏不用选；点「加入草稿」。回组织页看草稿条。
4. 点「采用」，写理由，确认。再点概览的「新建事项」看对话框。
5. 补充：到「订单系统重构」，新建事项，组织里选「一个角色直做」，看对话框，新建；打开这个事项详情里的「这个事项用的组织」。

应该看到：

- 对话框写「你的输入、建档 → 工程」「一个自有角色「工程」」「没有核验角色」「工程交完成就结束，记为开环完成」，还写「工程的名字、工具与模型设置」。
- 个人博客的成果库写开环完成，不写放行，没有「外包」字样；没有流转页。组织页头部小图的「结束」写开环完成，「成果怎么走」一行「你的输入、建档 → 工程 → 交完成 → 开环完成」；页面上有一条提醒，写明加一个核验角色以后交完成就会等它放行。
- 加质检以后，草稿条里「这样改以后事项怎么结束」变成「工程交完成以后等质检放行，打回则工程再做一轮」，开环完成的提醒消失；「成果怎么走」变成「你的输入、建档 → 工程 → 交完成 → 质检」「质检 → 放行 → 事项完成」。
- 采用以后，新建事项的对话框写「质检放行」，没有黄色的开环说明；已经在跑的「更新首页文案」按原来的组织跑完，头部提醒里写有 1 个事项在按旧组织跑。
- 补充：这个事项详情里「这个事项用的组织」写「一个角色直做」，项目的组织页版本没有变，对话框写明「只影响这个事项」。

请你判断：「发布的部门」这个起点你会不会找得到；加质检以后「等质检放行，打回则工程再做一轮」这句话够不够清楚；临时换形态放在新建事项里，会不会误点。

## 脚本三：几个角色直做（活动报名小程序）

1. 谁、要做什么项目：两三个人的小团队，想要「一个人做、一个人把关需求」；项目「活动报名小程序」。
2. 对话框说什么：你的输入与建档由工程接；产品、工程两个自有角色，靠询问交流，工程交完成，产品回答询问；没有核验角色，可以以后加一个。
3. 第一个事项谁接：工程接。
4. 中途有哪些页、没有哪些页：工程询问产品，流转页里看得到询问；有所在部门列。没有质检的往返。
5. 怎么结束、页面上写什么：工程交完成，事项以开环完成结束；组织页提醒写明加一个核验角色就会等它放行。
6. 最常做的改动：加一个自己的角色「运营」，回答活动规则的询问，必填它对什么负责、凭什么判断、怎么工作。

在原型里：

做什么：

1. 新建项目目录里选「几个角色直做」，看说明；取消。
2. 打开「活动报名小程序」，看项目标签（有「流转」）和概览的事项表（有「所在部门」）。点「流转」，找「询问」「回答」两行。
3. 点「组织」，看头部、部门表（产品、工程两行，「什么时候开工」一列，多一列「谁交完成」）和提醒。
4. 点「修改」，点「加部门」，起点保持「空白」，显示名写「运营」，三样说明先留空，模型选一个，不勾关注与交出的成果，点「加入草稿」。看草稿条，再点运营那一行填好三样，回组织页看拒绝消失。放弃草稿即可。

应该看到：

- 对话框写「你的输入、建档 → 工程」「产品、工程两个自有角色，靠询问交流，工程交完成」「没有核验角色」，还写「可以以后加一个」。
- 新建事项对话框写「这段话先交给：工程」。
- 流转页里有「询问」（工程 → 产品：候补要不要开放）和「回答」（产品 → 工程）；没有缺陷记录、放行。
- 组织页头部：「成果怎么走」两行：「你的输入、建档 → 工程 → 交完成 → 开环完成」「工程 → 询问 → 产品 → 回答 → 工程」；部门表里产品那一行「什么时候开工」写「在收到指导、询问时」，工程那一行写「接「你的输入」「建档」这几种来源，也在收到指导、询问时」，「谁交完成」一列只有工程。
- 页面上有一条提醒：没有核验角色，事项交完成就以开环完成结束；加一个核验角色以后交完成就会等它放行。
- 加运营但三样没填：草稿条里拒绝「新增的「运营」还缺「它对什么负责」、「凭什么判断」、「怎么工作」」，「采用」灰着；另有提醒「运营不交出任何成果，只回答询问」；填好以后拒绝消失。

请你判断：产品与工程之间「靠询问交流」在流转页里你看不看得懂；没有质检的往返，页面有没有给你留下多余的东西；加一个自己的角色这条路好不好找。

## 脚本四：三部门（订单系统重构）

1. 谁、要做什么项目：要独立核验的团队项目；项目「订单系统重构」。
2. 对话框说什么：默认选项；你的输入与建档由产品接；产品、工程、质检按成果轮转，质检核验，放行才结束。
3. 第一个事项谁接：产品。
4. 中途有哪些页、没有哪些页：有流转页、所在部门列、谁问谁；PRD、交付、缺陷记录一路可见。
5. 怎么结束、页面上写什么：质检放行，页面写放行与核验角色的显示名。组织页显示三个部门，质检标核验角色，全部标跟随发布；没有改动时事件序列基准与交给模型的请求快照一字不变。
6. 最常做的改动：加一个设计部门，新建一种成果「界面稿」，工程关注它；事项跑完；缺「它对什么负责、凭什么判断、怎么工作」三样时被拒绝；模型只写在本项目，全局「部门使用」没有多一行。

在原型里：

做什么：

1. 点「新建项目」，看目录默认选在「三部门」；取消。
2. 打开「订单系统重构」，点「新建事项」看对话框，取消。看项目标签（有流转）、概览（有所在部门、进行中的询问、流转汇总）。点「流转」「成果库」看成果一路可见。
3. 点「组织」，从上往下看：头部、部门表、观察者（三个都关着，不进部门表）、历史（一条）。
4. 点「修改」，点「加部门」，起点保持「空白」，显示名「设计」，三样说明先留空；关注的成果勾「PRD」；勾「新建一种成果」，名字写「界面稿」，「让哪些部门关注这种新成果」勾「工程」；模型选一个，点「加入草稿」。回组织页看拒绝；点设计那一行把三样填好；回组织页采用。最后到左侧栏「模型管理」看「部门使用」。

应该看到：

- 对话框写「你的输入、建档 → 产品」「产品、工程、质检，按成果轮转」「质检核验工程的交付」「质检放行才算完成，打回时工程返工」，标「默认」。
- 新建事项写「这段话先交给：产品」。
- 组织页头部「成果怎么走」五行：「你的输入、建档 → 产品」「产品 → PRD → 工程、质检」「工程 → 交付 → 质检」「质检 → 缺陷记录 → 工程」「质检 → 放行 → 事项完成」；头部写「全部跟随发布」，部门表三行的来源都是「跟随发布」，质检标「核验角色」。
- 成果库里放行写「放行（质检）」，也就是核验角色的显示名。
- 加设计后：拒绝「新增的「设计」还缺……」，「采用」灰着；工程的关注里多了「界面稿」；填好以后拒绝消失，采用以后设计部门出现在项目标签里。「模型管理」的「部门使用」没有「设计」；设计用的模型写在这个项目的部门设置里。

请你判断：「成果怎么走」五行你能不能一眼读懂；头部那张小图对你理解组织有没有帮助；三样必填放在这个位置，你会不会漏。

## 脚本五：三部门加运维（线上商城，只写到在目录里看到它）

1. 谁、要做什么项目：已经上线、要长期运行的服务；项目「线上商城」，现在用三部门。
2. 对话框说什么：在新建项目的下拉与组织页「换一份」的目录里看到「三部门加运维」灰着、标「阶段三」；读得懂它多一种事项的来源「运维发现的故障」；知道现在不能选。
3. 第一个事项谁接：阶段三再写。
4. 中途有哪些页、没有哪些页：阶段三再写。
5. 怎么结束、页面上写什么：阶段三再写。
6. 最常做的改动：阶段三再写。

在原型里：

做什么：

1. 点「新建项目」，在组织目录里找「三部门加运维」，点一下它。
2. 取消，打开「线上商城」，点「组织」，点「换一份」，找同一张卡。
3. 看项目本身：概览里有普通的事项，有等待模型服务的状态，组织页和三部门一样。

应该看到：

- 目录里「三部门加运维」那一张卡灰着，右上标「阶段三」，圆点不能选，点了也选不中；卡上写「多一种来源「运维发现的故障」」，其余三问写「阶段三再写」。画法同左侧栏「预留入口」的元观察、演化、经验。
- 页面其余地方（组织页、部门表、小图、成果怎么走）没有任何运维部门。
- 「线上商城」是普通的三部门项目，没有运维的声明、页面与校验。

请你判断：灰着的卡有没有让你读懂「它多一种来源」；知道它现在不能选以后，会不会误以为项目缺东西。

## 脚本六：观察者层（内部报表工具）

1. 谁、要做什么项目：长期跑、常不在场，想有人在事项外面看着有没有来回打转的用户；项目「内部报表工具」，用一个角色直做加观察者（说明观察者层能叠在任何一份形态上）。
2. 对话框说什么：在新建项目的组织下拉下面勾「加观察者」。
3. 第一个事项谁接：工程，与不加观察者时相同。
4. 中途有哪些页、没有哪些页：组织页有「观察者」一块，系统页里看得到最近的产出；观察者不进部门表，没有流转页。
5. 怎么结束、页面上写什么：不改事项怎么结束，仍是开环完成；观察者不能核验；关掉以后不再写入，它的写入只经写入口。
6. 最常做的改动：改一个观察者的读取范围，采用以后立即生效，不随事项冻结。

在原型里：

做什么：

1. 点「新建项目」，选「一个角色直做」，勾「加观察者」，名称随便写，点「新建项目」。看新项目的组织页，再回首页。
2. 打开「内部报表工具」，点「组织」：看头部、部门表（一行）、观察者那一块。
3. 点「修改」，把教训发现的读取范围改成「缺陷记录、返工与询问」，点「采用」，写理由。
4. 回概览，打开事项「销售报表导出」，看详情里的「这个事项用的组织」。
5. 左侧栏「工具与扩展」看观察者的说明。

应该看到：

- 新项目里「加观察者」勾上以后，组织页观察者块里教训发现、振荡检测是开，元观察是关；项目标签写「一个角色直做（改过 2 处）」。
- 内部报表工具的头部四个问题与个人博客相同，仍是「工程交完成就结束，记为开环完成」；观察者三行不在部门表里；项目没有流转页。
- 观察者块里教训发现、振荡检测各有「最近的产出」（例如 3 条教训证据）。
- 采用以后读取范围立即变了，历史多一条，差异只写观察者的读取范围；事项详情「这个事项用的组织」仍写和现在「相同」，因为那份比较不含观察者。

请你判断：观察者放在组织页的一块里，你找不找得到；关开与读取范围写成「不随事项冻结」够不够清楚；观察者不能核验，页面有没有让你误会。

## 脚本七：部门内子组织层（固件升级服务）

1. 谁、要做什么项目：项目大、工程一个角色忙不过来；项目「固件升级服务」，用三部门，工程的「由谁做」选子组织（中心型小组）。
2. 对话框说什么：新建项目时可以勾「工程内部用子组织（中心型小组）」；也可以建好以后在部门详情的「由谁做」里选。
3. 第一个事项谁接：产品接，与三部门相同；工程的一轮工作开一个子事项，它的来源是上一层交来的任务。
4. 中途有哪些页、没有哪些页：部门页显示内部角色在做什么，链到子事项；路径「组织 › 工程 › 内部」同一个页面。
5. 怎么结束、页面上写什么：子事项的结果作为这个角色的提案回到上一层，照常过裁决；超过嵌套上限被拒绝，层数到上限时「由谁做」不再能选子组织。
6. 最常做的改动：在内部去掉探索者。

在原型里：

做什么：

1. 点「新建项目」，选「三部门」，勾「工程内部用子组织（中心型小组）」，新建；看新项目的组织页与「工程」部门页。
2. 打开「固件升级服务」：看项目头部标签、组织页的部门表（工程标「内部是子组织」，名字下面写内部的四个角色）。
3. 点「工程」标签：看「内部的角色在做什么」，点其中一项的子事项链接。
4. 在组织页点「工程」一行进部门详情，看「由谁做」，点「打开内部」，看路径「组织 › 工程 › 内部」。
5. 在内部页点「修改」，在探索者那一行点「去掉」，点「采用」，写理由「内部不要探索者」。
6. 在内部页点「修改」，进主程的详情，「由谁做」选「子组织」，点「打开内部」，进审查者的详情，看「由谁做」里「子组织」。放弃草稿。

应该看到：

- 勾子组织的新项目：组织页头部「谁做」写「产品、工程（内部是子组织）、质检，按成果轮转」，工程那一行标「内部是子组织」，部门详情「由谁做」是子组织并有「打开内部」。
- 固件升级服务的部门页多一块「内部的角色在做什么」，列出工程架构师、主程、探索者、审查者各自在做什么和对应的子事项。
- 「组织 › 工程 › 内部」同一个页面：每一行是一个角色；事项的来源是「上一层交来的任务」，由工程架构师接；「成果怎么走」最后一行写「审查者 → 放行 → 结果作为提案回到上一层」；没有观察者一块。
- 去掉探索者以后，历史差异写「工程 › 内部：去掉部门「探索者」」，工程架构师对调研结论的关注一起去掉。
- 层数到上限：审查者的详情里「由谁做」的「子组织」灰着，写「已到嵌套上限，不能再选」。

请你判断：子组织和上一层用同一个页面，你会不会迷路；「由谁做」选子组织这个入口好不好找；在内部去掉角色的路径你觉得顺不顺。

## 补充条

按机制排的几条，脚本里没有单独写到。

1. 把质检改名并采用（订单系统重构，先用右下角场景「订单系统重构：改过 1 处，有事项按旧版本跑」也可以）：点「修改」，质检那一行点「改名」，改成「验收」，看草稿条，点「采用」，先不写理由确认，再写理由确认。应该看到理由为空时对话框写「理由不能为空」；采用以后项目标签、部门表、概览里事项的原因、成果库里的「放行（验收）」一起变，历史多一条；打开进行中的事项「订单列表分页」，「这个事项用的组织」仍写旧版本、和项目现在的「不同」，打开那一份，部门还叫「质检」。模型仍跟随「部门使用」里原来那一行。请你判断：改名只改名字、不改身份，页面上看得出来吗。
2. 在草稿里去掉质检再改回：点「修改」，质检那一行点「去掉」，看提醒「事项最后采纳的成果没有核验角色核验，事项以开环完成结束」和「这样改以后事项怎么结束」变成「交了完成就结束，记为开环完成」，「采用」仍可用；采用，写理由；再新建事项，对话框多一块黄色的开环完成说明。回组织页，在历史里找到去掉那一条之前的那一条，点「改回这一条」，采用；再新建事项，对话框又写「质检放行才算完成」。历史里每一次都在。请你判断：「改回」和「放弃草稿」你分得清吗。
3. 拒绝与提醒：在订单系统重构的草稿里试：去掉产品，出现拒绝「有一种事项的来源没有部门接」，逐条写明是「你的输入」「建档」，并给出「改给：工程」之类的按钮，「采用」灰着；点按钮改给工程接，拒绝消失。在头部「事项的来源由谁接」里每一种来源一行下拉，也能改给别的部门。其他拒绝：在「编辑定义」里写一个不存在的字段（未知的字段）、在「编辑定义」里让质检核验自己（谁能拒绝谁有环，部门详情的下拉里不给选自己）、给设计部门留空三样说明；提醒：去掉质检（开环完成）、把质检的模型换成不能看图像的模型。提醒都不挡采用。请你判断：「没有部门接」的原因和改法写得是否清楚。
4. 版本与理由：理由为空被拒绝（见第 1 条）。草稿的基准是你看到的组织版本：先点「修改」做一点改动，再用右下角「场景」切到「发布改了三部门」，草稿条下写「你看到的组织版本已经变了」，已按新的版本重新校验。命令重发不重做、采用时版本被别处改过的拒绝，原型里没法演示（只有一个浏览器），在设计说明的验收里。
5. 发布升级：场景「发布改了三部门」：组织页写明和上一个事项用的组织相比，工程的工具许可增加「迁移脚本检查」；工程的部门详情里工具许可有新工具。场景「发布的改动合不到一起」：订单系统重构带着本项目加的「只读数据库（MCP）」，发布不再带这个工具，组织页黄色说明写明原因，「新建事项」灰着并写同样的原因；点「在草稿里处理」，取消勾选，拒绝消失。场景「系统提了一个候选」：组织页多一块「待采用的候选」，放进草稿后走同一条采用命令。
6. 和某项目一样：点「新建项目」，组织选「和某项目一样」，下拉里选「固件升级服务」：写明复制什么、不复制什么；新建以后，新项目的组织页是三部门、改过 5 处，硬件适配的部门详情里模型和 Prompt 都在，设置页里没有源目录。
7. 旧组织的部门：在订单系统重构里去掉质检并采用，项目标签出现「质检（只在旧组织里）」，因为还有事项在按旧组织跑；概览的部门表里也标。打开进行中的事项详情的「这个事项用的组织」，打开的是它冻结的那一份，里面还有质检。

补充：目录里的任何一份形态与两个层，都不改事实与裁决、循环两层，这一条是代码上的验收，原型画不出来。
