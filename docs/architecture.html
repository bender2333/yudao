Yudao 总图

三个部门围着同一份事实循环，写入先过门，结论靠独立的证据。固定不变的只有四样：循环、边界、裁决、独立的证据；部门与轮转方式都是填进去的内容。鼠标放到方框上看对应的技术名词与状态。

怎么运转

固定的结构填进去的内容 已建建了一半未建
独立的证据主机跑的检查回执、另一个模型的判断、你的回答。不信部门自己说的。
观察者只看，只出证据与提案，不动手。
循环（固定）
界面你看到的页面与画面，只读事实；命令从这里发。
产品意图 → 要求（PRD）。裁决目标与取舍。
工程要求 → 交付。写代码、自测、交快照。
运维（以后）监控与发布。
一份事实发生过的事只记一份，只追加，谁都不能改。部门之间的询问也在这里。
轮转方式
按成果任务池（以后）
按成果：谁关注的成果有了新版本谁开工，质检放行才结束。任务池：发布、领取、完成、打回。
质检交付 → 缺陷或放行。只有它能放行。
下一个部门加部门只写声明。
产品 → 工程 → 质检 → 放行或打回工程；任何部门随时可以询问另一个部门
模型与工具调模型、改文件、跑命令、查网络；本机或远程。
裁决与边界每次写入先过这里：有没有资格、引用的是不是最新、到没到上限。保证一定会停。
评价评测题与判分器、发布检查。在系统之外，被开发的版本读不到。

什么能动

可以整体重写部门的循环、装配、执行、模型与工具、界面、观察者。重写以后外面看不出区别。
只能向后兼容薄驱动与三道合同（轮转、装配、执行），对外的合同。字段只增，带版本。
只由你改一份事实的写入口、裁决、边界、评价材料、看门狗。改之前你批准。
定义带版本的数据。部门、角色、工具、上限住在这里。改定义不改代码，能撤回。
