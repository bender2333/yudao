什么能动按「能不能被系统自己改」分三环

可以整体重写路由实现、装配实现、执行实现、模型与执行环境的适配、投影、画面、观察者。重写以后外面看不出区别。
只能向后兼容三道槽位契约（路由、装配、执行）、骨架事件、对外的合同、定义的格式。字段只增，带版本。
只由你批准一份事实的写入口、裁决、边界、薄驱动与插件加载、评价材料、看门狗。系统可以提案，生效要你批准。这说的是运行中的系统改自己；阶段一由外部模型开发这个仓库，改这一环的工单不事前批准，守的是内核测试、清单检查与测试覆盖（2026-10-27）。
定义带版本的数据。部门与角色、谁能拒绝谁、判定点、登记的机器、路由实现与它自己的定义、工作单元的大小、限定采用的范围、上限、停止原因清单，都住在这里。改定义不改代码，能撤回。

交叉演进：谁的定义与角色材料不由谁自己改；谁改谁从谁评价谁反推，被谁评价就不能改谁。工程被质检评价，所以工程不改质检的材料。

一轮工作的经过两种轮转方式共用一套状态词

下面的状态对一个部门成立。按成果时，状态由关注的成果推动；任务池时，由认领的工作单元推动。工作单元有多大是定义里的参数，池子允许一个单元就是整个事项，那时它就是按成果。

两环的关系：外环的「一轮工作中」就是内环在转；内环每转一圈写回一次事实，外环只看写回的事实决定下一步。你中途的指导是部门关注的成果：部门在等待时，指导让它开始一轮；在一轮工作中时，指导在下一步作为通知加入。

  • 每一步先问边界：时间、次数、重试、嵌套深度来自定义；到了就停，原因写进封闭清单里的一条。
  • 判定点：需要判断的小问题（挑上下文、含糊的读法）可以问一个小模型，答案先写成事件再被使用；重放时读事件，不再问模型。下游有独立核验兜底时默认继续，没有就升级成决定请求。
  • 增量与整份：任务池模式下每个单元各自核验，但放行门仍是整份交付对要求的一次核验。

要守的缝十道在系统里，三道在系统外

一道缝连接两边，各自可以重写，合同不能偷偷改。已定：规矩不再改，子架构师现在就守；未定：我还在定，先别依赖。每张卡写两侧、保证什么、规矩，以及交换什么；交换的是意思，不是类型，代码里叫什么由子架构师定，写在设计说明里。所有合同带版本，字段只增。

写入口已定一切写入方 ↔ 一份事实事实只从这里进，进了就不改。
  • 先过裁决与边界再写
  • 同一事务里核对执行权、派发编号与版本
  • 只追加；按消息身份去重
交换：消息身份、事项的执行权编号、这一轮的派发编号、期望版本、来源（部门、角色、工作单元）、内容（提案、回执、模型判断、你的回答、观察者信号）、证据引用。
路由已定薄驱动 ↔ 路由实现换轮转方式，循环本身不动。
  • 只回答谁开工、一轮怎么结束、事项怎么结束
  • 只读事实与冻结的定义，自己从事件折叠要用的状态，不存别的
  • 部门的名字不进代码；每种路由带自己的定义
交换：入：只读事实、冻结的定义、最新事件。出：下一步谁开工（部门或工作单元的认领）、这一轮怎么结束（继续、询问、等你、核验、结束）、事项是否结束及原因。
装配已定执行 ↔ 装配实现一轮看到的是事实的一个视图，不改事实。
  • 只读事实、定义与待并入的指导
  • 同样的事件重放出同样的请求；判定点的选择先写事件
  • 交给模型的那份与清单记进事实
交换：入：只读事实、角色定义、待并入的指导。出：交给模型的每一个字节、上下文清单（指令、意图、有效合同、摘要、放进去的事件位置）。
执行已定薄驱动 ↔ 执行实现一轮里的每一步都停得下来。
  • 每一步先问边界
  • 工具调用经裁决；结果写回事实，不自己存
  • 外包角色是执行的一种实现：全新的状态目录、无历史的快照，模型与工具走受控入口；只限有下游独立核验的角色
交换：入：装配结果、角色的工具。出：完成提案、工具请求、询问。每步前：用量与上限 → 继续或停止。
模型已定执行 ↔ 模型服务换模型不改循环。
  • 每次请求解析一次调用目标
  • 尝试与用量记进事实；重放读事件不再调模型
  • 凭据只在控制主机，不进事实与导出
交换：入：请求字节、调用目标。出：尝试记录、模型输出事件、用量。
动作已定工具 ↔ 执行环境每个动作有回执；结果未知时有核实办法。
  • 按类别带合同：成功证据、核实方法、能否取消
  • 本机与远程同一份合同
  • 工作区每次从封存快照建；环境可以温热
交换：请求：动作身份、起点快照、命令或改动、核实方法、能否取消。回执：退出状态、输出、终点快照、前后差异。
投影已定一份事实 → 读的人任何投影都能从事实重算。
  • 内核的最小投影是骨架的一部分，只给裁决读；应用可以读，但不为应用加字段。它不在这道缝里
  • 应用的投影（轨迹、图谱、状态视图）推倒重算，不写回事实
  • 骨架事件只增，应用事件可以排空
交换：折叠函数：当前状态 + 一条事件 → 下一状态；从头重算：事件序列 → 同一状态。
接口已定页面、命令行、评测、观察者 ↔ 应用层外面只经这里读与发。
  • 只有命令、查询、事件流三种
  • 命令带身份，重发不重做；事件流按位置续
  • 带版本号；改了合同版本必升
交换：命令（带身份）、查询（只读快照）、事件流（从某个位置起）。
画面已定翻译层 ↔ 画面层画面整个换掉，事实与页面不动。
  • 画面只收元件断言与动作，不读事实
  • 每条断言带回链到事件
  • 播放节奏归画面，回放走同一份合同
交换：元件断言（元件、状态、回链）、播放参数。
定义已定定义文件 ↔ 加载与校验改定义不改代码，能撤回。
  • 带版本；创建事项时冻结
  • 字段只增，旧文件新版本能读
  • 采纳前校验谁能拒绝谁无环、末端有独立证据
交换：版本、部门与角色（关注的成果、目标、证据来源、可见范围、工具许可）、谁能拒绝谁、判定点、登记的机器、路由实现与它的定义、工作单元的大小、限定采用的范围、上限、停止原因清单。

系统之外的三道

评价已定评价材料 → 系统被开发的版本读不到评它的题。
  • 只经接口层操作，像用户一样
  • 材料由运行中的上一版提供
  • 只由你改
交换：题、说明书、判分器在外面；经接口的命令与查询；判分看数据库与文件产物。
观察者已定观察者 ↔ 接口（读）与写入口（写）只看，不动手。
  • 按读取范围经接口读事实
  • 证据、提案与振荡信号都经写入口写入，经裁决
  • 振荡信号是边界的输入：内核按定义停下受影响的分支，交给你
交换：读取范围；写入：统计证据、改进提案、振荡信号（哪个事项、哪条分支、依据的事件）。
看门狗未定看门狗 ↔ 实例候选失败能退回。
  • 在进程外，不依赖 Yudao 的代码
  • 两个槽位；心跳、金丝雀、观察期指标
  • 只由你改
交换：健康探针、切换命令、排空命令。

自举与验收两层自举，三层验收

第一层：把 Yudao 当普通项目开发下一个版本
  • 改的对象是整个仓库，包括内核；内核的改动生效前要你批准。
  • 作为普通事项走三部门循环：工程改，质检在独立副本上核验并签回执。
  • 发布：新版本在候选槽旁路启动，稳定槽先排空、保留为退回点。
  • 看门狗在进程外检查：心跳、金丝雀任务、观察期指标；超时或不过就切回稳定版。
第二层：按运行证据改自己的组织与规则
  • 改的对象是定义与角色材料：部门与角色声明、关注的成果、可见范围、上限、判定点、经验教训。
  • 观察者给证据与提案；谁的定义与材料不由谁自己改。
  • 经独立评价通过后限定采用：只在指定范围（某类事项、某个比例）生效，不覆盖默认定义。
  • 事项创建时冻结定义版本，所以限定采用版与基线版能直接比较；指标变差就撤回，不重启、不回滚代码。
  • 降解走同一条路：某类工作连续成功、零返工，就把它的处理者从模型换成确定性程序，外面的合同不变。
验收层查什么怎么判
内核给定事件序列，状态与决定。用真实存储，不用替身。同样的事件重放出同样的状态；重放不调模型。
缝十三道合同的字段兼容、部门交接产物的结构、超出上限时的停止原因。合同快照核对，确定性断言。
真实场景操作代理按用户说明书与一句话目标操作真实界面。外面的确定性代码查数据库与文件产物判分；题对被测版本不可读。

拆开部署只有一份的只有一份事实

现在全部跑在一台电脑的一个进程里。将来要拆，拆的线就是第四节的缝：缝过了网络，合同不变，只多了超时与结果未知两件事。谁放在哪台机器写在定义里。

只有一份可以多份，放哪都行只读，随便几份任何登记的机器
  • 只有一份：一份事实与它的写入口、裁决、边界、薄驱动，模型凭据也只在这里。拆开时它是一个服务，别的都经网络来写；它不复制，所以不用分布式锁，认领也不用锁：向那条流写一个事件，写入口核对版本，两个认领只有一个成功。
  • 可以多份：部门成员。一个成员就是一个会话，放在哪台登记的机器都行，同一部门可以有几个成员同时在不同的地方；质检可以在另一个平台上重建副本，拿到错误独立的回执。工具、执行机器、模型服务同样。
  • 只读：投影、页面、观察者。从事实重算，想要几份有几份，坏了丢掉重算。
  • 要过网络的缝：写入口、动作、模型、接口四道。合同照旧，多出的只有超时与结果未知。
  • 部署是定义，不是代码：谁放在哪台机器写在带版本的定义里，换部署不改代码，能撤回。

拆开以后的三个硬问题

问题怎么解
工作区在别的机器上执行节点不保存跨激活的状态。每次激活从封存快照建工作区，只含这次要的文件，不带历史；上次被拒绝的尝试留下的东西不会污染这次。环境（依赖、编译缓存）可以温热。
消息丢了、重发了、迟到了过网的消息都带身份，写入口按身份去重；执行权与派发编号只由控制主机发；重派先经写入口写事件，旧编号交回的结果只记录不接纳。
进程停了又起控制核心是按事件重放的状态机，没有事件库之外的第二份事实。重启丢掉内存里的会话，从已提交的事件恢复；结果未知的在途动作按动作合同的核实方法查，查不到就从最近的快照重新装配执行。
