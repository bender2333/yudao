## 已确认

- 部门需要查阅资料、库与接口文档、检查方法与标准（产品、工程、质检的探索者职责）：提供网络取回，以及经官方 MCP SDK 接入、写在项目设置中的 MCP 工具。
- 搜索经 MCP 提供，Yudao 不内置搜索工具；M3 试用与验收使用 Exa 官方 MCP。
- 取回与项目设置中的 MCP 服务器在控制主机上运行，与 run 的执行位置无关，凭据只在控制主机（ADR-0025）。
- 三个部门始终都有取回工具，任何 http 与 https 地址都可以取回。每个项目各自在项目设置中写明 MCP 服务器（怎样启动或连接、哪些部门可以使用），设置带版本，事项创建时固定版本；服务器提供的工具全部直接提供给可以使用的部门；项目设置中没有 MCP 服务器时部门没有 MCP 工具。MCP 服务器子进程得到 Yudao 进程的全部环境变量，加上项目设置中写明的变量。
- 每类动作有恢复契约：取回与 MCP 工具结果未知时，作为工具结果交还发出它的会话，写明执行被中断、结果未知，附上已经收到的内容，由模型决定是否重新执行。
- 取回只发 GET，不带凭据与 Cookie，Yudao 服务自己的接口拒绝，因为部门能借它读到别的部门的工作过程与全部事件，也因为自举时被开发的实例与运行的实例在同一张网里；试用会话的浏览器使用同一条拒绝规则。
- 取回的内容与 MCP 的结果保存为外部来源工件，工具结果分页返回，可以作为「外部文档」类证据。
- 评测期间两边都不联网。
- 界面：项目设置的「MCP 服务器」一节、调用显示、系统「工具与扩展」页；不做新的原型。
- 2026-10-12 按 [ADR-0035](../adr/0035-mcp-and-skills-move-into-stage-3.md)：远程 MCP 服务器的 OAuth 登录、MCP 的提示与资源、服务器向用户请求输入不再是「不在范围内」，作为 MCP 扩展放在 Stage 3 的 M5（#494），本需求的 3.2B 不包括它们；SSE 传输、采样与 roots 继续不做。
