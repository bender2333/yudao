# D42 进程外运维代理与页面的边界

状态：有效。依据：[总图](../architecture.html)第一节「页面」方框与系统之外的「画面」方框、第四节「接口」「定义」「动作」三道缝、第五节第一层自举；设计：[进程外运维代理与通用命令行设计说明](../design/external-ops-agent.md)、[应用层与接口层设计说明](../design/app-and-interface.md)、[网页界面的提供与发布设计说明](../design/web-interface-and-release.md)。路线位置：[总体路线图](../program-roadmap.md)第 2 节「职能之间：真实项目」。

## 背景与职责区分

项目组织里的「运维」职能在循环内运行，按常设授权负责该项目已交付目标软件的部署、日志与状态观察以及发起修复事项；「进程外运维代理」运行在 Yudao 服务进程之外，协助用户配置与维护 Yudao 自身，两者面向的对象与所处边界彼此独立。

## 已确认

1. 页面的职责收束在高频观察与交互：查看循环状态与工作经过、回答决定请求、输入日常意图与职能指导、一键选用预设形态，以及设置页「高级」中的只读总览与历史恢复；浏览器内的自定义组织草稿表单、原始定义编辑视图、跨项目复制界面与新建事项前端临时选形态入口不再建设，后续不再为低频配置与系统调优深入设计专用配置表单与专属界面自动化测试。
2. 画面（楼、机房、城）属于独立的空间投影与高带宽指挥场景，与常规配置页面性质不同，继续按[总体路线图](../program-roadmap.md)第 4 节自己的步骤重点推进。
3. 低频配置、环境接入与日常巡检交给运行在 Yudao 服务进程之外的通用智能体（进程外运维代理）：用户通过日常使用的外部编程智能体，加载随 Yudao 发布包提供的运维技能，调用 Yudao 通用命令行完成配置、查询与事件等待。控制核心内部不内置拥有特权写权限的运维智能体。
4. 进程外运维代理对系统的改动按性质分三条通道进入，运行中的 Yudao 服务进程不提供热加载或动态执行任意代码的入口：
   - 第一条通道（定义、参数、模型目录、机器与项目设置）：经第四节「接口」的缝调用已登记的命令与查询；改动经过结构校验、按基准版本核对并写入事件日志，支持通过撤回命令恢复；模型服务的明文凭据只经凭据命令或控制主机数据目录的环境文件传入，不进入事件、日志、上下文与导出。
   - 第二条通道（动态脚本与外部工具扩展）：落在第四节「动作」的缝外侧，放入项目工作区的执行环境或配置为独立的 MCP 工具进程，按工具许可执行并返回动作回执，不进入控制核心进程。
   - 第三条通道（修改 Yudao 自身的代码）：按第五节第一层自举作为 Yudao 代码仓库的普通开发事项推进，在隔离工作区修改代码、运行测试并经过独立核验；触及内核清单路径时发出「内核修改」决定请求由用户批准；实例升级经过排空、发布检查与看门狗槽位切换，健康检查失败时回退到稳定槽位。

## 验收标准

- 通用命令行能够经网络连接运行中的 Yudao 服务，完成能力清单读取、单项命令与查询的合同说明读取、任意已登记查询的读取、任意已登记命令的幂等提交，以及有界事件流订阅。
- 发布包内置面向进程外运维代理的运维技能文档，可通过命令行读取全文或安装到指定的外部智能体技能目录；技能写明先读取后修改与基准版本规程、凭据隔离边界、三条改动通道的流向与常见运维规程。
- 外部智能体或自动化脚本仅凭通用命令行与随包运维技能，即可在无浏览器介入的条件下完成模型服务连接与选用、项目与组织形态切换、界限内参数调整与撤回、事项发起与异步事件等待。
