# D21 模型请求、原始数据与用量观测

状态：有效。依据：[总图](../architecture.html)第一节「页面」方框与第四节「投影」「接口」的缝；设计：[应用层与接口层设计说明](../design/app-and-interface.md)、[模型管理设计说明](../design/model-management.md)。路线位置：[总体路线图](../program-roadmap.md)第 5 节判据二「能度量」（阶段一：模型尝试、用量与主机回执）与判据四「看得见」。

界面提供可观测性：展示原始的请求、原始数据与 token 统计等信息，参考 Oh My Pi 的状态 Web 页面。

## 用户需要的查看路径

任务内观测入口 -> 按部门、状态或请求/模型搜索 -> 一次模型尝试 -> 概览、Request、Response、事件原文；同一次逻辑调用的失败和重试可互相切换。部门 Context 可以直接进入与该快照对应的请求，返回时仍保留原部门与查看位置。

用量统计与请求记录使用相同筛选范围，按部门及 Provider/模型分组，展示已上报用量、覆盖率和进行中次数。当前任务是范围边界，本项不建设跨项目分析平台。

## 采集与事实边界

- 部门协作请求、逻辑模型调用、物理尝试是不同对象，分别关联；浏览一次失败记录或切换尝试只查询历史，不重新调用模型。
- `ModelRequest.request_id` 和 `timeline.requests` 指部门协作请求。模型调用需按任务、部门激活和逻辑根步骤建立确定身份，每次尝试关联实际步骤及尝试次序；协作请求引用单独保留，不能用它打开模型详情或聚合重试。
- Context 工件说明装配内容及来源；Raw Request 还需保留模型、工具、输出限制、协议等实际请求内容。装配记录不冒充完整发送内容，SDK 请求对象和最终传输内容的范围需说明。
- 保存已取得的完整 Provider 响应对象及必要的流式事件原文；即时片段、失败、取消和缺少终态分别可见。只有输出 item 与 usage 时明确采集范围，不能从它们拼造完整 Raw Response。
- Web SSE 是内部事件通知，不是 Provider 原始流；新增采集需分别标注来源。每次实际尝试的开始、结束与耗时单独保存，准备但未发出的记录保持区别；部门整次激活耗时不能冒充单次请求耗时。
- 请求开始前记录实际选用的 Provider/模型配置；响应返回模型单独记录，无响应保持未知。沿用 D18 的任务绑定及脱敏约定。
- 原文工件、追加事件及其查询复用现有事实存储；显示裁剪或分页不能破坏保存内容。凭据、认证头和不可获取的内部推理不属于展示内容。
- 失败输出只作观察证据，不进入有效部门历史、工具执行或压缩摘要。只读查看、搜索、返回和导出不改变任务状态。

## 用量口径

界面输入量采用“输入（含缓存）”，缓存读取是其中子项，不再加到总量。内部归一化输入量不含缓存，需在统一统计边界转换，并与 Provider 原始 usage 对照。

输出及推理 Token 的关系按协议定义核对，不把包含关系当成可相加项。总 Token 不能同时叠加原始总量与其分项。不同 Provider 下同名模型分开归属。

缺失不等于零；只有明确上报零才显示零。部分尝试或部分字段缺失时保留已知小计及对应覆盖范围。上报值、本地估计和未上报分开，不用估计值悄悄补足账目。

用量按每次实际尝试计入，失败尝试上报的用量仍保留；重复事件和成功终态回报不重复累计。耗时来自实际测量，运行中显示进行中；费用未上报时保持未上报，估算费用须有独立来源和币种，不混加不同币种。

## 验收

验收覆盖成功、部分返回后失败、无返回失败、重试恢复、取消、准备后未发出、压缩、不同 Provider、部分用量及刷新重连。请求列表、详情、Context、汇总及导出必须能按同一来源核对。统计覆盖全部筛选结果，不能只计算当前可见的一页。
