# D37 新建项目的起始文件夹

状态：设计已确认，未实施。设计：[项目的起始文件夹设计说明](../design/project-initial-files.md)。路线位置：[路线图](../program-roadmap.md)阶段二，接入已有项目（D33）的补充。

## 用户原话

2026-10-06 架构师向用户提出：`project.create` 现在不带初始文件，评测场景 3 需要把一份数据文件放进新项目，从想法新建时带起点文件也是自然需求；建议给 `project.create` 增加可选的初始文件入口，复用 `project.onboard` 的公开树采集，由主机采集后作为第一个事项的初始树。用户回答：

> 同意这四件事，按你的建议改

## 已确认

- 新建项目时可以给出一个起始文件夹（控制主机上的路径）。它的快照是第一次采纳之前每个事项的起点，第一次采纳以后采纳成果是起点。
- 起始文件夹不建档：没有建档事项、基线核验与初始 PRD，项目来源仍是想法新建。已有项目的完整仓库仍经 `project.onboard` 接入并建档。
- 起始文件夹只在新建项目时给出，是一次性的采集；以后不能增加或替换。
- 项目的起点只在一处求出，开始事项、排队的事项与因升级重新开始的事项共用。
- 评测场景 3 的 Yudao 一侧用起始文件夹带入题目的数据文件，与 OpenCode 一侧起点相同。
