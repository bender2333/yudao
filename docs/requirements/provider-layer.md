## 2. 产品结果

用户无 Provider 配置也能打开控制台，在“模型与 Provider”中接入 OpenCode Go，输入 API Key、保存模型与部门绑定，然后用真实 Go 模型完成三部门任务。普通兼容服务仍可通过同一模块配置和使用。

Go 的认证、模型协议和请求身份由独立 Provider 模块处理；三部门、压缩、重试、连接测试、smoke、CLI 与后续调用方都使用它，不保留入口各自直连 SDK 的第二条路径。

## 3. 分层责任

| 责任 | Provider 模块 | 运行内核/调用方 |
| --- | --- | --- |
| 配置和凭据 | 读写校验、重载、生效修订、API Key 来源和脱敏 | 提供配置入口及要使用的模型选择 |
| 部门模型选择 | 每次模型请求解析给定选择，返回这一次请求的调用目标或具体错误 | 按项目部门设置与部门默认给出产品/工程/质检的选择；模块不硬编码部门 |
| 模型调用 | 统一消息与结果、协议编码、身份头、连接与单次取消 | 组装合法上下文、提供会话和尝试身份 |
| 错误和观察 | 结构化失败、实际用量、实际请求响应证据 | 保存领域事实，决定 D17 重试、步骤上限和停止 |
| 工具与部门循环 | 只返回工具调用意图 | 执行工具、Ask/React、交接、QA、交付和采纳 |
| 套餐观察 | 有来源的可选只读状态；缺失保持未知 | 不将其变成新的本地计费/预算控制 |

## 4. 必要能力

1. 统一 Provider 模块能脱离 Web 和三部门内核独立使用。内部 SDK、目录、认证与重载复杂性不泄漏给每个入口。
2. Go 采用 API Key；不据“订阅”一词引入 OAuth。其他订阅按用户选择后置。
3. 同一个服务可包含不同协议的模型。复用 Responses，新增 Chat Completions 和 Anthropic Messages；每个采用模型有明确的协议、能力来源及上下文/输出限制。
4. 使用真实 Yudao User-Agent 和稳定 x-opencode-session；同 run 同部门跨激活、重试、压缩保持会话一致，跨部门/任务及诊断隔离。取消按尝试隔离。
5. 模型发现仅更新候选，不自动替换绑定或给未知能力套默认。三种协议各一个代表模型真实验证通过，不声称所有列出的模型均已验收。
6. 结构合法但不完整的配置可保存；新建事项时只验证所选目标的运行就绪。D22 重载发布的新版本从相关部门的下一次模型请求起生效，包括进行中的事项；正在进行的请求与请求内的重试沿用原调用目标与认证。
7. 已知认证、订阅权限、限额及暂时连接错误分别报告；D17 决定重试。角色的模型因额度不足失败时，不得自动换 Key、模型、协议或切到按量服务。
8. 设置页区分已保存、已就绪、测试通过和套餐状态。保存不调用模型；测试针对明确模型与配置修订，不拿“第一个模型”隐式代表整份服务。
9. 观测保存统一输入与真实协议请求的关联、输出与工具身份、请求/实际模型及未知用量；密钥和认证头不进入公开材料。
10. 原目录、Web、编排器中的重复 Provider 行为被替换，不保留旧工厂转发或旧格式兼容层。

## 5. 验收条件

| 项 | 通过依据 |
| --- | --- |
| 独立模块 | 在没有 Web/Orchestrator 的测试宿主完成配置→解析调用目标→单次调用→取消；正式入口均使用同一接口 |
| D22 六条 | 启动、配置生效、进行中的事项、重载异常、凭据生命周期、回归六类通过 |
| 三协议 | 每个协议在真实 Go 代表模型完成文本/工具请求/工具结果往返；请求体、身份头、真实响应可核对 |
| 混合选择 | 一个三部门真实任务混合使用既有服务和 Go，从产品到 QA/release；工作/压缩/重试归属正确 |
| 按请求生效与隔离 | Go 模型选择/Key 变更从下一次模型请求起生效，正在进行的请求不受影响；取消诊断不取消生产请求；会话身份不混用 |
| 配置与界面 | 从空态完成 Go 接入；未就绪原因可操作；测试不改变绑定；1440/390 和键盘操作有行为验证 |
| 失败与限制 | 无效 Key、无订阅、限流、额度耗尽、未知模型能力、不完整流与取消分别有可核实处理；模拟只证明分类，真实外部结果单列 |
| 证据完整 | 全部场次包括首次失败，记录源码版本/配置修订/服务/模型/协议；导出与日志无密钥，真实证据可取回 |

不能用公开模型列表 HTTP 200、Fake、一次简单聊天成功或 SDK 能实例化，替代订阅权限与真实工具闭环。若没有用户已具备的 Go 凭据，真实部分记录受阻，不购买订阅或临时换其他服务冒充通过。

## 6. 与既有约束的关系

- 调用目标按每次模型请求解析（ADR-0005）；D18 的部门隔离与一次请求内的重试不更换调用目标继续有效。调用协议属于模型访问定义，同一服务方案下不同协议的模型属于同一份连接（ADR-0033）。
- D22 的启动与凭据选择保持，配置实现归属独立模块。
- D09 的用量只读、D17 的内核有界重试保持；既有原生 loop 与事件事实来源不迁移给 SDK。
- Stage 3 原“第二协议”中 Go 必需部分前移至 2.7；其余订阅、推理设置与更多服务后置。
- Go 套餐余额查询为可选观察，不以未公开稳定接口阻塞本阶段，也不承诺所有请求都在套餐额度内。
