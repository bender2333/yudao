# D06 运行中追加输入的处理时机

## 用户确认

> 当前工具完成后，在下一次模型调用前由产品部处理新输入（推荐）

确认时的条件：停止/取消命令仍按立即取消处理。

## 已确认

- 追加输入先按原文保存并确认接收。
- 已启动的工具可以完成，随后在下一次模型调用前由产品处理新输入。
- 产品维护相应要求后，后续部门依据有效需求继续。
- 一个模型响应中尚未启动的其他工具，不属于必须一起执行完的“当前工具”。
- 一般补充输入与立即停止/取消分别处理。
- 输入在模型调用中到达时，响应仍保留原绑定；在执行其工具或接纳提案之前先处理输入边界。
- 输入接纳与 release 共用控制顺序，已接收待处理输入不能被旧 release 越过；终态后明确新建任务。

## 本轮执行约定

输入接收、模型请求开始、工具开始、提案接纳和终态提交使用同一控制顺序。激活及已经发出的请求保留当时的输入版本。未处理原文交给产品后，由产品正常提交有效需求并记录已处理范围，接收确认本身不代表需求已更新。

已接收、已交给产品处理、已由有效需求接纳分别记录。产品正在处理的输入不会反复中断它自己的工具步骤或专家咨询；新到达的输入版本才要求在下一个执行边界重新安排产品工作。

对尚未处理的新用户输入，产品须提交完整的新 ProductSpec，说明改变、保留、废止及理由，再由主机记录已处理范围。普通咨询回复或只追加一条正式决定不代替这一步，避免用户改方向后旧要求未经处理就继续实施。没有新用户输入待处理时，正式补充决定仍沿用独立接纳流程。此为本轮明确的实施选择。

多个输入按接收顺序保留原文和边界。产品调用中再到达输入时，该响应也保持原版本；不得直接把新输入标记为已处理，或让旧提交跳过它。模型响应内未启动工具需记录明确的跳过结果，保持部门历史的工具协议完整。

活动任务收到文本 `/stop`、`/cancel` 时立即发出停止信号，并保存该条原文；按钮取消不生成用户未输入的文本。终态已确认后，追加工作由界面明确创建新任务，旧任务不隐式恢复。

引入 Git 后，停止控制不等待 Git 版本保存结果，正常情况下仍保留命令原文与提交；Git 或材料保存失败也必须停止旧模型及后续执行。界面区分已取消与版本未保存，失败事实尽可能保留原始命令，不虚报新输入已接纳，见 [D16](git-change-management.md)。

## 实现状态

已实现统一控制顺序。模型期间到达、工具队列边界、最后模型步骤与新输入交错、旧 release 先后顺序及终态拒收均通过确定性测试；产品咨询不会被已受领输入反复打断。浏览器同任务在 QA 调用期间追加要求，旧 QA 两项工具跳过，产品和工程更新后由新 QA 放行，完整原文和原版本均可回查。
