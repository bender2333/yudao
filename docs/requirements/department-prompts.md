# D02 三部门 prompt 展示与修改

> 2026-09-24：部门 Prompt 属于项目部门设置，修改从该部门的下一次模型请求起生效，包括进行中的事项；事项内 Prompt 编辑删除。见 [D24 模型管理](model-management.md)。查看、隐藏、修改与采用版本可回查继续有效。

## 用户原话

> 三部门的prompt可以隐藏或者展示，也能修改。

## 已确认

- 产品、研发、验收三个部门的 prompt 均可查看、隐藏和修改。
- 隐藏仅改变界面展示，不改变实际使用内容。
- 修改应进入部门实际调用，并能回查当次采用的内容。
- prompt 不能替代代码中的工具权限、合同校验和最终放行规则。

## 本轮设计选择

部门 Prompt 只在项目部门设置中修改，修改从该部门的下一次模型请求起生效，包括进行中的事项；已发请求保留原输入。没有写入项目部门设置时使用内置默认 Prompt，它属于带版本的定义（[ADR-0014](../adr/0014-versioned-definitions.md)），不在界面中编辑；不设事项级设置，事项内不编辑 Prompt（[D24](model-management.md)、[ADR-0005](../adr/0005-resolve-call-target-per-request.md)）。版本与采用范围可查，影响需求的内容通过产品处理，不取消当前工具。

每次模型请求读取当时最新的版本，请求事件与压缩事件记录实际采用的版本，避免将旧版本生成的材料误标为新版本。部门规则文本可编辑，主机权限与接纳条件由带版本的定义维护（ADR-0014）。

Prompt 版本改变不使压缩检查点失效，轨迹节录每次按当前的轨迹与图谱生成（[模型管理设计说明](../design/model-management.md)第 8.6 节）。只折叠界面不产生版本更新，也不触发上下文变化。

## 实现状态

已实现三部门 prompt 折叠查看、当前任务内编辑及采用历史。一次激活固定版本，下次目标部门激活采用更新；终态编辑明确拒绝。浏览器实际编辑工程 r2 并在模型输入中核对采用，版本篡改、更新期间旧请求与摘要适用性均通过自动化验证。项目部门设置中的 Prompt 与按每次模型请求生效随 D24 实施（[模型管理设计说明](../design/model-management.md)第 10 节）。
