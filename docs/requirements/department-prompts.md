# D02 三部门 prompt 展示与修改

状态：有效。依据：[总图](../architecture.html)第二节「定义」方框（内置默认 Prompt 属于带版本的定义，项目内的修改属项目部门设置）；设计：[模型管理设计说明](../design/model-management.md)、[总体架构](../design/architecture/overall-architecture.md)第 3 节。路线位置：[总体路线图](../program-roadmap.md)阶段一「单机诚实闭环，三道槽位立缝」。

## 已确认

- 产品、研发、验收三个部门的 prompt 均可查看、隐藏和修改。
- 隐藏仅改变界面展示，不改变实际使用内容。
- 修改应进入部门实际调用，并能回查当次采用的内容。
- prompt 不能替代代码中的工具权限、合同校验和最终放行规则。

## 设计选择

部门 Prompt 只在项目部门设置中修改，修改从该部门的下一次模型请求起生效，包括进行中的事项；已发请求保留原输入。没有写入项目部门设置时使用内置默认 Prompt，它属于带版本的定义（[总体架构](../design/architecture/overall-architecture.md)第 3 节「带版本的定义」一项），不在界面中编辑；不设事项级设置，事项内不编辑 Prompt（[D24](model-management.md)）。版本与采用范围可查，影响需求的内容通过产品处理，不取消当前工具。

每次模型请求读取当时最新的版本，请求事件与压缩事件记录实际采用的版本，避免将旧版本生成的材料误标为新版本。部门规则文本可编辑，主机权限与接纳条件由带版本的定义维护（总体架构第 3 节）。

Prompt 版本改变不使压缩检查点失效，轨迹节录每次按当前的轨迹与图谱生成（[模型管理设计说明](../design/model-management.md)第 8.6 节）。只折叠界面不产生版本更新，也不触发上下文变化。
