## 已确认范围

- 总览呈现任务状态、三部门协作及数据流转，并接受面向整个任务的输入。
- 产品、工程、质检各有独立工作区，工作消息与追加指导占主区，Context、Provider、Prompt 位于检查区。
- 独立观测入口包含模型请求记录、请求详情、原始数据及用量统计，可以从部门工作追到一次模型尝试。
- Provider 配置及尚未完成原型的相关配置界面预留。当前示例字段不表示已确认编辑、保存、连接测试或模型切换交互。
- 原型来源和冻结快照见 [原型基线](../prototypes/2026-09-06/README.md)，工作包见 [实施计划](../web-prototype-implementation-plan.md)。

## 实施依据

页面结构、主次关系、导航、检查区收放、移动端堆叠和已确认交互以快照为依据。示例任务、固定的三条流转、等待状态、Prompt 版本和用量值替换为真实事实。实际协作还需覆盖六个方向、返工和多次激活，不能把静态示例图作为运行规则。

原型末尾默认打开观测页是演示状态。进入一个任务默认总览；明确的部门或请求链接打开对应位置。刷新、浏览器返回、切换任务和断线恢复保持对象身份与草稿隔离，这是本轮实施约定。

现有任务创建与历史、停止、Prompt 编辑、PRD/PLAN、Git 差异、交付封存及下载能力继续保留。原型尚未画出的操作先形成补充交互说明，再并入同一工作台，不通过删除现有能力来匹配示例页面。

Prompt 页当前仅确认查看原文和实际版本；既有编辑能力的新版界面细节与其他未画出的配置操作一并列为待补原型。Provider 当前只预留检查区位置，待已有真实数据可读时展示实际采用信息，不增设配置管理表单。

## 完成条件与状态

状态：原型已取得并原样归档，任务已规划；新工作台尚未实现。Provider 等配置原型待补，不标记完成。

验收既比较界面，也检查真实行为：总览交接可追源、部门指导有真实处理记录、Context 精确绑定请求、尝试与用量不混淆、历史和实时一致。桌面及窄屏的导航、输入、长文本、焦点和错误状态均需通过。

本轮只规划及保存设计依据，不修改应用代码、启动新服务或改变既有任务。
