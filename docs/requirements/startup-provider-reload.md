# D22 启动与 Provider 热生效设计

> 原话：类似 openclaw 那种直接启动，不用带其他参数就能启动，然后在 yudao 的 provider 配置中，或者修改中间，都可以重新生效。
> 确认时间：2026-09-19。状态：已确认；Stage 2.7 已实现，按每次模型请求生效由 #45 实施（第 9 节）。
> 纳入 [Stage 2.7](../archive/stage-2-provider-plan.md)，与 [D23 统一 Provider 层](provider-layer.md) 一起实施。已确认的选择：无参启动、缺文件空目录、页面填 Key；目录、部门默认、项目部门设置与凭据的修改从相关部门的下一次模型请求起生效，包括进行中的事项（2026-09-24 用户决定，见 [D24 模型管理](model-management.md)、[ADR-0005](../adr/0005-resolve-call-target-per-request.md) 与[模型管理设计说明](../design/model-management.md)第 5.4 节，取代 2026-09-19 确认的「仅新任务生效」）。
> 关联：D09 次数/超时不变；D17 一次请求内的重试沿用该请求的调用目标。原“CLI 启动时读 JSON、不自动重载”在本项实现后删除。

## 1. 目标与范围

1. python -m harness 无参直接进入控制台；没有模型配置也能管理配置和查看已有任务。
2. 控制台保存、磁盘配置修改、受支持的凭据更新，都从相关部门的下一次模型请求起生效，包括进行中的事项。
3. 正在进行的模型请求不中断，一次请求内的重试沿用该请求的调用目标；每个请求事件记录所用的调用目标与配置修订，切换可以追溯。
4. CLI、Web 和嵌入调用使用同一个 Provider 模块，重载不是 Web 私有功能。

本项不实现恢复旧 run、不增加计费系统、不处理多实例写冲突合并。协议与 Go 接入属于 D23，不能继续用原稿“不引入新协议”限制整个 2.7 的范围。

## 2. 已核对的现状及必要修正

- CLI 的必填子命令和 provider-config 阻止无参启动，但不是唯一问题：目录结构校验与三部门运行就绪校验目前耦合，空态逐项保存也需调整。
- LoopSystem 装配本身不连模型；健康查询解析目录与凭据，任务创建时冻结。
- Web 已有 Provider/模型/绑定保存和连接测试，不再按“缺测试按钮”重新建设。
- 当前 _persist_catalog 在 Web 内写文件和替换内存；D23 将这些职责统一移入 Provider 模块。
- os.environ 是当前进程的环境视图。另一个终端或系统设置修改变量，不能使已运行 Python 进程天然热更新。
- 将 .env 一次性塞进 os.environ 会破坏来源优先级及删除/重载语义，本设计改为独立读取的凭据源。

## 3. 启动矩阵

### 3.1 默认入口

| 选项 | 默认值 | 规则 |
| --- | --- | --- |
| 子命令 | serve | 无参和省略 serve 的服务选项使用同一解析路径；显式 demo/smoke/replay/project 保留 |
| data-dir | 用户数据目录（Windows 为 `%LOCALAPPDATA%\Yudao`，Linux 为 `~/.local/share/yudao`） | [网页界面的提供与发布设计说明](../design/web-interface-and-release.md)第 3.3 节 |
| provider-config | `<data-dir>/providers.json` | 显式路径优先；没有明确给出时按生效的 data-dir 求出；路径在启动时解析为固定绝对路径 |
| host / port | 127.0.0.1 / 8765 | 占用时报错，不静默改端口 |
| 凭据文件 | `<data-dir>/.env` | 固定单路径，按生效的 data-dir 求出；不搜索用户主目录或其他项目 |

无参等价于全默认 serve。smoke 可使用默认配置路径，但缺少可用配置时应明确失败退出，不启动空壳验收，也不偷偷换 Fake。

### 3.2 服务可启动与任务可创建分开

| 状态 | 控制台 | 新建真实任务 |
| --- | --- | --- |
| 配置文件缺失 | 空目录启动，不自动复制模板、不生成伪配置 | 拒绝，说明尚未配置 |
| 文件 JSON/结构非法且无上一有效配置 | 启动，展示可定位且脱敏的 issues，不覆盖原文件 | 拒绝 |
| 目录结构合法但没有模型/未绑定完三部门 | 启动，允许逐项保存与修正 | 拒绝并指出缺项 |
| 已选模型能力未知、协议未支持或凭据缺失 | 启动，所选项显示未就绪 | 拒绝并指出具体选择 |
| 当前所需绑定与凭据齐全 | 启动，显示具备调用条件 | 可创建；不代表远端连接已验证 |
| 端口占用、数据目录不可写等宿主失败 | 明确失败退出 | 不创建 |

目录管理允许结构合法的半成品。完整的引用校验、模型能力与凭据检查在“发布所需任务目标”时执行；未被选用的未就绪服务不阻塞所选合法目标。坏字段/重复身份等结构错误不能以“草稿”名义进入有效目录。

## 4. 生效规则

### 4.1 发布与按请求生效

Provider 模块维护一个有效配置版本。界面写入、磁盘重读、手动重载均先校验，再整体发布，避免调用方看见半份目录。每次模型请求的解析取得一份一致的目录版本与凭据来源版本；同一次解析不混用轮询前后的状态。新建事项前按该项目的设置解析每个部门的每个角色，任何一个解析失败时拒绝新建（暂定默认值，见规则登记）。

进行中的事项从相关部门的下一次模型请求起使用新发布的版本，工作请求、压缩请求与协作请求都按这一规则解析；正在进行的请求照常完成，一次请求内的重试沿用该请求的调用目标（[模型管理设计说明](../design/model-management.md)第 5.4、6 节）。服务重启后按当前凭据来源继续解析；可靠执行恢复在 Stage 3 的 3.1 交付。

### 4.2 三个修改通道

| 通道 | 行为 |
| --- | --- |
| 界面保存 | 经过同一 Provider 管理接口，校验成功后原子写盘并发布；无需等下一轮轮询 |
| 外部文件修改 | Provider 模块管理的本地轮询重读 JSON 和 .env；默认约 1 秒，不新增监听依赖；内容变化被核对，mtime/size 只能作优化，不能漏掉同尺寸改写 |
| 凭据更新 | 页面输入更新内存覆盖；.env 修改被重新读取；进程环境按实际环境视图解析，不宣称能看到外部终端变更 |

手动 reload 立即检查本地配置源，不调用模型，不验证账户额度。测试连接是另一项明确操作，不能因为保存或后台轮询而隐式消耗推理调用。

文件重载由系统装配启动并在关闭时停止，Web 只提交命令和读取状态。嵌入进程也可以显式重载；短命 CLI 在执行前读取一致版本。

### 4.3 非法写入、删除与并发

- 外部 JSON/结构损坏：若本进程已有有效版本，则继续使用该版本，并持续展示“新文件未生效、当前仍用版本 X”和 reload_error；修复后发布并清除错误。首次启动没有有效版本则保持空态。
- 明确删除目录文件表示撤销默认配置：目录与部门默认一起清空，新建事项被拒绝，进行中事项里没有另选模型的部门进入待恢复，写明部门、模型与原因，用户修复以后继续（模型管理设计说明第 4.7 节）；不永久暗用被删除文件的旧内容。
- 合法空目录可以发布，三部门随之未就绪；这是有效清空，与 JSON 损坏不同。
- .env 删除或其中一个 Key 被删除，清除对应文件源值；不从缓存复活已删除密钥。其他高优先级来源按既定规则仍可生效。
- 界面与外部写入沿用用户选定的“后写赢”，不建设多实例冲突合并。模块内写操作串行，临时文件不共用，落盘成功才发布；失败不更新内存。
- 轮询与保存协调：不能用先读到的旧文件覆盖刚发布的新版本。外部编辑不受进程锁控制，后续重读以磁盘最终有效内容为准，向用户显示实际生效版本；不承诺跨多个文件编辑的全局事务。

此处保留最近一次有效配置是明确的运行连续性规则，不是旧格式兼容。D23 改动后的旧配置结构应明确报字段错误，不自动迁移或偷偷适配。

## 5. 凭据来源与页面填 Key

优先级保留：进程内存覆盖 > 宿主进程环境 > .yudao/.env。

- .env 作为独立字典解析，不修改 os.environ；先核对成熟 dotenv 库的解析、写入和原子性能力，不自定义残缺的 KEY=VALUE 语法。
- 页面 Key 默认只进入内存；明确显示“本进程有效，重启后需重新提供”。
- 用户勾选保存到 .env 时才持久化。持久写入失败时，不把本次操作报告为保存成功，也不悄悄改成只在内存生效。
- 原子替换需同时保持文件访问权限；POSIX 使用用户私有权限，Windows 验证实际 ACL，不把 chmod 数字当成权限已受保护的证明。
- 界面只显示配置状态、来源和覆盖关系。若进程环境覆盖 .env，明确说明重启后会采用哪个来源，不能承诺刚写入文件的 Key 一定成为有效值。
- 清除内存覆盖和移除持久凭据要区分；清除高优先级覆盖后可能露出下层来源，界面展示实际结果。
- 凭据版本使用非敏感修订标识，不能把密钥哈希当作公开身份。正文、认证头、密钥及其摘要都不进入日志、事件、Git、配置导出或观测工件。

.yudao/ 当前已整体被 .gitignore 排除。验收仍检查临时文件、导出和错误信息，不因 ignore 存在就认为所有路径自动脱敏。

## 6. 接口与存储变更

| 外部接口/存储 | 本项含义 |
| --- | --- |
| 现有 Provider / 模型 / 部门绑定接口 | HTTP 契约可保留，但处理器只转交 Provider 模块与绑定调用方；不再自行读写目录、解析密钥或拼模型请求 |
| GET /api/health | 服务健康和模型就绪分开；显示配置路径、有效修订、最近重载状态与 issues，不暴露密钥 |
| GET /api/providers | 返回可编辑目录及就绪状态；凭据只显示 configured/source/覆盖状态 |
| POST /api/provider-credentials | 提交凭据及是否持久化；不返回 secret；清除/删除通过显式命令，不拿空字符串猜用户意图 |
| POST /api/providers/reload | 重新读取本地源并返回实际生效修订及错误；不“探活”模型 |
| POST /api/providers/{id}/test | 显式选择模型，使用该模型协议和本次配置修订；与保存分开 |
| providers.json | 非敏感目录、模型访问定义及默认绑定；新结构与 D23 一致 |
| .yudao/.env | 可选持久凭据；与非敏感配置分开 |
| 模型请求事件 | 每次请求保存调用目标的公开部分（配置修订、连接、协议、上游模型、凭据引用）与选择来源；不要求维持旧事件结构 |

凭据写入接口属于本地管理能力：沿用回环地址默认值，校验同源写请求、限制敏感请求日志与响应缓存。从本机以外访问的认证由接口层提供（[ADR-0015](../adr/0015-desktop-client-and-http-contracts.md)），只在局域网内使用期间保留位置并标为 TODO；不能把“页面能填 Key”当成已有远程管理鉴权。

## 8. 验收标准（保留六条，扩充边界）

1. **无配置启动**：无参、无文件、坏 JSON、空目录、未绑定、缺 Key 均可进入控制台；只有就绪任务可创建。端口/目录宿主错误及不可用 smoke 明确失败。
2. **配置生效**：界面逐项保存可完成首份配置；合法磁盘修改、手动重载无需重启；相关部门的下一次模型请求使用实际有效修订，请求事件记录该修订，不混合前后状态。
3. **进行中的事项**：目录/模型/部门设置/凭据更新期间，正在进行的请求照常完成，请求内的重试沿用原调用目标；进行中事项的工作、压缩与协作请求从下一次请求起使用新目标；不串取消或请求身份。
4. **重载异常与删除**：损坏文件不覆盖最后有效配置，错误持续可见；修复清错；明确删除/清空不会暗用旧默认；同尺寸改写与界面/轮询交错不丢失最终状态。
5. **凭据生命周期**：页面内存 Key 从下一次模型请求起可用；重启后消失；显式落盘后按来源优先级恢复；.env 外改/删除、环境覆盖、持久化失败、撤掉覆盖均展示真实结果。
6. **回归与证据**：新增用例通过统一 Provider 接口验证以上行为及 secret 不泄漏，覆盖无 Web 进程场景；现有回归通过或有明确的非应用故障结论。界面键盘、错误提示、1440/390 交互验证通过，不以本地模拟替代 Go 的真实验收。
