## 已确认

- 模型管理参照 OMP：统一管理全部模型与能力数据，再提供给上层调用；运行时按实际使用的模型计算。
- 模型管理为产品、工程、质检各给出一项部门默认。项目里的部门设置可以另选本项目该部门的模型，不修改部门默认。
- 运行中可以更换模型、推理档位与部门 Prompt。项目部门设置的修改从该部门的下一次模型请求开始生效；部门默认的修改对没有另选模型的项目同样生效，包括进行中的事项。
- 设置只有全局与项目两层，不保留事项级设置，删除事项内的 Prompt 编辑。
- 三部门历史独立，用于上下文隔离；部门之间只传递主机接纳的结构化结果，对话不跨部门。
- 窗口未知的模型直接拒绝，由 Provider 模块负责。
- 目前只使用 1M 窗口的模型，暂不处理切换到小窗口模型。
- 压缩参照 OMP 与 opencode：阈值采用 OMP 公式，预留量取窗口的 15% 与 16384 中较大的一个；摘要请求使用该模型声明的最低推理档位。
- 推理档位参照 OMP：每个模型在目录中声明支持的档位，请求时限制在支持范围内，各协议映射到自己的参数。
- 准入作废后，部门默认与项目部门设置中的引用保留，该部门下一次模型请求直接报错并说明原因，不自动改用其他模型。
- 预置表改为仓库内的数据文件，每个服务方案带来源，整张表带版本号，随新版本发布生效；目前只有 OpenCode Go，另有自定义。
- 工具能力检查暂不加入。
- 以下几项在 2026-09-24 按参照对象提出，用户未提出异议：连接地址保存该协议的请求基址，与 OMP 相同；容量可以预填，逐行由用户修改或明确接受；Web 新建事项只提交事项原文，上下文窗口取调用目标的模型窗口，运行边界使用系统默认值。
