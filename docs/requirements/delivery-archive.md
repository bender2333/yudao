# D13 完整交付封存与恢复

## 来源与本轮决定

用户指定的第一阶段对齐 prompt 建议前移完整交付封存。当前返工后只能查部分声明文件与摘要，无法还原完整受测内容，因此本轮将此基础纳入批次 E。

## 有效规则

- 接受交付前保存主机公开范围内完整文件树与字节，包括未列在模型清单中的文件、隐藏文件、二进制及空目录。主机私有事实另存。
- 文件树规则与检查一致；模型清单不能缩小封存范围。链接、缺失、非法路径或采集中变化明确报错，不声称完整。
- 检查副本来自单次采集的原字节，交付验证和封存也使用同一份采集结果。封存保存后、交付接纳前再核验当前树，变化时拒绝本次接纳，不能用新采集内容替换已验证的依据。该机制检测普通本地变化，不宣称操作系统原子快照。
- 检查期间副本或原树发生变化，保留真实执行输出与变化事实，其回执不能用于放行。Python 检查禁止自动生成字节码，公开范围不因此排除缓存或其他未声明文件。
- 封存通过现有工件存储并关联交付与检查。原工作目录改变或不可用后，仍可仅凭持久工件在新目录恢复并核对完整树。
- 形成低耦合基础能力供后续复用，运行控制不依赖分析报告代码，不合回规划树旧业务代码。
