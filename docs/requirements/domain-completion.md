# D12 部门的专业补全

## 来源与本轮决定

用户于 2026-09-06 指定读取第一阶段对齐 prompt 并按既有授权推进。其要求三个部门依据行业知识、项目约定和成熟组件补齐常规缺口，仅对影响目标、承诺或重要成本且无法推断的取舍提问。

## 有效规则

产品负责需求与重要取舍，研发负责技术方案和自检，质量依据有效要求及适用共同约定独立检查。默认依据与用户原话分开；已有知识的采用不等待经验学习基线。QA 新提出的业务取舍先补定义，不追认为已约定缺陷。纯局部实现细节不强制跨部门询问。

## 状态

三部门共同专业补全规则已进入每次正常请求，产品约束和工程计划记录专业默认与依据。重要且不能推断的取舍保留咨询路径，原文不被默认决定覆盖。实际模型在完整任务中的采用效果在 F 验收；不建设独立知识图谱或新增部门。
