# D12 部门的专业补全

状态：有效。依据：[总图](../architecture.html)第一节「产品」「工程」「质检」方框；设计：[三部门的循环结构](../design/department-loop.md)。路线位置：[总体路线图](../program-roadmap.md)阶段一「单机诚实闭环，三道槽位立缝」，道 01 部门与核验。

## 有效规则

- 三个部门依据行业知识、项目约定和成熟组件补齐常规缺口，仅对影响目标、承诺或重要成本且无法推断的取舍提问。
- 产品负责需求与重要取舍，研发负责技术方案和自检，质量依据有效要求及适用共同约定独立检查。
- 默认依据与用户的原始输入分开；已有知识的采用不等待经验学习基线。QA 新提出的业务取舍先补定义，不追认为已约定缺陷。纯局部实现细节不强制跨部门询问。
- 共同的专业补全规则进入每次正常请求；产品的约束和工程的计划记录采用的专业默认与依据。
- 重要且不能推断的取舍保留咨询路径（[D07](expert-ask-react.md)），原文不被默认决定覆盖。
- 不建设独立知识图谱，不新增部门。

## 验收

用实际模型跑完整任务，看三个部门采用专业默认的效果。
