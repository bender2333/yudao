# D08 部门完整历史与逐次上下文

## 用户原话

> 继续添加细节，部门内的上下文要自己去维护，llm每次请求要先带上intend原文和当前要做的工作，以及之前的历史。等我们做好语义分解和洞见，数据流等等时候，我们再优化部门内的上下文管理系统，当前部门内不能遗忘过去的上下文，这部门可以参考OMP，因为单个部门相当于一个agent

## 已确认

- 每个部门相当于一个 Agent，自行维护本部门上下文；底层循环和状态仍由 Yudao 自己实现。
- 每次 LLM 请求先包含 `intend` 原文、当前要做的工作，再包含该部门之前的历史。
- 当前版本保留同一任务内本部门的完整模型与工具历史。部门交接后重新参与时继续保留，不能因创建一次新激活就清空。
- 部门之间通过允许的材料和专家问答协作，不共享其他部门完整私有历史。
- 当前有效要求在请求开头明确呈现；保留旧历史不等于让旧要求继续有效。
- 后续做好语义分解、洞见和数据流后，再优化上下文管理；本版不自动摘要、选择性遗忘或静默截断。
- 可以参考 OMP 的部门内历史和工具协议处理代码，不依赖 OMP 完整进程或会话。

## 实现与限制

原生重构将历史从持久事件中按任务和部门恢复，保留工具调用与结果关系。超过可发送的上下文容量时明确停止并保留记录，不能为了继续而偷偷删除历史。

## 实现状态

已确认，正在调整原生循环。此要求替代此前“每次激活只保留本次局部历史”的方案。跨任务长期记忆不在本条自动引入。
