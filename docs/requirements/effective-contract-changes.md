# D15 有效变化与执行依据

## 来源

本会话持续输入、PRD、专家问答和上下文要求，以及用户指定的第一阶段对齐 prompt 对版本与实际执行的补充。

## 有效规则

产品记录本次改变、仍须保留、合法废止的要求及关键理由。有效合同包括当前需求和实际生效的补充决定，其内容变化影响计划、待答请求、旧交付、检查及待发工作；摘要与原始历史保留为来源，不把旧指令恢复为当前目标。

通用专家协作中，产品补充决定作为独立的正式产品事实接纳，普通意见回复不进入合同。发布新需求时，对每条当前生效决定明确选择保留、整合进新需求正文或废止，并说明理由；主机检查是否完整说明了已有决定、是否引用真实来源，语义取舍仍由产品负责。此规则在 C 随旧单向流程的替换实施。

输入接纳、请求开始、工具开始、提案接纳和终态共用控制顺序。已发请求及迟到输出保持原绑定；先接纳的新输入不能被旧 release 跳过。终态后的新工作另起任务，replay 不等于继续运行。

## 状态

补充决定参与统一合同标识已实现；合同或计划改变后旧计划、交付、回执及摘要不能作为当前执行依据，模型请求和工具保留激活时绑定，旧提案不能接纳为新合同的产物。C 已验证正式决定处置、未结请求失效、动作结果归属和部分执行后的接续，审计同时核对实际模型输入及执行依据。输入与 release 交错及持续需求变更说明按 D 继续实施。
