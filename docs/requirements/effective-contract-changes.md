## 有效规则

产品记录本次改变、仍须保留、合法废止的要求及关键理由。有效合同包括当前需求和实际生效的补充决定，其内容变化影响计划、待答请求、旧交付、检查及待发工作；摘要与原始历史保留为来源，不把旧指令恢复为当前目标。

通用专家协作中，产品补充决定作为独立的正式产品事实接纳，普通意见回复不进入合同。发布新需求时，对每条当前生效决定明确选择保留、整合进新需求正文或废止，并说明理由；主机检查是否完整说明了已有决定、是否引用真实来源，语义取舍仍由产品负责。

输入接纳、请求开始、工具开始、提案接纳和终态共用控制顺序。已发请求及迟到输出保持原绑定；先接纳的新输入不能被旧 release 跳过。终态后的新工作另起任务，replay 不等于继续运行。

补充决定参与统一合同标识。合同或计划改变后，旧计划、交付、回执及摘要不能作为当前执行依据；模型请求和工具保留激活时绑定，旧提案不能接纳为新合同的产物。重新计算工件哈希后的版本或正文篡改也不能通过审计。

## 验收

验收覆盖：正式决定的处置、未结请求失效、动作结果归属、部分执行后的接续、输入与 release 的双向交错、持续需求变更说明、原文与 prompt 的版本绑定、版本或正文篡改。确定性的完整场景与真实模型的完整流程都要通过。
