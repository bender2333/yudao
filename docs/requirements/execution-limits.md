# D09 循环次数与超时限制

## 用户原话

> 细节，暂时不考虑provider 用量，先按照循环次数来进行限制，或者时间限制

## 已确认

- 当前不以 provider 用量作为任务是否继续的依据。
- 优先采用循环次数限制；时间限制也是允许的控制方式。
- 不围绕 provider 费用或 token 预算增加控制复杂度。

## 当前实施选择

原生循环采用已有的部门激活次数上限和部门内模型步骤上限。单次模型请求保留超时处理。删除任务 token 预算配置及由此触发的暂停，不保留旧配置回退。

SDK 返回的用量可作为只读事实保存，但不影响任务推进，也不猜算价格。上下文容量检查属于请求能否发送的约束，与 provider 用量预算分开；旧历史按 D10 自动压缩，固定原文和当前工作无法容纳时明确停止。

## 实现状态

已实现。采用部门激活次数、每次激活最多 32 次模型调用和单次请求超时；摘要调用同样计入 32 次限制并可取消。达到次数上限后暂停，不接受后续提交。尚未要求额外的任务总时限配置，当前不新增这一配置层。
