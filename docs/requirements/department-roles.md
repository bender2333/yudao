## 已确认

- 部门内多循环是确定要做的模块。
- 部门内有固定的角色。
- 产品部门的角色包括：产品部门经理，只关注本部门当前做到什么程度、数据流转是否正确；产品架构师，挖掘用户需求、设计产品；产品探索者，辅助查资料。
- 2026-09-24 用户选择工程与质检部门的角色，2026-09-25 增加各部门的审查者，并把工程的「开发者」改名为「主程」。当前的角色（中心角色见下文）：
  - 产品部门：产品部门经理、产品架构师（中心）、产品探索者、产品审查者。
  - 工程部门：工程经理、工程架构师（中心）、主程、工程探索者、工程审查者。
  - 质检部门：质检经理、测试工程师（中心）、质检探索者、质检审查者。
- 部门内的角色可以配置模型，设置分全局层与项目层，参照 OMP 的模型角色与 vibe 模式。
- 部门内的 SubAgent 就是这里的角色。
- 2026-09-24 用户决定：部门内多角色放在 Stage 4：部门内协作、上下文与界面。
- 2026-09-25 用户决定的部门内部规则（三个部门共用）：
  - **审查者**：产品、工程、质检三个部门都设审查者。产品审查者审查需求与规格；工程审查者审查设计与代码；质检审查者审查检查设计是否覆盖每条验收条件、缺陷记录是否有依据。审查者每次审查从新的上下文开始，只看待审查的成果、它的依据（PRD、计划、分派说明）与上一轮的审查意见，看不到作者的历史。
  - **交出条件**：部门向外层提交的每份成果（ProductSpec、工程计划、交付、质检结论）都要通过主机按部门规定的检查，其中包括一次针对该版本的审查通过记录；其余检查例如产品的数据流核对通过、工程的计划条目都有对应实现且自测通过、质检的每条验收条件都有检查结果。不满足时提交被拒绝，原因返回部门。
  - **外层返工**：返工回到部门后，返工原因写进部门账本，成为新的计划条目；连续角色保留事项内的历史，只处理返工涉及的部分，其余已完成的条目保持完成。
  - **对外接口**：部门对外只有经理一个接口。角色需要其他部门回答的问题时，以「需要输入」交回中心角色，需要对外发问时由经理发出。
  - **部门账本的显示**：房间白板显示计划条目与状态、审查次数与最近的审查意见、每一轮的进展判断、待决问题与对外询问。用户原话：「这部分内容，如果显示不了，就只展示1，但是鼠标点击，可以弹出完整画面」，即白板放不下时只显示计划条目与状态，点击白板弹出完整的账本。
  - **可以同时进行的工作**：探索者的多项查证；审查与作者的下一项工作；工程设计与实现分段进行（架构师设计下一部分时，主程实现已审查通过并被接纳的部分）；产品规格被接纳后，质检提前按 PRD 设计检查。
  - **预测性探索**：用户原话「所有角色看到prd后，可以根据预设角色内容，进行先一步预测性探索」。这改变了「同一事项同一时刻只有一个部门处于激活状态」的现有规则，改为一个部门持有当前交接，其他部门可以做准备工作：
    - 范围：只读查证（查资料、读代码）并起草本部门的草案（例如工程的设计草案、质检的检查设计）；不写工作区，不向外层提交。部门持有交接后，草案经过审查才能用于正式成果。
    - PRD 更新后，按旧版本做的预测性结果全部作废，按新版本重新探索。
    - 只在有空闲执行槽位时进行，优先级低于正式工作与其他事项；正式工作需要槽位时，预测性任务在安全节点让出。用量单独记录。
    - PRD 被接纳或更新后，主机通知各部门；由中心角色按角色的预设内容决定派哪些角色、做哪些探索，也可以不做。
  - **限制与停滞**：一次性角色（探索者、审查者）不设同时任务数与请求数上限，只受执行槽位与事项运行时间上限约束。中心角色的进展判断与主机记录的进展事实连续 3 轮都显示没有进展时，重新规划，相关连续角色从新的历史视图开始，原始历史完整保留，不结束事项。
  - **设置与历史**：模型选择中角色设置优先于部门设置；部门 Prompt 作为全部门规则，每个角色另有角色 Prompt。角色历史不跨事项延续，部门在项目中积累的知识经轨迹与图谱延续。
  - **画面**：部门内的分派与交回由小人走到工位递送任务卡与结果卡表现；部门之间的交接经过管道。
- 2026-09-25 用户决定三个部门都采用中心型协作：
  - 每个部门有一个中心角色，承担部门核心的规划与构建能力：产品部门为产品架构师（需求与规格），工程部门为工程架构师（规划与构建），质检部门为测试工程师（检查设计与判定）。
  - 部门内的其他角色是中心角色的工具，承担可以独立出来的任务，保持中心角色的上下文干净、工作高效：探索者查资料与查证；主程实现代码与自测；审查者审查成果。由中心角色分派任务、决定何时审查哪一部分，结果与审查意见交回中心角色，返工也由中心角色安排；预测性探索由中心角色决定。
  - 中心角色不做工具角色的写入工作：工作区只由主程写入，质检副本只由测试工程师写入；中心角色只写自己的设计、计划或检查设计草案。
  - 经理负责对外沟通：接收其他部门的询问与用户的指导并转给中心角色，把中心角色需要其他部门回答的问题发出去，对外汇报部门进度；中心角色认为完成后，由经理按主机检查提交部门成果。经理还对照账本与数据流核对，关注部门做到什么程度、数据流转是否正确，发现遗漏的条目、停滞或数据流转的缺口时提醒中心角色。经理不分派部门内的工作，不编写产物。
  - 用户说明此前也考虑过分形的组织方式，目前的重点是中心型协作。
