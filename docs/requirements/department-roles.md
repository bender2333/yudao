# D26 职能内多角色

状态：有效。依据：[总图](../architecture.html)第一节「工程」方框（一个职能的内部也可以是一个子组织）、第二节「定义」里的角色材料、第三节「子组织」；设计：[职能内多角色设计说明](../design/department-roles.md)、[形态与核验角色设计说明](../design/forms-and-verifier-role.md)「子组织」一节、[项目的组织设计说明](../design/project-organization.md)。路线位置：[总体路线图](../program-roadmap.md)第 3 节道 02 角色与外包（子事项承接职能内多角色）。

## 需求

- 职能内多角色是一份子组织定义，不是一个模块。职能的角色定义指向一份按直做轮转的子组织（含它自己的路由与核验角色），这个角色的一轮工作开一个子事项；子事项有自己的事件流、冻结的定义与边界，结束时它的成果作为这个角色的普通提案回到职能的事项，照常过裁决。执行里不另做一套子 agent，不加骨架事件种类。
- 角色（三个职能同构，运维按同一做法）：
  - 中心角色是直做里指定交完成的角色，承担职能核心的规划与构建：产品架构师（需求与规格）、工程架构师（规划与构建）、测试工程师（检查设计与判定）。
  - 探索者只读查证，可以几项同时进行。
  - 主程（工程）实现代码与自测，工作区只由它写入；质检副本只由测试工程师写入；中心角色只写自己的设计、计划或检查设计草案。
  - 审查者是子组织里的核验角色：产品审查需求与规格，工程审查设计与代码，质检审查检查设计是否覆盖每条验收条件、缺陷记录是否有依据。每次审查从新的上下文开始，只看待审查的成果、它的依据与上一轮的审查意见，看不到作者的历史。
  - 没有经理：其他职能的询问与用户的指导按路由送达，进度与停滞由边界判定并提醒，职能随时可以用询问工具询问另一个职能。哪些角色带询问与提交工具写在角色定义里。
- 角色由带版本的定义声明，随系统版本发布，每个角色写关注的成果、目标、证据来源、可见范围、写入范围、工具许可、是否核验角色及核验谁。用户在自己的项目上改组织（含增删角色、改由谁做）时，在「高级」里采用，经结构校验与确认就生效，范围只有这个项目，不经对照；发布带的默认形态与系统提出的候选经候选、结构校验与对照（系统提出的候选在阶段四）。
- 交出条件：职能向外提交的每份成果都要通过主机按职能规定的检查，其中包括针对该版本的审查通过记录；审查的密度是验证密度参数（[D35](self-hosting.md)的检查定义）。不满足时提交被拒绝，原因返回职能。
- 外层返工：返工原因进入子事项，只处理返工涉及的部分，已完成的部分保持完成。
- 边界：子事项的时间与用量从上一层剩下的里扣，层数有上限；探索者与审查者的同时任务数、请求数与审查次数各有上限，见规则登记。停滞只按主机记录的进展事实判定，连续 3 轮（暂定默认值）没有进展时重新规划，不结束事项；同一个计划条目第 2 次（暂定默认值）被审查退回时提醒用户，此后每再退回一次再提醒一次，用户可以用职能指导（[D20](department-guidance.md)）回应。
- 可以同时进行的工作：探索者的多项查证；审查与作者的下一项工作；工程设计与实现分段进行。其他职能在等待时可以做预测性探索：只读查证与起草本职能的草案，不写工作区、不向外提交；只在有空闲执行槽位时进行，正式工作需要槽位时让出，用量单独记录；要求更新后按旧版本做的结果作废；做不做由中心角色决定。
- 模型与材料：角色可以各自设置模型，角色设置优先于职能设置（[D24](model-management.md)）；职能 Prompt 是全职能的规则，每个角色另有角色 Prompt。角色历史不跨事项延续，职能在项目中积累的知识经轨迹与图谱延续（[D25](semantic-system.md)）。
- 教训与洞见不由角色写出，由教训发现模块产生（[D25](semantic-system.md)）；工具角色整理尝试时只写尝试本身。
- 对产品、工程、质检、运维四个职能一起引入，先后由 [D32](comparison-experiment.md) 对照实验的结果决定；职能内多角色与单角色职能的对照用 D32 的任务集，审查者的可见范围（是否看到本职能记录的事实与决定）是其中一组取值。

## 验收标准

- 换一份定义，工程从一个角色变成子组织，事实与裁决、循环两层的代码不改；换回去能撤回。
- 子事项的创建事件带上一层的事项、一轮与角色的引用和层数；结束时上一层只收到一份普通提案，骨架事件种类没有增加。
- 层数到上限时拒绝再开；上一层停，子事项跟着停。
- 审查者的结论是子组织里的核验，审查者看不到作者的历史，有用例守着。
- 交出检查：没有对应版本的审查通过记录时提交被拒绝。
