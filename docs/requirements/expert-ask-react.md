# D07 三部门相互专家问答

## 用户原话

> Ask → React工程遇到需要产品决定的问题，可以提出请求；产品回应后继续执行  不只是这一个流，验收部门也可以随时要求产品重新解释，产品部门也可以向研发和验收提问，比如这个实现是否难，成本之类的，也就是它们都是领域专家。

## 已确认

- Ask/React 不限于研发向产品提问，三个部门都是领域专家，都能提问和回答。
- 验收可请产品重新解释要求，不必先制造一个缺陷结论。
- 产品可向研发和验收咨询难度、成本、约束与可验证性，再作需求取舍。
- 问题、必要背景、依据与回答可追溯，不因此共享完整私有对话。
- 专家回答与最终责任分别记录：产品决定需求，研发负责实施，验收独立放行。
- 咨询回答不必更新 PRD，也不能自动视为交付通过。

## 本轮设计选择

首批同一时刻一个未结请求，不嵌套；记录原工作及依据，回答或拒绝后接续仍适用的工作。取消、超时和需求版本变化均有明确结束记录，旧回复不能用于新合同。普通请求超时沿用部门调用和次数上限，不引入外部队列。

产品在初版 PRD 形成前也可咨询工程或质量，此时依据为原始输入与当前工作；没有有效合同和计划仍不允许工程修改交付。三部门图保留三个节点，咨询期间显示实际接收者、请求方向与返回工作。

咨询结果提供意见，不自动生成为产品决定。要求需要变化时，由产品通过正常需求接纳形成新的有效 PRD；工程动作沿用事前计划、真实工具和交付接纳，质量动作沿用独立检查。实际结果引用正常流程产生的材料或工具回执，不以回复中的“已做完”代替。

原工作与请求处理分别记录。结果到达后先检查原工作的依据是否仍适用，再接续；动作已经改变需求或交付时，以新的有效材料安排后续工作，不能直接恢复过时的检查或放行。通用协作就绪后删除旧单向专用模型、路由和界面，不保存兼容路径。
