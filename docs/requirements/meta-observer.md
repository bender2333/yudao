# D28 元观察与规则检查

状态：有效；设计在阶段五进行。依据：[总图](../architecture.html)第一节「观察者」方框、第二节「定义」方框、第三节「判定点」一条、第四节「观察者」的缝、第五节的第二层自举与第六节「拆开部署」；[ADR-0044](../adr/0044-verifier-role-and-open-loop.md)（观察者不做部门）；调研[JEV 决策模型：能力边界与在 Yudao 中的用法](../research/jev-decision-model.md)。路线位置：[总体路线图](../program-roadmap.md)阶段五「受治理的演化」（观察者的元观察），第 3 节道 07 观察者。

## 已确认

- 元观察与规则检查（下文简称元观察）位于产品、工程、质检以及运维部门之外，不承担交付工作。它是一个观察者加判定点，不是组织定义里的部门。观察者部分是总图「观察者」方框里的观察者之一，与教训发现、演化并列：在系统外面，按读取范围经接口读事实，只出证据、提案与振荡信号，都经写入口写入、经裁决，不动手。判断部分用判定点。
- 引入 JEV（TypeSafe 发布的决策模型 Jev）。
- 元观察只做流程审查和观察，结果用于未来的系统演化（阶段五）。
- 判定点写在定义里，事先规定。判定点的答案先写成事件再被使用；经过本地中文样本校准之后，控制核心才按判定点的结果自动推进，校准通过之前只记录，不改变流程。观察者自己不推进任何东西。每个判定点的结果分通过、不通过、不确定三种。
- 质检放行、产品取舍、规则修改都不交给元观察。
- 元观察的读取范围由控制核心给出，不含作者的工作过程；部门不能向它分派工作。
- 运行时是一个观察者加判定点（[总体架构](../design/architecture/overall-architecture.md)「十项长期决定」）。观察者在控制主机上运行（[ADR-0018](../adr/0018-single-control-host-remote-execution.md)）；观察者属于只读的一类，从事实重算，可以有多份（总图第六节「拆开部署」）；部署形态见 [D29](remote-execution.md)。

## JEV 用于语义系统的证据核对

- JEV 同时用于语义系统的证据核对：角色记录事实时，由 JEV 判断证据是否支持陈述，只核对外部文档与需要解读的运行输出，见 [D25 语义系统](semantic-system.md)上下文组装专题第 3 条。
- 证据核对按本记录的规则校准：用本地中文样本选取阈值，再用另一批样本复核；通过之前只记录，不显示给模型。
- JEV 的 systemone 协议在阶段四接入 Provider 模块，元观察在阶段五使用同一协议。

## JEV 的准入

JEV 的使用有两层准入，两者都需要：

- JEV 的模型访问定义按模型测试准入（[模型管理设计说明](../design/model-management.md)第 4.3 节）：加入目录以后是候选，模型测试通过才能被选用。
- 每个判定点（包括证据核对）按本地中文样本校准通过，控制核心才按它的结果自动推进；未通过校准的判定点只记录、不推进（已确认第 4 条，D25 上下文组装专题第 16 条）。

## 设计中待确定的规则

以下是架构师提出、用户尚未逐项决定的规则，在阶段五设计时确定：

- 判定点清单。候选：询问应由哪个部门回答；回答是否回应了询问；新缺陷或新询问是否与之前的重复；缺陷是否引用了 PRD 条目；DeliverySpec 是否逐条覆盖 PRD；部门产出是否越权，例如替质检宣布放行。
- 不交给 JEV 的判断：循环整体是否有进展（跨步骤的因果判断，由轮次、重复询问、缺陷集合是否变化等确定的统计发现，再交给 LLM 分析；发现以后由观察者写成振荡信号）；代码是否正确；没有参照材料的质量判断。
- 校准样本的来源与标注方式。阈值在一批样本上选取，再用另一批样本复核；未通过校准的判定点只记录、不推进。证据核对的校准做法已由 D25 上下文组装专题第 16 条确定（样本从真实运行中抽取，两批各 200 条（暂定默认值），已准入的强 LLM 给出参照标注，分歧样本与随机抽取的 10%（暂定默认值）由用户裁定，数值与理由见规则登记）；元观察各判定点的样本在阶段五设计时确定。
- 不确定结果的去向由判定点事先规定，从定义允许的去向里选（例如交回提问的角色，由它按角色材料决定继续还是发决定请求；证据核对只标记「不确定」，事实的状态不变，并作为开环列出）；需要另一个模型独立判断的地方，是定义里的一个角色或检查，作为独立的证据，不是判定点的升级（[总体架构](../design/architecture/overall-architecture.md)「拿不准时继续还是问用户」）。循环停滞时，按总图第四节「观察者」的缝，观察者写入振荡信号，内核按定义停下受影响的分支并交给用户；对停滞事先规定的处理动作（例如请产品部门裁决、通知用户）在设计时确定。
- 每次判定的记录内容：状态、问题、选项顺序、模型版本、概率与置信度；重放使用记录的结果，不重新调用；定期抽样复核。
- 元观察的输入范围：事件与已提交的材料。部门产出由模型生成，写入判定状态之前按不可信内容处理，JEV 的判断与确定的检查一起使用。
- 观察范围是否扩展到阶段四引入的部门内部角色之间。
- 审查与观察结果进入语义系统的知识图谱、供系统演化使用的方式。
