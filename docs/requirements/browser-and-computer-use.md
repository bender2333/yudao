# D34 浏览器与 computer use

状态：有效；浏览器部分是阶段二薄片 ③ 的交付，computer use 部分还没有排入阶段（见本文「computer use 专题待重新确定的事项」）。依据：[总图](../architecture.html)第四节「动作」的缝（浏览器与桌面是动作的两个类别）与第一节「模型与工具」方框；设计：[浏览器与 computer use 设计说明](../design/browser-and-computer-use.md)。路线位置：[总体路线图](../program-roadmap.md)阶段二薄片 ③「质检自己核验网页」；computer use 在第 3 节道 05 动作与工具的未知落点里。

## 已确认

- 质检部门一定装有 computer use、浏览器，以及浏览器自动化相关的技能和工具，确保质检能够从 PRD 生成对应的测试并操作交付物；两个工具参考 Codex 的做法。
- 浏览器工具使用 Playwright MCP，经 [D36](network-and-mcp.md) 的 MCP 接入：每个动作一个工具；每一步把页面的可访问性结构文本交给模型，模型能看图时同时附上截图；截图另外保存为证据。
- computer use 用来操作桌面程序：部门通过截图、点击与输入操作被测的桌面程序，桌面程序在控制主机上、用户已经登录的交互桌面上用真实输入操作，开始前经用户同意，整台控制主机同一时刻只有一个桌面会话（[设计说明](../design/browser-and-computer-use.md)第 5.1 节）。网页应用使用浏览器工具，桌面程序使用 computer use。排队等待桌面会话与等待桌面解锁都是带原因的等待状态，不消耗模型与动作，各有一个时长上限参数，超过时转为决定请求并通知用户一次。
- 两个工具在执行环境中运行，被测的交付软件在同一个执行环境中启动。安全暂放低优先级，按 Playwright MCP 等普通浏览器 MCP 的默认做法运行；另加一条与网络取回相同的拒绝规则：试用会话的浏览器拒绝访问 Yudao 服务自己的地址。
- 质检两个工具都可以使用；工程可以使用浏览器做研发自测，模型能看图时也可以使用 computer use；运维是否使用在阶段三设计运维部门时决定。
- 质检部门的模型应当有视觉能力，设置时只提醒，不强制。部门定义写明建议能力，质检的建议能力是图像输入；保存项目部门设置或部门默认时，所选模型不支持图像，照常保存并提醒用户缺少的能力与影响；请求时按模型实际具备的能力提供工具，不支持图像时不提供 computer use，浏览器只给可访问性结构（[模型管理设计说明](../design/model-management.md)第 5.6 节）。质检没有核验的条目按已有规则如实报告，不能放行。
- 评测使用的模型由用户单独提供，有视觉能力，Yudao 与 OpenCode 两边相同（[D32](comparison-experiment.md)）。
- 浏览器在阶段二薄片 ③ 验收；computer use 还没有排入阶段；评测场景 1 的 Yudao 一侧依赖浏览器。

## 设计确定的内容

设计写在[浏览器与 computer use 设计说明](../design/browser-and-computer-use.md)：试用的位置与执行位置上的程序（第 3.1、3.2 节）；Playwright MCP 的运行方式与启用的能力（第 4 节）；控制主机交互桌面上的 8 个屏幕工具、截图与坐标、用户同意与独占（第 5 节）；截图作为证据的保存与显示（第 7 节）；质检从 PRD 生成试用用例、逐条结论与放行，试用记录绑定交付快照（第 8 节）。

设计说明第 16 节的六项决定：

1. 验收条件用「ProductSpec 摘要 + 验收条件序号」引用；每条验收条件都有绑定当前交付快照的通过证据才能放行。
2. QAReview 的结论包含 `cannot_verify`，并有决定请求「质检无法核验」，选项为重新核验、停止事项。
3. 试用在 run 的执行位置上直接进行，执行位置上需要的程序由用户安装（[设计说明](../design/browser-and-computer-use.md)第 3.1、3.2 节）。
4. 启动方式由工程写在交付说明中：网页应用写启动命令与就绪条件（一个地址有 HTTP 响应），桌面程序写启动命令与就绪条件（出现可见窗口），就绪时限的暂定默认值是 300 秒，包含安装与构建，见规则登记；质检按交付说明启动，用户不需要另外登记启动命令。交付说明没有写启动方式、而验收条件需要试用时，质检退回工程补写。
5. 不提供 `browser_evaluate` 与 `browser_run_code_unsafe`。
6. 屏幕工具使用 Yudao 自己的 8 个函数工具。

## computer use 专题待重新确定的事项

- 已有的设计（[设计说明](../design/browser-and-computer-use.md)中 computer use 的部分）：只考虑 Windows，桌面程序在控制主机上、用户的交互桌面上用真实输入试用，开始前经用户同意，整台控制主机同一时刻只有一个桌面会话。
- 要重新确定的事项：界面改为网页以后（[网页界面的提供与发布设计说明](../design/web-interface-and-release.md)），桌面会话期间的提示框（置顶、不出现在截图中）与「停止使用桌面」由谁提供；阶段三把 Yudao 服务做成系统服务以后，系统服务看不到用户的交互桌面。
