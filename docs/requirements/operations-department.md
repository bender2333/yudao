## 已确认

- 运维部门负责交付物（用户项目的软件）上线之后的工作：部署、运行观察、性能与故障处理。
- Yudao 平台自身的运维先由人负责。愿景是由 Yudao 自己的运维部门负责平台运维；自举难度大，前期由人来做。
- 运维部门的生命周期跟随项目：产品、工程、质检围绕单个事项的 run 工作，运维部门在项目采纳交付物之后接手，长期存在。
- 运行中发现的问题（故障、性能下降、容量不足）作为新事项进入「产品 → 工程 → 质检」流程。
- 运维部门与其他部门可以双向询问，常见的往来是产品与工程。
- 路线位置：Stage 5：运维部门与元观察。原 Stage 3 的 3.8 运维工作包并入本项。

## 设计中待用户确认的规则

以下是架构师在讨论中提出、用户尚未逐项决定的规则，在 Stage 5 设计时确定：

- 性能分工：上线前按 PRD 性能要求进行的验收归质检；上线后的性能观察与容量归运维。
- 运行目标（可用性、时延等）由产品写入 PRD，运维测量并报告达成情况；工程随交付提供部署说明、健康检查与运行数据输出。
- 部署、回滚、重启等外部动作逐项授权，缓解操作只在登记过的清单内执行；运维不修改功能要求，也不代替质检放行。
- 首个发布对象。运行责任样例建议先用贯穿验收的文本 CLI 工具。
- 项目级的运维部门与 run 内的产品、工程、质检之间的询问方式。
- 运行责任样例中的平台与交付物责任分开、发布成功与运维接收分别记录、恢复以用户可见的行为与观察窗口为准，在 Stage 5 设计时沿用。
