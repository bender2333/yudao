# D05 研发先分解任务与计划

## 用户原话

> 研发部门需要先进行任务分解和计划，再去实现。

## 已确认

- 研发先依据当前产品要求进行任务分解并形成计划，再开展实施。
- 计划应有可检查的产出和执行顺序，事后总结不能冒充事前计划。
- 计划不能自行修改产品要求；需要取舍时提出专家请求。

## 本轮设计选择

计划绑定当前合同，保存为受控工件及 PLAN.md，内容含影响范围、有序任务、可验证产出和必要重构。普通计划自动接续；代码修改前必须已有有效计划。职责内调整说明原因，要求或重要承诺改变回产品。不新增人工批准。

## 实现状态

事前计划、合同绑定、调整原因、受控 `PLAN.md` 及 Web 原文查看已实现。无有效计划或超出计划范围的写入返回明确失败，部门可以补交计划后继续；普通计划接纳后自动继续。模型在私有推理中想过步骤不等于已有可验收的计划流程。
