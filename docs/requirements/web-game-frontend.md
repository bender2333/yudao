# D30 游戏化的 Web 界面与界面实现

状态：有效。依据：[总图](../architecture.html)第一节「界面」方框与第四节「接口」「画面」的缝；[画面总图](../architecture-view.html)；设计：[应用层与接口层设计说明](../design/app-and-interface.md)、[网页界面的提供与发布设计说明](../design/web-interface-and-release.md)、[画面与播放设计说明](../design/visualization.md)；原型：当前定稿的版本写在[原型变更记录](../prototypes/CHANGELOG.md)开头，界面的结构、行为与外观以它为准（[ADR-0021](../adr/0021-client-pixel-view-follows-v9-structure.md)）。路线位置：[总体路线图](../program-roadmap.md)第 4 节三个空间（步 0 起）与第 3 节道 09 画面与空间。

## 已确认

- 出发点：让 agent 与 AI 的交互可视化。agent、事物、工作与语义聚合成游戏画面上的抽象，例如小人空闲时走来走去。
- 参考游戏的技术，让用户沉浸其中；参考对象不限于 agent 可视化项目，一般的游戏技术都可以参考。
- 部门房间里的像素小人与动画尽可能丰富，动画属于表演层，不占用承载事实的视觉通道，不回写；项目概览用画面展示循环状态；角色当前的任务与流式输出属于事实，来自事件。
- 界面以原型为依据；阶段一至阶段四（含 D24）的界面完整设计，阶段五的元观察、系统演化与持续改进只保留入口位置。
- 界面与后端解耦，并保证未来的灵活性。
- 真实前端的每个界面随对应的后端工单实现，前端只显示真实数据；原型为每个界面写明读取的查询与提交的命令。
- 「资料与依据」按事项只读查看资料。
- 技术选型（[总体架构](../design/architecture/overall-architecture.md)第 9 节、[应用层与接口层设计说明](../design/app-and-interface.md)）：界面使用 React 19、TypeScript、Vite、PixiJS 8、XState 5 与 GSAP。接口层使用 FastAPI，OpenAPI 由 pydantic 类型生成：命令带身份与基准版本，返回接受或拒绝；查询返回快照与它对应的全局位置；一条可以按范围筛选的事件流（SSE）带全局位置，断线后按位置补齐，发现缺口时重新同步快照；能力清单列出当前部署提供的查询、命令与覆盖层；从本机以外访问需要认证。
- 界面是 Yudao 服务提供的网页（[网页界面的提供与发布设计说明](../design/web-interface-and-release.md)）。构建好的页面文件随 wheel 发布，接口层在提供接口的同时提供这些文件；在浏览器里打开服务的地址就是界面，局域网中的其他电脑打开同一个地址；需要单独的窗口时用 Edge 或 Chrome 的「安装此站点为应用」。以 Windows 上的 Edge 与 Chrome 为准，不考虑手机。Yudao 服务用 `uv tool install` 安装成 `yudao` 命令，一次发布是一个 wheel，包含构建好的页面文件与执行代理的安装包，页面与服务的版本总是相同；每个试用里程碑交给用户之前发布一次，版本号按里程碑递增。服务手动启动：启动命令在服务就绪以后用默认浏览器打开页面地址，停止服务就是结束这个进程；局域网访问用启动参数 `--access lan`；注册为系统服务与登录时启动随阶段三的长时间运行。界面的端到端测试用 Playwright 驱动浏览器。
- 界面的结构、行为与外观以当前定稿的原型为准（[ADR-0021](../adr/0021-client-pixel-view-follows-v9-structure.md)），截图对照也用它；版本号只写在[原型变更记录](../prototypes/CHANGELOG.md)开头，原型定稿时改这一处。验收用截图对照：每个页面与像素画面在 1440×900、1920×1080 两种窗口，设备像素比 1、1.25、1.5，浅色与深色主题下截图，与当前定稿原型同一场景的截图并排做成联系表，连同按场景截取的动作过程交给用户查看，界面工单的验收都包含这一项。像素画面的图形与文字按屏幕的实际分辨率绘制，纹理使用最近邻采样，画面中的文字使用微软雅黑。页面的内容区最宽 1280 像素、居中，整体放大用浏览器的缩放。

## 长时间运行以后的界面

单人使用、多机部署、长时间自我运行以后，界面的使用方式是用户隔几个小时或几天回来查看；决定、登记与确认都需要界面。

- 界面增加系统首页，从上到下：待你决定（跨项目的决定请求，写明等待时长与挡住的项目）；离开期间的报告（从上次查看到现在完成与放行的事项、故障、修复、部署与回滚、等待模型服务、用量、磁盘与报到状态，每项数字来自事件，参照《缺氧》的周期报告）；项目列表。项目概览仍然以像素循环画面为主体。
- 上次查看的位置由控制主机记录一个，用户点击「已看过」时更新；报告可以切换为最近 24 小时或最近 7 天。
- 机房：每台登记的机器是一台设备，显示名称、用途、在线状态与正在执行的动作；上线与离线来自机器流中的事件，探测的瞬时值只在实时通道显示；执行代理心跳中断时指示灯熄灭，对应的动作显示「结果未知」；运行环境单独标出，发布、回滚与故障显示在对应的设备上。机房画在哪里见下一节。「机器」系统页（`#/sys/machines`）登记机器、查看状态。
- 界面只在局域网内打开；从外面访问与手机随消息渠道放到以后。只在局域网内使用期间，认证与加密保留位置并标为 TODO，离开局域网访问之前加入访问令牌与 TLS。
- 不主动推送提醒（[网页界面的提供与发布设计说明](../design/web-interface-and-release.md)第 5.3 节）：在本机打开页面时，出现决定请求、进入等待模型服务、磁盘空间不足时用浏览器的系统通知提示，标签页的标题显示待决定的数量；离开期间发生的事由首页的待你决定与离开期间的报告给出。浏览器只允许 https 页面与本机地址使用系统通知，从其他电脑经局域网的 http 地址打开时没有系统通知。其中磁盘空间不足的通知在阶段三加入：它的阈值参数与事件随长时间运行的「数据保留」一起定（[D27](operations-department.md)），阶段一、二的页面只有前两种通知。
- 页面与服务出自同一个发布，版本总是相同（[网页界面的提供与发布设计说明](../design/web-interface-and-release.md)第 2 节）；同一接口版本内增加的查询与页面由能力清单决定是否显示。
- 可靠恢复、执行环境服务、接入已有项目与阶段三的运维各自连同界面一起验收。阶段四只加入部门内多角色、语义系统相关的界面与可观测性的深入视图。

## 首页与画面的要求

- 界面首先回答：用户回来的时候，哪些事需要决定，离开期间发生了什么，能不能放心再离开。系统首页、决定请求的处理与离开期间的报告是主体；像素画面负责让人一眼看出正常还是异常。
- 首页顶部是一排状态项（参照《缺氧》）：待你决定的数量、结果未知的动作、离线的机器、等待模型服务的 run、磁盘空间、正在修复的故障；每一项取自事实，正常时显示为灰色的「无」，异常时亮起并链接到对应位置。不给汇总的「可以离开」结论。
- 机器由系统登记，多个项目共用，机房属于系统这一层：首页画一栋楼，每个项目一层（状态灯、当前部门、事项小旗，点击进入项目概览），地下室是所有项目共用的机房；项目楼层只在走廊尽头画一扇通往机房的门，并显示本项目正在使用的机器。
- 部门之间的交接经过管道：管道表示组织定义中的许可关系，包裹在管道中的移动表示实际发生的轨迹；PRD、交付箱、返工单、放行单作为包裹在管道中移动；询问与回答走颜色不同的细的传信管；返工时包裹反向流动；等待模型服务时管道停止流动；同一项目排队的事项是管道入口前的一串包裹。
- 决定请求在首页的卡片中就地回答：卡片展开后显示这个决定需要的材料，项目中的页面使用同一张卡片。
- 画面可以回放离开期间的关键事实（交接、询问与回答、返工、放行、采纳、故障、修复、部署与回滚、进入与离开等待、决定请求），没有关键事实的时间段跳过；时间轴刻度与报告中的项目互相跳转；可以暂停、单步与调速。
- 质检房间增加试用台：测试工程师操作浏览器或桌面程序，显示器上嵌入最近一张真实截图的缩略图（像素边框）；检查区增加试用记录；资料页的质检部分列出绑定到交付快照的截图。
- 同一项目排队中的用户新要求可以调整顺序，修复事项始终排在前面。
- 原型的档位按阶段一至阶段四细分，每一档对应一次验收要看到的界面。
- 评测结果不进入界面，评测工具自己生成报告。

## 上下文的界面要求

来源：[D25 语义系统](semantic-system.md)上下文组装专题第 19 条。以下是原型的要求，细节在原型中确定。

- 请求详情按栏目显示每个栏目的来源、已用量与上限，以及每条内容的放入原因。
- 历史中的通知、接触时附加的内容与旧工具结果的占位分别标出，可以打开原文。
- 在部门工作间点击角色，可以看到它当前的焦点、目录与已附加的实体。
- 「上下文」覆盖层显示每个角色的上下文用量占工作上限的比例，标出接近压缩阈值、清理旧工具结果与压缩的时刻。
- 以上数值取自上下文清单与请求事件。
