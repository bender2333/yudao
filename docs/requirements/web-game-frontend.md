## 已确认

- 出发点：让 agent 与 AI 的交互可视化。agent、事物、工作与语义聚合成游戏画面上的抽象，例如小人空闲时走来走去。
- 参考游戏的技术，让用户沉浸其中；参考对象不限于 agent 可视化项目，一般的游戏技术都可以参考。
- 部门房间里的像素小人与动画尽可能丰富；项目概览用画面展示循环状态。
- 界面以 v7 原型为依据；Stage 3、D24、Stage 4、Stage 5 的界面完整设计，Stage 6、Stage 7 与持续改进工作线只保留入口位置。
- 界面与后端解耦，并保证未来的灵活性。
- 真实前端的每个界面随对应的后端工单实现，前端只显示真实数据；原型为每个界面写明读取的查询与提交的命令。
- v6 的「资料与依据」改为按事项只读查看资料。
- 实现顺序：先写界面与 UI 的技术设计与需求文档，再按技术文档拆分任务、建立工单。
- 2026-09-26 用户决定（[ADR-0015](../adr/0015-desktop-client-and-http-contracts.md)）：客户端是桌面程序，外壳使用 Electron，界面使用 React 19、TypeScript、Vite、PixiJS 8、XState 5 与 GSAP；后端不提供界面文件，客户端按地址连接本机或远端的部署。接口层使用 FastAPI，OpenAPI 由 pydantic 类型生成：命令带身份与基准版本，返回接受或拒绝；查询返回快照与它对应的全局位置；一条可以按范围筛选的事件流（SSE）带全局位置，断线后按位置补齐，发现缺口时重新同步快照；能力清单列出当前部署提供的查询、命令与覆盖层；从本机以外访问需要认证。界面的端到端测试用 Playwright 启动 Electron 应用。

## 上下文的界面要求

来源：[D25 语义系统](semantic-system.md)上下文组装专题第 19 条。以下是原型的要求，细节在原型中确定。

- 请求详情按栏目显示每个栏目的来源、已用量与上限，以及每条内容的放入原因。
- 历史中的通知、接触时附加的内容与旧工具结果的占位分别标出，可以打开原文。
- 在部门工作间点击角色，可以看到它当前的焦点、目录与已附加的实体。
- 「上下文」覆盖层显示每个角色的上下文用量占工作上限的比例，标出接近压缩阈值、清理旧工具结果与压缩的时刻。
- 以上数值取自上下文清单与请求事件。
