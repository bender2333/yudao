# D04 产品部门维护 PRD.md

## 用户原话

> 产品部门负责进行转换和需求维护，最终版本记录到PRD.md中。

## 已确认

- 产品部门负责把用户意图和资料转换为需求，并持续维护。
- 最终有效需求记录到 `PRD.md`。
- 用户原文与产品解释分别保存，需求维护不改变 `intend.md` 原文。
- 产品可以咨询其他领域专家后决定需求取舍，见 [D07](expert-ask-react.md)。

## 本轮设计选择

事件中的有效合同是唯一权威；同一次接纳生成 PRD 工件与受控 PRD.md，包含有效补充决定与变更说明。草稿不推进执行。合同标识变化后核对计划、咨询、旧交付与检查，见 D15。

持续输入交给产品后，以完整新 ProductSpec 处理本次已受领的原文范围。已有前版时说明本次改变、仍保留、合法废止及关键理由，并继续逐项处理当前有效补充决定。主机检查记录与引用是否齐全，产品承担需求取舍的语义判断；普通咨询回复及只追加单条正式决定不标记新用户输入已处理。
