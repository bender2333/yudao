> 参考 OMP 自动压缩模型输入后继续，保留摘要依据和原始历史

## 已确认

- 当前阶段参考 OMP 的代码实现处理上下文窗口、历史记忆和压缩。
- 模型输入接近容量上限时自动压缩并继续，不必等语义系统建成后才具备压缩能力。
- 原始部门历史完整保留；压缩只形成新的模型输入视图，不删除或覆盖原始经历。
- 摘要保存其依据、覆盖的历史范围和来源摘要，可以回查原文。
- 部门分别压缩自己的历史，不把其他部门私有上下文混入摘要。
- 每次正常请求仍先带 intend 原文和当前工作，再带该部门历史的当前视图。

## 实现边界

借鉴 OMP 的追加压缩记录、保留近期完整回合、基于最新摘要重建模型上下文等方式。代码由 Yudao 维护，不依赖 OMP 进程或会话。

摘要调用也必须可观察、可取消，并计入模型步骤上限。摘要请求本身必须符合上下文容量，不把已经超窗的完整输入再次直接提交给模型。不能压缩的固定原文与当前工作本身过大时，明确停止并保留事实。

本条补充 [D08](department-history.md)：原始历史不能遗忘；允许通过有来源的摘要压缩模型当次看到的旧历史。此前“本版不自动摘要”的暂定策略被本次确认取代。

## 实现状态

已实现，真实运行验收中。自动化验证覆盖分块摘要、工具回合边界、跨激活恢复、来源完整性、取消和步骤上限。

当前沿用项目的本地 token 估计，在窗口约 85% 时触发，预留输出空间。它不是特定模型 tokenizer 的精确计数；provider 返回超窗或因输出限制形成不完整响应时明确保留失败，不盲重试。新增 [D17](provider-retries.md) 后，压缩调用的连接、超时等瞬时失败与工作调用一样有界重试，失败部分输出不成为摘要或有效历史。摘要请求和正常工作请求分别可查，摘要的原始事件、材料摘要和连续片段范围均保存。

不可解读的加密推理仍完整保存在原始协议项中；摘要材料只携带它的来源、长度和内容摘要，避免把密文误当成可读知识。分块尚未覆盖完整工具回合时继续摘要，不恢复正常工作；工具输出及超长摘要不被采纳。

空摘要或超限摘要不终止任务，部门继续工作，后续激活重试压缩（可能用更小的历史切片）。摘要请求的输出上限固定为 4096 token，与模型声明的输出上限无关；推理模型的 reasoning 输出与摘要正文共享该预算。序列化历史时工具输出截断为 2000 字符。预检确保摘要提示词不超过窗口减去输出预算。

未来语义分解、洞见与数据流是在此基础上优化部门上下文管理，不替代当前完整历史保存要求。
