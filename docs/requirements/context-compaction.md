# D10 上下文窗口、记忆与自动压缩

状态：有效。依据：[总图](../architecture.html)第三节内环「上下文逼近上限 → 压缩」与第四节「装配」的缝；设计：[语义系统设计说明](../design/semantic-system.md)第 11 节、[模型管理设计说明](../design/model-management.md)第 8 节。路线位置：[总体路线图](../program-roadmap.md)第 3 节道 04 装配与语义（减法视图与压缩）。

压缩以 [D25 语义系统](semantic-system.md)（已确认第 22 条，上下文组装专题第 7、8、12 条）为准：被移出的历史由角色整理的尝试、补录的图谱内容与主机生成的轨迹节录代替，本页所说摘要的依据、覆盖范围与来源由轨迹节点的起止位置与证据引用承担。

## 已确认

- 参考 OMP 的代码实现处理上下文窗口、历史记忆和压缩。
- 模型输入接近容量上限时自动压缩并继续，不必等语义系统建成后才具备压缩能力。
- 原始部门历史完整保留；压缩只形成新的模型输入视图，不删除或覆盖原始经历。
- 摘要保存其依据、覆盖的历史范围和来源摘要，可以回查原文。
- 部门分别压缩自己的历史，摘要与整理只含本部门的工作过程；其他部门的内容只按可见范围规定的途径进入请求。
- 每次正常请求仍先带 intend 原文和当前工作，再带该部门历史的当前视图。

## 实现边界

借鉴 OMP 与 opencode 的压缩做法（阈值、保留近期原始记录、分界位置、检查点），代码由 Yudao 维护，不依赖 OMP 进程或会话。达到压缩阈值时先清理旧工具结果；仍超过阈值时，角色整理分界之前的尝试并补录图谱内容，主机校验通过后把更早的历史移出请求，历史开头放主机按轨迹节点生成的轨迹节录（[语义系统设计说明](../design/semantic-system.md)第 11 节，[模型管理设计说明](../design/model-management.md)第 8 节）。

整理请求也必须可观察、可取消，并计入模型步骤上限；整理请求本身必须符合上下文容量，不把已经超窗的完整输入再次直接提交给模型。整理没有通过校验或请求失败时，本次压缩不生效，这一步按未压缩的历史继续，下一步再次压缩。规则、intend 原文与当前有效要求本身过大，或未压缩的历史已经放不进窗口时，事项以上下文超限失败结束并保留事实（模型管理设计说明第 8.7 节）。

本条补充 [D08](department-history.md)：原始历史不能遗忘；压缩只改变模型当次看到的旧历史，原文始终保留在事件中。
