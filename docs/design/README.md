# 设计文档索引

本目录保存模块设计、架构图与设计说明。正本是总图 `docs/architecture.html`：每份设计说明细化总图的一节、一个方框或一道缝，第 3 行写明总图位置与依据（下面每条的总图位置取自这一行），与总图不符的地方改设计说明。设计说明的写法见[设计说明规范](../agents/design-spec.md)。需求原文见 [requirements](../requirements/README.md)，难以撤销的决定见 [adr](../adr/)。

- [骨架与应用设计说明](skeleton-and-application.md)：划分骨架与应用两层，骨架是下一个版本必须读得懂的事实、对方所依赖的合同和应用重写时必须成立的保证，其余是可以整体重写的应用；写明三道缝的契约与最小投影。总图位置：第二节三环；第四节「路由」「装配」「执行」三道缝与「投影」的缝里的最小投影。
- 总体架构设计（`architecture/`）
  - [总体架构：总图与职责分层](architecture/overall-architecture.md)：把全部模块放进同一个结构，写明总图的技术对照、各层的职责与边界、十项长期决定、合同与使用的技术，以及缝的清单与设计说明的挂靠。总图位置：全部六节的技术对照；第 1.3 节对应第四节「要守的缝」。
  - [总图的词与代码名的对照](architecture/name-map.md)：子架构师维护的对照表，列总图的词、代码里现在的名字、归哪道缝；立缝时逐行消。总图位置：第四节「要守的缝」的十三道缝，以及第一节的方框、第三节内环六步与外环九个状态。
- [可信内核设计说明](trusted-kernel.md)：内核是「决定什么成为事实」与「评价一个版本好不好」所用到的全部东西；写明它的边界与清单、四项技术保证，以及自我修改怎样按风险分级放开。总图位置：第一节「一份事实」与「裁决与边界」方框；第二节「只由你批准」那一环；第四节「写入口」的缝。
- [规则登记与参数设计说明](rules-and-parameters.md)：规则登记不另建系统，在定义现有的条目上增加四项记录与取值界限；写明参数怎样成为带版本的数据，怎样对照、采用与撤回，怎样复查与淘汰。总图位置：第二节「定义」方框；第四节「定义」的缝；第五节第二层的限定采用。
- [上下文装配：把视图当作事件日志上的纯函数](context-assembly.md)：把「视图」写成事件日志上的纯函数，先用真实运行记录量清楚什么被用到、什么是浪费，再从测量里提减法规则，并给出装入顺序与截断、三项证明。总图位置：第四节「装配」缝（装配契约：执行实现 ↔ 装配实现），第一节「装配实现」方框（第三环「可以整体重写」）。
- [三部门的循环结构](department-loop.md)：规定三个部门的循环怎样按关注的成果开始工作、怎样同时运行、怎样互相询问、用户的指导怎样送达、工作中途要求变化时怎样处理，以及工程计划的去留。总图位置：第三节外环（成果驱动是第四节「路由」的缝的当前实现）。
- [循环与收敛设计说明](loops-and-convergence.md)：写明循环层怎样声明、怎样保证一定会停、子循环怎样发起、怎样检测是否收敛，以及防止滑向静态编排、容纳变化的判据。总图位置：第三节的边界、停止与子循环；第一节「裁决与边界」方框。
- [形态与核验角色设计说明](forms-and-verifier-role.md)：同一套底下的层只换路由与定义，跑出单 agent、普通多 agent、三部门、外包退化与子组织几种形态；写明四层各认识什么、核验角色（一套核验，任何路由都能放）、直做路由与开环完成、形态随事项冻结。总图位置：第一节「轮转方式」「独立的证据」「质检」方框；第二节「定义」与四层；第三节「开环完成」「子组织」；第四节「路由」「定义」「执行」三道缝。
- [验证的独立性设计说明](independent-verification.md)：按信息的内聚划分部门之间共享的与隔开的内容，可见范围作为参数；写明先判断后看解释、验证密度、检验覆盖与开环，以及什么事到用户面前。总图位置：第一节「独立的证据」方框；第四节「装配」的缝里作者与验证者的可见范围。
- [模型管理设计说明](model-management.md)：写明模型目录、部门与角色的模型选择、推理档位、调用目标解析与上下文容量的判断标准，其他文档与它冲突时以它为准。总图位置：第四节「模型」的缝；第二节「定义」里的模型设置。
- [本地通用工具设计说明](local-tools.md)：写明三个部门使用的本地工具的边界，含使用过程与工作区；网络与 MCP、执行环境服务、浏览器等新增的工具同样遵守。总图位置：第四节「动作」的缝；第一节「模型与工具」方框。
- [执行环境服务设计说明](execution-environment.md)：写明执行环境服务的合同与本机进程、远程执行代理两种实现，用户登记机器、项目授权并设置执行位置、每个 run 按创建时冻结的执行位置派发动作，以及远程动作的心跳、结果未知与迟到回执怎样处理。总图位置：第四节「动作」的缝；第六节「可以多份」的执行机器与三个硬问题的第一个。
- [浏览器与 computer use 设计说明](browser-and-computer-use.md)：试用会话怎样在执行位置上启动交付的软件，浏览器工具与 computer use 怎样提供给部门，截图怎样作为证据，质检怎样按验收条件建立试用用例、逐条给出结论并决定放行。总图位置：第四节「动作」的缝（浏览器与桌面是动作的两个类别）；第一节「模型与工具」方框。
- [网络取回与 MCP 工具设计说明](network-and-mcp.md)：写明网络取回与项目设置中的 MCP 服务器的放置、工具的提供与工具许可、取回与 MCP 的规则、恢复契约，以及结果怎样成为工件与证据。总图位置：第四节「动作」的缝（取回与 MCP 工具是动作的类别）；第一节「模型与工具」方框。
- [接入已有项目设计说明](existing-project-onboarding.md)：已有项目经建档事项接入，包括产品的初始 PRD、工程的结构说明、质检的基线核对，初始 PRD 确认以后现有代码成为项目的第一次采纳。总图位置：第一节「你」与「一份事实」方框（接入已有项目是事项的一种起点）。
- [项目的起始文件夹设计说明](project-initial-files.md)：新建项目时用户给出一个起始文件夹，它的快照成为项目的起点文件，不建档；写明项目的起点怎样取、事项怎样从快照开始。总图位置：第一节「一份事实」方框（起始文件夹的快照是事项的起点）。
- [画面与播放设计说明](visualization.md)：像素画面（首页的楼、项目楼层、部门房间）怎样从事实得到画面，分几层、每层管什么、事件与查询结果怎样变成画面上的状态与动作、动作什么时候演、堆积了怎么取舍。总图位置：第四节「画面」的缝；第一节「界面」方框；[总体架构](architecture/overall-architecture.md)第 1.6、2、5 节相应写有。
- [应用层与接口层设计说明](app-and-interface.md)：写明应用层与接口层怎样分层和分模块，以及命令、查询与读取模型、事件流、能力清单与认证；系统首页、机器页与系统通知以它为准。总图位置：第四节「接口」的缝；第一节「界面」方框。
- [网页界面的提供与发布设计说明](web-interface-and-release.md)：写明 Yudao 服务在控制主机上的安装、命令行入口、数据目录、启动与停止，接口层怎样提供网页界面并在启动后打开浏览器，以及一次发布的构成、版本号与发布脚本。总图位置：第一节「界面」方框；第四节「接口」的缝；第五节第一层自举的发布、排空与看门狗。
- [部门指导的处理设计](department-guidance.md)：用户给部门的指导怎样处理，写明三类职责、按接收部门是否正在工作送达（通知，或开始一轮工作）、处理结果与来源、必验反例与界面对应。总图位置：第三节外环「你中途的指导」那条规矩；第一节「你」方框。
- [语义系统设计说明](semantic-system.md)：分整理与上下文组装两部分，整理把工作过程记录成轨迹、把工作中得到的内容记录成图谱，上下文组装在每次模型请求时选出正确、当前有效的内容，按固定的栏目交给角色。总图位置：第四节「投影」的缝（图谱是应用投影）与「装配」的缝；第一节「观察者」方框（教训发现）。
- [部门内多角色设计说明](department-roles.md)：把每个部门变成围绕一个中心角色的小组（中心型协作），中心角色承担部门核心的规划与判断，探索者、主程与审查者承担可以独立出来的任务，只把结论交回中心角色。总图位置：第一节「产品」「工程」「质检」方框；第二节「定义」里的角色材料。
- [评测场景：版本回归与 OpenCode 对照](evaluation-scenarios.md)：同一套场景、同一个评分器服务两件事，即 Yudao 新旧版本的回归比较，和 Yudao 与单独运行的 OpenCode 的对照；写明三个场景、运行条件、评分、报告与版本比较。总图位置：第四节系统之外「评价」的缝；第五节验收表的「真实场景」一层。
- [测试分层设计说明](test-pyramid.md)：测试按用到的资源分为单元、模块、集成三层，写明三层的定义与登记表、各角色运行哪一层、测试往下层移的规则与测试的写法。总图位置：第五节验收表。
- [恢复契约与故障矩阵](recovery-contract-and-fault-matrix.md)：恢复分事实重建、观察恢复、控制恢复、动作恢复四种能力分别验收；写明最小恢复依据、执行权与一致边界、动作分类与处置、角色任务的恢复和故障矩阵。总图位置：第六节三个硬问题的第二、三个；第四节「动作」的缝里的核实方法。
