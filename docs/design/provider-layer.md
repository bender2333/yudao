# Provider 设计说明：统一调用、多厂商接入与配置生效

> 2026-09-24：模型目录、部门选择、调用目标解析、推理档位与配置生效时机以[模型管理设计说明](model-management.md)为准。本文中「冻结目标」「新任务取得有效修订，旧任务保留原目标」的内容由它取代；调用协议属于模型访问定义（[ADR-0033](../adr/0033-protocol-belongs-to-model-access.md)），协议的预填、请求基址与认证方式以它的第 4 节为准；模块边界、统一调用、取消与观测部分继续有效。

## 1. 要解决的问题

现在 Provider 相关工作分散在目录、运行时、编排器和 Web 中：配置目录生成具体适配器，Web 自行解析 Key 并拼连接测试请求，正式执行则由编排器建立 Responses 连接。继续加订阅和协议，会让每个入口都必须了解这些细节。

新的 Provider 模块把这些变化集中起来：调用方只要说明“使用哪个已解析目标、输入是什么、怎样取消”，就能得到一致的响应、用量与失败事实。更换服务不要求部门循环增加服务品牌判断，新增设置入口也不需要重新写一套文件重载。

这里的“独立”是一个可在没有 Web、没有部门编排器的情况下使用和测试的 Python 模块，建议归入 harness/providers/；不是新增常驻微服务，也不提前发布独立 SDK。

## 2. 概念与数据归属

| 概念 | 表达什么 | 归属与有效期 |
| --- | --- | --- |
| 服务方案 | 例如 OpenCode Go、用户自定义兼容服务；提供有来源的端点、认证方式、默认协议与模型列表地址 | Provider 模块维护的数据表，带 revision 与来源；不是任意品牌名称猜协议 |
| 模型能力表 | 各服务方案下常见模型的输入方式、输出方式、窗口、输出上限、是否支持工具调用与推理，取自 models.dev 的快照 | Provider 模块内与预置表分开的另一份数据文件，带 revision、快照日期与来源；随版本更新，只用于预填模型访问定义（[模型管理设计说明](model-management.md)第 4.1 节） |
| Provider 配置 | 用户的一份服务连接配置：名称、服务方案、地址、凭据引用、模型列表地址；不声明协议 | 本地非敏感目录；同一服务可以配置多个独立连接 |
| 模型访问定义 | 这份连接下的模型 ID、调用协议、能力与运行上限 | 目录内独立记录；一个定义一条协议，需要多条时建多条定义 |
| 候选模型 | 上游模型列表拉回、尚未形成访问定义的模型 ID | 刷新结果，可过期；不等于可用模型 |
| 准入 | 候选变成可绑定模型的唯一路径：勾选加入为访问定义（协议与容量预填，用户可以修改）、模型测试通过 | 加入以后自动进行一次模型测试，用户也可以再次测试；结果绑定配置修订 |
| 凭据 | API Key 及来源/非敏感版本 | 内存、进程环境或明确持久化的 .env；不在普通配置里 |
| 部门绑定 | 产品/工程/质检选择哪个 Provider 配置与模型 | Yudao 调用方负责；Provider 模块不硬编码“三部门” |
| 冻结目标 | 一次任务创建时取得的确定模型、协议、能力、配置修订及认证句柄 | 模块返回的不可变目标；内核只持有句柄和可公开身份 |
| 会话身份 | 上游识别一段连续对话的稳定标识 | 内核提供稳定语义，Provider 将其映射为所需请求头 |
| 调用尝试 | 一次实际调用或取消的身份 | 每次尝试独立；不能拿会话 ID 当成共享取消开关 |
| 套餐状态 | 服务端报告的订阅权限、使用窗口与未知项 | 可选只读观察；不是 Yudao 的任务预算，也不是调用协议 |

Go 的“订阅”、API Key 的“认证”和 Responses/Chat/Messages 的“协议”是三件事。套餐有额度不等于客户端需要 OAuth；Model ID 出现在列表也不等于账号有权调用。

## 4. 统一接口要让调用方知道什么

| 接口能力 | 调用方提交 | 模块保证 |
| --- | --- | --- |
| 管理与观察配置 | 目录修改、凭据修改、重载命令，或只读查询 | 一致的有效修订、可定位错误、脱敏视图；结构合法的未就绪配置可保存 |
| 解析一组目标 | Provider/模型选择及当前运行约束 | 一次读取一致配置与凭据，返回全部成功的冻结目标，或逐项原因；不偷偷借其他目标 |
| 单次模型调用与取消 | 冻结目标、统一消息/工具说明、会话和尝试身份、取消信号、观察接收方 | 一次实际尝试、统一结果、原协议证据、作用于本次调用的取消 |
| 连接、模型与工具能力测试 | 明确选择的目标、配置修订和测试种类（连接 / 单模型真实推理 / 工具往返） | 使用相同协议/凭据/身份路径；结果说明测了什么，不创建任务、不改默认绑定、不计入 D09 |
| 刷新候选与可选套餐观察 | 用户选择的服务、显式刷新动作，以及自定义模型列表地址 | 来源、采集时间、未知/过期状态；候选不自动成为可用模型，不自动改现用绑定，不写入 providers.json |

这些能力是同一模块的接口，不意味着必须映射成一堆公开类。外部无需创建具体协议 SDK client，也无需知道客户端缓存、文件轮询线程或凭据查找顺序的实现。

部门绑定仍保存在现有非敏感配置文件中以减少存储改造，但由 Yudao 装配侧解释为目标选择；解析模块接受任意选择列表。这样后续分析、技能或其他调用方也能使用同一接口，不必伪装成产品部门。

## 5. 配置与调用分别怎样流动

### 5.1 从零启动与发布配置

~~~mermaid
sequenceDiagram
    actor User as 用户
    participant UI as CLI或设置页
    participant PR as Provider模块
    participant Disk as 配置与凭据文件
    participant Core as 运行内核
    UI->>PR: 启动并读取本地配置
    PR->>Disk: 读取目录和独立凭据源
    Disk-->>PR: 缺失或未就绪
    PR-->>UI: 服务可用，模型尚未就绪
    User->>UI: 选择Go、填写Key、保存模型与绑定
    UI->>PR: 分别保存凭据与非敏感配置
    PR->>Disk: 按各操作规则原子保存
    PR-->>UI: 实际生效修订、来源和未完成项
    User->>UI: 创建事项
    UI->>Core: 创建命令
    Core->>PR: 解析本任务的目标列表
    PR-->>Core: 一致的冻结目标
    Core-->>UI: 事项已创建
~~~

保存不是调用测试。目录保存和凭据保存是两个有明确结果的操作，不承诺跨 JSON 与 .env 的文件事务；界面不能在其中一步失败时显示整份接入成功。配置就绪检查只针对本次选择，不要求用户把目录里每份草稿都配置完。

后台重载由模块管理；失败保留上一有效版本并显示警告，明确删除则撤销对应来源。新任务取得有效修订，旧任务保留原目标。完整矩阵由 D22 定义，不在 Web 重复实现。

Provider 返回工具意图，工具由内核执行。它不自动再调用模型，不运行三部门循环，不决定 QA 或完成状态。SDK 内部推理重试关闭；内核仍是 D17 次数、等待、新输入和停止的唯一决策者。

请求证据需在发送前交给现有审计接收方成功保存，无法保存时不继续发送。独立 Provider 测试可以使用自己的观察接收方，不必加载 Yudao 事件库；正式内核接入必须维持审计要求。

### 5.3 配置改变与在途任务

~~~mermaid
sequenceDiagram
    participant Old as 已创建任务
    participant PR as Provider模块
    participant UI as 设置页或文件重载
    participant New as 新任务
    Old->>PR: 使用冻结目标A调用
    UI->>PR: 校验并发布配置B
~~~

连接复用按真实端点、协议和认证句柄隔离；配置更新不能把旧 client 的认证改成新 Key。资源释放以调用/任务作用域为准，删除配置不强制关闭还在使用旧快照的任务连接。

取消始终针对尝试，不以 Provider 或稳定会话 ID 批量取消其他工作。Stage 2.7 不提供进程重启后继续旧任务；Stage 3 恢复未来复用同一目标解析/核实能力，不能绕过本模块重建 SDK。

## 6. 统一消息与协议适配

当前 ModelRequest 直接依赖 AssembledContext，并携带部门/合同细节；既有输出采用 Responses 形状。仅移动文件不足以实现独立，必须把调用接口收束为 Provider 自己的消息、工具调用/结果、取消与观察契约。

内核仍负责决定哪些内容可以进入上下文。Provider 将已装配内容编码成对应协议：
- 保留指令层级、消息顺序、工具调用 ID 与结果配对，不把用户材料提升为系统指令。
- 标准输出包含可见文本、完整工具调用、结束原因、可核实实际模型和标准用量；错误与不完整结果不进入有效历史。
- 必要的推理签名、加密块和协议扩展作为有来源的不透明数据保留并按原协议续传；不伪造缺失项，不把它们当成可公开的模型内部推理。
- 统一输入、实际发送 JSON、原响应/流事件分别记录并关联，不能把统一格式冒称实际 wire 内容。
- 缓存输入、缓存写入、输出及推理 token 按协议实际含义映射，保留来源与未知；不把不同 SDK 字段直接相加造成重复统计。
- 不支持的工具能力、输入类型或必需协议项在请求前拒绝，不能丢字段后“尽量调用成功”。

本阶段新增三种必要适配：复用 Responses；用现有 OpenAI SDK 接入 Chat Completions；用官方 Anthropic Python SDK 接入 Messages。继续复用 HTTPX，不自行编写 SSE 协议栈。SDK 选择及版本在实现包中核对后锁定。

## 7. OpenCode Go 的服务特性

### 7.1 认证与路由

官方允许第三方编码代理使用 Go API Key。选择 Go 时提供其官方接入地址和有来源的模型规则，用户不需要手工拼 URL；自定义服务仍允许显式填写地址。

协议放在每个模型访问定义中，新建时预填：内置服务方案取模型能力表中这个模型的协议（取自 models.dev 每个模型的 `provider.npm`，没有单独声明时取服务方案的默认协议，Go 为 Chat Completions）；自定义服务预填 Chat Completions；用户可以修改，绝不自动试换（[ADR-0033](../adr/0033-protocol-belongs-to-model-access.md)）。同一个 Go Key 下各协议的模型属于同一份连接。Go 三种协议均纳入 2.7，至少各一个代表模型通过真实工具往返；不以一个 Responses 模型通了就宣布所有 Go 模型已验证。UI 只把已登记所需能力、且已通过测试的模型标为可用于任务。

模型列表 GET 刷新的是候选。本次实际列表只有模型 ID，缺少容量/协议/工具能力，所以候选不能直接绑定：勾选加入为访问定义（协议与容量预填），模型测试通过后才准入。自定义连接的模型列表地址默认是连接地址加 `/models`，显示在新建与编辑连接的表单上，用户可以修改：参考实现里 DeepSeek 的 `/models` 在根路径下，Anthropic 协议的地址在 `/anthropic` 子路径下，这类服务由用户把模型列表地址改到根路径。获取失败时写明请求的地址与返回的状态码，没有收到响应时写明连接失败的原因。官方文档、模型能力资料和真实验证共同形成有版本的采用定义；无法确认的字段不套全局默认。文档与旧 OMP 路由矛盾时不自动试换协议，以固定选择的真实验证结果为准。

### 7.2 客户端与会话身份

所有 Go 推理请求使用真实 Yudao User-Agent，并发送 x-opencode-session。内核为同一 run 的同一部门生成稳定、无任务正文的会话身份；跨激活、重试和压缩保持同一对话身份，不同 run/部门隔离。

压缩等辅助请求仍必须带身份，但不因此开启服务端会话续接或共享其他部门内容。测试连接使用独立的诊断会话，与生产任务分开；每个实际尝试仍有独立追踪和取消身份。

对话标识服务于 Go 的路由和缓存，不代表 Yudao 采用 previous_response_id。内核仍发送自己确定的完整有效上下文。

### 7.3 限流、额度和费用

- 网络抖动、明确临时限流按 D17 有界重试；确认凭据无效、无订阅权限或额度耗尽时给出相应原因，不无限等待：等待模型服务有时长上限（`wait.model_service.max_sec`，暂定默认值，见规则登记），不自动换 Key、模型或服务。
- 仅凭 HTTP 429 不能断定月额度耗尽；优先结构化错误、可核实头和有来源状态，未知保持未知。已知服务等待超过现行 D17 上限时明确停止。
- 页面可以提供官方套餐控制台入口。可选额度查询带时间和来源，接口不稳定/失败则显示未知或已过期；其失败不等于推理不可用。
- Go 官方有“Use balance”设置，用户开启后可能在同一 Go 端点消耗 Zen 余额。Yudao 不调整该设置，也不承诺“订阅请求必然不再付费”；缺少响应证据时不能把费用标零。
- 不建立计费系统与预算控制，不用月费推算每次调用价格，不把套餐剩余额度变成 D09 的本地 token 预算。费用等于用量乘以用户在模型访问定义中填写的单价，进入评测报告与对照记录，不进入运行中的控制；没有填写单价时费用保持未知，不填零（[模型管理设计说明](model-management.md)第 4.3 节）。

事实依据和限制见 [一手资料报告](../archive/research/opencode-go-provider-integration.md)。

### 8.1 首次接入

1. 空态显示“添加模型服务”，可选择 OpenCode Go 或自定义连接；未配置不影响浏览历史。
2. 选择 Go 后展示 Key 输入、官方获取入口和凭据保存方式；连接的 ID、名称与凭据引用按服务方案自动填写（Go 使用方案自己的名字，自定义服务按地址的主机名），用户可以修改。自定义服务的地址没有写 `http://` 或 `https://` 时按 `https://` 处理，输入框显示补全后的地址；模型列表地址显示在表单上，默认是连接地址加 `/models`。点「添加」时 Key 随连接一起保存，默认本进程有效；持久化由用户显式选择。已保存的 Key 永不回填。
3. 保存后进入模型选择。刷新得到的是候选：勾选要用的模型，点一次「加入」，每个模型成为一个访问定义。协议按模型能力表预填（自定义服务预填 Chat Completions）；窗口与输出上限先取上游模型列表返回的值，没有时取模型能力表，有预填值就直接采用，界面标明来源，用户以后可以修改；两处都没有时由用户填写，填好以后才能加入。获取失败时写明请求的地址与状态码，用户可以修改模型列表地址，或手动添加访问定义。
4. 加入以后对每个新的访问定义自动执行一次模型测试，即一次真实最小推理：通过即准入；未通过时显示原因，定义留在候选，用户修改以后可以再测试。连接测试读取模型列表地址，证明地址与凭据，连接下没有访问定义时也可以进行。未保存的修改需先保存，避免“测的是草稿、任务用的是旧值”。测试中有进度与取消，结果带模型和配置修订。
5. 选择产品/工程/质检绑定，保存后显示“新任务将使用此配置，已有任务保持原配置”。
6. 绑定完整且目标就绪后提供“回到项目创建事项”；不以测试成功自动创建任务。

“测试连接”按服务方案的认证方式读取模型列表地址，证明地址与凭据可用，不改变准入；“工具能力检查”单独说明会做一次无副作用工具往返、消耗一次或多次模型请求。后者仍由诊断调用方执行工具回路，不能给 Provider 模块新增 Agent loop。

### 8.2 状态与错误

| 状态 | 页面表达 | 用户下一步 |
| --- | --- | --- |
| 未配置 | 无默认模型服务 | 添加连接 |
| 已保存但未就绪 | 缺凭据、缺模型能力或部门绑定 | 跳到对应字段 |
| 就绪但未测试 | 配置具备调用条件 | 可显式测试，不宣称远端已通 |
| 候选未准入 | 加入的访问定义模型测试未通过，显示原因 | 按原因修改协议、容量或连接后再测试，通过后再绑定 |
| 测试通过 | 所选模型、测试类型、修订及时间 | 绑定或创建任务 |
| 测试失败 | 认证/权限/限流/连接/协议等可核实原因；缺凭据与凭据无效分开 | 按原因修正，不丢已填非敏感字段 |
| 文件更新未生效 | 最近有效版本仍在用；展示脱敏重载错误 | 修复文件后重载 |
| 临时 Key | 来源为进程内存，重启失效 | 按需显式持久化 |
| 额度未知或数据过期 | 不可获取/采集时间，不显示零或绿色正常 | 打开官方控制台 |

配置、远端认证、账户额度和任务状态分别呈现，避免一个绿点代表全部可用。错误放在相应字段附近，保存/测试按钮反馈加载、成功和失败；保留可见标签和键盘操作，1440/390 均不依赖 hover 才能读完整字段。

### 8.3 更新、清除与返回

更改 Key、模型或绑定后，旧测试结果保留为历史并标记不对应当前修订。文件自动重载不能清空用户正在编辑的表单；显示外部变化，提交仍遵循 D22 的后写赢规则。

删除 Provider 仍检查模型与绑定引用；不把运行中快照当成可随意改写的管理配置。清除临时 Key 与删除持久 Key 用不同明确动作，操作后显示实际生效来源。返回工作台保留项目与事项选择，不因设置操作新建 run。

## 9. 存储与替换范围

沿用 providers.json 保存非敏感目录和默认绑定、.yudao/.env 可选保存 Key、事件/工件保存任务采用的非敏感身份与实际调用证据。新增的服务方案、模型级协议、能力来源、配置修订由统一模块定义。

候选模型不落盘：刷新结果只服务本次设置页会话，每次打开重新拉取。providers.json 放的是用户配置，不存未准入的候选清单；落盘的是准入结果——访问定义、协议、能力来源与测试结果摘要。上游不可用时界面显示“候选未知”，不拿上次结果冒充当前。

目录在连接上声明协议时，读取直接报错并指出字段位置，不加默认继承或兼容读取，由用户在界面按访问定义声明协议后保存。导入/导出、示例、测试夹具和启动文档随同一工作包更新，不写 migration。

实现时移除目录对象创建适配器、Web 拼测试请求/解析凭据/持久目录、编排器直接创建 Responses client 等重复路径。模块内部复用既有可靠行为；不在旧实现外再包一层同样复杂的转发器。

## 10. 设计验收与开放边界

独立性的证明是：不启动 Web、不加载部门内核也能完成配置、解析目标、一次模型调用和取消；正式工作、压缩、重试、smoke 和诊断都经过同一接口。测试观察模块输入输出、捕获真实网络请求，不绑定私有类布局。

本阶段不做其他订阅 OAuth、多 Key 自动轮换、备用服务切换、动态插件市场、自动选择模型、账户充值、跨版本恢复或费用硬预算。未来确有其他订阅时在认证/服务实现内部增加必要机制，调用方继续使用同一接口；不现在预建它们。

多厂商的边界同样明确：预置表与模型能力表是模块内数据、不做远端热更；不开放自定义协议形状，只有已实现的三条协议；不做全量批量体检；协议内的细微差异（stream_options、developer role 之类）在真实差异出现前不抽象成方言字段。

设计已覆盖行为和职责；实现状态、逐包验收及真实调用证据统一在 Stage 2.7 计划中更新。
