# 部门指导的处理设计

日期：2026-09-06。对应 [D20](../requirements/department-guidance.md) 与 Web 计划 W0/W6。以下是本轮架构选择，不冒称用户已逐项指定。已实现：接口 `POST /api/runs/{run_id}/departments/{department}/guidance`（`harness/web/server.py`）接收指导，`harness/interactions.py` 的 `receive_guidance` 保存原文并写入接收事件（提交 `fe78667`，`fcb06ab` 把「已解释」与「已完成」分开）；测试与真实运行证据见 [D20](../requirements/department-guidance.md) 的「验收与状态」。

## 三类职责

| 职责 | 负责的结果 | 不承担的责任 |
| --- | --- | --- |
| 原文与接收 | 保存任务、接收部门、原文及顺序，返回可追溯的接收记录 | 发送成功不表示模型已看到或处理 |
| 部门工作与调度 | 在同一个原生循环中安排指定部门，核对工作依据和正常权限，保存回应 | 不创建独立聊天运行器，不让页面直接推进部门或修改合同 |
| 界面与观察 | 显示草稿、接收、实际输入及回应，能够回到对应工作和请求 | 不根据计时器模拟处理，不把其他部门的私有原文自动广播 |

原有全局输入仍保存到 intend 并由产品处理。部门指导作为带范围的独立原文保存，不自动拼入全局 intend，也不修改该部门 Prompt。界面切换或重试发送不得改变原接收部门。

## 生效顺序

取消优先于新的执行；已经发生的工具结果仍保存。全局新输入按既有规则先由产品形成新的有效工作依据，部门指导随后依据新工作判断是否仍适用。原型中的发送动画不改变这个顺序。

| 情形 | 处理约定 |
| --- | --- |
| 当前部门正在进行模型调用 | 保留该次请求的实际输入；新指导排队。调用返回后保留旧回复的观察记录，不据此开始新工具或接纳提交；在新的部门激活中纳入指导 |
| 当前部门的工具已经开始 | 等工具结束并记录实际结果，在下一安全节点转入新指导；不自动回滚真实文件操作，也不继续执行旧回复中尚未开始的工具 |
| 接收部门尚未活动 | 在当前激活结束后安排该部门处理；已有未结协作先按原规则结束，不建立嵌套协作或第二条执行循环 |
| 指导要求改变需求或验收 | 指定部门通过既有协作交产品处理，传递必要原文及来源；产品形成有效要求后才影响工程与 QA |
| 最终 QA 准备放行 | 当前任务所有已接收指导都必须有可追溯的处理结果；有待处理指导时先完成相应部门工作，再重新核对 QA 所依据的实际合同与交付 |
| 任务已结束 | 拒收新的指导并保留用户草稿；不恢复旧执行，不把指导偷偷写入新任务 |

调度需要保留被暂时让出的工作及其依据。指导只要求解释或回应时，处理后回到仍然有效的原工作；如果形成了新的产品要求、工程计划或交付，则按现有失效与返回规则重新确定工作。不能仅按原阶段名称恢复已过期的工作。

同一部门连续收到的指导按接收顺序处理。一次激活可以处理一个已冻结的批次；运行中追加的原文进入下一批，不能让同一次模型请求的依据在事后变化。持续输入也不得延长原有模型步骤或激活次数上限。

## 处理结果与来源

接收、进入实际模型输入、部门回应分别保存。回应说明已经采取的动作、无需变更的理由、不能执行的边界，或提交产品处理的结果。只回复“收到”不能冒充已经完成文件修改或需求变更。

跨部门传递保留必要原文的准确引用及来源，不以模型改写后的描述冒充用户原话。未被转交的私有指导不会因协作或页面刷新进入其他部门输入。正式产品要求和计划对外共享，原始部门对话的可见范围保持独立。

指导不授予额外工具权限。工程不能据此绕过事前计划，质检不能据此修改交付，产品不能把普通对话直接记为独立 QA 放行。模型回应与主机实际接纳的结果分别记录。

## 必验反例

1. 模型等待期间追加指导，旧回复返回后不得执行尚未开始的写操作或提交旧判断。
2. 写工具在途时追加指导，实际已写内容仍可查；下一激活看到真实工作区及新指导，不宣称已经回滚。
3. 工程咨询产品期间收到质检指导，协作正常结束后才安排质检，不能覆盖已有咨询身份。
4. 工程指导要求改变目标时，工程不能直接改产品合同；产品收到必要的准确来源后形成正式处理。
5. QA 放行与新指导到达交错时，结果必须归属明确；正式终态之后的请求拒收，正式接收的指导不能被遗漏。
6. 切换任务、部门、刷新、断线或重复发送时，不串草稿、不串接收对象，不重复形成同一接收事实。
7. 指导处理引起合同或交付变化后，不能恢复旧上下文、旧计划或旧 QA 结果。
8. 指导与全局输入同时存在时，各自原文及范围保持可查，取消仍立即生效。

## 界面对应

部门页继续采用冻结原型的主消息区与右侧检查区。输入区明确接收部门，接收记录、实际输入与回应可沿消息进入同一次 Context 和模型尝试。等待、拒收和查询失败使用真实状态；发送中的对象固定，切换查看对象不改写已发命令。

W6 开工时将上述规则映射到现有激活、协作、合同和输入边界，分别实施接收、调度、接纳及查询。所有者与接口先明确，再按当前模块责任交给子代理；不为未完成的复杂度替换已经工作的原生循环。
