# Journal 2026-07-22

## 三部门 MVP 验证方案重设计

- 用户明确要求抛弃现有 U/P/V 设计，从零重做三部门工作方式与验证方法。
- 核心问题锁定为：三部门是否比单 Agent 更容易做对复杂软件任务。
- 处理臂改为 S（单 Agent）与 T（需求/开发/质检工单闭环）；两边各自跑到完成，不作等预算质量声明，成本单独报告。
- 三部门采用长期私有会话；跨部门只传验收单、澄清单、交付单、返工单和放行单，最新有效工单覆盖旧记忆。
- 质检部只读且拥有唯一放行权；真正正确性仍由循环外 0–100 隐藏评分与 fatal 门槛判定。
- 暂不引入容器；新方案移除任意 shell，使用相对路径文件工具、预登记检查和一次性检查镜像。结论必须限定为本机软隔离工程证据。
- 正式设计：12 道自建复杂题 × S/T × 3 次，共 72 个 run；支持门槛为 T 赢至少 10/12、平均有效分提升至少 5、fatal 与 false-complete 均不增加。
- 设计文档：`docs/native-harness/three-department-work-order-validation-design.md`。
- 本次未改 harness 代码、未调用 live 模型、未运行实验。
- 会话开始时已有 `docs/journal/2026-07-10.md` 修改和 `docs/native-harness/ISSUES-content-filter.md` 未跟踪，均未参与本次提交。
