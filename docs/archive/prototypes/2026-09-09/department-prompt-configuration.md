# 项目级部门 Prompt 配置

状态：原型交互及接入约定。本文不表示生产项目级 HTTP 接口已经实现。

## 用户需求与作用域

用户要求产品、工程、质检都支持独立的自定义 Prompt，并增加配置入口。配置以“项目 + 部门”为单位，适用于该部门后续工作，不属于某一个事项。三个部门的文本与版本分别保存，项目之间互不继承本次编辑。

既有 D02 已确认部门规则文本可修改、一次激活固定版本、下一次部门激活采用新版本，历史实际输入可回查。当前生产 `LoopSystem.update_prompt(run_id, department, text)` 仍是 run 范围，不能直接宣称已经实现本原型的项目级配置。项目持续性落地时接入项目配置责任，继续复用原有版本、记录与采用机制。

## 界面约定

- 每个部门工作区头部提供“配置 Prompt”，检查区 Prompt 页签提供同一配置入口；检查区收起时仍能打开编辑。
- 编辑窗口显示项目名、部门名、当前已保存版本及生效范围。编辑完整的部门规则文本，用户可查看默认内容并将其填回编辑区。
- 保存只更新绑定的项目和部门；空白文本明确拒绝，同一文本重复保存不制造无意义的新版本。取消不改变已保存配置。
- 恢复默认先填入编辑区，仍需保存才能改变配置；这是普通保存操作，不删除历史记录。
- 保存后显示“已保存，供本部门下次工作使用”。原型仅更新内存，不产生模型请求，也不伪造“已用于请求”的事实。
- Prompt 检查区分开显示项目当前配置与所选请求实际采用内容。更改项目配置不改写旧请求的 Prompt、Context 或用量。
- 编辑后仍能按原路径查看观测、返回部门、切换项目和收放左栏；原有对话草稿独立保留。

## 配置接入接口（设计约定）

| 操作 | 输入与范围 | 返回与行为 |
| --- | --- | --- |
| 读取配置 | 项目标识、部门 | 当前文本、默认文本、配置版本、更新时间 |
| 保存配置 | 项目标识、部门、完整文本、所编辑的配置版本 | 新的已保存配置及版本；版本已变化时说明冲突并保留草稿 |
| 恢复默认 | 在客户端把读取到的默认文本放入编辑区 | 通过同一保存操作提交，不另建一套生效流程 |
| 查看实际使用内容 | 确定的请求/尝试身份 | 当次 Prompt 原文和版本；只读，不从当前配置回填 |

正式服务可将读取/保存映射为项目部门资源上的 GET/PUT；具体路由与项目管理接口一并确定。查询实际请求继续使用已有观测数据。浏览器只提交配置内容，不负责重启部门、写入有效需求或改变工具权限。

项目配置的存在不依赖活跃 run；对已结束执行保存项目配置，影响后续新工作，不恢复旧执行。活跃部门本次工作继续使用已固定版本，下一次激活采用当时最新配置。工具权限、合同校验和质检放行规则仍由运行系统负责，不属于自定义 Prompt 可修改的内容。

## 原型边界

文本、版本、默认内容和保存回执都是浏览器内存示例，刷新后恢复初始状态。真实保存失败、跨客户端编辑冲突和模型采用需要在正式服务接入后验证；本轮不以原型保存成功代替这些验证。
