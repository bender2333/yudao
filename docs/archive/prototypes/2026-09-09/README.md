## 本版组织方式

项目负责长期目标、资料和成果；项目内直接进入协作总览、产品、工程、质检、观测、资料与设置。进入部门不要求先建立或选择工作项，也不要求存在活跃执行。

协作总览提供流程与看板两种呈现。卡片代表项目中的协作事项，展示承接部门、交接材料、状态及待决原因。两种视图使用同一组事项和交接记录，返工返回原部门时保留来源。原型不引入部门内部任务拆解、冲刺、估点或敏捷层级。

部门页默认面向整个项目，可聚焦一个事项。部门对话与追加指导为主区；Context、Provider、Prompt 为可收放的检查区。项目长期工作依据和某一次实际请求的输入快照分开，查看其他请求不会改变当前对话的接收范围。

观测页保留请求列表、部门/事项/状态筛选、一次逻辑调用的各次尝试、Request/Response/事件原文及用量统计。从部门 Context 进入关联请求，返回时恢复部门与聚焦范围。输入 Token 包含缓存读，缓存不再重复相加；失败但未上报用量的尝试保持未知，不填为零。

### 导航调整（2026-09-09）

- “资料与依据”和“项目设置”入口集中在项目概览，部门与观测页面不再重复展示。
- 从项目概览或部门进入观测时保留来源界面；观测列表、用量与详情中可返回进入前的页面。查看请求、切换尝试不会替换来源部门的事项范围和草稿。
- 左侧 Yudao 项目栏可折叠与展开，折叠后保留可发现的展开按钮。折叠状态与部门检查区的收放独立。

### 三部门独立自定义 Prompt

- 产品、工程、质检工作区头部及 Prompt 检查页签均可打开对应部门的配置；检查区收起时头部按钮仍可用。
- 按项目和部门独立保存正文、默认内容和配置版本。提供编辑、保存、取消及恢复默认；恢复默认先填入草稿，保存后才更新。
- 检查区分别展示项目当前配置与所选请求实际采用内容，修改配置不改写历史请求。保存用于后续部门工作，原型不会生成真实模型调用。
- 配置交互与读取/保存接口约定见 [部门 Prompt 配置](department-prompt-configuration.md)。当前生产接口仍为 run 范围，项目级持久接口属于后续正式接入。

## 必须能体验的路径

1. 选择项目，直接进入任一部门；没有活跃事项的项目仍可进行项目级讨论。
2. 协作总览切换流程/看板，打开同一事项并查看交接与返工记录。
3. 从事项聚焦到部门，切回全部项目工作；两个范围的输入草稿保持独立。
4. 部门中选择一次 Context，查看对应请求、失败/成功尝试及 Raw 内容，然后返回原部门范围。
5. 观测筛选同时影响请求记录与用量汇总，未上报用量保持明确。
6. 从想法建立项目，或登记已有项目的代码/资料并查看三部门建档示例；两种入口汇合到相同的项目级导航。
7. 项目搜索、置顶、重命名、归档/恢复及资料登记保持可用。
