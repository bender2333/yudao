# 三部门协作与模型管理原型设计 (v5)

日期：2026-09-22。性质：界面原型设计说明与事实记录。

## 1. 原型要回答的问题

1. 如何将模型服务的资源管理（连接库、协议、凭据、模型提取与准入）与业务消费（项目管理、三部门协作流转）清晰分层，避免信息架构错位？
2. 宿主级的三部门模型与推理努力程度（Effort）分配应置于何处，既能作为全机新事项的冻结基线，又不会干扰具体的项目概览？
3. 如何通过具象化的设计呈现部门工作区与未来多 Agent 协同（SubAgent）的状态，同时保证人类指令交互与配置操作自然便捷？

## 2. 系统分层与信息架构

系统整体划分为三层控制复杂度：

```mermaid

    subgraph 1. 顶层导航与视角分离
        NavSide[左侧导航: 项目列表 / 搜索 / 新建项目 / 底栏模型管理入口]
        NavTop[顶部面包屑导航 + 自动推进运行指示]
        NavTabs[顶栏选项卡: 项目概览 / 产品部 / 工程部 / 质检部]

    subgraph 2. 资源视角: 模型管理 (全机全局)
```

## 3. 核心设计与交互规范

### 3.1 模型管理与全局三部门分配
- **访问入口**：常驻于左侧导航栏底部的“模型管理”。
- **遵循 CC SWITCH 机制**：单份 Provider 配置对应唯一的上游调用协议（OpenAI Responses / Anthropic Messages / Chat Completions），彻底杜绝模型与协议的错位。
- **预置模板驱动**：提供预置药丸（OpenCode Go / AnyRouter / StepFun / Anthropic / 自定义），自动带出端点、协议、文档与环境变量凭据引用。
- **获取模型列表**：支持一键向 `/models` 端点发起探测并以芯片形式拉取候选模型池，点击即可一键加入映射列表。
- **能力参数真实性**：上下文窗口与最大输出限制在保存前由用户显式核验或修改，防止虚假占位值导致压缩引擎崩溃。
- **折叠卡片列表**：已配置的 Provider 默认收起折叠，展示协议标签、凭据就绪状态与包含模型数；展开后可查看模型列表、单项最小推理测试或删除（含部门依赖校验）。
- **底置三部门全局分配**：位于模型管理页的最底部，明确标识为全机全局生效。为产品部、工程部、质检部指定默认 Provider、已准入模型及 1–4 级 Effort（低/中/深/极）思考深度滑块，点击“保存全局分配”后作为全机新建事项的冻结基线。

### 3.2 项目概览页
- 移除此前杂糅的三部门模型分配卡片，使概览回归纯粹的业务与状态维度：项目当前目标、已采纳成果基线、工作项统计与最近跨部门流转交接历史。

### 3.3 部门工作间（2D 像素风房间舞台）
- **区域感与物理界限**：全宽展示，采用厚重深色双重边框与顶部硬核门楣标识（`ROOM_ENGINEERING // AGENT WORKSPACE`），彻底区别于普通页面。
- **CRT 显像管任务看板**：墙壁悬挂复古绿光 CRT 显像管风格监视屏（`TASK MONITOR // CRT-01`），以等宽字符实时呈现当前目标、Effort 与执行周期。
- **2D 像素小人与工位**：地砖采用斜向透视纹理，责任小人坐在办公桌前，具备微动的头部与眨眼动画，头顶悬浮粗描边的像素对话/思考气泡；支持一键“+ 派发协作者 (SubAgent)”实现多个小人并排办公，形象化映射多 Agent 协同。
- **部门设置下拉菜单**：移除多余的“返回概览”按钮，在右上角原位置提供“部门设置 ▼”菜单，点击就地呼出模态弹窗进行当前部门的“模型与 Effort 配置”以及“部门 Prompt 规则”修改。
- **人类操作固定在最底端**：房间下方承接流式事件日志，而人类输入框与发送按钮始终固定在页面最下方，输入指令后小人头顶气泡即刻反馈，并将指令注入下轮 Context。
