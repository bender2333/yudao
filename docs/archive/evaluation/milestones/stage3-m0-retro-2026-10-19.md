### 4.3 CI 与测试：运行机上的不稳定项

- 现象：`test_release_script.py` 的用例在运行机上「worker crashed」：20 次集成层运行（13 次 main 推送、7 次 PR 或手动）里 3 次（39089166393、5cc30260 两次尝试算一次、39174544310），只看 main 推送是 1 / 13。本机不是没有：10-17 派发者在本机 `-n 4` 整层时 `test_release_script` 10 项红，当时写「高负载下的时序抖动，不在本 PR 范围」（#463 评论 21:19Z），没有开工单。`test_department_providers.py` 的 1 项出现 1 次。
- 原因链：`release_build` 夹具是模块级（`test_release_script.py:92`），每个 xdist worker 各自做一次 `npm ci`、Vite 构建与 `uv build`，`-n 4` 时四个构建同时跑。待定：worker 被结束的直接原因（内存或超时）要运行机上的日志，`--log-failed` 只有 `worker crashed` 一行；运行机的核数与内存没有核实。
- 对照：同一夹具、不含 #547 的 8 次 main 运行 0 次崩溃；与 #547 的关系待定（第 3.3 节）。
- 改动层：CI 与测试（C1）。第二个问题在规则：派发者规则第 5 节第 2 步只拿「前一个合并提交」比较，复发的不稳定项会让它重新打开无关的工单；而且这项崩溃上一次出现在 PR 事件的运行上（39089166393），只看 main 推送的历史也找不到。派发者这次没有执行第 2 步，所以没有发生。规则改法见 C2。

### 4.4 执行环境：运行记录在复盘读不到的地方
