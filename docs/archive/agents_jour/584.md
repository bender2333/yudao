执行者 9router/ag/gemini-3.8-flash-high / 2026-10-18 00:55 / 原因定位：
1. ADR-0038 / 工单 #542 将写回检查由「根据名称查找登记命令」改造为直接经 bash -c 执行命令字符串（`run_writeback_checks` 遍历命令字符串）。

3. `test_event_payloads.py` 中的 `_release_script` 调用 `harness/proposals.py` 的 `delivery_turn`，其 `checks` 默认值为 `{"smoke": 0}`，导致采纳事项 C 的 `adoption.check_names` 为 `["smoke"]`。
4. 采纳写回执行时，`perform_writeback` 合并 `source_dir.check_commands` 与 `adoption.check_names`，在独立工作区执行 `bash -c "smoke"`。在系统环境 / Git bash 下 `"smoke"` 不是可执行命令，进程返回退出码 127。
5. 检查未通过，`perform_writeback` 按设计停止写回并写出 `WRITEBACK_STOPPED`（`reason="verification_failed"`），而测试在第二步推进目标提交后期望的是检查通过并写出 `WRITEBACK_COMPLETED`。
结论：产品代码行为完全符合 ADR-0034 与 ADR-0038 设计；失败原因是测试辅助函数 `_release_script` 未适配命令字符串规范，仍传递旧命令名 `"smoke"` 导致写回检查执行失败。原因在测试端。
