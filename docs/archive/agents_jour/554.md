# 工单 #554：工程与质检问答的事实与解释

依据：[三部门的循环结构](../../docs/design/department-loop.md)第 4.6 节与[验证的独立性设计说明](../../docs/design/independent-verification.md)第 4 节。从 #472 拆出（#472 正文验收第 8、9、10 条由本工单完成）。分支：`issue-554`，worktree 在 `D:/codes/yudao-worktrees/issue-554`，起点是 main 的 `b500b2dc`。

## 记录

执行者 minimax-M3.1-Flash / 2026-10-24 /

1. 口径（三条）：
   - **工程给出的内容分两部分**：工程向质检提的问题与背景、工程回答质检的回答，各写一份事实（接口、使用方式、文件位置、怎样运行、主机证据的引用）与一份解释（实现的理由、对正确性的判断、对失败与审查意见的看法）。其他组合（问产品、问工程）不变。
   - **质检在形成自己的判断以前只看到事实部分**：条件是事件日志里已经有当前交付的结论（独立判断事件由 #358 加入以后以它为界；本工单按工单正文，以缺陷记录或放行为界）。新的交付到达后按新交付重新计算：此前全部工程内容的解释部分重新藏起来，等质检对新交付的结论。
   - **三条通道**：交付说明、质检收到的工程回答、质检分支看到的工程的问题。事件里保存的原文不变，藏与不藏由上下文装配决定。
2. 实现：
   - `harness/definitions/tools.json`：`ask` 与 `answer` 各增 `facts`、`explanation` 两个参数；`ask` 的 `question`/`background` 与 `answer` 的 `answer` 不再是必填（工程与质检之间用两部分，其他组合照旧写）；两个工具的说明写明什么时候用哪一组。
   - `harness/app/payloads.py`：`AskStartedPayload` 与 `AskAnsweredPayload` 增 `facts`、`explanation`（可空）；`question` 可空。
   - `harness/orchestrator.py`：询问与回答的事件把两部分写进载荷；询问的内容（问题或事实部分）至少给一份。
   - `harness/engine.py`：回答的文字取 `answer`/`text`/`facts`；产品修订规格时排除这两个字段。
   - `harness/projection.py`：询问栈的条目记下 `facts`、`explanation`。
   - `harness/context.py`：新增纯函数 `quality_engineering_content(events, delivery=...)`——输入事件，输出质检请求里可以放入的工程内容（事实部分总在、解释部分按条件、三条通道）；配套 `engineering_facts_text`；交付说明的解释部分字段由提案合同标明（`harness/definitions/proposal_contracts.json` 的 `delivery_spec.parts`），装配时按条件去掉。
   - `harness/context.py` 的装配：交付说明、待回答的询问、工作文字按条件给事实部分；质检对当前交付下结论以后，问答里的解释部分作为 `engineering_explanation` 进入它之后的请求。
   - `harness/definitions/__init__.py`：事实与解释的划分是主机装配时用的，不进模型看到的提案合同（工单验收第 4 条要求提示快照的变化只在 ask 与 answer 的参数）。
3. 测试：
   - `harness/tests/test_engineering_facts.py`（单元层，4 条）：纯函数的三条通道与交付变化的组合——交付说明的解释部分在质检下结论前不给、下结论以后给；回答与问题在结论前只有事实部分；新的交付到达后解释部分重新藏起来；还没有交付时解释部分从不出来。
   - `harness/tests/test_quality_facts.py`（集成层，1 条）：工程回问质检时质检分支的请求里只有事实部分；质检询问工程时工具结果与历史记录只有事实部分；质检提交缺陷记录以后的请求里有解释部分；新的交付到达以后解释部分重新藏起来。
   - `harness/tests/event_sequences/tool_denied_guidance_only.json`：上下文摘要随工具定义变化重写（内容哈希一行）。
   - `harness/tests/prompt_snapshot.json`：ask 与 answer 的参数与说明变化。
4. 留给架构师的两点：
   - **独立判断事件还没有（#358）**：本工单按工单正文以「缺陷记录或放行」为界。真实的流程里质检提交结论时交付同时作废，所以交付说明的解释部分在缺陷记录之后没有可见的窗口，只有问答的解释部分有；#358 把独立判断拆成单独的事件以后，交付说明的解释部分会在质检下结论与提交结论之间可见。工单验收第 8 条的「提交缺陷记录以后的请求中有解释部分」在当前实现里由问答的解释部分满足。
   - **事实与解释的划分放在提案合同里**（`delivery_spec.parts`），按[验证的独立性设计说明](../../docs/design/independent-verification.md)第 4 节「交付说明的每个字段在提案合同里标明属于事实还是解释」；这份划分不进模型看到的合同，模型按字段填写即可。
