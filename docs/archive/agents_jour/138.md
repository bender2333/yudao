# 工单 #138：初始 PRD 的决定卡片与资料

## 背景与目标

工单正文（#138）要求：接入已有项目的建档 run 产出初始 PRD 的决定卡片与资料页按
`docs/stage-3/3.8-*.md` 设计展示，界面上能看到 PRD 原文、结构说明、基线核验汇总、
快照来源与规模，资料页按轮列出。本工单只改 `client/`，后端字段由 #137 起已提供。

## 卡点（架构师定位并改写正文）

原以为「顶栏下拉与概览两处卡片显示的修改意见不一致」是数据或后端问题。
架构师在工单评论里指出卡点在客户端视图标识：`contract/view-sync.ts:44-74`
`ViewSync.open` 对同一标识先关后换、迟到结果丢弃。同一个决定同时出现在顶栏下拉
与概览文字列表，两处共用标识必有一处收不到修改意见。按工单条件 1「每处列表
自己的标识」修，不改 view-sync 语义。

资料页建档各轮的展示拆到 #573，本工单保留已写好的资料页改动。

## 改动

界面：

- `views/decisions/card.tsx`：`DecisionCardList` 新增必填 prop `viewId: string`，
  决定卡片的修改意见按该标识查询。四个调用处各给唯一标识：
  `shell/topbar.tsx` → `"topbar.decisions"`、
  `views/project/floor-screen.tsx` → `"floor.decisions"`、
  `views/home/page.tsx` → `"home.decisions"`、
  `views/project/recovery.tsx` → `"recovery.decisions"`。
- `views/decisions/card-logic.ts`：卡片列表按设计第 3.2 节补材料轮次、PRD 摘要
  （没有摘要时显示「没有摘要」）、PRD 与结构说明工件、基线核验汇总、快照来源与规模；
  删掉 `push("修改意见工件", refPath(request.revision_note_ref))`——工件路径不显示给用户；
  第一轮 notes 为空时卡片自然不显示「上一轮修改意见」行。
- `views/project/materials.tsx`：资料页按轮列出初始 PRD、结构说明、基线核验与确认记录。
- `views/project/overview.tsx`：成果是建档基线时显示快照来源与现有缺陷数。
- `card.tsx`：删掉调试用的 `console.log("NOTES-DATA", …)`。

测试：

- `tests/unit/card-logic.test.js`：原 `assert.equal(map["修改意见工件"], "REVISION_NOTE.md")`
  改为 `assert.equal(map["修改意见工件"], undefined)`；补卡片列表新行的单元测试。
- `tests/e2e/backend.py`：建档脚本 4 轮 → 6 轮（`return [turn for index in range(6) …]`），
  供一次「提出修改」往返；`MODEL_CALLS_PER_PROJECT = 12` 断言不变。
- `tests/e2e/onboarding-prd.spec.ts`：删 `PAGE-LOG` 输出行、删 190-206 行 TEMP DEBUG 段；
  三条用例项目名改为 `修改往返主用例` / `修改往返资料页` / `修改往返宽屏`，
  `projectId(page, project)`、`waitFirstCard(page, project)`、`onboardAndWaitFirstCard(page, project)`
  参数化；基线核验状态断言从 `verified` 改为界面文案 `已核实`（`CONCLUSION_NAMES` 映射）；
  要求文案断言从写死的 `step 0` 改为 `/read the project layout at step \d+/`——
  建档脚本的模型调用队列在本文件内共享，第几条用例接入决定用到第几轮的要求文案。
