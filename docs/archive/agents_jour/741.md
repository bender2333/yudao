   - `client/src/renderer/src/views/project/settings.tsx` 第 202 行与 `client/src/renderer/src/views/project/department.tsx` 第 408 行：「来源」用的是设置记录的来源 `setting.source`（有没有这条记录），不是这一段 Prompt 的来源；接口已经给了能分清的 `department_setting_configured`（`harness/app/project_queries.py` 第 1764 与 586 行），页面没有用它。

3. 实现的取舍（写在这里，事后好核对）：
   - 草稿里把部门 Prompt 拆成两件事：`text`（文本框里的文字）与 `writePrompt`（这一段是不是由本项目写入）。没有写入时文本框是空的，保存时 `department_prompt` 给 `null`，服务端按「没有写入」处理（`harness/providers/selection.py` 的 `event_payload()` 只在写入了这一项时才把它放进事件，投影据此把文字换成内置默认并把 `configured_prompt` 记为否）。
   - **文本框为空 ⟺ 这一段不由本项目写入**：输入框里清空（只有空白字符也一样）就变成「不写入」，输入任何文字就变成「写入」。这样只有一个状态，不另设一个勾选框。
   - 按钮分成两个，各做各的事：「撤销本次修改」还原成已保存的那一份（原来的「恢复默认」做的其实是这件事，改名以后名实相符）；「使用内置默认 Prompt」把这一段变成不写入。
   - **来源按项说**：模型（本项目写入 / 跟随部门默认）、推理档位（本项目写入 / 跟随）、部门 Prompt（本项目写入 / 内置默认），按这一项有没有写入判断，不按设置记录有没有判断。原来那张只用于设置记录来源的对照表（`labels.ts` 的 `SETTING_SOURCE`）没有用了，去掉。
   - **接口不改**：要让表单在复位以前就显示内置默认的那一段文字，接口得再给一个字段（内置默认的文字）；那要重写 OpenAPI 快照并重新生成客户端类型。这一轮不做，代价是：复位以前表单里看不到内置默认的文字（设置页上那一段仍然显示当前生效的内容，复位以后显示的就是内置默认那一段）。接口版本与客户端类型因此没有变化。
