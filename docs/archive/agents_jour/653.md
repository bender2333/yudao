2. 实现：
   - 新增 `client/src/renderer/src/contract/stream-state.ts`：`StreamState` 是三档的判别式联合（`connecting` / `connected` / `interrupted`），`interrupted` 自己带着断开的时间；`nextStreamState` 是状态迁移。建立之前的连接失败不改状态（流自己在退避重试，这时仍是「连接中」），连上以后断开才变成 `interrupted`，重连成功回到 `connected`，状态没有变化时返回原来的那一个，调用处据此知道不用再通知界面；
   - `client-app.ts`：`ClientState` 的 `connected` 变体带 `stream: StreamState`；`open()` 先报「连接中」；`setStreamConnected` 经 `nextStreamState` 迁移。原来两个字段（`streamConnected` 与 `disconnectedAt`）合成了一个，界面分辨「还没连上过」与「连上以后断了」不再靠「断开时间为空」猜；
   - `labels.ts`：`connectionText` 给三档的中文写法；`topbar.tsx` 按它显示；`app.tsx` 把 `state.stream` 传给顶栏，窗口变灰的判断也改为 `state.stream.kind === "interrupted"`。
3. 位置的一处讲究：`client-app.ts` 用了 TypeScript 的参数属性，`event-stream.ts` 与 `connection.ts` 用了无扩展名的相对导入，Node 在运行期都解析不了，客户端单元测试（`node --test` 直接跑模块）不能从这些模块导入。状态词汇与迁移因此放进没有依赖的 `contract/stream-state.ts`；`labels.ts` 用类型导入引用它（类型导入在运行期擦除，没有引入运行期依赖）。
4. 测试：

   - 既有的两个端到端用例核对过仍然成立：`shell.spec.ts` 的「事件流断开时窗口整体变灰并写明断开的时间」与 `service-outage.spec.ts` 的「服务停止以后二十秒内没有 pageerror」都按「已连接 → 连接中断 → 已连接」写，与新的三档一致。
