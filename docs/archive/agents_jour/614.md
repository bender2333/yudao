1. 动手前核对：
   - 依据：`git log --oneline f0fba2bb..origin/main -- docs/design/test-pyramid.md` 无输出，设计说明无改动；
   - 「只改」清单：手写文件仅 1 个（`harness/tests/test_release_script.py`），未超出；
   - 函数与字段：`release_template`、`release_build`、`test_build_produces_a_wheel_with_the_page_files` 等用例均在代码中找到；
   - CI 环境：main 提交 `f0fba2bb` 已经在 CI 的集成层命令中加入了 `--dist loadgroup`，支持按 `xdist_group` 标记调度测试用例。
2. 崩溃原因排查与证据：
   - 检查历史崩溃运行（如 39209750129、39174544310、39267542905）：
     - 运行 39209750129 日志显示：gw0、gw3、gw4、gw5、gw1、gw2 共 6 个 worker 依次在执行 `test_release_script.py` 的不同用例时崩溃（`node down: Not properly terminated`，退出码 1，无断言失败日志）；
     - 运行 39174544310 日志显示：`worker 'gw3' crashed while running 'harness/tests/test_release_script.py::test_build_produces_a_wheel_with_the_page_files'`；
     - 运行 39267542905 日志显示：多个 worker 崩溃导致 `xdist KeyError: <WorkerController gw5>`。
   - 根本原因分析：
     - `harness/tests/test_release_script.py` 中定义了模块级夹具 `release_template` 与 `release_build`，执行真实完整的发布流程（复制全仓库、git init、提交推送、`npm ci`、Vite 构建前端页面产物、`uv build` 打包 wheel）；
     - 在 pytest-xdist 多进程调度下，模块级夹具在每个 worker 进程中独立初始化；
     - 之前该文件未标记 `xdist_group`，15 个用例被分发到 4 个不同 worker。4 个 worker 并发执行 `npm ci`、Vite 构建与 wheel 打包，在 GitHub Actions Windows Runner（2 vCPU, 7GB 内存）上迅速耗尽 CPU 与内存，导致 worker 进程被操作系统/Runner 终止（`node down: Not properly terminated`）；
     - 进程杀伤排查：全局 `taskkill` 调用均带有具体的目标子进程 PID（`/PID str(process.pid)`），排除了其他测试误杀 worker 的可能。
3. 修复实现：
   - 在 `harness/tests/test_release_script.py` 模块顶部声明 `pytestmark = pytest.mark.xdist_group("release_build")`；
   - 在 CI 现有的 `-n 4 --dist loadgroup` 调度机制下，带有相同 `xdist_group` 名称的所有用例作为一个调度工作单元统一分配至同一个 worker；
   - 使得 `release_template` 与 `release_build` 夹具全过程仅执行一次，避免多 worker 并发构建。
4. 本地自测验证：
   - 单进程运行 `PYTHONUTF8=1 uv run python -m pytest harness/tests/test_release_script.py`：15 passed in 184.04s；
   - 运行分层架构检查 `PYTHONUTF8=1 uv run python -m pytest harness/tests/test_layers.py`：1 passed in 3.40s；
   - 调度验证：通过 pytest 钩子与 LoadGroupScheduling 模拟验证，模块内全部 15 个用例均携带 `xdist_group("release_build")`，并在 `--dist loadgroup` 下被调度至同一个 worker。
