### 改了什么

1. **结论只剩两种**：`submit_review` 的 verdict 去掉 `rework_product`（`harness/definitions/tools.json`、`harness/definitions/proposal_contracts.json`、`harness/app/payloads.py`、`harness/models.py`），编排里转回产品阶段的分支删除（`harness/validation.py` 的 `_accept_review`）。`harness/` 里剩下带 `rework_product` 的地方都属于基线核验（`submit_baseline_review`，接入已有项目的事项），按工单保留。
2. **返工的判定跟着改**：`harness/projection.py`、`harness/orchestrator.py`、`harness/app/home.py`、`harness/projects.py`、`harness/app/read_models.py` 里「返工」的判定集合从两个结论改为只有 `rework_engineering`；交付被作废的理由从 `qa_rework_product` 改为 `qa_rework_engineering`。
3. **质检的提示写明询问产品**：`harness/definitions/work_items.json` 里普通事项的质检提示补一段：结论只有缺陷记录与放行两种（verdict 取 rework_engineering 或 release），要求本身有问题时用 `ask` 询问产品，产品在回答里修订 PRD。
4. **界面与原型**：`client/src/renderer/src/views/project/materials.tsx` 去掉「退回产品」这个判定文字；原型 v11 的 `js/pixel/engine.js`（动作目录与 qa_submitted 的动作表）、`js/pixel/floor.js`（返工画面的来源）、`js/ui/views/materials.js`（判定文字）同样改；像素登记表重新生成。

### 测试怎么改的

工单正文：用到 `review_turn("rework_product", ...)` 的用例改为质检询问产品、产品修订 PRD；只测「质检返工给产品」的用例按 ADR-0039 删除。

1. **删除一条**：`harness/tests/test_orchestrator.py` 的 `test_quality_rework_routes_to_product`（只测质检把工作退回产品这条路径，ADR-0039 删除了这条路径）。
2. **机械改**：`test_definitions.py`（结论枚举的期望值）、`test_event_sequence_compare.py`（比较用的样例数据）、`test_lesson_candidates.py`（候选来源的参数化去掉 rework_product 那一档）。
3. **改写**：其余用到这条路径的用例按各自要测的东西改触发方式：
   - 产品要求要修订（`test_proposal_version_check.py` 三条、`test_orchestrator.py` 的 `test_new_product_spec_cannot_reuse_old_qa_checks`）：用询问产品的分支（`ask` + `answer` 带 PRD 修订）或工程在分支里询问产品。
   - 产品要给出正式决定（`test_context.py` 三条、`test_contracts_plans.py`、`test_contracts_plans_module.py` 两条、`test_materials_status.py`）：质检不再把工作退回产品，产品的工作改由用户的指导触发（`system.add_guidance(run_id, "product", ...)`），共同点放在 `harness/tests/helpers.py` 的 `guidance_reply`。
   - `test_context.py` 的 `test_superseded_delivery_is_not_injected_as_current`：旧交付被取代以后不再当作当前交付注入，用工程在分支里询问产品、产品在回答里修订 PRD。
4. **新增一条**：`harness/tests/test_ask_branch.py` 的 `test_quality_asks_the_product_and_the_answer_revises_the_prd`——质检询问产品，产品在回答里修订 PRD（修订版是第 2 版），质检对旧交付的放行被拒绝（交付依据的 PRD 版本过期，#471）。

### 一处要写明的中间状态

产品修订 PRD 以后，事项还在质检阶段（`product_spec` 的修订没有阶段迁移），旧交付被新版本取代，质检对它的放行被拒绝。**在 #556（部门按关注的成果开始工作，删除阶段状态机）落地以前，PRD 修订以后没有让工程自己开始一轮返工的机制**：工程不会因为 PRD 变了就自动开工，质检的结论被拒以后事项停在质检阶段。因此 #474 正文验收第 3 条里「工程在之后开始一轮返工」这一半由 #556 完成；本工单完成的是「质检询问产品、产品在回答里修订 PRD」与「质检对旧交付的放行被拒绝」这两半。测试按这个中间状态写：需要产品修订以后工程继续工作的用例，用用户的指导把产品请回工作（修订以后阶段不变，工程照常工作）。
