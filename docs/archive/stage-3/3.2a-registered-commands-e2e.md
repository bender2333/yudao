# 3.2A 登记命令端到端验收路径（真实模型）

本文只描述调用方后续如何跑真实模型全链路验收，不执行模型调用。

## 前置

- 可信本地代码项目一份（已审阅的构建/测试入口）。
- Provider 目录已配好三部门绑定，服务可用。

## 步骤

1. 启动控制台：`python -m harness`（默认端口 8765）。
2. 创建项目：`POST /api/projects`（`{"name": ..., "goal": ...}`）。
3. 登记命令（每条固定 `argv`，额外参数走 `args` 白名单，限额按入口填写）：
   `PUT /api/projects/{id}/commands/{name}`（`{"argv": [...], "args": [...], "timeout_sec": ..., "output_limit": ..., "base_version": 0}`）。
4. 用可信快照创建事项：`POST /api/projects/{id}/work-items`（`{"text": ..., "source_dir": "<可信项目目录>"}`）。
5. 让真实模型完成全链路：搜索 → 区间阅读 → 区间编辑 → `run_command`（登记名 + 白名单参数）→ 工程 `run_check` 提交交付 → 质检 `collect_evidence` 独立核验 → 封存 → 采纳。
6. 核对 `tool_started` 携带登记名、完整参数与快照摘要，`tool_called` 的主机回执绑定同一快照、退出状态、输出与尝试；质检 release 引用质检部主机回执，不复用工程回执。

## 反例抽查

未登记名、越界参数、超时常驻进程、输出过量、退出失败、私有路径参数均应有真实可验证状态；超时后用系统进程表确认整棵进程树无残留。
