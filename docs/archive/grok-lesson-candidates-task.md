# Grok 小步实现：可审计经验候选

仅完成本批后立即返回，由 Codex 验收并统一 commit/push。不要执行任何 git 写操作；AGENTS.md 中的小步提交要求由主任务负责落实。

## 目标与边界

落实用户已确认的 `docs/grok-contract-review-task.md` 第 5 项：首版只记录可审计 lesson/经验候选，不自动改变规则或模型。

- 从已有明确的返工、缺陷或失败事实产生最小候选记录，区分观察事实与待验证建议。
- 候选可追溯到来源 run、事件、当前 spec，以及实际存在的交付/检查证据。
- 候选通过现有事件与投影体系保存，可查询、导出、重放。不要引入第二个事实库。
- 没有相应证据的成功任务不凭空产生经验。不要为了生成候选增加 LLM 调用。
- 候选不自动注入任何部门上下文，不修改规则、模型配置或放行条件。知识图谱、长期记忆、候选评分、经验自动复用属于后续阶段。

保持当前模块边界和最小实现，记录候选不能破坏已经确定的 DONE/FAILED/PAUSED 状态或重复计费。只处理这一项，不重新实现已完成的合同、检查、取消或 OMP 隔离功能。

## 验收

构造明确 QA 返工与失败场景，验证候选能追溯到实际来源。导出和 replay 保留相同候选；后续部门默认上下文中没有候选；普通成功 run 不生成虚构经验；部门规则、模型配置和最终放行权保持原有逻辑。

运行相应确定性测试与完整 `harness/tests`，不调用真实 provider。只追加中文日记中的本批事实，返回文件和测试结果，不宣布完整 MVP 通过。
