### 4.2 三个中等压力场景

状态：已执行（2026-09-21，冻结 `bcfe89db01fe570d884a655c5110fa402ab30559`，Provider 为 OpenCode Go 的 `mimo-v2.5`，Chat Completions）。三个场景各有一条完整真实流程到达 release，首次失败与重跑全部保留；结果与缺失事项见 [3.0B 场景报告](stage-3/3.0b-scenarios-report-2026-09-21.md)。

沿用一个可信、小型 Python 文本报表项目，避免三个完全不同系统造成无法比较。测试准备先固定需求、输入样本、每次变更和公开检查；这些清单入库后才采集结果。

| 场景 | 固定要检验的行为 | 完成条件 |
| --- | --- | --- |
| 多文件增量变更 | 在已有采用成果上增加报表能力，保留旧行为；输入含正常、空和非法情况 | 新旧公开检查均通过，工程与 QA 独立检查，完整交付、Git、采纳和 replay 对应 |
| 返工与定向指导 | 在验收副本植入一个事先声明的缺陷，QA 指出后工程修复；工程激活期间追加一条不改变目标的指导 | 返工引用正确版本，指导实际进入合法上下文，最终交付通过；植入缺陷标为受控场景，不称自然回归 |
| 小窗与方向调整 | 同一任务资料触发真实压缩；产品处理一次事先固定的需求变更 | 至少一次有效压缩后仍完成最终合同的独立 QA，原始材料、摘要来源、旧结果失效、最终交付均可追溯 |

每个场景至少一条完整真实流程通过，所有首次失败与复跑纳入报告；这是功能覆盖，不是统计成功率或学习收益证明。功能链路无法完成时修复并重新冻结受影响版本。小窗大小在采集前根据固定材料与模型有效容量确定，不临场缩改材料或扩大限额去获得成功。

### 4.3 证据包与验收回执

每份证据至少包含：应用 SHA / 差异、场景与检查版本、公开需求和输入、脱敏 Provider 绑定与容量、项目/事项/run 身份、有序事件、相关工件与完整交付、Git 核验、真实检查回执、逐尝试状态与用量、停止原因、浏览器/API 操作记录、结论及缺失项。

原始数据放独立场景目录，报告提供可取回的位置和完整性摘要；不提交密钥，不只保留截图。事件库、工件和 Git 作为同一一致备份采集，不能任意复制一个仍在写入的 SQLite 文件。

独立复核从导出的副本检查交付与 replay，不依赖执行时残留的工作目录。所有取消、失败、缺失与未知成本保留，评价人员不替执行者补结果。
