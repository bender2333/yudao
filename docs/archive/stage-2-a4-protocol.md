## 4. 候选正文

只补已观察到的工程工作顺序。产品、质检保持 `DEFAULT_PROMPTS`。不发明工具或身份。

工程：在默认正文后追加：

```
写入、删除、移动文件或 run_check、submit_delivery 之前，必须已有被主机接纳的当前计划。计划被拒后先根据回执改正，不得继续改代码。
本 run 已有计划时，新计划必须说明相对上一份计划改了什么以及为什么，即使上一份已被拒收或已失效。

```

保存到候选项目的工程配置。基线项目三部门都不写这些段落。

## 5. 确认任务（执行前冻结）

两个项目：`a4-baseline`、`a4-candidate`。长期目标相同。每个任务是该项目内的一个事项，独立工作区，原始起点均为空目录。按任务交替：先基线后候选，或先候选后基线，同一任务两组都跑完再开下一任务。失败保留。

任务原文（公开要求，检查不得加隐藏业务）：

1. **方向变更的文本处理**：做命令行工具，从标准输入逐行输出；空输入不崩溃且无输出。本任务只要求 stdin 逐行原样输出。公开检查：`printf 'a\nb\n' | python src/echo.py` 输出两行 `a` / `b`，空输入退出码 0。同一项目不在 A4 做第二次变更（第二次变更属于 B4）。
2. **结构化数据**：读 CSV `id,name,status`，输出相同表头的 CSV，保留输入行顺序。公开检查用固定三行输入，期望三行输出。缺文件时非零退出并写错误到 stderr。
3. **需澄清的要求**：任务原文同时说「按字母排序」和「保持原序」。产品必须先形成单一有效合同（提问或自行取舍并写进合同）；工程不得在合同未决时写代码。公开检查按最终合同执行，评价看协作是否发生、合同是否单一。
4. **带公开回归的修复**：事项原文描述当前错误行为是丢掉空行（不预置代码）。工程实现正确行为：保留空行。公开检查包含空行样例。

样本量 = 上述 4 个任务 × 2 组 = 8 次事项。同一事项多轮不增加样本。

## 6. 评价

独立、只读。对每组封存交付跑任务里写明的主机检查。比较：意图保持、计划合规（含拒收后是否先改正）、纠正/重复错误、协作正确性、QA/错误放行、实际请求成本（含失败与压缩）。工程自检、内部 QA、外部检查分开记。

结论只允许：采用（只把候选写入被测项目配置）、缩小范围、保留原版。没有改善也出正式报告。不改 `department_prompts.py`。
