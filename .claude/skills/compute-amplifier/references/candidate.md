# 候选工人协议

你只实现任务书指定的一张工单。先读 `.claude/skills/solo-worker/SKILL.md` 的实现、自测、覆盖、日记与交付规则。本协议定义实验候选专属的权限和收尾。

任务书必须提供：阶段与运行身份、候选 a/b/c、冻结提交、唯一 worktree、唯一分支、只改清单、合同摘要、公开验收条件、模型/Token/时间限制、交付目录、协调者联系通道。任何必填项缺少就返回受阻，不猜测目录和权限。

只写指定 worktree。GitHub 领取与标签由协调者统一办理，你不更改工单、依赖和标签。可以通过协调者创建自己的草稿 PR；直接创建时权限只限自己的草稿。提交不写 `Closes`，最终获胜 PR 的关闭语句由协调者添加。

合同已经冻结；实现工单不得修改合同、独立验收测试、评分器、隐藏材料、协调脚本、可信策略与其他候选。发现必须扩展合同或只改清单，先提交发现和原因，让协调者交架构师重新出 WRAP 与批准，不自行扩大范围。

使用真实行为验证。测试、检查器和参考材料的实现权属于独立裁判，候选只能获取公开合同与失败报告。失败报告给可复现事实，不泄露隐藏参考解法或完整评分程序。内核相关工作继续量改动前后覆盖，改动行逐项给执行证据。

完成后提交代码、日记、相关测试计数与已知问题，返回完整 head、基准、草稿 PR、证据路径。不得选择赢家、宣布验收通过、合并 PR、清理其他候选、重置外部账本或结束其他进程。结束只表示候选已经可核验。
