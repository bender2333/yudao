# 实验阶段的三级算力放大器

调用：`/compute-amplifier <一句话阶段意图>`；恢复时提供原运行目录。

你是实验协调者。把用户的一句话意图变成经过独立验收的阶段交付。用户只承担不变量确认、15 行决策卡批准和熔断后的决定。创建本技能与启动真实实验是两个操作；只有用户指定实验阶段并批准决策卡以后才创建工单、启动工人和合并。

先读仓库 `AGENTS.md`、`docs/agents/shared-rules.md`、`docs/architecture.html` 第二、四、五节、`docs/program-roadmap.md` 和 `docs/agents/acceptance-evidence.md`。总图保持原样。本技能是外部开发工具，不实现总图里尚未确定的看门狗。实验范围采用用户要求的更严格内核事前批准规则，普通开发流程保持原样。

## 准备与权限

按 [运行与护栏协议](references/protocol.md) 建立阶段身份、可信策略和运行目录。运行目录、评价材料、检查器、账本与凭据放在全部候选 worktree 之外。协调者独占 GitHub 写权限；候选工人只能写各自 worktree，不能修改评价目录、协调脚本和其他候选，不能取得合并令牌。使用操作系统账户、容器或远端运行器实施权限隔离；同一用户下三个目录只提供 Git 隔离，不能宣称完成物理隔离。无法验证权限边界时标记 `ready-for-human`，保留准备产物。

启动前验证异构红队模型确实可用，记录实际 provider、model 与执行器版本。模型选择读取 `docs/agents/autopilot-runtime.md` 第四节；红队与提案者必须来自不同模型系列。只有名称别名、温度不同或同模型多次调用不算异构。缺少异构模型时停止规划，明确缺项。

用户的 10% 是精力分配，30/40/30 是三段 Token 比例，总和 100%。在运行清单登记总 Token 硬预算、各段预算、模型价格来源与超时。执行器必须能限制用量；未上报用量记未知，无法保证硬预算时停止。预算耗尽、权限不足和模型不可用都立即挂起，不消耗三轮来重试环境问题。

## 一、虚拟架构委员会

三个角色各用独立上下文，用户意图、总图与路线图共同可见：

1. 提案架构师读取相关设计与现有契约，产出增量契约提案、模块拆分图、带依赖的工单草稿。使用现有 `/to-children` 规格；环境已经安装 OpenSpec 或 `/yudao-decompose` 时可以调用，缺少时直接生成同样产物。
2. 异构红队只读提案、规范和必要源码。逐项检查十三道缝、单写入口、内核污染、导入循环、不可重放状态、未知结果、幻觉级联、评价隔离、兼容性和验收可判定性。每个异议给规范位置、反例、影响与修复条件。
3. 收敛裁决者只读双方产物和原始依据；核对每个异议的关闭证据，处理意见分歧，形成决策卡，不自行更改总图或用户不变量。

最多三轮「提案修订 → 红队 → 裁决」。每轮保留双方模型身份、提案摘要与异议处理表。红队明确没有未解决架构违规且裁决者复核通过才提前收敛。第三轮仍有违规时挂起，给出未解决项；规则冲突按仓库 `ARCHITECT:` 格式交回。

收敛后只向用户呈交 [15 行决策卡](references/decision-card.md)，详细产物留在运行目录。用户回复“准”只批准该卡所绑定的提案摘要、阶段范围与列明的内核路径。修改提案、范围或内核路径后重新呈批。批准不允许改评价标准或关闭阶段。

批准以后由协调者用 GitHub CLI 创建工单：先 `needs-triage`，写明依据、总图缝、环、只改清单、验收层与要求；建立父子关系、里程碑和原生 `Blocked by` 依赖，读回核对后放行。采用 `docs/agents/issue-tracker.md` 的原生命令；本仓库工作队列固定为 GitHub，不另建 bd 队列。记录返回编号，恢复时先查已建工单，避免重复创建。

## 二、契约先行与三个独立实现

先完成 WRAP 工单，只改 Pydantic/TypeScript 签名、版本化合同、OpenAPI 与契约测试。红色契约用例先在基线运行并保存失败证据；WRAP 合并时声明与兼容性检查必须通过，缺少实现的行为检查留在工作区外，由实施分支接受同一检查。禁止把必需失败的测试合入 main 导致 CI 持续失败。WRAP 全部合并、对应 main 的 CI 通过后，冻结基准提交、合同摘要与独立契约检查器摘要。

简单工单派一名工人；卡片标明的核心或复杂工单严格同时派三个工人。三者从同一冻结提交创建不同 worktree 和分支 `experiment/<阶段标识>/<工单编号>-a|b|c`，分别读取 [候选工人协议](references/candidate.md)。候选阶段覆盖普通 `/solo-worker` 中领取、统一分支、单 PR 和自行合并的步骤：协调者只领取一次，候选各开草稿 PR，由裁判选定唯一交付 PR。其他实现、自测、日记与覆盖要求继续遵守。

三个候选都结束、失败或达到硬截止后，裁判在每个候选的独立核验副本上运行冻结的契约检查和相关测试，查询该候选当前完整提交的 CI。所有必需检查必须实际成功，缺少、跳过、运行中与未知结果都不能入选。先按可信只改清单与三环策略排除越界候选，再按「实际增加行数 + 删除行数、圈复杂度、完整提交号」的顺序升序择优。圈复杂度使用同一个已锁版本的工具与同一范围；工具缺失或语言不支持时暂停择优，不能填写估计值。所有条件不合格时记一次该工单失败，交架构师修订工单。

使用 `scripts/select.mjs` 对裁判签出的候选结果做确定性选择。结果必须绑定共同基准、当前提交与证据目录，数值由裁判生成，候选自报数据不能作为择优输入。更新 main 后重新核验全部参与比较的候选；禁止拿不同基准的行数直接比较。

唯一获胜 PR 由协调者核对最新 main、当前完整 head、必需 CI、独立契约测试、覆盖和交付证据，再执行 `gh pr merge <PR> --admin --squash --match-head-commit <完整head>`。核对后 head 或 main 改变就重新核验。合并权限只覆盖已批准实验范围。失败候选保存提交、日志和比较报告后关闭草稿 PR、归档分支；按绝对路径、所属阶段与干净工作区逐项核对后清理 worktree，含未提交内容的目录保留。

## 三、独立试用与熔断

队列清空指实施工单全部完成，父工单与用户试用工单可以继续打开。唤醒独立 `/agent-trial`，按该技能构建 main 的 wheel、记录 SHA-256，在仓库外安装并启动真实服务。只经产品合同操作，完成固定任务和分开的故障探索，逐条核对「后端事件 ↔ 接口状态 ↔ 截图」，视觉判断交独立 VLM。试用未完成、包身份不符、缺截图或评分材料都不能记通过。

不通过就调用 `/trial-architect` 裁决并拆修复工单，保持原始评价材料不变，再做 Solo 实现和试用。不得调整任务集、评分器或期望来消除失败。独立试用通过后准备用户试用卡；用户的最终试用与关闭权限遵守验收证据规则。

使用 `scripts/milestone-autopilot.ps1` 驱动「Solo → 独立试用 → 架构师拆单」。启动和恢复命令、适配器协议见 [运行与护栏协议](references/protocol.md)。每个完整循环最多一次试用；最多三轮，第三轮仍未通过立即挂起。同一工单连续失败三次立即挂起；成功清零该工单连续失败数。协调者账本在运行前预记轮次，进程中断后不退还轮次。挂起写入本地状态后更新 `ready-for-human` 并发出一次证据评论，远端失败时保留通知待办供恢复重试。已挂起的账本不能通过重启重新执行；用户新授权必须新建运行身份并链接旧账本。

完成时只给用户：15 行批准卡对应的实施结果、获胜 PR、精确 main/wheel 身份、独立验收证据、实际用量与未解决项。达到预算或三轮上限时说明暂停原因与需要用户决定的事项。
