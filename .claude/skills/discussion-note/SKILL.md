# discussion-note

一次小范围活动做完了，手上有些事实、有些发现，但**现在没有人被它挡住**。这时候不要把结论塞进工单、也不要让它只留在自己的会话里——写成一篇 Discussions 帖子，钉在公告板上：架构师分诊时看得到，以后做同类事情的人也能照着复用。

## 与三条既有通道的分工

| 手上的事 | 走哪里 | 会不会改变状态 |
| --- | --- | --- |
| 这张工单做不下去（设计冲突、超范围、连续三次没过） | `needs-triage` / `ARCHITECT:` | 会：改标签、结束这一轮 |
| PR 上的实现分歧、审查意见 | PR 评论 | 会：影响合并 |
| 要改规则文件、CI、评价标准 | `ready-for-human` | 会：等用户 |
| **跨工单、跨会话的发现、证据、想法**，需要架构师判断但不阻塞 | **本技能：Discussions** | 不会 |

## 什么时候值得发（三条都成立才发）

1. **换一个会话也读得懂**：不依赖你脑子里的上下文。
2. **以后能复用**：别人能照着复现、或照着结论做决定。
3. **现在没人在等它**：有工单正被它挡着时，先走 `needs-triage`，别只发帖。

反例：只对自己有用的待办清单；还没核实的猜测（先核实，再发「我的判断」一节）；单张工单内的阻塞。

## 硬边界

- 不发工单评论、不改标签、不改负责人、不开 PR、不派活。
- 不动 `.ralph/` 账本；要留一行痕迹用 `solo.mjs note --text "..."`。
- 不 @ 人、不催回复。帖子是备忘录：无人回应是正常的。
- 只读：扫描用 `gh` / `git`；要跑实验就写在仓库外的临时目录或已忽略的 `.tmp/`。不改仓库文件。
- 例外一条：这条结论**会影响某张正在做的工单**，而只在帖子里会漏掉时，可以在那张工单上补一行「另见 <链接>」——只加链接，不改标签、不改正文、不催。

## 两种形态

| 形态 | 什么时候 | 骨架 |
| --- | --- | --- |
| **A 报告型** | 扫了一遍、走查了一遍，有结论与表 | 范围 → 结论 → 事实 → 发现 → 判断 → 边界 → 复现 |
| **B 素材型** | 试跑、复现、实验、想法，事实多结论少 | 做了什么 → 原始事实 → 观察 → 可能去处 → 复现 |

两种都遵守下面两条硬要求。

## 一、事实与判断分节

这是整篇帖子的价值所在：架构师要能**独立判断**，后来的人要能**只信事实**。

- **事实**：命令与它的结果、工单号、`文件:行号`、计数、时间。写「`gh api ...` 返回 #1015 的 blocked_by = 860」，不写「#1015 缺依赖」。
- **判断**：你的解读、猜测、建议。写「我的判断：正文漏了这段，依赖只存在 GitHub 上，所以刷新台账时会被当成可派」。
- 别人的判断不要混进事实；没核实的东西标「未核实」。

## 二、可复现

- 帖子里写命令与参数，不只给结论。
- 用了脚本就写路径；数据与截图写清放在哪、会不会保留（`.tmp/` 不进仓库，仓库外的路径写全）。
- 现成的一种是「依赖与『只改』重叠扫描」：`.claude/skills/discussion-note/scripts/overlap-scan.ps1`（Windows）：

```powershell
pwsh -NoProfile -File .claude/skills/discussion-note/scripts/overlap-scan.ps1 `
  -Milestone "阶段一：单机诚实闭环，三道槽位立缝" `
  -Signature "<署名>"
```

其他活动没有现成脚本，就把用到的命令原样贴进帖子。

## 标题前缀与分类

标题按内容加前缀，便于搜索与去重：`扫描：`、`观察：`、`复现：`、`想法：`、`证据：`。标题里带范围与日期。

| 分类 | 放什么 | 例子 |
| --- | --- | --- |
| **Issues** | 待分诊的发现、缺口、清单问题（默认） | [#1042 重叠扫描](https://github.com/bender2333/yudao/discussions/1042) |
| Ideas | 设计想法、诊断、方案对照 | #700 场景 3 对照的七处问题、#628 控制论对照 |
| General | 试用记录、评测记录 | #839 试用、#640 评测 |
| Show and tell | 展示 | #949 |
| Q&A | 提问 | |
| Announcements | **维护者复盘专用，agent 不发** | #613 |

编号：仓库 `R_kgDOSpFnRw`，Issues 分类 `DIC_kwDOSpFnR84DJn-5`。仓库是公开的，只有发布者 `bender2333` 的帖子被采信，`gh` 要以这个身份登录。

## 发之前

1. **重跑或复核一次**，以发帖时刻为准，标题里写活动时间。2026-10-26 就撞过：#952 在扫描之后、发帖之前合并，正文里「没有一张可以立刻派」当场过期。
2. **查重**：最近十篇里有没有同前缀、同范围的帖子；有就补评论，不新开。

```powershell
gh api graphql --raw-field query='query { repository(owner:"bender2333", name:"yudao") { discussions(first:10, orderBy:{field:CREATED_AT, direction:DESC}) { nodes { number title url category { name } } } } }'
```

3. 写两个文件（标题不要带 `#`）：

```
.tmp/discussion-note/title.txt
.tmp/discussion-note/body.md
```

4. 发帖（`-F` 读文件，别把长正文塞进命令行）：

```powershell
gh api graphql -f query='mutation($repo:ID!,$cat:ID!,$title:String!,$body:String!){ createDiscussion(input:{repositoryId:$repo, categoryId:$cat, title:$title, body:$body}) { discussion { number url } } }' `
  -f repo=R_kgDOSpFnRw -f cat=DIC_kwDOSpFnR84DJn-5 `
  -F title=@.tmp/discussion-note/title.txt -F body=@.tmp/discussion-note/body.md
```

5. 把链接带回会话的收尾。**不要**顺手把它贴到工单上（上表那条例外除外）。

## 正文模板

### A 报告型

```markdown
## 这份东西是什么

谁在什么时候做了什么范围的活动；只读声明（有没有改工单、PR、代码，没有就明说）；数据来源与口径。

## 结论（三条以内）

1. …
2. …

## 事实

- `命令` → 结果要点（工单号、文件:行号、计数）
- 不贴长日志，贴命令与它证明了什么

## 发现（按要紧程度）

### 一、<一句话说清是什么>
事实：…
影响：会让哪几张工单撞、或哪条规矩落空
建议：重切 / 合张 / 加依赖 / 改设计说明（写清是建议，不是决定）

### 二、…

## 我的判断与还没核实的地方

## 没做什么 / 边界

没改工单、没派活；只到文件级；某几张的清单缺失导致重叠可能低估……

## 需要架构师看的

一两个具体问题，或「这几条要定归属」。不 @。

## 复现

命令、脚本路径、数据位置、是否保留。

---

— <署名> / <YYYY-MM-DD HH:mm> / <只读扫描 | 试跑 | 复现>，未改动工单、PR 与代码
```

### B 素材型

```markdown
## 这份东西是什么

## 我做了什么

范围与边界：只读 / 只跑了一次 / 只看了这几个文件；耗时。

## 原始事实

命令、输出要点、数据文件与截图的位置（写明是否保留）。

## 我的观察

可以是猜想，标「未核实」。与事实分开。

## 可能有用在哪

可能的去处：进哪张工单、归哪个桶、做设计时的参考、以后可以照着复用的命令。

## 复现

## 边界与不确定

---

— <署名> / <YYYY-MM-DD HH:mm> / <只读扫描 | 试跑 | 复现>，未改动工单、PR 与代码
```

一帖一件事；多件事用二级标题分开；超过平台长度就正文放结论与表、评论放逐条摘要，**两处都署名**。

## 署名（必须）

最后一行固定是署名，与本会话在别处用的一致，格式 `— <harness>-<模型 ID> / <时间> / <活动性质>`：

| 会话 | 署名 |
| --- | --- |
| solo 循环里的执行者 | `solo-<模型 ID>` |
| 架构师会话 | `claude-架构师` |
| DSH 的 Lead / 子代理 | `lead-<模型 ID>`、`<子代理名>-<模型 ID>` |
| Hermes、OpenCode 等其他 harness | `<harness>-<模型 ID>` |

不要冒用别人的身份（`bender2333` 是账号，署名说明是谁写的这份东西）。补发的评论末尾同样署名。

## 不许写进正文

凭据、令牌、私钥、`provider.md` 路径；本机绝对路径里的用户名；长日志与测试原始输出；对某个人的评价；把没核实的东西说成事实。

## 失败与收尾

- `createDiscussion` 报分类不存在或没权限：先查一次分类编号（`gh api graphql` 查 `discussionCategories`），仍不行就停下，报告留在 `.tmp/discussion-note/` 并说清卡在哪。
- 正文超上限：拆成帖子 + 评论，两处都署名。
- 发完就结束：不等回复、不追着改工单。架构师的处理结果发生在它的会话里，不回到这里。
