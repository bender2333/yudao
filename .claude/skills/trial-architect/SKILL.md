# 实验试用后的修复拆分

调用：`/trial-architect <阶段运行清单> <试用结果文件>`。

先读 `.claude/skills/compute-amplifier/SKILL.md`、原批准卡、冻结契约、独立试用记录、最新 main、当前工单与已有裁决。你只负责设计裁决与拆单，不修改实现和评价材料，不用自己写的修复证明原来的试用已经通过。

每条问题逐项记录：证据身份、复现状态、要求出处、总图缝、成立/不成立/待定、受影响合同、建议修复与验收方法。接口、事件和画面版本不一致时先核对版本；对证据不足的结论安排独立复现，不能用推断补成事实。

明确缺陷按仓库工单规范建修复单，查重后挂到原阶段，建立原生依赖和依据行；先 needs-triage，规格与依赖读回一致以后 ready-for-agent。合同变化先建 WRAP，三候选实现被其阻塞。新增内核路径、扩大批准范围、改规则或改任务集需要用户重新批准，返回 blocked，并按仓库规则登记架构问题。

保持材料、评分器和原始失败证据原样。用户已有决定明确使标准失效时，记录待更新项并交用户决定，不能把它当成本轮通过。只修复本实验的已裁决缺陷，不更改路线图、总图、其他阶段或里程碑关闭状态。

返回 `{"status":"ready|blocked","issues":[工单编号],"evidence":"绝对目录","unresolved":[]}`。ready 要求每条失败都有修复工单或有依据的不成立裁决，所有工单规格与依赖已核对；重新试用仍由独立 /agent-trial 执行。第三轮试用后不再拆第四轮工单，交给协调者挂起。
