# 验收

流程的正本是[工作方式](../../../docs/agents/workflow.md)第 5、6 节；证据的身份与写法见[验收证据规则](../../../docs/agents/acceptance-evidence.md)「记录身份与结论」。

## 何时用 / 何时不用

- 用：`parent` 工单的子工单全部关闭、自己还开着。
- 不用：阶段的结束核对，由总架构师按验收证据规则「阶段的结束与进入」做；试用工单的关闭，见 `/trial-intake`。

## 先读什么

父工单的正文（验收标准、依据、总图位置）、它的子工单与各自的交付说明、「依据」指到的设计说明的「验收」一节。

## 步骤

1. **列标准**：把父工单的验收标准逐条编号。父工单的验收取自设计说明的「验收」一节，两边不一致时以设计说明为准，并在评论里写明。完成：每条都有编号。
2. **找证据**：每条在当前 main 上找证据：用例名与它所在的层、CI 运行的链接、提交、页面路径或命令与输出。证据要在 main 上，不在分支上；工单关闭、CI 绿了都不是证据本身。完成：每条后面有证据或写「没找到」。
3. **给结论**：每条只有三种：过了、没过、说不清。说不清不算过。完成：每条一个结论。
4. **写 `VERDICT:` 评论**：第一行 `VERDICT: <全部过了 | n 条没过 | n 条说不清> @ <main 短提交>`，下面一行一条：编号、标准、证据、结论。
5. **办理**：
   - 全部过了：关闭父工单。需求索引与设计索引只在新增或改名时改，不记状态。
   - 有没过或说不清的：每条补成一张缺口子工单，按 [`/to-children`](../to-children/SKILL.md) 的模板写，放进这个里程碑，标 `ready-for-agent`；验收写「原来哪一条没过、补上什么证据算过」。父工单保持打开。
6. **自定的边界**：读各子工单交付说明里的「自定的边界」。每条判断一次：对的，按 [`/to-design`](../to-design/SKILL.md) 写进设计说明；不对的，补一张缺口子工单改回来。完成：每条都有去处。
7. **缝的变化**：这个薄片的父工单都关了时，把总图第四节缝的已定、未定要改的行写进交给总架构师的那条评论（阶段工单或试用工单上），需要时附一份 [`/seam-diff`](../seam-diff/SKILL.md) 报告。缝的已定、未定只由总架构师改。

## 常见借口

| 借口 | 为什么不行 |
| --- | --- |
| 「子工单都关了，就是过了」 | 子工单关闭说明有人交付了，不说明父工单的标准成立 |
| 「CI 是绿的」 | CI 跑的是已有的测试，未必覆盖这一条标准 |
| 「交付说明里写了做到了」 | 交付说明是执行者的话；证据要在 main 上能重新找到 |
| 「这条说不清，先算过，试用时再看」 | 说不清不算过，补成缺口工单 |

## 危险信号

- 每条的证据都是同一个 CI 运行链接。
- 验收标准被改写得比设计说明的「验收」松。
- 父工单关了，缝的已定、未定没人告诉总架构师。

## 交付

父工单上一条 `VERDICT:` 评论；全过时关闭父工单，否则列出缺口子工单的编号。回复：父工单、几条过了、缺口工单、要告诉总架构师的缝。
