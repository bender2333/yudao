# 试用

目标是发现真实用户会遇到的问题并提供可信证据。交付评分与性能比较单独记录。本技能使用试用环境的配置与数据，保持被测源码、规则和设计原样；发现写进报告，由维护者裁决与建工单。决定依据见 [ADR-0039](../../../docs/adr/0039-agent-trial-observation-reproduction-and-judgment.md)。

运行者是架构师会话，操作分给新的代理。原始观察、证据复核、独立复现、问题裁决、修复进度与修复后验证分别记录；一次已观察但尚未独立复现的现象可以入表。符合设计的体验障碍可以作为体验问题候选。

## 1. 准入、模型与预算

从本薄片取得试用工单，从[运行配置第 4 节](../../../docs/agents/autopilot-runtime.md)取得本轮模型计划；地址和凭据从 `YUDAO_EVAL_BASE_URL`、`YUDAO_EVAL_API_KEY` 读取。缺少必要来源时明确缺项，准备条件不满足就停在准备阶段。由架构师循环启动时这些来源相同，不重复向人索取。

| 角色 | 模型或可见材料 | 产出 |
| --- | --- | --- |
| 被测产品与工程 | 运行配置的 model1 | 产品正常运行的原始事实 |
| 被测质检 | 运行配置的 model2，按声明配置图像输入 | 同上 |
| F1、R1 新手段 | model2；只给本段任务书、README、输入路径与 [novice.md](method/novice.md) | 各自的 novice 记录、截图、文字和错误采集 |
| 专家段 | model2；原始记录、导出、承诺清单与 [expert.md](method/expert.md) | 证据核对、覆盖与候选 |
| 看图 | model2；截图与具体读数问题，保留原话 | 视觉读数或第一眼观感 |
| 独立复现 | model1；操作、触发条件、实例清单与 [reproduce.md](method/reproduce.md) | 新实例操作及独立结论 |

被测部门可以用不同模型。复现必须逐部门复用原现场的模型、窗口、输出上限等配置；更换的是观察代理，不顺带更换被测质检。观察者不读作者的根因分析。同模型的视觉读数不自动成为独立证明。

整轮上限约 4 小时 45 分。准备最多 25 分钟，F1 运行最多 120 分钟，R1 最多 55 分钟，专家与评分最多 50 分钟，独立复现最多 30 分钟（与专家并行），补测与探索预留 15 分钟，成稿预留 20 分钟。整轮截止时间优先，各段实际起止写进记录；重叠时间不重复加总。

运行到终态就转下一段。剩余时间先用于未覆盖的承诺能力和高影响复现，再做新探索。到截止时记录没做什么及原因，交付部分完成报告，不延长固定任务去等待想要的结果。F1、R1 的任务耗时与包含配置和操作的新手段耗时分别记。

## 2. 判据与任务集

开轮先查询最新试用帖，保存其正文和当时的分诊来源；不能只沿用旧归档的 prev-post 文件。再读该帖以后 [docs/decision.md](../../../docs/decision.md) 的有关决定，以及 [trial-tasks@4](../../../docs/trial/tasks.md)。任务集属于评价标准，修改由用户决定；执行本轮时按原文输入。

本技能与任务集共同规定：F1、R1 是固定任务，额外需求、改配置、取消探针等另建探索事项或实例。用户临时指定的额外操作保留原话与时间，单列变体，不能混算成固定任务。

判据过期时注明原判据和取代它的决定。例如页面显示原始标识与英文原文按用户已有决定处理；看到英文不能单独判缺陷。

## 3. 安装、身份与配置

用干净克隆的 main 构建：`uv run python scripts/release.py`，只构建，不带 `--publish`。构建提交是脚本接受的远端 main；实际提交与请求提交不同就分别记录，不能把文档差异的推断当作两包相同的证明。

安装到仓库外的独立虚拟环境。记录 wheel 完整 SHA-256；从仓库外启动，并核对实际解释器、`harness` 导入位置及安装内容与 wheel 一致。仅版本号相同或接口返回 200 都不足以证明包身份。

用 [instance.ps1](scripts/instance.ps1) 启停并保存实例清单：

```powershell
pwsh -NoProfile -File .claude/skills/trial/scripts/instance.ps1 -Action Start -Manifest <归档>/instance.json -Python <独立环境>/Scripts/python.exe -Wheel <wheel> -Commit <完整提交> -DataDir <数据目录> -Port 8766 -TaskSet trial-tasks@4 -MaterialVersion scenario-3@2 -SkillCommit <技能提交>
pwsh -NoProfile -File .claude/skills/trial/scripts/instance.ps1 -Action Inspect -Manifest <归档>/instance.json -ModelsFile <归档>/models.json
```

页面配置顺序（2026-10-31 起按 #1297 重做后的页面）：连接服务、选择模型、部门使用。连接与凭据在「连接服务」这一步一起提交（服务地址与 API Key 一次填完，点「获取模型」即保存连接、Key 与候选）；勾选候选后系统自动补全参数并做模型测试，通过的模型变为已启用；首个启用的模型自动成为三个部门的部门默认，一般不用手动改。配置以后把实际的逐部门模型、协议、窗口、输出上限保存为清单，接口查询由协调者做。以目录和导出的真实调用配置核对，区分本地模型定义名、请求模型与提供方回报模型。凭据来源与引用版本照页面读数记录，不预先把设计行为当缺陷。

R1 重启用同一个 manifest 和数据目录。复现使用同一 wheel、另一虚拟环境与全新数据目录，另配浏览器端口。实例状态不同就记录差异，恢复成相同条件后才计同条件复现。启动和停止只操作本轮记录并核实身份的进程。

控制用的 manifest 会随启停更新。每段完成 Inspect 后另存本段身份快照，result 引用快照；R1 重启不能覆盖 F1 的身份记录。具体字段与命令见 [records.md](method/records.md)。

## 4. 新手段

分别起 F1、R1 新代理，只给本段输入与 [novice.md](method/novice.md)。F1 输入由协调者按任务集准备；R1 复制任务集的准备、四步、上限及「出岔子时」处理，四段输入保留原话，专家判据与作者结论留给专家段。记录每两分钟实际观察和每次操作，时间以浏览器 `observed_at` 为准；采样空档写原因。

每个页面第一次打开留视口截图、audit 和第一眼原话。新手段只保留观感与四问，不从后台判断原因。两段都结束后交专家，固定任务内不运行会改变条件的探索探针。

## 5. 专家、覆盖与探索

按 [expert.md](method/expert.md) 核对卡点、R1 八件事实、画面对账、错误去向、承诺覆盖、机械读数与第一眼。没有发生、没有测到、受阻与未完成分别写明；现场证据完整可以入问题表，复现与裁决另列。

补测与探索按 [probes.md](method/probes.md) 在单独事项或实例执行。每条承诺拆出子项；没有质检放行或检查回执就保留覆盖缺口。取消核对包括部门状态、原进程和端口，不能只看页面。

看图可以用子代理或脚本，模型取运行配置，不把预期结论交给看图者：

```powershell
node .claude/skills/trial/scripts/vision.mjs --image <截图> --prompt-file <具体读数问题文件>
```

第一眼原话进观察，体验候选注明具体操作障碍。audit 对比度与占比先核对截图、颜色和背景；未知保留未知，已知工具误报不能因另一次同样读数就升级为产品缺陷。整页图限高，细节单独截图。

## 6. 读数与评分

```powershell
node .claude/skills/trial/scripts/readout.mjs <F1导出> <R1导出> --json
```

从导出重算时间、尝试、目的、配置与用量；事件时间统一按带时区的时间点比较，保留事件 id 和位置。新手接手到交回、事项创建到结束、具体工具或请求的耗时分别给出。费用没有回报时写未知，不写免费或零。

F1 只要有封存交付，就按评测运行器取回交付、调用隐藏评分器；未取回或评分失败时记缺项与原因。没有交付时说明未交付，R1 不做隐藏评分。评分与检查点引用实际产物：

```powershell
uv run python -c "import sys,json;sys.path.insert(0,'evals/runner');import yudao;e=json.load(open('<F1导出>',encoding='utf-8'));print(yudao.fetch_delivery(yudao.YudaoClient('<产品地址>'),yudao.last_archived_delivery(e),'<交付目录>'))"
uv run python evals/scorer/scorer.py --delivery <交付目录> --result <评分文件>
```

`yudao_metrics.collect(export, outcome, replay)` 的 outcome 包含 `timed_out`、`elapsed_seconds` 与实际隐藏失败项；重放结果也引用真实返回。单 agent 对照本轮不运行。与评测或前次结果比较前逐项核对包、材料、评分器、部门模型、窗口与输出上限，不同条件只并列说明。

## 7. 问题、复核与独立复现

每条发现给稳定编号 `T<被测提交短号>-NN`、现象、期望依据、实际、操作位置、任务、证据、影响、绕过办法及频率。类型为缺陷主张或体验问题候选；符合设计的体验障碍仍可提交架构师裁决。

查重同时读取打开的工单与既有问题的裁决，写重复、相邻或无关及来源。重复的保留与原问题的关系，由维护者补入原工单；相邻说明区别。换浏览器或接口后不出现，只说明路径差异，不能自动归为试用环境问题。

按影响、绕过代价、已观察频率排序。挡住目标及状态、恢复、并发异常优先独立复现；静态文字和布局可以先由另一观察者复核。复现任务按 [reproduce.md](method/reproduce.md) 单独交接，只包含操作、触发条件和待观察现象。

结论分别记录：复现到、同条件触发后未出现、未触发、条件不同、证据复核、尚未执行。时间用完仍未触发就结束该项。只重读原导出不算新增复现，有限样本只陈述次数；问题是否成立等架构师明确裁决。

## 8. 建议

每条建议说明妨碍哪个用户目标、证据编号、与上一轮的差异或不可比原因、对应路线图五条判据中的哪条。根因不明时保留不确定性；建议不自动成为新规则或修复任务。

## 9. 记录、检查与发帖

协调者按 [records.md](method/records.md) 把实例、任务、发现、独立复现、裁决及缺项写进本轮 `result.json`。报告事实表从同一记录和原始导出生成，专家分析与观感保留原始引用。

用 `report.mjs --init <result.json> --task-set trial-tasks@4 --material scenario-3@2 --commit <提交> F1=<导出> R1=<导出>` 初始化，再用 `report.mjs --check <result.json> --json --render <facts.md>` 核对并生成事实表。身份错误、数字与来源矛盾、坏引用或明文凭据必须先处理；评分、复现和覆盖的明确缺项允许形成部分完成报告。核对自由叙述是否有来源，不能用手工抄数改写机器表。

正文顺序：环境与前提（含实际包、模型、任务版本和完成程度）、交付与评分、新手段、专家与覆盖、问题、建议、观察及第一眼、历史裁决回查。每条问题显式列出复现和裁决状态；未测到的内容逐项写原因。

发布材料中的路径与身份脱敏为 `<数据目录>`、`<仓库>`、`<运行目录>`；凭据、Authorization 与 .env 内容不进入任务书、命令参数、日志或正文，截图另核对地址、路径和账号。材料片段每处最多二十行。原始证据留本地原样保存，发布只复制所需的脱敏片段。报告检测只给位置，不回显敏感值。

只有执行本技能的一轮试用才发帖，General 分类，一轮一篇。标题 `试用：<阶段> · <产品版本>（<实际提交短号>）· <日期> — <本轮事实>`，正文开头注明由 agent 按本技能执行；部分完成在正文显式标注。用用户自己的 gh 账号，UTF-8 无 BOM 文件传参：

```powershell
gh api graphql -f 'query=mutation($repo:ID!,$cat:ID!,$title:String!,$body:String!){createDiscussion(input:{repositoryId:$repo,categoryId:$cat,title:$title,body:$body}){discussion{number url}}}' -f repo=R_kgDOSpFnRw -f cat=DIC_kwDOSpFnR84DIxLV -F title=@<归档>/title.txt -F body=@<归档>/body.md
```

发完读回标题、分类与正文，并把帖子身份和校验结果存档。失败停在本轮草稿，回报文件和失败原因，不换账号重发。

## 10. 问题裁决、回查与命中率

维护者是用户在场的架构师或架构师循环。每条缺陷主张明确写成立、不成立或待定，并给裁决依据；体验候选另记是否采纳。关联工单、修复进度、修复后验证及其版本分别保留。

缺陷命中率 = 成立 ÷（成立 + 不成立），无已裁决样本就写未知，同时列待定数量。工单关闭或不计划关闭都不能自动替代问题裁决；修复后没再试也不删除历史裁决。更正时引用新裁决和适用版本，原始观察保留。

开轮从 GitHub 最新创建的试用帖开始回查，并读取分诊发生的工单或评论。按稳定问题编号关联每条裁决，不能只因合并了同一张工单就算它涵盖的所有问题成立。本轮回查结果存到本轮归档，旧归档保持原样。

## 11. 归档与收尾

归档位于本机 `.yudao/trial/<提交短号>-<日期时分>/`（不进版本控制）。保存 result、实例清单、各段任务书和记录、原始导出、评分、截图、文字、复现输出、脱敏后的发布草稿与回执。路径可在本地实例清单中保留，发布表格只用逻辑名。

按实例清单关闭本轮创建的服务和浏览器，核实 PID 创建时间后再操作。原始材料保留，停止或删除仅针对本轮建立的环境和目录；复用的已有安装保持原样。用户指定保留到某时刻的实例按指示处理。

## 12. 断点续跑

每次换段更新 `state.md`：实际提交与 wheel 摘要、实例清单路径、任务和材料版本、阶段起止、截止时间、各任务进度、下一步、已知缺项、报告与裁决来源。

恢复先 Inspect 原实例，再核对剩余时间。浏览器用原 profile 和端口重连；服务 Restart 复用数据目录。观察时间从日志和截图读，代理自报时间另列；没有产出不等于已经崩溃，要核对进程、就绪状态与错误输出。

## 13. 工具入口

| 工具 | 用法与职责 |
| --- | --- |
| `preflight.ps1` | `-Ticket <工单> -TaskSet trial-tasks@4`；准备条件与工具版本，`-InstanceManifest` 追加实际包核对 |
| `instance.ps1` | `-Action Start|Inspect|Restart|Stop -Manifest <json>`；包身份、就绪、PID 与数据目录，配置后 Inspect 保存部门计划 |
| `browser.mjs` | `start/open/text/shot/audit/click/type/press/watch`；用独立端口与 profile；所有操作回报真实 observed_at |
| `browser.mjs type` | 普通值用 `--value`，多行用 `--file`，凭据用 `--env`；替换加 `--replace`，R1 错一位加 `--wrong-key` |
| `vision.mjs` | `--image <图> --prompt-file <问题>`；环境读取 Key，问具体读数，保留原话 |
| `readout.mjs` | `<导出...> --json`；按来源重算时间、配置、用量与关键事件；`--types` 列事件种类 |
| `report.mjs` | 初始化记录、核对并生成事实表；命令与字段以 [records.md](method/records.md) 为准 |

浏览器常用：`start --browser chrome --port 9222 --profile <本轮目录>`；第二实例使用自己的端口和 profile。截图 `shot --out <文件> [--full]`，文字 `text [--css <选择器>]`，只读页面状态 `eval --expr <JavaScript>`。`audit` 的背景未知保留未知。

## 14. 历史入口

已有试用帖 #839、#1153、#1212、#1231 是历史证据入口；实际最新一篇通过 GitHub 查询，读数以对应导出和裁决为准。旧任务集读数保留原版本，不与 @4 混作同一固定任务。历史问题与修复状态在本轮回查里生成，不在技能正文手工复制进度表。
