# 专家段：把现象核对到证据

输入：两个新手段的记录、截图、页面文字、audit 与错误日志；运行导出、运行中的查询与重放结果；试用工单的承诺清单；任务集的检查点及 R1 八件事实。接口参数查被测实例的 `/openapi.json`。协调者交原始材料，不先交根因结论或修复建议。

## 1. 卡点与体验问题

逐处卡点按时间核对事件，记录定位用时、支持判断的材料和剩余不确定性。

| 分类 | 需要说明的事实 |
| --- | --- |
| 系统异常 | 错误、状态矛盾或任务不再推进发生在何处 |
| 该说的信息缺少 | 页面缺少哪个状态、原因、下一步或结果范围 |
| 体验问题候选 | 行为可以符合设计，但具体操作怎样妨碍用户理解或完成目标 |
| 试用者误解 | 页面实际写了什么，新手段漏看或误解了什么 |
| 尚不能定位 | 已观察到什么，欠缺哪份证据 |

候选不等于已确认缺陷。要求或设计写作依据，现场事实写作实际，架构师后续给出明确裁决；模型观感和工单状态不能代替裁决。

## 2. R1 的八件事实

每项写结论和事件 id，未做到写受阻原因：

1. 卡片内容、出现到回答的时间、回答后从哪里继续、已完成工作与已用量是否保留；区分错 Key 与重启丢凭据两种触发。
2. 四处歧义如何处理，用户在页面上能否看到这些选择。
3. 给工程的指导是否影响后续动作与交付依赖。
4. 给产品的指导是否有页面答复，期间其他部门是否继续。
5. 重启后状态、恢复位置及前后用时用量是否连续。
6. 追加输入是否进入同一个事项。
7. PRD 新版本是否去掉分类并加入按月汇总。
8. Excel 格式歧义与不用第三方包的指导怎样处理；区分写进要求与已经实现的部分。

## 3. 画面、错误与事件

取建事项、第一次交接、第一次询问、决定请求、指导答复、重启恢复、追加输入、放行或取消各自第一次事件。未发生就写未发生。

| 事件 id 与时间 | 第一张后续直播截图及采样时间 | 同位置回放截图 | 页面文字或视觉读数 | 结论与限制 |
| --- | --- | --- | --- | --- |

只核对[视觉通道表](../../../../docs/design/visualization.md)承载的事实。截图离事件超过一次采样时，要核对中间是否还有事件；无法支持同刻比较就写缺项，不能用终态截图补造直播。看图模型只拿截图及具体读数问题，保留原话与通道限制。

错误日志的每条记录对到页面操作或事件。401 演练、预期拒绝、重启断开与讲不通的错误分别写明。页面显示英文原文与原始标识按已有用户决定处理，不能仅因英文或技术词出现就判缺陷。

## 4. 承诺能力的覆盖

逐项展开承诺，给事件 id、截图与运行身份；一条承诺包含多个动作时分别标出。结果使用已做到、部分做到、未做到、未测到，说明具体子项。部门工作停止与其后台进程停止分别核对。

补测在单独事项或实例上按[探针方法](probes.md)做，注明身份、任务与条件。用复现实例补证时核对配置与包身份。没有走到放行就不能补出放行证据。

## 5. 工具读数与原始证据

- 用 `readout.mjs` 重算，按部门及调用配置核对窗口和输入，不能借用另一个部门的窗口。
- 导出是原始证据，命令、输出和用户起始文件夹里的路径保留原样；发布报告另行脱敏。凭据值命中只报告位置。
- audit 低对比度候选先核对颜色和有效背景，背景未知就写未知。检查工具版本及已知误报，相同错误读数重复出现不能证明产品缺陷。
- `underfilled`、截断与对比度读数结合原截图解释；观感、机械读数和适用要求分别说明。
- 第一眼表原样汇入报告材料，给记录文件、截图、audit 和原话引用；已有记录就不能写成本轮没有。
- 原因只从被测版本的日志或对应版本源码定位。当前工作区已更新时写明差异，不能把当前实现当成旧实例的事实。

## 6. 产出

写 `expert.md`：卡点核对、R1 八件事实、画面对账、错误去向、覆盖清单、机械核对、第一眼引用。候选各带现象、步骤、期望依据、实际、证据、任务、影响、绕过办法和已有问题关系。

把证据引用与缺项写入本轮 `result.json`（格式见 [records.md](records.md)），根因推断明确标为推断。独立复现按 [reproduce.md](reproduce.md) 交接，问题成立与否由架构师裁决。
