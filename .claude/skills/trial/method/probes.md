# 补测与探索

固定任务结束以后，协调者先列承诺能力的覆盖缺口与高影响候选，再分配补测与探索时间。每项使用单独事项或实例，记录包身份、部门配置、输入和动作；结果单列，不混入 F1、R1 的固定读数。

新手段只执行分配的固定任务与页面观察。专家段、另起的探索代理或协调者执行以下操作。接口参数查被测实例的 `/openapi.json`，进程核对只针对本轮记录的实例。

| 方向 | 操作 | 留下的证据 |
| --- | --- | --- |
| 承诺缺口 | 优先补测没走到的询问、放行、恢复或取消子项 | 事件、画面、检查回执及运行身份；仍未做到就注明 |
| 信息顺序 | 从首屏判断事项、工作部门、上一步结论和下一步动作 | 视口图、文字及判断依据；体验候选交架构师裁决 |
| 可写性 | 在新事项中提交、修改输入，观察原文与版本提示 | 操作前后文字、输入事件、哪些状态允许修改 |
| 空状态 | 空项目、全新数据目录、不存在对象或不完整参数 | 页面、接口状态与原文；预期来自合同 |
| 时长与代价 | 页面耗时、用量和限额，离开页面再回来 | 前后采样时间、读数与导出；缺失与看漏分别处理 |
| 用户可纠正 | 错 Key、错误目录、空字段或长字段 | 点击位置、是否产生请求、页面版本、卡片与恢复链 |
| 撤销与回看 | 取消起了后台服务的事项，回放首尾和中间刻度 | 取消前后状态、事件、进程创建时间与端口归属 |
| 其他路径 | 窄窗口、缩放、刷新、重连、双页或重复提交 | 实际操作、截图、audit 和事件，一次只改待核对的条件 |

取消前记录服务端口、PID、创建时间与命令；三十秒以后核对原进程和端口，分开记录部门停止与后台服务退出。结束时只清理本轮启动并能确认身份的进程。

每项先做一次，再按主手册第 7 节决定是否独立复现；静态内容可以先由另一观察者复核。每次改变配置或目录状态均留痕；污染目录留在证据里，下一项用新的目录。

整轮剩余时间先用于承诺缺口和高影响复现，再做新探索。没有完成的项目写原因，报告允许部分完成。任务文本、配置或观察工具变化都要保留，不把不同条件结果加进同条件发生次数。
