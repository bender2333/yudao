# 新手段：只从 README 与页面走一遍

用一个新的上下文执行这一段。只接收本方法、README 路径、产品地址、任务输入文件、起始文件夹、归档目录、部门模型计划与浏览器端口。R1 另接收任务集的准备、四步、上限及「出岔子时」处理、四段输入原话、凭据环境变量名和本实例的启停命令。F1 与 R1 使用各自的记录文件。

只读 README 的启动方式与页面入口、页面上能看到的文字以及本方法。设计说明、源码、其他角色的分析、导出与服务日志由专家段阅读。页面上的事情用浏览器操作；R1 停止与重启本实例是任务指定的命令行动作。

## 准备与凭据

1. 按给定地址打开页面，从第一眼开始记录新手段耗时。
2. 在页面上配置连接、凭据、模型测试与部门默认。部门模型按本轮计划，不自行猜窗口、输出上限或更换模型。
3. 凭据只用环境变量引用输入到密码框：

   ```powershell
   node .claude/skills/trial/scripts/browser.mjs type --port <端口> --css "input[type=password]" --env YUDAO_EVAL_API_KEY --replace
   ```

   R1 配错一位加 `--wrong-key`，改回时去掉该参数。环境变量未继承时让协调者把用户级变量载入该进程，任务书和命令参数中均保留变量名。
4. 多行需求从文件输入，保留换行：`type --css <选择器> --file <输入文件> --replace`。不用 shell 命令替换拼接原文。

配置完成后由协调者保存实际部门配置及实例身份。F1 运行期间只观察页面和操作必要导航，输入、配置和事项状态只按任务规定改变；额外探索留给另一个事项或实例。任务到时的取消仍是规定动作。

## 每一步与四问

有点击或提交就立刻记录；等待时每两分钟观察一次。页面连续变化时记录实际看到的变化。使用浏览器输出的 `observed_at` 作为观察时间，保留时区。工具未返回、代理无产出或错过采样时，记录实际空档及原因，不能事后补造观察。

| 观察时间 | 看到什么 | 以为会怎样 | 实际怎样 | 犹豫或猜错 | 四问 | 证据 |
| --- | --- | --- | --- | --- | --- | --- |

每一步回答：

1. 知不知道这一步要做什么；
2. 看不看得到能做这件事的地方；
3. 能不能把它和自己的目标联系起来；
4. 做完能不能看出事情在推进。

有一问答否，或自己犹豫、猜错，就记卡点 `N-01` 起。表里写了犹豫或猜错时，同时给出卡点编号。页面静止时照实写内容与四问答案，不从后台推断它仍在推进。

卡点只写现象、当时的理解与具体点击位置（选择器、可见文字或坐标）。原因、是否违反设计和修法留给后续分析。

## 证据与第一眼

从第一次打开页面起，用 `watch --out <本段错误日志>` 收集控制台与失败请求。这一段只采集，不阅读日志。每次观察保存截图，关键文字用 `text` 存档；浏览器命令的 JSON 输出另存，保留真实采样时间。整页图可能限高，细节单独截取。

每个路由第一次打开时：

1. 保存视口截图：`shot --out <归档>/shots/<任务>-<页面>-first.jpg`，不加 `--full`。
2. 运行 `audit`，输出存到 `text/<任务>-<页面>-audit.json`，此时只存档。
3. 自己看图；不能直接读图时，把同一张图交给看图模型，问这一句原话：

   > 假装你是第一次看到这个页面的人，用三句话说：哪里看着不对、不协调、没填满、对不上、像没做完。只说看到的，不猜原因，不给修法。

4. 在本段文件的「第一眼」表保存原话：

   | 页面 | 观察时间 | 截图 | audit 文件 | 原话 |
   | --- | --- | --- | --- | --- |

## R1 的四步与中断

协调者把任务集的准备、四步、上限及「出岔子时」处理复制进本段任务书，四段输入保留原话；任务集的解释与专家判据留给专家段。记录配错凭据、卡片出现、改正凭据、选择继续、两段指导、停止、重启、追加输入各自发生的时间。

保存凭据后，先看页面版本、来源或结果提示是否改变；错 Key 没产生预定卡片就如实记录，不把重启丢失内存凭据产生的卡片算成同一次触发。恢复不了时按任务规定记录受阻步骤和剩余未执行步骤。

停止与重启使用协调者提供的 `instance.ps1` 命令及本实例清单，保留同一数据目录。恢复后先看页面，写完这一步，再继续操作。
