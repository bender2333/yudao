# 模块对齐

用户平时只看总图、对照表（`docs/design/architecture/name-map.md`）与工单指出的一两个契约文件，不读实现（`CLAUDE.md`「用户的参与方式」）。这个技能把一个模块的现状压成一屏，让用户只定走向；拆单与批准接在后面，一次会话做完三步，中间不清空上下文。

你以子架构师身份做（`CLAUDE.md`「子架构师」）：总图是正本，与总图不符时改设计说明与代码，不改总图；认为总图错了，登记到 `docs/architecture-issues.md`，这一条留给总架构师。

## 一、体检卡

1. 定位：在总图 `docs/architecture.html` 里找到目标是哪一节、哪个方框或哪道缝；在对照表里找到属于它的行；在 `docs/design/README.md` 里找到它的设计说明。总图里没有位置的东西停下来告诉用户，先交总架构师。
2. 派一个只读子代理（Explore）扫目标模块的代码，给它：目标、总图那一节的文字、对照表里相关的行、设计说明路径。要它回答：实现在哪些文件；哪些文件是契约或驱动（别的模块靠它们接上来的类型、协议、事件清单、路由表），哪些只是实现；对照表里标「不一致」「代码里还没有」的行在代码里现在是什么样；缝的两侧有没有保存契约之外的跨步状态、有没有写部门与阶段的名字（薄驱动的规矩）；开着的相关工单（`gh issue list --search "<关键词>" --state open`）。
3. 向用户输出体检卡，**不超过 15 行**，不贴代码：

   ```
   体检卡：<目标>
   总图位置：第 <n> 节 <方框或缝>；建设状态：<已建 | 建了一半 | 未建>；缝：<已定 | 未定>
   对照表：<k> 行不一致（<列总图的词 → 代码名>）；<m> 行代码里还没有
   抽查这几处（各管什么）：
   - <路径>:<行号> — <这是契约/驱动，管什么>
   - <路径>:<行号> — <…>
   不用看：<实现文件的目录或清单，一句话说明为什么不用看>
   薄封装：<哪里该包一层把现有实现接到缝上，或者不用>
   切片：<接上以后用户先能看到什么>
   走向，请选：
   1. <选项 A 一句话> / <选项 B 一句话>
   2. <第二题，可以没有>
   ```

   抽查文件给 1 至 3 个，只给契约或驱动文件，带行号；走向选择题 1 至 2 个，每个选项一句话写清代价。子代理报回的其余内容留在你的上下文里，不输出。
4. 完成：用户在每个选择题上选了一项，或者说这个模块现在不动。

## 二、归桶

用户定了走向以后，读 [`/to-parents`](../to-parents/SKILL.md) 按它做，范围写成这个模块、缝或道。桶里的父工单已经存在、里程碑已经开始派发时按它「已在派发的范围」只对桶与补缺。完成：每个桶有一张父工单，旧工单有去向，用户同意了那张表。

## 三、拆子工单与批准

对每张父工单读 [`/to-children`](../to-children/SKILL.md) 按它做。它第 5 步里需你批准环的子工单在这里当场办：

1. 标 `waiting`，把编号与「只改」清单交总架构师（会话消息，或告诉用户转达）；用户不逐张批准。
2. 总架构师核对清单落在哪一环、与对齐的走向一致，写批准行 `批准：总架构师 <日期>`，加 `kernel-approved`，改 `ready-for-agent`（`CLAUDE.md`「工单规范」）。
3. 完成：每张需你批准的子工单带 `kernel-approved`，或标 `waiting` 等总架构师；可重写与只增环的标 `ready-for-agent`。

## 收尾

- `claude_jour.md` 追加一条：目标、用户选的走向、父工单与子工单编号、批准了哪几张。
- 对照表的行不在这里改：立缝工单关闭时子架构师再把那一行改成「一致」。
- 用户的走向结论改了设计说明的，按 `CLAUDE.md`「冻结」一条处理已放出的工单。
