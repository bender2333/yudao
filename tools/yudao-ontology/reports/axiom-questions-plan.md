# 抽公理：先从本体提问题，再去文档找结论（方案）

11-10 你定的方向：从本体出发，先看现有对象，先问它们之间该有什么联系，再去文档找结论。原先那版「从带必须、必有的句子里挑」倒过来了。只出方案，研究分支，main 不动。

## 1. 为什么倒过来

挑「必须」句只能找到写成规矩的那部分，漏三类：

- 不带情态词的规矩。例如总图「任何职能随时可以询问另一个职能」，没有「必须」，却是一条公理；表格里的一行、「由谁做」的分工也是。
- 只在实例里看得出的规律：每个都这样，但没人写成一句话。
- 谁都没写的：本该有联系、文档一句没提。这是最值钱的空位，从文档出发永远找不到，因为找的是已经写了的。

而且挑句子没法说「挑全了」：情态词多在详细说明里，总图和术语表里少。

从对象出发反过来：问题由模型里的词汇生成，数得清；文档只当证据。文档没说，本身就是一个结论。

## 2. 从哪些对象出发

模型里有实例的类 18 个（部件 34、成果种类 20、缝 13、外环的状态 9、角色 7、职能 4、形态 4、层 4、事项的来源 4、目标函数 4、证据来源 4、环 3、轮转方式 3、结束方式 3、核验声明 2、询问、上限、停止原因清单）。

- 两两 153 对，其中 135 对之间模型里一条关系都没有。
- 已有的 18 种关系里，每一种都只覆盖了一部分实例，例如：
  - 角色有目标函数：7 个里 4 个有，缺「产品 · 工程」的两个角色和「一个角色」。
  - 成果种类有结束方式：20 个里 4 个有。
  - 部件在哪一环：34 个里 19 个有，缺工具、接口、模型服务等。
  - 核验声明的核验者：一条挂在职能上，一条挂在角色上。
  - 职能可以询问：有产品→工程、产品→质检、质检→工程、工程→质检，没有工程→产品、质检→产品。

## 3. 问题怎么生

符号层按几种固定的问法，对类与关系机械地生成问题；大模型只把它说成项目里的话，并划掉说不通的组合（划掉要写理由，你可以抽查）。

| 问法 | 例子 |
|---|---|
| 必有：每个 A 都有某个 B 吗 | 每个角色都必有一个目标函数吗，还是只有默认三职能里的有？ |
| 至多：一个 A 最多几个 B | 一份核验声明只有一个核验者吗？ |
| 对称：A 对 B 有，B 对 A 也有吗 | 可以询问是双向的吗，工程能问产品吗？ |
| 粒度：这条关系挂在哪一层 | 核验者是角色还是职能？两种都允许的话，什么时候用哪个？ |
| 跟着走：A 停了或结束了，B 怎样 | 提问方停了，询问分支怎样？ |
| 继承：A 属于 B，B 有 C，A 也有 C 吗 | 角色属于职能，职能可以询问，角色也可以询问吗？ |
| 有界：会循环或嵌套的，有上限吗 | 询问会嵌套，有没有层数上限？算谁的用量？ |

先后：先问已有关系里只覆盖了一部分的（约 30 道），再问同一句原句里一起出现、模型里却没连上的两类，最后其余的组合只列出来不逐个查。

能不能穷尽：在现有的词和这几种问法以内是穷尽的，题目数得清。模型里还没有的新概念不在里面，那些仍靠抽取：新段落进来，先长出新的类，再对它生问题。

## 4. 去文档找结论

每道题交给一个看不到参照模型答案的 agent，手里有题目、正名表和原句核对，去查总图、术语表、设计说明、定义文件、代码与测试。ADR、变更记录只当线索，不当证据，因为它们是历史。

结论只有五种：

1. 文档明说：写成公理草稿或断言，带原句。
2. 模型漏抽：文档明说、模型里少了几条实例。补进去，过三道检查就进，不用你点。
3. 现状都这样，但没写成规矩：报成提示，意图还是巧合要你判。
4. 文档说法互相打架：报违例候选，先照第 0.2 节分开设计矛盾和抽错。
5. 文档没说：空位，是一个设计问题，交你或总架构师。

## 5. 符号层核，然后交你

每条公理草稿先核三样：和现有模型一致吗；加进去以后推出哪些新空位、冒出哪些新违例；埋一个它该抓的错，它真抓得到吗。

交你时一批一页，按上面五种分组。要你点的只有三种：明说的公理、现状的提示、空位。漏抽的补断言自动进，事后列给你看。公理点过才进第 0 批。

## 6. 「必须」句还有什么用

不当生成器，留两个用处：

- 证据之一：一道题能对上一句「必须」，是最强的证据。
- 查问法够不够：每句「必须」都该对得上某道题。对不上，说明问法里少了一种关系，补一种问法。

## 7. 先试了两道（main 4fb600d）

- 可以询问是双向的吗：总图「任何职能随时可以询问另一个职能」；项目组织设计说明 4.9 默认写「其余职能」。结论：模型漏抽了工程→产品、质检→产品，补上；另有公理草稿「同一组织里任两个职能默认互相可以询问」。这句没有「必须」，原来的挑法挑不到。
- 询问有没有上限：术语表「询问」写被询问职能的上限取它自己的声明值与提问方剩余量中较小的一个，用量计入提问方；「询问链」写层数不超过规则参数，默认 3。代码里有规则参数 `organization.ask_chain_max_depth` 和测试，是独立证据。结论：明说，可以写成公理。注意这和子组织的层数上限是两样东西，不是矛盾。
